2.6 Validación de Datos y Gestión Básica de Errores

📋 Información Curricular y Resultados de Aprendizaje

Módulo: Programación (PRG — Código 0485) | 1º DAW | IES Mestre Ramón Esteve

Resultado de Aprendizaje: RA3 (Escribe y depura código, analizando y utilizando las estructuras de control del lenguaje).

Criterios de Evaluación asociados:

  • CEd: Depuración y verificación de programas mediante trazas y control de ejecución.
  • CEh: Tratamiento básico de situaciones anómalas en la entrada de datos.
  • CEi: Aplicación de buenas prácticas de programación (Clean Code) y robustez de código.

1. Errores de Compilación vs Tiempo de Ejecución (Runtime Exceptions)

A la hora de programar en Java, nos enfrentamos a dos naturalezas de errores radicalmente distintas:

  1. Errores de compilación (sintaxis): Son detectados por el compilador (javac) antes de que el programa llegue a ejecutarse (ej: falta un punto y coma ;, una variable no declarada o un error tipográfico en una palabra clave). Visual Studio Code los subraya en rojo inmediatamente.
  2. Errores en tiempo de ejecución (Excepciones o Runtime Exceptions): El programa compila a la perfección sin ningún error sintáctico, pero durante la ejecución real ocurre un evento imprevisto (ej: el usuario escribe "hola" cuando Scanner esperaba un número, o intentamos dividir entre cero 10 / 0). Si no se controlan, la Máquina Virtual de Java (JVM) aborta el programa bruscamente y muestra una traza de error en la consola.

2. La Vía Recomendada en Bucles: Validación Preventiva con Scanner (Clean Code)

💡 Regla de Oro de la Industria: «Exceptions should be exceptional»

Nunca utilices excepciones para controlar el flujo normal y habitual de un programa. Que un usuario se equivoque al teclear en la consola no es una catástrofe de software excepcional; es una situación perfectamente previsible.

Por eso, en este bloque de Estructuras de Control y Bucles, la forma más limpia, eficiente y elegante de validar datos es la validación preventiva mediante los métodos de inspección de la clase Scanner y bucles while.

2.1. Métodos de inspección de Scanner

  • sc.hasNextInt(): Devuelve true si el usuario ha introducido un número entero válido.
  • sc.hasNextDouble(): Devuelve true si ha introducido un número decimal válido.
  • sc.hasNextBoolean(): Devuelve true si ha introducido "true" o "false".

2.2. El patrón estándar de validación con bucle while

Código Java
JAVA 
package ut2.validacion;

import java.util.Scanner;

public class ValidacionPreventiva {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int edad = 0;

        System.out.print("Introduce tu edad (número entero positivo): ");

        // 1. Mientras lo que haya en el buffer NO sea un entero, avisamos y descartamos:
        while (!sc.hasNextInt()) {
            System.out.println("⚠️ Error: Debes escribir un número entero, no texto ni símbolos.");
            sc.next(); // ⚠️ Crucial: descartar la entrada incorrecta para vaciar el buffer
            System.out.print("Prueba otra vez: ");
        }

        // 2. Cuando llegamos aquí, la entrada es un entero válido 100% garantizado:
        edad = sc.nextInt();

        // 3. Validación de rango lógico con condicionales normales:
        if (edad >= 18 && edad <= 120) {
            System.out.println("✅ Acceso concedido. Tienes " + edad + " años.");
        } else if (edad < 18 && edad >= 0) {
            System.out.println("🚫 Acceso denegado: Eres menor de edad (" + edad + " años).");
        } else {
            System.out.println("❌ Error: La edad introducida no es biológicamente válida.");
        }

        sc.close();
    }
}

⚠️ ¡Cuidado con el vaciado del buffer de Scanner!

Dentro del cuerpo del while (!sc.hasNextInt()) es estrictamente obligatorio incluir sc.next(); o sc.nextLine();. Si lo olvidas, el dato incorrecto se queda atascado en el buffer del teclado y el bucle se convertirá en un bucle infinito.

3. Introducción Defensiva a try-catch-finally

A pesar de la validación preventiva, existen situaciones donde ciertas operaciones no pueden verificarse previamente con un simple if, o donde una conversión de texto a número puede fallar. Para estos casos, Java proporciona la estructura try-catch-finally:

try {
    // Bloque protegido: código que podría provocar un fallo imprevisto
} catch (TipoDeExcepcion e) {
    // Bloque de rescate: código que se ejecuta solo si ocurre ese error específico
} finally {
    // Bloque opcional: se ejecuta SIEMPRE (haya o no haya habido error)
}

4. 🚨 Aviso Pedagógico: ¿Debo poner try-catch en todos los ejercicios de bucles?

🛑 ¡NO! No satures tus ejercicios de bucles con bloques try-catch

En las actividades y retos de la UT2 (algoritmos matemáticos, números primos, tablas de multiplicar, menús de consola, series de Fibonacci, etc.):

  • La prioridad absoluta es dominar la lógica algorítmica: contadores, acumuladores, condiciones compuestas (&&, ||), centinelas y bucles for / while.
  • La validación recomendada es la preventiva: usa while (!sc.hasNextInt()) o condicionales if (numero <= 0).
  • No es obligatorio envolver cada lectura en try-catch, a menos que el enunciado del ejercicio lo exija de forma explícita.

Ejercicio 1: Calculadora de Divisiones Segura (CalculadoraDivisionSegura.java)

Desarrolla una aplicación de consola especializada en divisiones enteras:

  1. Solicita al usuario por teclado dos números enteros: el dividendo y el divisor.
  2. Implementa la división en un método independiente: public static int dividir(int a, int b) throws ArithmeticException.
  3. Gestiona de forma diferenciada:
    • La división por cero (ArithmeticException).
    • La introducción de letras o símbolos (InputMismatchException).
  4. Utiliza un bloque finally para asegurar el cierre del Scanner y emitir un mensaje de cierre de operación.
Código Java
JAVA 
package ut2.actividades;

import java.util.InputMismatchException;
import java.util.Scanner;

public class CalculadoraDivisionSegura {
    public static int dividir(int dividendo, int divisor) throws ArithmeticException {
        return dividendo / divisor;
    }

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        try {
            System.out.print("Introduce el dividendo (entero): ");
            int dividendo = sc.nextInt();

            System.out.print("Introduce el divisor (entero): ");
            int divisor = sc.nextInt();

            int cociente = dividir(dividendo, divisor);
            System.out.println("✅ Resultado de la división entera: " + cociente);
        } catch (ArithmeticException e) {
            System.err.println("⚠️ Error aritmético: Indeterminación matemática (no se puede dividir por 0).");
        } catch (InputMismatchException e) {
            System.err.println("⚠️ Error de formato: Has introducido letras o símbolos en lugar de números.");
        } finally {
            sc.close();
            System.out.println("🔒 Operación finalizada.");
        }
    }
}

Ejercicio 2: Conversor de Precios con Auditoría de Seguridad (ConversorPreciosSeguro.java)

Desarrolla un sistema capaz de convertir precios introducidos como texto:

  1. El usuario introduce el precio de un producto en formato texto (ej: "24.95").
  2. Intenta convertirlo a número decimal con Double.parseDouble().
  3. Captura la excepción NumberFormatException si el usuario introduce comas , o letras, manteniendo en tal caso el último precio válido registrado.
  4. Utiliza obligatoriamente un bloque finally para emitir el mensaje de registro de auditoría.
Código Java
JAVA 
package ut2.actividades;

import java.util.Scanner;

public class ConversorPreciosSeguro {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        double ultimoPrecioValido = 0.0;

        System.out.print("Introduce el precio del producto (ej. 24.95): ");
        String texto = sc.nextLine();

        try {
            double precio = Double.parseDouble(texto);
            if (precio <= 0) {
                System.out.println("⚠️ Aviso: El precio debería ser mayor que cero.");
            } else {
                ultimoPrecioValido = precio;
                System.out.printf("✅ Precio registrado correctamente: %.2f €%n", ultimoPrecioValido);
            }
        } catch (NumberFormatException e) {
            System.err.println("⚠️ Error: '" + texto + "' no tiene formato decimal válido (usa el punto '.' para decimales).");
            System.out.println("   Se mantendrá el último precio válido: " + ultimoPrecioValido + " €");
        } finally {
            System.out.println("📋 Auditoría: Registro de conversión de precio completado.");
            sc.close();
        }
    }
}
