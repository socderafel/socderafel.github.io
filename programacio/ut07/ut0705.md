# 7.5 Consultes de selecció (SELECT / executeQuery)

## 1. Navegació d'un `ResultSet`

Com ja es ha vist, en un objecte *ResultSet* es troben els resultats de l'ejecució d'una sentència SQL. Per tant, un objecte *ResultSet* conté les files que satisfacen les condicions d'una sentència SQL, i ofereix mètodes de navegació pels registres com `next()` que desplaza el cursos al següent registre del *ResultSet*.

A més d'aquest mètode de desplazament bàsic, existeixen altres de desplazament lliure que podrem utilitzar sempre i quan el *ResultSet* siga de tipus `ResultSet.TYPE_SCROLL_INSENSITIVE` o `ResultSet.TYPE_SCROLL_SENSITIVE` com es ha aquest abans.

Alguns d'aquests mètodes són:

- 

**`void beforeFirst()`**: mueve el cursor abans de la primera fila.

- 

**`boolean first()`**: mueve el cursor a la primera fila.

- 

**`boolean next()`**: mueve el cursor a la següent fila. Permitido en tots els tipus de ResultSet.

- 

**`boolean previous()`**: mueve el cursor a la fila anterior.

- 

**`boolean last()`**: mueve el cursor a la última fila.

- 

**`void afterLast()`**: mover el cursor després de la última fila.

- 

**`boolean absolute(int row)`**: posiciona el cursor en el número de registre indicat. Cal tindre en compte que el primer registre és el 1, no el zero. 

<details markdown="1">

<summary>💡 Exemple `absolute(n)`</summary>

`absolute(7)` desplazará el cursor al setè registre. Si  valor és negatiu es posiciona en el número de registre indicat però començant a comptar des del final (l'últim és el -1). Per exemple si té 10 registres i llamamos `absolute(-2)` es desplazará al registre número 9.

</details>

- **`boolean relative(int registros)`**: desplaza el cursor un número relatiu de registres, que pot ser positiu o negatiu. 

<details markdown="1">

<summary>💡 Exemple `relative(n)`</summary>

Si el cursor està en el registre 5 i llamamos a `relative(10)` es desplazará al registre número 15. Si després llamamos a `relative(-4)` es desplazará al registre 11.

</details>

Els mètodes que retornen un tipus boolean devolverán *true* si ha sigut possible mover el cursor a un registre vàlid, i *false* en cas contrari, per exemple si no té cap registre o hem saltado a un número de registre que no existeix.

Tots aquests mètodes poden produir una excepció de tipus *SQLException*.

També existeixen altres mètodes relacionats amb la posició del cursor.

- **`int getRow()`**: retorna el número de registre actual. Zero si no hi ha registre actual.

- **`boolean isBeforeFirst()`**: retorna *true* si el cursor està abans del primer registre.

- **`boolean isFirst()`**: retorna *true* si el cursor està en el primer registre.

- **`boolean isLast()`**: retorna *true* si el cursor està en l'últim registre.

- **`boolean isAfterLast()`**: retorna *true* si el cursor està després de l'últim registre.

## 2. Obtenent dades del `ResultSet`

Els mètodes *getXXX()* ofereixen els mitjans per a recuperar els valors de les columnes (camps) de la fila (registre) actual del *ResultSet*. No és necessari que les columnes siguen obtenides utilitzant un ordre determinat.

Per a designar una columna podem utilitzar el seu nom o bé el seu número (començant per 1).

Per exemple si la segona columna d'un objecte *ResultSet* es anomena *títol* i emmagatzema dades de tipus *String*, es podrà recuperar el seu valor de les dos formes següents:

```java
// rs es un objeto ResultSet
String valor = rs.getString(2);
String valor = rs.getString("titulo");
```

> **📌  **
> 

> És important tindre en compte que les columnes es numeran d'esquerra a dreta i que la primera és la número 1, no la zero.
> També que les columnes no són case sensitive, és a dir, no distingeixen entre majúscules i minúscules.

> **📌 A tindre en compte**
> 

> La informació referente a les columnes d'un ResultSet es pot obtindre llamant al **mètode getMetaData()** que retornarà un objecte *ResultSetMetaData* que contendrá el número, tipus i propietats de les columnes del *ResultSet*.
EXEMPLE:

```sql
import java.sql.*;

public class EjemploResultSetMetaData {
    private static final String JDBC_URL = "jdbc:mysql://localhost:3306/pr_tuNombre";
    private static final String USUARIO = "pr_tuNombre";
    private static final String PASSWD = "1234";

    public static void main(String[] args) {
        try (Connection con = DriverManager.getConnection(JDBC_URL, USUARIO, PASSWD);
             Statement stmt = con.createStatement();
             ResultSet rs = stmt.executeQuery("SELECT id, nombre, fecha_ingreso, salario FROM proveedores")) {

            // Obtener metadata del ResulSet
            ResultSetMetaData rsmd = rs.getMetaData();

            // Obtener el número de columnas
            int columnCount = rsmd.getColumnCount();
            System.out.println("Número de columnas: " + columnCount);

            // Listar las columnas de detalles
            for (int i = 1; i <= columnCount; i++) {
                String columnName = rsmd.getColumnName(i);
                String columnType = rsmd.getColumnTypeName(i);
                int columnDisplaySize = rsmd.getColumnDisplaySize(i);
                boolean isNullable = rsmd.isNullable(i) == ResultSetMetaData.columnNullable;

                System.out.println("Columna " + i + ":");
                System.out.println("  Nombre: " + columnName);
                System.out.println("  Tipo: " + columnType);
                System.out.println("  Tamaño display: " + columnDisplaySize);
                System.out.println("  Nullable: " + isNullable);
            }

            // Iterar sobre el conjunto de resultados
            while (rs.next()) {
                for (int i = 1; i <= columnCount; i++) {
                    System.out.print(rs.getString(i) + " ");
                }
                System.out.println();
            }

        } catch (SQLException ex) {
            System.out.println("Error de SQL: " + ex.getMessage());
        }
    }
}
```

Si coneixem el nom d'una columna, però no el seu índex, el mètode **`findColumn()`** pot ser utilitzat per a obtindre el número de columna, pasándole com argument un objecte *String* que siga el nom de la columna corresponent, aquest mètode ens retornarà un enter que serà l'índex corresponent a la columna.

## 3. Tipus de dades i conversions

Quan es llança un mètode *getXXX()* determinat sobre un objecte ResultSet per a obtindre el valor d'un camp del registre actual, el driver JDBC converteix el dada que es vol recuperar al tipus Java especificat i llavors retorna un valor Java adequat. Per exemple si utilitzem el mètode *getString()* i el tipus del dada en la base de dades és *VARCHAR*, el driver JDBC convertirá el dada VARCHAR de tipus SQL a un objecte *String* de Java.

Alguna cosa semblant succeeix amb altres tipus de dades SQL com per exemple *DATE*. Podrem accedir a ell tant amb *getDate()* com amb *getString()*. La diferència és que el primer retornarà un objecte Java de tipus *Date* i el segon retornarà un *String*.

Sempre que siga possible el driver JDBC convertirá el tipus de dada emmagatzemat en la base de dades al tipus solicitado pel mètode *getXXX()*, però hi ha conversions que no es poden realitzar i lanzarán una excepció, com per exemple si intentem fer un *getInt()* sobre un camp que no conté un valor numèric.

## 4. Sentències que no retornen dades

Les executem amb el mètode `executeUpdate`. Seran totes les sentències SQL **excepte el SELECT**, que és la de consulta. És a dir, ens servirà per a les següents sentències:

- Sentències que canvien les estructures internes de la BD on es guarden les dades (instruccions conegudes amb les sigles **DDL**, de l'anglès **Data Definition Language**), com per exemple `CREATE TABLE`, `CREATE VIEW`, `ALTER TABLE`, `DROP TABLE`, …,

- Sentències per a otorgar permisos als usuaris existents o crear altres nous (subgrupo d'instruccions conegudes com **DCL** o **Data Control Language**), com per exemple `GRANT`.

- I també les sentències per a modificar les dades guardats utilitzant les instruccions `INSERT`, `UPDATE` i `DELETE`.

Encara que es tracta de sentències molt dispares, des del punt de vista de la comunicació amb el SGBD es comporten de manera molt similar, seguint el següent patró:

1. Instanciació del `Statement` a partir d'una connexió activa.

1. Ejecució d'una sentència SQL passada per paràmetre al mètode `executeUpdate`.

1. Tancament de l'objecte `Statement` instanciado.

Mirem aquest exemple, en el que crearem una taula molt senzilla en la Base de dades MySql/network.

## 5. Sentències que retornen dades

Les executem amb el mètode `executeQuery`. Servirà per a la sentència **SELECT** (sentència de consulta). Les dades que ens retorne aquesta sentència les haurem de guardar en un objecte de la classe `java.sql.ResultSet`, és a dir conjunt de resultat. Per tant, l'ejecució de les consultes tindrà una forma similar a la següent:

```java
ResultSet rs = st.executeQuery(sentenciaSQL);
```

- L'objecte `ResultSet` conté el resultat de la consulta organitzat per files, per la qual cosa en cada moment es pot consultar una fila.

- Per a anar visitant totes les files d'una a una, anirem llamant el mètode `next()` de l'objecte `ResultSet`, ja que cada vegada que s'execute `next` avanzará a la següent fila. 

- Inmediatament després d'una ejecució, el `ResultSet` es troba posicionado justo abans de la primera fila, per tant per a accedir a la primera fila serà necessari executar `next` una vegada. 

- Quan les files es acaven, el mètode `next` retornarà fals.

Des de cada fila es podrà accedir al valor de les seues columnes amb ajuda de diversos mètodes `getXXX` disponibles segons el tipus de dades a retornar i passant per paràmetre el número de columna que deseamos obtindre. El nom dels mètodes comença per `get` seguit del nom del tipus de dades. Així, si volem recuperar la segona columna, sabent que és un dada de tipus `String` caldrà executar:

```java
rs.getString(2);
```

Les columnes es comencen a comptar a partir del **valor 1** (no zero). La major part dels SGDB suporten la possibilitat de passar per paràmetre el nom de la columna, però no tots, així que normalment es opta pel paràmetre numèric.

Per exemple *MySql* sí que deixa accedir per nom, per tant, suponent que el camp 1 es anomena *id*, també es pot fer:

```java
rs.getInt("id");
```

En aquest exemple accedim a la taula usuaris i mostrem tots els seus registres

```sql
public void getAllUsers() throws SQLException{ 
    Statement st = con.createStatement(); 
    ResultSet rs = st.executeQuery("SELECT FROM usuarios"); 
    while (rs.next()){ 
        System.out.print(rs.getInt(1) + "\t"); 
        system.out.print(rs.getString(2) + "\t"); 
        system.out.println(rs.getString(3)); 
    }
    //Siempre se debe cerrar
    st.close(); 
    rs.close(); 
}
```

## 6. Assegurar la liberació de recursos

Les instàncies de `Connection` i les de `Statement` guarden, en memòria, molta informació relacionada amb les ejecucions realitzades. A més, mentre continúan activas mantenen en el SGBD una sessió oberta, que supondrá un conjunt important de recursos oberts, destinats a servir de forma eficient les peticions dels clients. És important tancar aquests objectes per a liberar recursos tant del client com del servidor.

Si en un mateix mètode hem de tancar un objecte `Statement` i el `Connection` a partir del qual l'hem creat, es haurà de tancar primer el `Statement` i després el `Connection`. Si el fem al revés, quan intentem tancar el `Statement` ens saltará una excepció de tipus `SQLException`, ja que el tancament de la connexió li hi hauria dejado inaccesible.

A més de respetar l'ordre, assegurar la liberació dels recursos situant les operacions de tancament dins d'un bloc `finally`. D'aquesta manera, encara que es produzcan errors, no es dejarán d'executar les instruccions de tancament.

Cal tindre en compte encara un detall més quan siga necessari realitzar el tancament de diversos objectes alhora. En aquest cas, encara que les situamos una després d'una altra, totes les instruccions de tancament dins del bloc `finally`, no seria suficient garantía per a assegurar l'ejecució de tots els cierres, ja que, si mentre es produeix el tancament d'un dels objectes es llança una excepció, els objectes invocats en una posició posterior a la del que es ha producido l'error no es cerrarán.

La solució d'aquest problema passa per evitar el lanzament de qualsevol excepció durant el procés de tancament. Una possible forma és encapsular cada tancament entre sentències `try-catch` dins del `finally`.

<details markdown="1">

<summary>💡 Ací tens un exemple</summary>

```sql
private void getAllUsers() {
    Statement st = null;
    ResultSet rs = null; 

    try { 
        st = con.createStatement(); 
        rs = st.executeQuery("SELECT * FROM usuarios"); 

        while (rs.next()){ 
            System.out.print(rs.getInt(1) + "\t"); 
            system.out.print(rs.getString(2) + "\t"); 
            System.out.println(rs.getString(3)); 
        }

    } catch(SQLException e){ 
        System.out.println "ERROR: " + e.getMessage());

    } finally { 
        try{ 
            //Siempre se debe cerrar todo lo abierto
            if (rs != null) {
                rs.close();
            }
        } catch (java.sql.SQLException ex){ 
            System.out+.printIn("ERROR: " + ex.getMessage()); 
        }

        try{ 
            //Siempre se debe cerrar todo lo abierto 
            if (st != null) {
                st.close();
            }
        } catch (java.sql.SQLException ex){ 
            System.out.printIn("ERROR: " + ex.getMessage()); 
        }
    }
}
```

</details>
