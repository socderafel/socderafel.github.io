1. ¿Por qué estudiamos las excepciones a fondo en la UT5?

En la UT2 vimos una primera toma de contacto defensiva con try-catch para evitar que la consola se cerrase con números o divisiones por cero. Sin embargo, en el mundo real del software corporativo, las excepciones son objetos de pleno derecho.

Ahora que dominamos los pilares fundamentales de la Programación Orientada a Objetos (POO):

  • Sabemos qué es una Clase, cómo definir atributos y métodos constructores (UT4).
  • Sabemos cómo funciona la Herencia mediante la palabra clave extends (UT5).
  • Sabemos cómo invocar a la superclase mediante super(...) y aplicar el Polimorfismo (UT5).

Con esta base conceptual sólida, podemos comprender con total claridad cómo está diseñado el sistema de tratamiento de errores de Java.

2.1. Comparativa de las tres grandes ramas

Categoría Superclase ¿Comprobada por compilador? Significado y causa habitual ¿Debemos capturarla?
Errores Críticos del Sistema (Error) java.lang.Error ❌ No (Unchecked) Fallos irrecuperables de la Máquina Virtual (JVM) o del sistema operativo (falta de memoria física OutOfMemoryError, desbordamiento de pila recursiva StackOverflowError). NO. El programa no puede recuperarse; debe terminar.
Excepciones de Tiempo de Ejecución (RuntimeException) java.lang.RuntimeException ❌ No (Unchecked) Bugs y fallos de lógica del propio programador (acceder a un índice fuera de rango ArrayIndexOutOfBoundsException, invocar un método sobre una referencia null con NullPointerException, pasar un argumento no válido con IllegalArgumentException). Se deben prevenir con código limpio (condicionales if (ref != null)). No es obligatorio rodearlas de try-catch.
Excepciones Comprobadas (Checked Exceptions) Cualquier subclase directa de java.lang.Exception (salvo RuntimeException) ✅ SÍ (Obligatorias) Situaciones anómalas externas ajenas al programador pero previsibles en producción (el fichero a leer no existe FileNotFoundException, la base de datos se ha caído SQLException, la red no responde IOException). SÍ. El compilador obliga por contrato a gestionarlas: o las capturas con try-catch o las declaras en la firma con throws.

3. Lanzamiento y Propagación: throw vs throws

Palabra Clave Rol Sintáctico ¿Dónde se coloca? Significado
throw (con w) Verbo de acción (orden imperativa) Dentro del cuerpo de un método Instancia y lanza una excepción inmediatamente: throw new MiExcepcion("Mensaje");
throws (con s) Cláusula de contrato (declaración formal) En la firma / cabecera de un método Advierte al programador que llame a este método de que puede emitir este tipo de excepción: public void abrir() throws IOException

3.1. Ejemplo de throw y throws en acción

Código Java
JAVA 
package ut5.excepciones;

public class CalculadoraAvanzada {

    // La cláusula 'throws' en la firma avisa a quien llame a este método
    // de que está obligado a gestionar o volver a propagar la excepción:
    public static double calcularRaizCuadrada(double numero) throws IllegalArgumentException {
        if (numero < 0) {
            // La instrucción 'throw' (verbo) instancia y dispara la excepción inmediatamente:
            throw new IllegalArgumentException(
                "No se puede calcular la raíz cuadrada real de un número negativo: " + numero
            );
        }
        return Math.sqrt(numero);
    }

    public static void main(String[] args) {
        try {
            System.out.println("Raíz de 25: " + calcularRaizCuadrada(25));
            System.out.println("Raíz de -9: " + calcularRaizCuadrada(-9)); // Provoca error
        } catch (IllegalArgumentException e) {
            System.out.println("⚠️ Excepción capturada en main: " + e.getMessage());
        }
    }
}

4. Creación de Excepciones Personalizadas (Custom Exceptions)

Aunque Java cuenta con centenares de excepciones estándar, en aplicaciones profesionales necesitamos modelar errores propios del dominio de nuestro negocio (ej: SaldoInsuficienteException, VehiculoNoDisponibleException, ContrabandoException).

4.1. ¿Cómo diseñar una excepción personalizada?

  1. Heredar de la clase adecuada:
    • Hereda de Exception si deseas que sea una excepción comprobada (checked) que obligue al invocador a gestionarla explícitamente.
    • Hereda de RuntimeException si deseas que sea no comprobada (unchecked).
  2. Invocar a la superclase: En el constructor, pasa el mensaje descriptivo a la superclase mediante super(mensaje);.
  3. Añadir atributos de contexto: Puedes almacenar variables de estado (ej: el saldo actual, el identificador de usuario) para que quien capture la excepción tenga acceso a información técnica detallada del problema.

4.2. Paso 1: La clase de excepción personalizada

Código Java
JAVA 
package ut5.banco;

/**
 * Excepción personalizada de tipo 'Checked' (hereda de Exception).
 * Incorpora atributos de contexto para aportar información técnica del fallo.
 */
public class SaldoInsuficienteException extends Exception {
    private final double saldoActual;
    private final double importeSolicitado;

    // Constructor que recibe el mensaje y los datos de contexto del problema:
    public SaldoInsuficienteException(String mensaje, double saldoActual, double importeSolicitado) {
        super(mensaje); // Invoca al constructor de java.lang.Exception
        this.saldoActual = saldoActual;
        this.importeSolicitado = importeSolicitado;
    }

    public double getSaldoActual() {
        return saldoActual;
    }

    public double getImporteSolicitado() {
        return importeSolicitado;
    }

    // Método de utilidad para saber cuánto dinero le falta al usuario:
    public double getDeficit() {
        return importeSolicitado - saldoActual;
    }
}

4.3. Paso 2: La clase de negocio que la utiliza y lanza

Código Java
JAVA 
package ut5.banco;

public class CuentaBancaria {
    private final String iban;
    private final String titular;
    private double saldo;

    public CuentaBancaria(String iban, String titular, double saldoInicial) {
        if (saldoInicial < 0) {
            throw new IllegalArgumentException("El saldo inicial no puede ser negativo.");
        }
        this.iban = iban;
        this.titular = titular;
        this.saldo = saldoInicial;
    }

    public void retirar(double cantidad) throws SaldoInsuficienteException {
        if (cantidad <= 0) {
            throw new IllegalArgumentException("La cantidad a retirar debe ser mayor que cero.");
        }
        if (cantidad > this.saldo) {
            // Disparamos nuestra propia excepción personalizada con contexto completo:
            throw new SaldoInsuficienteException(
                "Operación rechazada: Fondos insuficientes en la cuenta " + iban,
                this.saldo,
                cantidad
            );
        }
        this.saldo -= cantidad;
        System.out.printf("✅ Retirada de %.2f € efectuada. Saldo restante: %.2f €%n", cantidad, saldo);
    }

    public double getSaldo() {
        return saldo;
    }

    public String getIban() {
        return iban;
    }
}

5. La Instrucción try-with-resources (Interfaz AutoCloseable)

Desde Java 7 existe la construcción try-with-resources: cualquier objeto cuya clase implemente la interfaz estándar java.lang.AutoCloseable se cerrará de manera automática y garantizada al finalizar el bloque try, tanto si termina con éxito como si se produce una excepción imprevista.

Código Java
JAVA 
package ut5.recursos;

import java.util.Scanner;

public class EjemploTryWithResources {
    public static void main(String[] args) {
        // try-with-resources: cualquier objeto que implemente AutoCloseable
        // se cerrará AUTOMÁTICAMENTE al salir del bloque sin necesidad de finally:
        try (Scanner sc = new Scanner(System.in)) {
            System.out.print("Introduce tu nombre: ");
            String nombre = sc.nextLine();
            System.out.println("Hola, " + nombre + ". Tu recurso Scanner se cerrará solo.");
        } // Aquí se invoca sc.close() de forma garantizada incluso si hay un fallo
    }
}

6. ✍️ Actividades Prácticas de la Unidad (UT5)

Actividad 1: Gestión de Alquiler de Flota de Vehículos (FlotaVehiculos.java)

Una empresa de alquiler necesita controlar la disponibilidad de su flota mediante Programación Orientada a Objetos y Herencia:

  1. Crea la excepción personalizada comprobada VehiculoNoDisponibleException extends Exception que guarde en un atributo la matrícula afectada.
  2. Crea una clase abstracta Vehiculo con atributos protegidos matricula, marca, alquilado y el método abstracto public abstract void alquilar() throws VehiculoNoDisponibleException.
  3. Implementa las subclases Coche, Moto y Furgoneta.
  4. Si un cliente intenta alquilar un vehículo cuyo estado ya es alquilado == true, dispara la excepción personalizada informando de la matrícula en el mensaje.
Código Java
JAVA 
package ut5.actividades.vehiculos;

// 1. Excepción personalizada con matrícula de contexto
class VehiculoNoDisponibleException extends Exception {
    private final String matricula;
    public VehiculoNoDisponibleException(String matricula, String mensaje) {
        super(mensaje + " [Matrícula: " + matricula + "]");
        this.matricula = matricula;
    }
    public String getMatricula() { return matricula; }
}

// 2. Clase abstracta Vehiculo con método polimórfico
abstract class Vehiculo {
    protected String matricula;
    protected String marca;
    protected boolean alquilado;

    public Vehiculo(String matricula, String marca) {
        this.matricula = matricula;
        this.marca = marca;
        this.alquilado = false;
    }
    public abstract void alquilar() throws VehiculoNoDisponibleException;
    public void devolver() {
        this.alquilado = false;
        System.out.println("Vehículo " + matricula + " devuelto con éxito.");
    }
}

// 3. Subclase concreta Coche
class Coche extends Vehiculo {
    public Coche(String matricula, String marca) { super(matricula, marca); }
    @Override
    public void alquilar() throws VehiculoNoDisponibleException {
        if (alquilado) {
            throw new VehiculoNoDisponibleException(matricula, "El vehículo ya se encuentra reservado actualmente.");
        }
        alquilado = true;
        System.out.println("🚗 Coche " + marca + " (" + matricula + ") alquilado correctamente.");
    }
}

Actividad 2: Simulador de Pasarela de Pagos Multicliente (PasarelaPagos.java)

Diseña un sistema financiero polimórfico capaz de trabajar con múltiples pasarelas de pago:

  1. Crea dos excepciones personalizadas independientes:
    • ImporteInvalidoException: Si el importe a abonar es menor o igual a 0 €.
    • SaldoInsuficienteException: Si el importe supera el saldo disponible.
  2. Crea la clase abstracta MetodoPago con método pagar(double importe) y subclases TarjetaCredito, PayPal y Bizum.
  3. Almacena varias formas de pago en una colección polimórfica List<MetodoPago>.
  4. Recorre la lista intentando aplicar el mismo cargo a todos ellos.
  5. Regla estricta: Captura cada excepción en bloques catch independientes; está prohibido usar un único catch(Exception e) genérico.
Código Java
JAVA 
package ut5.actividades.pasarela;

import java.util.List;

class ImporteInvalidoException extends Exception {
    public ImporteInvalidoException(String msg) { super(msg); }
}

abstract class MetodoPago {
    protected String titular;
    protected double saldoDisponible;
    public MetodoPago(String titular, double saldo) {
        this.titular = titular;
        this.saldoDisponible = saldo;
    }
    public void pagar(double importe) throws ImporteInvalidoException, SaldoInsuficienteException {
        if (importe <= 0) {
            throw new ImporteInvalidoException("El importe a pagar debe ser mayor que cero.");
        }
        if (importe > saldoDisponible) {
            throw new SaldoInsuficienteException("Fondos insuficientes", saldoDisponible, importe);
        }
        saldoDisponible -= importe;
        System.out.printf("💳 Cargo de %.2f € realizado con éxito en %s (%s). Restante: %.2f €%n",
                          importe, getClass().getSimpleName(), titular, saldoDisponible);
    }
}

7. 🏆 Reto de la Unidad: Hub Logístico DistribueixValència

Reto de Programación: Triaje Automatizado con Excepciones de Seguridad

El centro logístico automatizado de la Comunitat Valenciana necesita un software de control de paquetería:

  1. Crea la clase Paquete con codigo, pesoKg, destino y descripcionContenido.
  2. Implementa dos excepciones personalizadas:
    • PesoExcedidoException: Se dispara si el paquete supera los 50.0 kg (límite mecánico de la cinta).
    • ContrabandoException: Se dispara si la descripción contiene términos prohibidos (ej: "explosivo", "químico", "armas").
  3. El método triarPaquete(Paquete p) throws PesoExcedidoException, ContrabandoException analiza el paquete. Si pasa los controles, se añade a la cola de reparto; si falla, se detiene la cinta y se registra la incidencia en el informe de seguridad.
Código Java
JAVA 
package ut5.retos.hubvalencia;

// 1. Excepciones de Seguridad del Hub Logístico
class ContrabandoException extends Exception {
    private final String mercanciaProhibida;
    public ContrabandoException(String codigo, String mercancia) {
        super("ALERTA SEGURIDAD en paquete " + codigo + ": Mercancía prohibida: " + mercancia);
        this.mercanciaProhibida = mercancia;
    }
    public String getMercancia() { return mercanciaProhibida; }
}

class PesoExcedidoException extends Exception {
    private final double peso;
    public PesoExcedidoException(String codigo, double peso, double limite) {
        super("CINTA DETENIDA en paquete " + codigo + ": Peso (" + peso + " kg) supera límite de " + limite + " kg");
        this.peso = peso;
    }
}
