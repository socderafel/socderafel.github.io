# 6.2 Lectura i escriptura de fitxers

En ocasions necessitem que les dades que introdueix l'usuari o que produeix un programa persistan quan éste finalitza; és a dir, que es conserven quan el programa acaba la seua ejecució. Per a això és necessari l'ús d'una base de dades o de fitxers, que permitan guardar les dades en un emmagatzematge secundari com un pendrive, disc duro, DVD, etc.

Abordarem distints aspectes relacionats amb l'emmagatzematge en fitxers: 

- Introducció a conceptes bàsics com els de registre i camp.

- Classificació dels fitxers segons el contingut i forma d'accés.

- Operacions bàsiques amb fitxers de distint tipus.

## 1. Registres i camps

Llamamos **camp** a un dada en particular emmagatzemat en una base de dades o fitxer. Un camp pot ser el nom d'un client, la data de naixement d'un alumne, el número de telèfon d'un comercio. Els camps poden ser de distints tipus: alfanumérics, numèrics, dates, etc.

L'agrupació d'un o més camps formen un **registre**. Un registre d'alumne podria consistir, per exemple, dels següents camps:

```java
1. Número de expediente.
2. Nombre y apellidos.
3. Domicilio.
```

Un fitxer pot estar format per registres, la qual cosa dotaría al fitxer d'estructura. En un fitxer d'alumnes tindríem un registre per cada alumne. Els camps del registre serien cada un de les dades que s'emmagatzema de l'alumne: nº expediente, nom, etc …

En Java no existeixen específicament els conceptes de camp i registre. El més similar que coneixem són les classes (similars a un registre) i, dins de les classes, els atributs (similars a camps). 

Tampoc en Java els fitxers estan formats per registres. Java considera els fitxers simplement com fluxos secuencials de bytes. Quan s'obri un fitxer s'associa a ell un flux (*stream*) a través del qual es llegix o escriu en el fitxer.

Exemple de fitxer:

```java
65255
José Mateo Ruiz
C/ Paz, …
56488
Ángela Lopez Villa
Av. Blas..
24645
Armando García Ledesma
C/ Tuej …
```

Exemple de registre en el fitxer anterior:

```java
24645
Armando García Ledesma
C/ Tuej …
```

Exemple de camp en el registre anterior:

```java
Armando García Ledesma
```

## 2. Fitxers de text VS fitxers binaris

Des d'un punt de vista a molt sota nivell, un fitxer és un conjunt de bits emmagatzemats en memòria secundària, accesibles a través d'una ruta i un nom de fitxer. 

Aquest punt de vista a sota nivell és massa simple, ja que quan es recupera i tracta la informació que conté el fitxer, eixos bits es agrupen en unitats majors que les dotan de significat. Així, depenent de quin és el contingut del fitxer (de com es interpretan els bits que conté el fitxer), podem distingir dos tipus de fitxers:

- Fitxers de text (o de caràcters).

- Fitxers binaris (o de bytes).

Un **fitxer de text** està format únicament per caràcters. Els bits que conté es interpretan atenent a una taula de caràcters, ja siga ASCII o Unicode. Aquest tipus de fitxers es poden obrir amb un editor de text pla i són, en general, llegibles. Per exemple, els fitxers `.java` que contenen els programes que elaboramos, són fitxers de text.

D'altra banda, els **fitxers binaris** contenen seqüències de bytes que es agrupen per a representar un altre tipus d'informació: números, sonits, imatges, etc. Un fitxer binari es pot obrir també amb un editor de text pla però, en aquest cas, el contingut serà ininteligible. Existeixen molts exemples de fitxers binaris: el fitxer `.exe` que conté la versió ejecutable d'un programa és un fitxer binari.

Les operacions de lectura/escriptura que utilitzem a l'accedir des d'un programa a un fitxer de text estan orientades al caràcter: llegir o escriure un caràcter, una seqüència de caràcters, una línia de text, etc. En canvi les operacions de lectura/escriptura en fitxers binaris estan orientades a byte: es llegixen o escriuen dades binaris, com enters, bytes, double, etc.

## 3. Accés seqüencial VS accés directe

Existeixen dos maneres d'accedir a la informació que conté un fitxer:

- Accés seqüencial.

- Accés directe (o aleatorio).

Amb **accés seqüencial**, per a poder llegir el byte que es troba en determinada posició del fitxer és necessari llegir, prèviament, tots els bytes anteriors. A l'escriure, les dades es sitúan en el fitxer un a continuació de l'un altre, en el mateix ordre en que es introdueixen. És a dir, la nova informació es col·loca en el fitxer a continuació de la que ja existeix. No és possible realitzar modificacions de les dades existents, tan només afegir al final.

No obstant això, amb el **accés directe**, és possible accedir a determinada posició (adreça) del fitxer de manera directa i, posteriorment, fer l'operació de lectura o escriptura deseada.

No sempre és necessari realitzar un accés directe a un fitxer. En moltes ocasions el processament que realitzem de les seues dades consisteix en l'escriptura o lectura de tot el fitxer seguint l'ordre en que es troben. Per a això basta amb un accés seqüencial.

## 4. Streams per a treballar amb fitxers

Per a treballar amb fitxers disposem de les següents classes:

| Streams per a fitxers | Fitxers binaris | Fitxers de text |
| --- | --- | --- |
| per a lectura | **`FileInputStream`** | **`FileReader`** |
| per a escriptura | **`FileOutputStream`** | **`FileWriter`** |

- `FileInputStream` permet llegir bytes d'un fitxer.

- `FileOutputStream` permet escriure bytes d'un fitxer.

- `FileReader` permet llegir d'un fitxer un o diversos caràcters.

- `FileWriter` permet escriure en un fitxer un o diversos caràcters o un String.  

> **📌 Consulta**
> 

> Consulta en la documentació els distints constructors disponibles per a aquestes classes.

<details markdown="1">

<summary>💡 Exemple: crear un fitxer</summary>

En el següent exemple veiem com crear un fitxer de text i escriure una frase en ell.

```java
package UT06.P2_Ficheros;

import java.io.*;

public class P2_1_CrearFichero {

    public static void main(String[] args) {
        FileWriter f = null;
        try {
            f = new FileWriter("texto.txt");
            f.write("Este texto se escribe en el fichero\n\r");

        } catch (IOException e) {
            System.out.println("Problema al abrir o escribir ");

        } finally {
            if (f != null) {
                try {
                    f.close();
                } catch (IOException e) {
                    System.out.println("Problema al cerrar el fichero");
                }
            }
        }
    }
}
```

La creació del `FileWriter` pot provocar `IOException`, el mateix que el mètode `write`. Per això les instruccions es troben en un bloc `try-catch`.  
  

Al finalitzar el seu ús, i tan pronto com siga possible, cal tancar els *streams* (`close`) .

</details>

<details markdown="1">

<summary>💡 Exemple: sobreescribir un fitxer</summary>

És molt important tindre en compte que quan es crea un `FileWriter` o un `FileOutputStream` i es escriu en ell:  

- si el fitxer no existeix es crea.  

    - si el fitxer existeix, **el seu contingut es reemplaça** pel nou. El contingut previo que tinguera el fitxer es perd.  
  

  Veurem una sèrie d'exemples que muestren com llegir i escriure secuencialment sobre/en un fitxer i també escriure en un fitxer indicant que la informació es afegisca a la que ja hi ha i no es reescriba el fitxer. Per a açò últim usarem el constructor de FileWriter que rep dos paràmetres; el primer paràmetre és el nom del fitxer i el segon paràmetre, `append`, el pasarem amb el valor *true*.  
  

El següent exemple mostra com afegir una línia al final d'un fitxer de text.

```java
package UT06.P2_Ficheros;

import java.io.*;

public class P2_2_SobreescribirFichero {

    public static void main(String[] args) {
        try (FileWriter f = new FileWriter("texto.txt", true);) {
            f.write("Este texto se añade en el fichero\n\r");

        } catch (IOException e) {
            System.out.println("Problema al abrir o escribir ");
        }
    }
}
```

En aquest exemple es ha utilitzat la nova sintaxi disponible per als blocs try-catch: el que es denomina **`try with resource`**. Aquesta sintaxi permet crear un objecte en la capçalera del bloc try. L'objecte creat es cerrará automàticament al finalitzar. L'objecte ha de pertànyer a l'interface Closeable, és a dir, ha de tindre mètode close().

</details>

### 4.1. Lectura i escriptura d'informació estructurada

Si observamos la documentació de les classes **FileInputStream** i **FileOutputStream** veurem que les operacions de lectura i escriptura són molt bàsiques i permeten únicament llegir o escriure un o diversos bytes. És a dir, són operacions de molt sota nivell. Si el que volem és escriure informació binària més complexa, com per exemple un dada de tipus `double`, `boolean` o `int`, tindríem que fer-ho a través d'un *stream* que permitiese eixe tipus d'operacions i asociar-lo al `FileInputStream` o `FileOutputStream`. 

Podríem, per exemple, associar un `DataInputStream` a un `FileInputStream` per a llegir del fitxer un dada de tipus `int`.

En exemples posteriors es ilustrará com associar un *stream* a un `FileXXXStream`.

<details markdown="1">

<summary>💡 Exemple: lectura d'un fitxer seqüencial de text</summary>

Llegir un fitxer de text i mostrar el número de vocals que conté.

```java
package UT06.P2_Ficheros;

import java.io.*;

public class P2_3_LecturaSecuencialTexto {

    final static String VOCALES = "aáàeééiíoóòuúüAÁÀEÉÈIÍOÓÒUÚÜ";

    public static void main(String[] args) {
        try (FileReader f = new FileReader(new File("texto.txt"));) {
            int contadorVocales = 0;
            int caracter;
            while ((caracter = f.read()) != -1) {
                char letra = (char) caracter;
                if (VOCALES.indexOf(letra) != -1) {
                    contadorVocales++;
                }
            }
            System.out.println("Numero de vocales: " + contadorVocales);

        } catch (FileNotFoundException e) {
            System.out.println("ERROR: Probrema al abrir el fichero");

        } catch (IOException e) {
            System.out.println("ERROR: Problema al leer");
        }
    }
}
```

Observa que:

- 

Per a llegir el fitxer de text usem un `InputReader`.

- 

Al crear el *stream* (`InputReader`) és possible indicar un objecte de tipus `File`.

- 

L'operació `read()` retorna un enter. Per a obtindre el caràcter corresponent hem de fer una conversió explícita de tipus.

- 

L'operació `read()` retorna -1 quan no queda informació que llegir del *stream*.

- 

La guarda del bucle `while` combina una assignació amb una comparació. En primer lloc es realitza l'assignació i després es compara caràcter amb -1.

- 

`FileNotFoundException` succeeix quan el fitxer no es pot obrir (no existeix, permís denegado, etc), mentre que `IOException` es llançarà si falla l'operació `read().`

</details>

<details markdown="1">

<summary>💡 Exemple: escriptura d'un fitxer seqüencial de text</summary>

Donada una cadena escribirla en un fitxer en ordre invers:

```java
package UT06.P2_Ficheros;

import java.io.*;

public class P2_4_EscrituraSecuencialTexto {

    final static String CADENA = "En un lugar de la mancha...";

    public static void main(String[] args) {
        try (FileWriter f = new FileWriter(new File("texto.txt"));) {
            for (int i = CADENA.length() - 1; i >= 0; i--) {
                f.write(CADENA.charAt(i));
            }
            System.out.println("FIN");

        } catch (FileNotFoundException e) {
            System.out.println("ERROR: Probrema al abrir el fichero");

        } catch (IOException e) {
            System.out.println("ERROR: Problema al escribir");

        }
    }
}
```

Observa que:

- 

Per a escriure el fitxer de text usem un `FileWriter`.

- 

Tal com es ha creat el *stream*, el fitxer (si ja existeix) es sobreescribirá.

- 

El maneig d'excepcions és com el del cas previo.

</details>

<details markdown="1">

<summary>💡 Exemple: escriptura d'un fitxer seqüencial binari</summary>

Ja hem vist que amb `FileInputStream` i `FileOutputStream` es pot llegir i escriure bytes d'informació de/a un fitxer.  
  

No obstant això açò pot no ser suficient quan la informació que hem de llegir o escriure és més complexa i els bytes es agrupen per a representar distints tipus de dades.  
  

Imaginem per exemple que volem guardar en un fitxer “jugadors.dat”, l'any de naixement i l'estatura de cinc jugadors de baloncesto:

```java
package UT06.P2_Ficheros;

import java.io.*;
import java.util.Scanner;

public class P2_6_EscrituraSecuencialBinario {

  public static void main(String[] args) {
     Scanner tec = new Scanner(System.in);
     try (DataOutputStream fs = new DataOutputStream(
                                  new BufferedOutputStream(
                                    new FileOutputStream("jugadores.dat")));) {
         for (int i = 1; i <= 5; i++) {
            //Pedimos datos al usuario
            System.out.println(" ---- Jugador " + i + " -----");
            System.out.print("Nombre: ");
            String nombre = tec.nextLine();

            System.out.print("Nacimiento: ");
            int anyo = tec.nextInt();

            System.out.print("Estatura: ");
            double est = tec.nextDouble();
            //Vaciar salto linea
            tec.nextLine();

            //Volcamos información al fichero
            fs.writeUTF(nombre);
            fs.writeInt(anyo);
            fs.writeDouble(est);
         }

      } catch (FileNotFoundException e) {
          System.out.println("ERROR: Probrema al abrir el fichero");

      } catch (IOException e) {
          System.out.println("ERROR: Problema al leer o escribir");

      }
  }
}
```

Observa que:

- 

Per a escriure informació binària usem un `DataInputStream` associat al *stream*. La classe té mètodes per a escriure `int`, `byte`, `double`, `boolean`, etc.

- 

A més, com hem fet en exemples previos, usem un *buffer*. Fíjate com en el constructor es enlazan unes classes amb altres.

- 

Malgrat que en Java els fitxers són seqüències de bytes, estem dotant al fitxer de certa estructura: primer apareix el nom, després l'any i finalment l'estatura. Cada un d'aquests tres dades constituirían un registre de format per tres camps. Per a poder recuperar informació d'un fitxer binari és necessari conèixer com es estructura ésta dins del fitxer.

</details>

<details markdown="1">

<summary>💡 Exemple: lectura d'un fitxer seqüencial binari</summary>

```java
package UT06.P2_Ficheros;

import java.io.*;
import java.util.Scanner;

public class P2_7_LecturaSecuencialBinario {

  public static void main(String[] args) {
     Scanner tec = new Scanner(System.in);
     try (DataInputStream fe = new DataInputStream(
                                new BufferedInputStream(
                                 new FileInputStream("jugadores.dat")));) {
        while (true) {
           //Leemos nombre
           System.out.println(fe.readUTF());
           //leemos y desechamos resto de datos
           fe.readInt();
           fe.readDouble();
        }

     } catch (EOFException e) {
          //Se lanzará cuando se llegue al final del fichero

     } catch (FileNotFoundException e) {
          System.out.println("ERROR: Probrema al abrir el fichero");

     } catch (IOException e) {
          System.out.println("ERROR: Problema al leer o escribir");

     }
  }
}
```

Observa que:

- 

Malgrat que necessitem solament el nom de cada jugador, és necessari llegir també l'any i l'estatura. No és possible accedir al nom del segon jugador sense llegir prèviament totes les dades del primer jugador.

- 

La lectura es fa a través d'un bucle infinit (**while (true)**), que finalizará quan es arribe el final del fitxer i al llegir de nou es produïsca l'excepció **EOFException**.

</details>

## 5. Fitxers amb buffering

Qualsevol operació que implique accedir a memòria externa és molt costosa, per la qual cosa és interessant intentar reduir al màxim les operacions de lectura/escriptura que realitzem sobre els fitxers, fent que cada operació lea o escriga molts caràcters. A més, això també permet operacions de més alt nivell, com la de llegir una línia completa i devolverla en forma de cadena.

En el llibre *Head First Java*, descriu els *buffers* de la següent forma: "*Si no haguera buffers, seria com comprar sense un carrito: hauria de portar els productes un a un fins a la caixa. Els buffers et donen un lloc en el que deixar temporalment les coses fins a que està lleno. Per això has de fer menys viatges quan uses el carrito.*"

Les classes `BufferedReader`, `BufferedWritter`, `BufferedInputStream` i `BufferedOutputStream` permeten realitzar *buffering*. Situades "per davant" d'un *stream* de fitxer acumulan les operacions de lectura i escriptura i quan hi ha suficient informació es porten finalment al fitxer.

> **📌 Recorda**
> 

> Recorda la importància de tancar els fluxos per a asegurarte que es buida el *buffer*.

<details markdown="1">

<summary>💡 Exemple: usant *buffers* per a llegir i escriure de/en fitxer</summary>

En el següent codigo s'usen *buffers* per a llegir línies d'un fitxer i escribirlas en un altre convertides a majúscules.

```java
package UT06.P2_Ficheros;

import java.io.*;

public class P2_5_Buffers {

    final static String ENTRADA = "texto.txt";
    final static String SALIDA = "textoMayusculas.txt";

    public static void main(String[] args) {
        try (BufferedReader fe = new BufferedReader(new FileReader(ENTRADA));
             BufferedWriter fs = new BufferedWriter(new FileWriter(SALIDA))){
            String linea;
            while ((linea = fe.readLine()) != null) {
                fs.write(linea.toUpperCase());
                fs.newLine();
            }
            System.out.println("FIN");

        } catch (FileNotFoundException e) {
            System.out.println("ERROR: Probrema al abrir el fichero");

        } catch (IOException e) {
            System.out.println("ERROR: Problema al leer o escribir");
        }
    }
}
```

Observa que:

- 

Usem *buffers* tant per a llegir com per a escriure. Açò permet minimitzar els accessos a disc.

- 

Els *buffers* queden associats a un `FileReader` i `FileWriter` respectivament. Realitzem les operacions de lectura/escriptura sobre les classes `Buffered…` i quan és necessari la classe accedeix internament al *stream* que maneja el fitxer.

- 

És necessari escriure explícitament els salts de línia. Açò es fa mitjançant el mètode `newLine()`. Aquest mètode permet afegir un salt de línia sense preocuparnos de quin és el caràcter de salt de línia. El salt de línia és distint en distints sistemes: en uns és `\n`, en altres `\r`, en altres `\n\r`, … 

- 

`BufferedReader` disposa d'un mètode per a llegir línies completes (`readLine()`). Quan es arriba al final del fitxer aquest mètode retorna `null`.

- 

Fíjate com en el bloc `try with resources` creem diversos objectes. Si la creació de qualsevol d'ells falla, es cerrarán tots els *stream* que es han obert.

</details>

## 6. `try` VS `try with resources`

En ocasions el propi IDE ens sugiere que usemos el bloc `try with resources` en lloc d'un simple `try`, així una sentència com aquesta:

```java
FileReader fr = new FileReader(path);
BufferedReader br = new BufferedReader(fr);
try {
    return br.readLine();
} finally {
    br.close();
    fr.close();
}
```

Acaba convertida en alguna cosa semblant a aquesta:

```java
static String readFirstLineFromFile(String path) throws IOException {
    try (FileReader fr = new FileReader(path);
         BufferedReader br = new BufferedReader(fr)) {
        return br.readLine();
    }
}
```

> **📌 utilitzar el mètode `close()` ??**
> 

> La principal diferència és que fins a Java 7 només es podia fer com en la primera versió. A més, en la segona versió ens "ahorramos" tindre que tancar els recursos, ja que el realitzarà automàticament en cas que es produïsca algun error evitant així l'enmascarament d'excepcions. Per tant, segueix sent necessari tancar el *stream* per exemple a l'usar un *buffer* perquè es vacíe totalment en el fitxer de destí.
