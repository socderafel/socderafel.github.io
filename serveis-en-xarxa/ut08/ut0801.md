El servei **Web (HTTP/HTTPS)** és la capa visible d'Internet per a la gran majoria dels usuaris. Un **Servidor Web** és un programa dimoni que escolta peticions a la xarxa a través dels ports estàndard de la capa de transport (TCP 80 per a HTTP no xifrat i TCP 443 per a HTTPS) i serveix recursos estàtics (documents HTML, fulls d'estils CSS, imatges, vídeos) o delega l'execució d'aplicacions dinàmiques a intèrprets com PHP, Node.js o Python.

---

## 1. El Protocol HTTP: Peticions, Mètodes i Respostes

HTTP (*Hypertext Transfer Protocol*) és un protocol sense estat (*stateless*) que segueix el model clàssic de petició-resposta:

```
[ NAVEGADOR CLIENT ] ── 1. Petició HTTP (Mètode GET /index.html) ──> [ SERVIDOR WEB ]
[ NAVEGADOR CLIENT ] <── 2. Resposta HTTP (Codi 200 OK + Contingut) ─ [ SERVIDOR WEB ]
```

### Mètodes HTTP Principals:
- **`GET`:** Demana un recurs al servidor (pàgina web, imatge). Les dades van a la mateixa URL (`?nom=joan`).
- **`POST`:** Envia dades al servidor perquè siguen processades (formularis, contrasenyes, càrrega de fitxers). Les dades viatgen ocultes al cos (*body*) de la petició.
- **`HEAD`:** Demana exclusivament les capçaleres de resposta sense descarregar el contingut (molt útil per comprovar si un enllaç funciona o quan es va modificar per última vegada).

### Famílies de Codis d'Estat HTTP:
- **`2xx` (Èxit):** `200 OK` (petició processada satisfactòriament).
- **`3xx` (Redirecció):** `301 Moved Permanently` (recurs mogut de manera definitiva, habitual en redireccions forçoses a HTTPS).
- **`4xx` (Error del Client):** `400 Bad Request`, `403 Forbidden` (permisos denegats), `404 Not Found` (pàgina inexistent).
- **`5xx` (Error del Servidor):** `500 Internal Server Error` (fallada en codi PHP), `502 Bad Gateway`, `503 Service Unavailable`.

## 2. Models d'Arquitectura i Concurrència: Apache vs Nginx

Els dos titans del món dels servidors web aborden el repte de donar servei a milers de visitants concurrents mitjançant filosofies diferents:

| Paràmetre | Apache HTTP Server (Apache2) | Nginx |
| :--- | :--- | :--- |
| **Model d'Arquitectura** | **Basat en Processos / Fils (MPM):** Mòduls `prefork` (un procés aïllat per client), `worker` (híbrid processos/fils) o `event`. | **Asíncron Basat en Esdeveniments (*Event-Driven*):** Un petit nombre de processos de treball (*workers*) gestionen milers de connexions simultànies mitjançant bucles d'esdeveniments no bloquejants (`epoll`). |
| **Configuració Descentralitzada** | Admet fitxers de configuració local **`.htaccess`** a cada carpeta d'usuari (ideal per a hosting compartit). | No admet `.htaccess`. Tota la configuració està centralitzada a `/etc/nginx/`, oferint màxima velocitat. |
| **Punt Fort Principal** | Flexibilitat modular, compatibilitat universal i facilitat d'integració amb llenguatges com PHP mitjançant mòduls directes. | Velocitat imbatible servint continguts estàtics i excel·lència com a Servidor Intermediari Invers (*Reverse Proxy*) i equilibrador de càrrega. |

---

## 3. Instal·lació d'Apache2 a Debian/Ubuntu

```bash
sudo apt update
sudo apt install -y apache2 apache2-utils
```

L'arbre de configuració a `/etc/apache2/` s'estructura de manera modular:
- `apache2.conf`: Configuració troncal del servei.
- `ports.conf`: Ports on escolta el servei (`Listen 80`, `Listen 443`).
- `mods-available/` i `mods-enabled/`: Mòduls disponibles i mòduls activats.
- `sites-available/` i `sites-enabled/`: Llocs virtuals disponibles i activats.
