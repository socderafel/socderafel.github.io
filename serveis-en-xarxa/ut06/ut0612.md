# 6.12 - [Ubuntu Server] Instal·lació de vsftpd, mode pasivo, jaula chroot i pruebas en FileZilla (RA3-CEb,c,d,e)

⚠️ **Obligatori seguir les normes per a la presentació de treballs escritos.**

Totes les evidències hauran d'incloure capturas de pantalla completes on es aprecie clarament el nom de l'equip, usuari i la data/hora.

Una vegada completades i verificades totes les pràctiques sobre Windows Server, passem al segon bloc del laboratorio desplegant el servei de transferència de fitxers en **Linux (`Ubuntu Server 24.04 LTS`)** mitjançant el demonio **`vsftpd`**. *(Mentre trabatges exclusivament en aquesta tasca i en la Tasca 13, pots mantindre detenida la màquina de Windows Server per a ahorrar saldo en AWS Academy).*

### 12.0 Lanzament de la instància EC2 de Ubuntu Server 24.04 LTS en AWS

1. En la consola de **AWS EC2** -> **Instances** -> polsar en **Launch instances** (**Llançar instàncies**) i desplegar la segona màquina virtual del laboratorio amb les següents especificacions:

| Paràmetre de configuració | Valor requerido |
| --- | --- |
| **Name (Nom)** | `Ubuntu_FTPSSH` |
| **Application and US Images (AMI)** | `Ubuntu Server 24.04 LTS (HVM), SSD Volume Type` (64 bits x86) |
| **Instance type (Tipus d'instància)** | `t3.micro` (Recomanat — 2 vCPU, 1 GiB RAM, **Apto per a la capa gratuïta**) o `t2.micro` |
| **Key pair (login)** | `vockey` (o parell de claus del laboratorio) |
| **Network settings (Security group)** | Seleccionar **Select existing security group** i triar **`grup-servidors-ftp-ssh`** (creat en l'apartat 6.1) |
| **Configure storage** | `8 GiB` o `10 GiB` gp3 (SSD) |

💡 **En Ubuntu Server sí utilitzem la capa gratuïta (t2.micro / t3.micro)**

A diferència de Windows Server, la màquina `Ubuntu_FTPSSH` funciona exclusivament en mode terminal consola (CLI sense entorn d'escriptori) i el demonio `vsftpd` és extremadament lleuger (consume menys de 150 MiB de RAM). Per tant, ací sí seleccionarem el tipus **`t2.micro`** (o `t3.micro`), que compta amb l'etiqueta verd **Apto per a la capa gratuïta** (*Free tier eligible*), optimitzant al màxim els créditos del laboratorio.

1. Esperar a que la instància passe a estat `Running` i anotar el seu **Adreça IPv4 pública**:

*Figura 49: Instància Ubuntu_FTPSSH en estat En ejecució (Running) en el panell d'instàncies de AWS EC2 amb la seua adreça IPv4 pública assignada.*

### 12.1 Verificació de ports en el Security Group de Ubuntu

1. En la consola de AWS -> **EC2** -> comprovar que el Security Group (`grup-servidors-ftp-ssh`) associat a la instància `Ubuntu_FTPSSH` té oberts els ports:

1. Port `22` TCP (SSH).

1. Port `21` TCP (FTP Control).

1. Rang de ports `40000-40100` TCP (FTP Pasivo en Linux).

### 12.2 Instal·lació del servei vsftpd

1. Connectar-se a la instància `Ubuntu_FTPSSH` per SSH utilitzant AWS EC2 Instance Connect (o mitjançant client SSH / PuTTY amb la clau del laboratorio):

![Connexió a la terminal de Ubuntu_FTPSSH mitjançant EC2 Instance Connect en el navegador](../img/49b_ec2_instance_connect_ubuntu_terminal.png)

*Figura 49b: Sessió interactiva en la terminal de Ubuntu Server oberta directament en el navegador amb EC2 Instance Connect, mostrant el prompt `ubuntu@ip-...` i la barra inferior amb la instància i IP pública assignada.*

1. Actualitzar l'índex de repositorios i instal·lar el paquet `vsftpd`:
   

```bash
sudo apt update && sudo apt install -y vsftpd
```

### 12.3 Configuració de mode pasivo, NAT i jaula chroot en /etc/vsftpd.conf

1. Obrir el fitxer de configuració principal del servei:
   

```bash
sudo nano /etc/vsftpd.conf
```

1. 

Modificar les següents directivas per a garantir el funcionament en IPv4, habilitar l'escriptura, l'enjaulado (`chroot`) i el rang pasivo en AWS:

1. 

**Al principi del fitxer:** Comprovar que el servei escolta en mode IPv4 independent i comentar la directiva de IPv6:
     

```bash
listen=YES
#listen_ipv6=YES
```

     *(Important: En Ubuntu 24.04, si `listen_ipv6=YES` està activo, entrará en conflicto amb `pasv_address` i provocará desconexiones `ECONNABORTED` a l'intentar transferir fitxers).*

1. 

**Al final del fitxer:** Afegir el bloc d'enjaulado, mode pasivo per a AWS i compatibilitat d'anomenades al sistema (`seccomp_sandbox`):
     

```bash
# Acceso de usuarios locales con permisos de escritura
anonymous_enable=NO
local_enable=YES
write_enable=YES
local_umask=022

# Enjaulado (chroot jail) de usuarios en su directorio /home/<usuario>
chroot_local_user=YES
allow_writeable_chroot=YES

# Configuración de modo pasivo para AWS Cloud
pasv_enable=YES
pasv_min_port=40000
pasv_max_port=40100
pasv_address=<TU_IP_PUBLICA_UBUNTU>
seccomp_sandbox=NO
```

![Configuració del mode pasivo i chroot en vsftpd.conf](../img/50_ubuntu_vsftpd_conf.png)

*Figura 50: Configuració del fitxer /etc/vsftpd.conf en nano mostrant les directivas d'enjaulado chroot_local_user, mode pasivo pasv_enable, rang de ports 40000-40100 i l'adreça IP pública en pasv_address.*

### 12.4 Creació d'usuaris locals i activació del servei

1. Crear els usuaris `alumne_redes` i `usuari_ventas` en Ubuntu Server:
   

```bash
sudo adduser alumne_redes
# Asignar la contraseña: Smx2026..@
sudo adduser usuari_ventas
# Asignar la contraseña: Smx2026..@
```

1. Reiniciar el servei `vsftpd` i verificar que es troba activo (`active (running)`):
   

```bash
sudo systemctl restart vsftpd
sudo systemctl status vsftpd
```

![Verificació de l'estat activo del servei vsftpd en Ubuntu Server](../img/51_ubuntu_vsftpd_status.png)

*Figura 51: Terminal de Ubuntu Server mostrant l'ejecució de systemctl status vsftpd amb l'estat active (running) i el procés principal vsftpd en ejecució.*

### 12.5 Prova de transferència i verificació d'enjaulado (chroot) des de FileZilla

⚠️ **Retomas la connexió a Ubuntu en un dia diferent o després de reiniciar?**

Si la màquina virtual `Ubuntu_FTPSSH` es ha detenido i tornat a iniciar:
* **En FileZilla:** Introdueix en el camp **Servidor** la **nova IP pública de Ubuntu** (visible en la consola de AWS EC2).
* **Problema crític en `vsftpd` si no actualizas la IP:** Si el fitxer `/etc/vsftpd.conf` conserva la IP d'un dia anterior en la directiva `pasv_address`, FileZilla conectará al port 21 però es congelará indefinidament en `150 Here comes the directory listing...` i fallará per *timeout*.
* 👉 **Solució:** Obri la terminal de Ubuntu i actualitza la directiva amb:
  

```bash
sudo nano /etc/vsftpd.conf
# Modifica la línea: pasv_address=<NUEVA_IP_PUBLICA_UBUNTU>
sudo systemctl restart vsftpd
```

  Consulta els detalls complets en el Apartat 12.3: Configuració de mode pasivo en vsftpd.

1. Obrir **FileZilla Client** en el vostre PC de l'aula i connectar cap a **Ubuntu Server**:

1. **Servidor:** `<IP_PUBLICA_UBUNTU>`

1. **Nom d'usuari:** `alumne_redes` (i posteriorment provar amb `usuari_ventas`)

1. **Contrasenya:** `Smx2026..@`

1. **Port:** `21`

1. Pujar un fitxer anomenat `prueba_ubuntu.txt` i comprovar que la transferència en mode pasivo (`40000-40100`) es completa amb èxit.

1. Verificar que gràcies a la directiva `chroot_local_user=YES`, l'usuari apareix enjaulado en `/` (que correspon físicament al seu directori personal `/home/alumne_redes`), impident que puga pujar de nivell cap a `/home` o `/etc`.
