# 7.1 Fonaments de les Xarxes Privades Virtuals (VPN)

Una **Xarxa Privada Virtual (VPN - *Virtual Private Network*)** és una tecnologia de xarxa que permet estendre una xarxa local privada a través d'una xarxa pública no de confiança, com ara Internet, mantenint la seguretat, la integritat i la confidencialitat de les comunicacions mitjançant tècniques avançades d'encapsulament (*tunelització*) i xifratge criptogràfic.

---

## 1. Per què són necessàries les VPN?

En el model tradicional d'oficina tancada, tots els ordinadors es connectaven mitjançant cablejat Ethernet o Wi-Fi corporativa darrere d'un tallafocs de perímetre. Amb la transformació digital, el teletreball i les seus delegades, sorgeixen dues necessitats crítiques:

1. **Accés segur a recursos interns:** Un comercial o tècnic desplaçat necessita consultar la base de dades interna, servidors de fitxers SMB o l'aplicació ERP de la seu central sense exposar aquests serveis directament a Internet amb adreces IP públiques.
2. **Interconnexió de seus remotes:** Una empresa amb seus a València, Alacant i Castelló necessita que els seus servidors i equips es comuniquen entre si de manera transparent com si estigueren al mateix commutador (*switch*), sense incórrer en els elevats costos de les línies dedicades punt a punt (com les antigues línies X.25 o Frame Relay).

```
   [Equip Remot / Teletreballador]
               │
               ▼ (Xifratge AES-GCM / ChaCha20)
     ═════════════════════
     ║  Túnel VPN Segur  ║  (Trànsit encapsulat sobre Internet)
     ═════════════════════
               ▼
     [Servidor / Passarel·la VPN Corporativa]
               │
               ▼ (Accés transparent)
   [Xarxa Local Privada 192.168.10.0/24: Servidors, NAS, ERP]
```

---

## 2. Tipologies de VPN segons la seua Arquitectura

| Tipologia | Denominació Tècnica | Cas d'Ús Principal | Components |
| :--- | :--- | :--- | :--- |
| **Accés Remot (*Remote Access*)** | *Road Warrior* o Client-to-Site | Usuaris mòbils o teletreballadors que es connecten des de casa o hotels a la seu central. | Client de programari instal·lat a l'ordinador/mòbil de l'usuari + Passarel·la VPN a la seu. |
| **Punt a Punt (*Site-to-Site*)** | *LAN-to-LAN* | Unió permanent de dues seus o centres de dades a través d'Internet de manera transparent. | Dos encaminadors/tallafocs VPN (un a cada extrem). Els equips d'ambdues xarxes no necessiten cap programari client. |
| **D'Extranet (*B2B*)** | Xarxa col·laborativa | Connexió controlada i aïllada entre una empresa i els seus proveïdors o socis comercials. | Passarel·la VPN amb llistes de control d'accés (ACL) molt estrictes que limiten la visibilitat. |

---

## 3. Principals Protocols de VPN

Al llarg de la història de les xarxes s'han emprat diversos protocols de tunelització i seguretat:

### A. PPTP (Point-to-Point Tunneling Protocol) - *Obsolet*
Desenvolupat per Microsoft als anys 90. Utilitza el port TCP 1723 i GRE. **Totalment desaconsellat en l'actualitat** a causa de vulnerabilitats greus en el protocol d'autenticació MS-CHAPv2 que permeten desxifrar el tràfic en minuts.

### B. IPsec (Internet Protocol Security)
Opera en el nivell de xarxa (Capa 3 OSI). És un conjunt d'estàndards (IKEv1/IKEv2, ESP, AH) molt robust i eficient, suportat de manera nativa per la majoria de routers industrials (Cisco, Mikrotik) i sistemes operatius. S'utilitza principalment en connexions *Site-to-Site*. La seua configuració pot ser complexa a causa del gran nombre de paràmetres criptogràfics.

### C. OpenVPN
Protocol de codi obert basat en la biblioteca OpenSSL. Opera en Capa d'Aplicació (Capa 7) mitjançant dispositius virtuals `tun` (Capa 3, encaminament IP) o `tap` (Capa 2, pont Ethernet). Suporta TCP i UDP (recomanat UDP 1194). És molt flexible i capaç de travessar tallafocs i NATs agressius, però la seua execució en l'espai d'usuari (*user-space*) introdueix una sobrecàrrega de rendiment.

### D. WireGuard
El protocol VPN modern de referència. Integrat directament al nucli (*kernel*) de Linux des de la versió 5.6. Ofereix una velocitat i una latència molt superiors a OpenVPN i IPsec gràcies a la seua arquitectura lleugera (menys de 4.000 línies de codi enfront de les centenars de milers d'OpenVPN) i l'ús de criptografia moderna d'última generació (ChaCha20, Curve25519, Poly1305).

# 7.2 Desplegament de VPN Moderna amb WireGuard

**WireGuard** tracta els túnels VPN d'una manera radicalment innovadora i senzilla: cada extrem de la connexió és considerat un *par* (*peer*) que s'autentica mitjançant claus criptogràfiques asimètriques públiques i privades, de forma anàloga a com funciona SSH. No existeix el concepte d'estat de connexió feixuc (*handshake* constant); el tràfic només s'envia quan hi ha dades a transmetre.

---

## 1. Instal·lació i Generació de Claus

En distribucions Debian i Ubuntu modernes, WireGuard s'instal·la directament des dels repositoris oficials:

```bash
sudo apt update
sudo apt install -y wireguard wireguard-tools
```

Cada participant del túnel (servidor o client) ha de generar el seu propi parell de claus: una **clau privada** (que mai s'ha de compartir) i una **clau pública** (que s'intercanvia amb l'altre extrem):

```bash
# Crear directori segur amb permisos restringits
mkdir -p -m 0700 /etc/wireguard
cd /etc/wireguard

# Generar clau privada i derivar la clau pública
wg genkey | tee server_private.key | wg pubkey > server_public.key
chmod 600 server_private.key
```

---

## 2. Configuració del Servidor WireGuard (`/etc/wireguard/wg0.conf`)

La interfície de xarxa virtual de WireGuard s'anomena típicament `wg0`. El fitxer de configuració conté dues seccions principals: `[Interface]` (la màquina local) i `[Peer]` (cada client autoritzat).

```ini
[Interface]
# Adreça IP privada que tindrà el servidor dins del túnel VPN
Address = 10.8.0.1/24

# Port d'escolta UDP (el port estàndard és 51820)
ListenPort = 51820

# Clau privada del servidor
PrivateKey = aAAA...SERVER_PRIVATE_KEY...=

# Regles iptables per a habilitar NAT (masquerade) quan la interfície s'alça (PostUp) i es tomba (PostDown)
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE

# ==========================================
# Client 1: Portàtil de Teletreball (Portatil-Pepe)
# ==========================================
[Peer]
# Clau pública del client
PublicKey = bBBB...CLIENT_PUBLIC_KEY...=

# Adreça IP fixa assignada al client dins del túnel
AllowedIPs = 10.8.0.2/32
```

> **Habilitar reenviament de paquets al sistema operatiu:**
> Perquè el servidor puga reenviar paquets entre la interfície `wg0` i la xarxa local o Internet, cal activar el *forwarding*:
> ```bash
> echo "net.ipv4.ip_forward = 1" | sudo tee -a /etc/sysctl.conf
> sudo sysctl -p
> ```

---

## 3. Configuració del Client (`client.conf`)

A l'ordinador portàtil o dispositiu mòbil de l'usuari (Windows, macOS, Linux, Android, iOS):

```ini
[Interface]
Address = 10.8.0.2/24
PrivateKey = cCCC...CLIENT_PRIVATE_KEY...=
DNS = 10.8.0.1, 1.1.1.1

[Peer]
PublicKey = dDDD...SERVER_PUBLIC_KEY...=
# Adreça IP pública o domini DDNS del servidor de l'empresa
Endpoint = vpn.iesmestreesteve.es:51820

# Tràfic que viatjarà pel túnel:
# 0.0.0.0/0 envia TOT el tràfic d'Internet pel túnel (Full Tunnel)
# 10.8.0.0/24, 192.168.10.0/24 només envia el tràfic de l'empresa (Split Tunneling)
AllowedIPs = 0.0.0.0/0, ::/0
PersistentKeepalive = 25
```

---

## 4. Gestió i Monitorització del Servei

WireGuard proporciona la comanda auxiliar `wg-quick` per a arrancar la interfície i gestionar el servei a través de `systemd`:

```bash
# Iniciar i habilitar l'arrencada automàtica del túnel wg0
sudo systemctl enable --now wg-quick@wg0

# Comprovar l'estat dels túnels actius, peers connectats i bytes transmesos
sudo wg show
```

```
interface: wg0
  public key: dDDD...SERVER_PUBLIC_KEY...=
  private key: (hidden)
  listening port: 51820

peer: bBBB...CLIENT_PUBLIC_KEY...=
  endpoint: 85.12.34.56:61234
  allowed ips: 10.8.0.2/32
  latest handshake: 42 seconds ago
  transfer: 12.45 MiB received, 85.10 MiB sent
```
