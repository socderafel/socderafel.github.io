# 2.2 Capes d'Usuari i Transport: Protocols d'Aplicació i TCP vs UDP

Quan un usuari obri un navegador web, envia un correu o connecta un client de videojocs, la comunicació s'origina a la capa superior d'**Aplicació**, però necessita del servei de la capa de **Transport** per garantir que els fluxos de dades arriben al programa correcte dins del sistema operatiu amfitrió.

---

## 1. Protocols Clau de la Capa d'Aplicació

La capa d'aplicació proporciona serveis de xarxa directament a les aplicacions d'usuari final. Els protocols més rellevants en un entorn de xarxa local corporativa són:

* **HTTP (Hypertext Transfer Protocol) / HTTPS:** Protocol client-servidor per a la transferència de recursos web (HTML, CSS, JSON). HTTPS utilitza xifratge TLS/SSL per garantir confidencialitat i autenticitat.
* **DNS (Domain Name System):** Base de dades distribuïda que tradueix noms de domini fàcils de recordar (`www.iesrafael.es`) a adreces IP numèriques (`192.168.1.50`).
* **DHCP (Dynamic Host Configuration Protocol):** Assigna de forma automàtica adreces IP, màscares de xarxa, portes d'enllaç i servidors DNS als clients de la xarxa en iniciar-se.
* **SSH (Secure Shell):** Permet l'administració remota segura per consola d'ordres mitjançant connexions xifrades.
* **FTP / SFTP (File Transfer Protocol):** Transferència de fitxers entre equips en xarxa.

---

## 2. La Capa de Transport: TCP vs UDP

La capa de transport és el cor de la comunicació extrem a extrem (*end-to-end*). Aquesta capa permet la **multiplexació**: que múltiples aplicacions funcionen alhora a l'ordinador sense barrejar els seus fluxos de dades. Els dos protocols fonamentals són:

```
+-----------------------------------+-----------------------------------+
| TCP (Transmission Control Proto)  | UDP (User Datagram Protocol)      |
+-----------------------------------+-----------------------------------+
| Orientat a connexió (3-Way Hand)  | Sense connexió (Connectionless)   |
| Fiable (confirmació ACK i reenviament)| No fiable (Best effort, sense ACK)|
| Control de flux i congestió       | Sense control de flux, màxima velocitat|
| Ordenació garantida de paquets    | Arribada desordenada admissible   |
| Exemples: Web (HTTP/S), SSH, Correu| Exemples: Streaming vídeo, DNS, VoIP|
+-----------------------------------+-----------------------------------+
```

### El Protocol d'Apretada de Mans de Tres Vies (TCP 3-Way Handshake)
Abans que TCP puga transmetre una sola dada útil, estableix un circuit virtual entre emissor i receptor mitjançant tres passos:
1. **SYN (Synchronize):** El client envia un segment amb el bit SYN actiu i un número de seqüència inicial aleatori $ISN_c$.
2. **SYN-ACK (Synchronize-Acknowledgment):** El servidor respon acceptant la connexió amb el seu propi $ISN_s$ i confirmant la recepció del client ($ACK = ISN_c + 1$).
3. **ACK (Acknowledgment):** El client confirma la resposta del servidor ($ACK = ISN_s + 1$). A partir d'aquest instant, la sessió queda establerta.

---

## 3. Concepte de Port i Sòcol (Socket)

Una adreça IP identifica un equip a la xarxa, però no indica quin programa ha de rebre les dades. Per a això s'empren els **números de port** (camps de 16 bits, amb valors de $0$ a $65.535$):

* **Ports Ben Coneguts (Well-Known Ports, 0 - 1023):** Reservats per als protocols estàndard del sistema.
  - Port `20/21`: FTP (Transferència i control).
  - Port `22`: SSH (Consola segura).
  - Port `53`: DNS (Consultes per UDP, transferències per TCP).
  - Port `67/68`: DHCP (Servidor UDP 67 / Client UDP 68).
  - Port `80`: HTTP (Web no xifrat).
  - Port `443`: HTTPS (Web xifrat TLS).
* **Ports Registrats (1024 - 49151):** Utilitzats per aplicacions i fabricants específics (MySQL `3306`, RDP `3389`).
* **Ports Dinàmics o Privats (49152 - 65535):** Assignats automàticament pel sistema operatiu del client quan obri una connexió sortint.

> **Definició de Sòcol (Socket):** La combinació única d'una adreça IP i un número de port (per exemple: `192.168.1.10:443`). Un sòcol identifica unívocament un extrem de la comunicació.
