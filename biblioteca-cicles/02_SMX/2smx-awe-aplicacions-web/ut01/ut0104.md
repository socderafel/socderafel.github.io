La tercera pota indispensable de la pila LAMP és el motor de bases de dades relacional. **MariaDB** és la bifurcació (*fork*) comunitària, lliure i $100\%$ compatible amb MySQL més utilitzada en distribucions GNU/Linux per excel·lència.

Un dels pitjors errors de seguretat d'un tècnic principiant és configurar una aplicació web (com WordPress) utilitzant el compte d'administrador absolut `root` de la base de dades. Cada aplicació web ha de tindre **la seua pròpia base de dades aïllada** i un **usuari específic dedicat** amb privilegis limitats únicament sobre aquesta base de dades.

---

## 1. Assegurament Inicial del Servidor MariaDB

Després d'instal·lar el paquet `mariadb-server`, s'ha d'executar l'assistent de seguretat oficial:

```bash
# Instal·lació de MariaDB
sudo apt install -y mariadb-server

# Execució del script d'assegurament (Hardening)
sudo mysql_secure_installation
```
Aquest script interactiu permet:
- Assignar contrasenya segura per a l'administrador `root`.
- Eliminar comptes d'usuaris anònims de prova.
- Deshabilitar l'inici de sessió remot de `root` (forçant connexions només des de `localhost`).
- Eliminar la base de dades de proves (`test`).

---

## 2. Creació de la Base de Dades i Usuari per a un CMS

La preparació d'una nova aplicació web es realitza des de la consola SQL de MariaDB:

```sql
-- Entrar a la consola SQL
sudo mysql -u root

-- 1. Crear la base de dades amb codificació UTF-8 completa (admet emoticones i símbols)
CREATE DATABASE bd_wordpress CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 2. Crear un usuari específic que només pot connectar-se localment des del mateix servidor
CREATE USER 'usuari_wp'@'localhost' IDENTIFIED BY 'ContrasenyaUltrasegura#2026';

-- 3. Concedir tots els privilegis ÚNICAMENT sobre la seua base de dades
GRANT ALL PRIVILEGES ON bd_wordpress.* TO 'usuari_wp'@'localhost';

-- 4. Recarregar la taula de privilegis a la memòria
FLUSH PRIVILEGES;

-- 5. Eixir de la consola
EXIT;
```
