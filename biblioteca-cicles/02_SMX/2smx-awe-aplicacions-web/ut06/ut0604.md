Una política de respatler manual mai funciona a la pràctica: si depèn que el tècnic s'enrecorde d'executar comandes cada vespre, tard o d'hora s'oblidarà. La seguretat operativa exigeix **scripts de Bash automatitzats mitjançant el cron del sistema** i una supervisió activa dels fitxers de registre (*logs*) per detectar anomalies abans que provoquen la caiguda dels serveis.

---

## 1. Script Professional de Còpia de Seguretat Automatitzada

Creem un script executable a `/usr/local/bin/backup_web_total.sh`:

```bash
#!/bin/bash
# ==============================================================================
# Script de Respatler Automatitzat de Pila Web per a 2n SMX
# ==============================================================================
set -euo pipefail

DEST_DIR="/var/backups/web_daily"
DATE=$(date +%Y-%m-%d_%H%M)
RETENTION_DAYS=14

mkdir -p "$DEST_DIR"

echo "=== Iniciant còpia de seguretat: $DATE ==="

# 1. Respatler de totes les bases de dades
echo "Exportant bases de dades MariaDB..."
mariadb-dump --all-databases --single-transaction --quick | gzip > "$DEST_DIR/db_all_$DATE.sql.gz"

# 2. Respatler de fitxers web i dades
echo "Empaquetant codi d'aplicacions web..."
tar -czf "$DEST_DIR/var_www_$DATE.tar.gz" /var/www

# 3. Neteja de còpies antigues (Rotació automàtica)
echo "Eliminant còpies amb més de $RETENTION_DAYS dies..."
find "$DEST_DIR" -type f -name "*.gz" -mtime +$RETENTION_DAYS -delete

echo "=== Còpia de seguretat finalitzada amb èxit ==="
```

Donar permisos d'execució exclusius per a root:
```bash
sudo chmod 700 /usr/local/bin/backup_web_total.sh
```

---

## 2. Programació al Crontab del Sistema

Programem l'execució diària de matinada (per exemple a les 03:00 hores, quan el trànsit d'usuaris és mínim):

```bash
sudo crontab -e
```
Afegir la línia:
```cron
0 3 * * * /usr/local/bin/backup_web_total.sh >> /var/log/backup_web.log 2>&1
```

---

## 3. Anàlisi i Monitoratge de Registres d'Apache (*Logs*)

Els servidors web mantenen dos fitxers clau a `/var/log/apache2/`:
1. **`access.log`:** Registra cada petició rebuda amb IP d'origen, data/hora, mètode HTTP (GET/POST), codi d'estat de resposta (200, 404, 500) i User-Agent.
2. **`error.log`:** Registra fallades internes de PHP, errors de permisos, directòris no trobats o peticions bloquejades per regles de seguretat.

### Comandes Clau d'Auditoria per Consola:
```bash
# Monitorar les peticions entrants en temps real:
sudo tail -f /var/log/apache2/access.log

# Trobar els 10 intents d'accés més freqüents a pàgines inexistents (error 404):
sudo awk '$9 == 404 {print $7}' /var/log/apache2/access.log | sort | uniq -c | sort -nr | head -n 10

# Detectar IPs que estan fent atacs de força bruta contra wp-login.php:
sudo grep "POST /wp-login.php" /var/log/apache2/access.log | awk '{print $1}' | sort | uniq -c | sort -nr
```

---

## 4. Rotació de Registres amb `logrotate`

Si no es controlen, els fitxers de registre poden créixer fins a omplir tot el disc dur del servidor. El servei **`logrotate`** de Linux comprimeix i arxiva periòdicament els registres antics:
- Comprimeix els registres en format `.gz` cada dia o setmana.
- Manté un nombre limitat de rotacions (ex: 14 setmanes) i esborra els més vells automàticament.
