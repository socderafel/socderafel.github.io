Una fallada de disc dur, un atac de *ransomware* o una actualització fallida poden destruir en segons mesos de feina docent o corporativa. Una aplicació web **mai es pot recuperar copiant només els fitxers**: cal una còpia sincronitzada de dos elements independents: la **base de dades relacional** i els **fitxers del sistema**.

---

## 1. La Regla d'Or 3-2-1 del Respatler de Dades

L'estàndard professional de seguretat informàtica recomana:
- **3 Còpies:** Conservar 3 còpies de les dades (l'original en producció + 2 còpies de seguretat).
- **2 Suports Diferents:** Emmagatzemar les còpies en 2 suports físics diferents (ex: disc local SSD + cabina NAS / emmagatzematge magnètic).
- **1 Còpia Fora de la Instal·lació (*Off-Site*):** Mantenir almenys 1 còpia fora de l'edifici físic (ex: enviament xifrat a un servidor remot o al núvol) per sobreviure a incendis, robatoris o catàstrofes naturals.

---

## 2. Còpia de Seguretat de la Base de Dades: `mariadb-dump` / `mysqldump`

Copiar directament els fitxers físics de `/var/lib/mysql/` mentre la base de dades s'està executant produeix fitxers corruptes. S'ha d'utilitzar l'eina oficial d'exportació lògica:

```bash
# Exportació coherent i consistent d'una base de dades a fitxer SQL comprimit
sudo mariadb-dump -u root -p --single-transaction --quick --routines --triggers     nom_base_dades | gzip > /var/backups/db_backup_$(date +%F_%H%M).sql.gz
```

Paràmetres clau:
- `--single-transaction`: Permet fer la còpia d'una base de dades InnoDB sense bloquejar l'accés ni aturar la web.
- `gzip`: Comprimeix el fitxer de text SQL reduint el seu pes fins a un 85%.

---

## 3. Còpia del Sistema de Fitxers amb `tar` i `rsync`

Per copiar el codi de les aplicacions (`/var/www/`) i els directoris de dades privats (`/var/moodledata`, `/var/nextcloud-data`):

### A. Empaquetament Comprimit amb `tar`:
```bash
sudo tar -czvf /var/backups/web_files_$(date +%F).tar.gz /var/www/html /var/moodledata
```

### B. Sincronització Incremental amb `rsync`:
Mentre que `tar` crea arxius gegants cada vegada, `rsync` és l'eina ideal per transferir còpies cap a un altre servidor o NAS via SSH, transmetent exclusivament els blocs d'arxiu que han canviat:
```bash
# Sincronitzar amb servidor de backups remot per SSH de manera incremental
rsync -avz --delete -e ssh /var/backups/ usuari_backup@nas.iesrafael.local:/volum_backups/
```

---

## 4. Xifratge de Còpies de Seguretat amb GPG

Si una còpia de seguretat conté dades d'expedients d'alumnes o contrasenyes i s'envia a un núvol remot, **és obligatori xifrar-la** segons el RGPD per evitar sancions si algú intercepta el fitxer:

```bash
# Xifrar el fitxer amb algorisme AES-256 mitjançant una contrasenya simètrica robusta
gpg --symmetric --cipher-algo AES256 /var/backups/db_backup_2026-11-03.sql.gz
# Genera el fitxer xifrat: db_backup_2026-11-03.sql.gz.gpg
```
