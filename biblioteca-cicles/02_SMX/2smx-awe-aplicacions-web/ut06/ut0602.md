Un servidor web acabat d'instal·lar amb els valors per defecte és altament vulnerable al reconeixement d'empremta digital (*Fingerprinting*) i a atacs automatitzats. El procés d'**enduriment (*Hardening*)** consisteix a aplicar regles restrictives de configuració per minimitzar la superfície d'atac i protegir el lloc contra les amenaces catalogades a l'**OWASP Top 10**.

---

## 1. Ocultació d'Informació del Servidor (*Information Leakage*)

Per defecte, Apache revela la seua versió exacta, el sistema operatiu i els mòduls instal·lats en cada capçalera HTTP de resposta i a les pàgines d'error 404:

A `/etc/apache2/conf-available/security.conf`:
```apache
# No revelar la versió d'Apache ni del sistema operatiu (retorna només "Apache")
ServerTokens Prod

# Desactivar el peu de pàgina amb dades del servidor en pàgines d'error generades per Apache
ServerSignature Off

# Evitar atacs Clickjacking impedint que el lloc s'incruste en iframes externs
Header always set X-Frame-Options "SAMEORIGIN"

# Evitar sniffing de tipus MIME al navegador
Header always set X-Content-Type-Options "nosniff"

# Protecció bàsica contra Cross-Site Scripting
Header always set X-XSS-Protection "1; mode=block"
```

---

## 2. Prevenció de les Vulnerabilitats Web Més Comunes (OWASP Top 10)

| Vulnerabilitat | Descripció de l'Atac | Mecanisme Tècnic de Protecció |
| :--- | :--- | :--- |
| **Injecció SQL (SQLi)** | L'atacant introdueix fragments de codi SQL en formularis per enganyar la base de dades i saltar-se l'autenticació o extreure dades. | Ús obligatori de **sentències preparades (Prepared Statements / PDO)** i desinfecció d'entrades. |
| **Cross-Site Scripting (XSS)** | Injecció de codi JavaScript maliciós en entrades de comentaris o fòrums que s'executa al navegador d'altres usuaris per robar les seues galetes de sessió. | Escapament de caràcters HTML (`htmlspecialchars`) i capçalera **Content Security Policy (CSP)**. |
| **Cross-Site Request Forgery (CSRF)** | Enganya la víctima perquè execute sense adonar-se una acció no desitjada en una web on ja està autenticada (ex: canvi de contrasenya). | Ús de **tokens únics anti-CSRF (*Nonces*)** en cada formulari enviat per POST. |
| **Llistat de Directoris (*Directory Listing*)** | Si no hi ha cap fitxer `index.html` o `index.php`, Apache mostra tot el contingut de la carpeta al públic. | Desactivar la directiva `Indexes`: `Options -Indexes`. |

---

## 3. Tallafocs d'Aplicació Web (WAF): ModSecurity

Un tallafocs de xarxa tradicional (com `iptables` o `ufw`) només filtra ports (80 o 443), però no entén si una petició HTTP porta un atac d'injecció SQL dins del text. Un **WAF** (*Web Application Firewall*) com **ModSecurity** analitza el contingut intern de cada paquet HTTP/HTTPS abans que arribe a WordPress o Moodle:

```bash
# Instal·lar ModSecurity per a Apache i el conjunt de regles OWASP Core Rule Set (CRS)
sudo apt update
sudo apt install -y libapache2-mod-security2
sudo cp /etc/modsecurity/modsecurity.conf-recommended /etc/modsecurity/modsecurity.conf
```

A `/etc/modsecurity/modsecurity.conf`, activar el motor de bloqueig:
```
SecRuleEngine On
```

Si un atacant envia a l'adreça web un patró tipus `?id=1' OR '1'='1`, ModSecurity talla la connexió immediatament retornant un error HTTP 403 Forbidden abans que la petició toque MariaDB!
