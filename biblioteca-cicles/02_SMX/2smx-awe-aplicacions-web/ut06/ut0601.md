En qualsevol aplicació web moderna (WordPress, Moodle, Nextcloud o Roundcube), l'ús del protocol **HTTPS** (*Hypertext Transfer Protocol Secure*) no és opcional: és una exigència legal (RGPD) i tècnica per a protegir contrasenyes, dades mèdiques o acadèmiques i cookies de sessió contra atacs d'intercepció a la xarxa (*Man-in-the-Middle*).

---

## 1. Com Funciona el Xifratge SSL/TLS?

El protocol TLS (*Transport Layer Security*, successor del vell SSL) combina dos tipus de criptografia:
1. **Criptografia Asimètrica (Clau Pública i Privada):** S'utilitza exclusivament durant l'encaixada de mans inicial (*TLS Handshake*) per autenticar el servidor i intercanviar de manera segura una clau secreta de sessió.
2. **Criptografia Simètrica (AES-256 o ChaCha20):** Un cop acordada la clau efímera, tot el trànsit d'informació web es xifra amb aquesta clau compartida, oferint una velocitat de transferència ultraràpida sense carregar la CPU del servidor.

```
[ NAVEGADOR CLIENT ]                                              [ SERVIDOR WEB APACHE ]
         │                                                                   │
         ├── 1. ClientHello (Versions TLS, suites de xifratge suportades) ──>│
         │                                                                   │
         │<── 2. ServerHello + Certificat X.509 + Clau Pública del Servidor ─┤
         │                                                                   │
         ├── 3. Verifica la signatura del certificat amb l'AC (Let's Encrypt)│
         ├── 4. Genera clau de sessió simètrica i la xifra amb la clau pública
         ├── 5. Envia clau de sessió xifrada ───────────────────────────────>│
         │                                                                   │ Desxifra amb Clau Privada
         │<══ 6. CANAL SEGUR XIFRAT AMB AES-256 (HTTP sobre TLS - Port 443) ═╡
```

---

## 2. Autoritats de Certificació (AC) i Let's Encrypt

Un certificat digital és vàlid només si està signat per una **Autoritat de Certificació (AC)** reconeguda pels navegadors:
- **Let's Encrypt:** És una autoritat de certificació gratuïta, oberta i automatitzada que emet certificats vàlids durant 90 dies mitjançant el protocol ACME.
- **Certbot:** És el client oficial desenvolupat per la EFF (*Electronic Frontier Foundation*) que sol·licita, valida i renova automàticament els certificats a servidors Linux.

---

## 3. Desplegament de Certificats amb Certbot a Apache

```bash
# 1. Instal·lar Certbot i el connector d'Apache
sudo apt update
sudo apt install -y certbot python3-certbot-apache

# 2. Sol·licitar i configurar el certificat automàticament
sudo certbot --apache -d portal.iesrafael.es -d aules.iesrafael.es

# 3. Comprovar la renovació automàtica simulada
sudo certbot renew --dry-run
```

Certbot modifica automàticament el fitxer del Virtual Host afegint les directives de certificat:
```apache
SSLEngine on
SSLCertificateFile /etc/letsencrypt/live/portal.iesrafael.es/fullchain.pem
SSLCertificateKeyFile /etc/letsencrypt/live/portal.iesrafael.es/privkey.pem
Include /etc/letsencrypt/options-ssl-apache.conf
```

---

## 4. Redirecció Forçosa a HTTPS i Seguretat HSTS

Per garantir que cap visitant envie dades per l'antic port HTTP no xifrat (Port 80):
1. **Redirecció 301 Permanent a Apache:**
   ```apache
   <VirtualHost *:80>
       ServerName portal.iesrafael.es
       Redirect permanent / https://portal.iesrafael.es/
   </VirtualHost>
   ```
2. **Capçalera HSTS (*HTTP Strict Transport Security*):**
   Indica al navegador que durant el proper any s'ha de negar rotundament a connectar-se per HTTP pla, fins i tot si l'usuari escriu manualment `http://`:
   ```apache
   Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
   ```
