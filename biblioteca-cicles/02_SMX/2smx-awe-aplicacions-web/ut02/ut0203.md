En un entorn corporatiu o educatiu, l'administració de WordPress no pot recaure en un únic compte compartit. El principi de **mínim privilegi** exigeix assignar a cada membre de l'organització exclusivament les funcions necessàries per dur a terme la seua tasca editorial o tècnica.

---

## 1. La Jerarquia de Rols Estàndard de WordPress

WordPress incorpora de sèrie un model de control d'accés basat en rols (**RBAC** - *Role-Based Access Control*). Cada rol agrupa un conjunt determinat de permisos (*capabilities*):

| Rol de WordPress | Àmbit de Treball | Capacitats Principals (*Capabilities*) | Cas d'Ús Típic |
| :--- | :--- | :--- | :--- |
| **Superadministrador** | Multisite Network | Accés global a tota la xarxa de llocs, gestió de dominis i actualització de plugins globals | Administrador de sistemes IT |
| **Administrador** | Lloc individual | Accés complet al tauler: instal·lar/eliminar temes i connectors, gestionar usuaris, canviar ajustos globals | Responsable tècnic del lloc web |
| **Editor** | Contingut global | Publicar, editar i eliminar **qualsevol** entrada o pàgina (pròpia o d'altres usuaris), moderar comentaris | Cap de redacció o coordinador de continguts |
| **Autor** | Contingut propi | Crear, editar, publicar i eliminar **únicament les seues pròpies** entrades. Pot pujar arxius multimèdia | Redactor de plantilla |
| **Col·laborador** | Redacció de borradors | Escriure i modificar les seues pròpies entrades, però **no pot publicar-les** directament ni pujar arxius | Alumne en pràctiques o redactor extern |
| **Subscriptor** | Lectura i perfil | Només pot accedir al lloc web, llegir contingut privat i modificar les dades del seu perfil | Usuari registrat o client |

---

## 2. Creació i Gestió d'Usuaris des del Tauler

Des de l'apartat **Usuaris ➔ Afegeix un nou usuari** es defineixen:
1. **Nom d'usuari (*Username*):** Identificador únic alfanumèric immutable.
2. **Correu electrònic:** Requerit per a notificacions de sistema i restabliment de contrasenya.
3. **Contrasenya:** WordPress genera automàticament cadenes d'alta entropia (16+ caràcters amb símbols).
4. **Rol assignat:** Selecció estricta segons la responsabilitat de l'usuari.

---

## 3. Polítiques de Seguretat i Enduriment d'Autenticació

Per protegir el tauler d'accés (`/wp-login.php` i `/wp-admin/`) contra atacs de força bruta i robatori de sessions:

### A. Autenticació de Doble Factor (2FA)
Mitjançant connectors com *Two-Factor* o *Wordfence Security*, s'exigeix l'ús d'aplicacions autenticadores TOTP (com Google Authenticator o Aegis) generant codis temporals de 6 dígits.

### B. Limitació d'Intents d'Inici de Sessió (*Limit Login Attempts*)
Per defecte, WordPress permet intents infinits d'inici de sessió. Instal·lant connectors o configurant regles a nivell de servidor web (amb `fail2ban`), es bloqueja la IP de l'origen després de 3 o 5 intents fallits consecutius durant 60 minuts.

### C. Desactivació del Registre d'Usuaris Públics
A **Ajustos ➔ Generals**, l'opció *"Qualsevol persona pot registrar-se"* ha d'estar **desmarcada** en llocs corporatius o escolars per evitar la creació massiva de comptes bot no autoritzats.

```
       [ Atacant Força Bruta ] ──> 3 intents fallits ──> [ Bloqueig IP per Fail2ban ]
                                                                    │
       [ Usuari Legítim ] ────> Nom d'usuari + Clau ──> [ Repte TOTP 2FA ] ──> Accés OK
```

---

## 4. Auditoria de Seguretat i Registre d'Accions

En organitzacions amb múltiples editors, és indispensable saber qui ha modificat o suprimit un contingut. Connectors com **WP Activity Log** registren:
- Data, hora i adreça IP de cada connexió.
- Canvis d'estat de les pàgines (publicació, eliminació, pas a paperera).
- Activacions o desactivacions de connectors per part d'administradors.
