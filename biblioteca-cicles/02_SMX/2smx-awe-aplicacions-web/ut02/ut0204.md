La potència editorial de WordPress rau en la clara distinció entre els continguts dinàmics cronològics (Entrades), la informació estàtica institucional (Pàgines), la seua categorització semàntica (Taxonomies) i la capa visual de presentació (Temes).

---

## 1. Entrades (*Posts*) vs Pàgines (*Pages*)

| Característica | Entrades (*Posts*) | Pàgines (*Pages*) |
| :--- | :--- | :--- |
| **Objectiu** | Articles de notícies, comunicats, novetats diàries | Contingut estàtic i permanent de referència |
| **Organització temporal** | Cronològica inversa (amb data, hora i autor visible) | Atemporal (sense data rellevant en la presentació) |
| **Taxonomies** | Suporta **Categories** (jeràrquiques) i **Etiquetes** | No admet categories ni etiquetes per defecte |
| **Estructura** | Agrupades en arxius per data, autor i categoria | Jeràrquica en arbre (pàgines mares i filles) |
| **Exemples típics** | *"Inici de les matriculacions 2026/27"*, *"Festa de final de curs"* | *"Qui som"*, *"On estem"*, *"Política de Privacitat"* |

---

## 2. Taxonomies: Categories i Etiquetes (*Tags*)

Per mantenir un lloc web corporatiu navegable i accessible:
- **Categories:** Són classificacions àmplies i obligatòries que accepten jerarquia (ex: *Departaments* ➔ *Informàtica* ➔ *Cicles Formatius*). Si una entrada no té categoria assignada, WordPress li assigna automàticament la categoria per defecte (*Sense categoria* / *Uncategorized*).
- **Etiquetes (*Tags*):** Són paraules clau opcionals i no jeràrquiques que connecten continguts de diferents categories (ex: *#Ubuntu*, *#Beques*, *#Exàmens*).

---

## 3. L'Editor de Blocs (Gutenberg) i el Disseny Basat en Components

WordPress utilitza l'editor de blocs modular (**Gutenberg**):
- Cada paràgraf, encapçalat, llista, taula o imatge és un component aïllat (`wp:paragraph`, `wp:heading`).
- Permet reutilitzar blocs i crear patrons de disseny (*Block Patterns*) corporatius per a garantir coherència visual entre diferents redactors.

---

## 4. L'Arquitectura de Temes i la Jerarquia de Plantilles

Un tema de WordPress controla la presentació visual completa del lloc web. Els temes es troben a `/var/www/portal-wordpress/wp-content/themes/<nom-tema>/` i es regeixen per la **jerarquia de plantilles** de WordPress:

```
Peticions HTTP ──> front-page.php ──> home.php ──> index.php
Peticions de Post ──> single-{post_type}.php ──> single.php ──> singular.php ──> index.php
Peticions de Pàgina ──> page-{slug}.php ──> page.php ──> singular.php ──> index.php
Peticions de Categoria ──> category-{slug}.php ──> category.php ──> archive.php ──> index.php
```

Fitxers obligatoris en qualsevol tema clàssic:
- `style.css`: Full d'estils principal amb la capçalera de metadades del tema.
- `index.php`: Plantilla principal de reserva (*fallback*).
- `functions.php`: Fitxer de codi PHP on es registren menús, barres laterals i suport per a imatges destacades.

---

## 5. Per què és Obligatori Crear un Tema Fill (*Child Theme*)?

Quan s'instal·la un tema de tercers (com Astra, GeneratePress o Twenty Twenty-Four) i es vol personalitzar el codi CSS o afegir codi PHP a `functions.php`, **mai s'ha de modificar directament el tema original (pare)**:
- Quan el desenvolupador del tema pare publique una actualització de seguretat, **tots els canvis locals s'esborraran**.
- La solució és crear un **Tema Fill (*Child Theme*)**.

### Estructura i Creació d'un Tema Fill

1. Crear la carpeta del tema fill:
   ```bash
   sudo mkdir /var/www/portal-wordpress/wp-content/themes/astra-child
   ```
2. Crear el fitxer `/var/www/portal-wordpress/wp-content/themes/astra-child/style.css`:
   ```css
   /*
    Theme Name:   Astra Child Corporatiu IES
    Theme URI:    https://iesrafael.local/
    Description:  Tema fill personalitzat per a l'institut
    Author:       Departament d'Informàtica
    Template:     astra
    Version:      1.0.0
   */
   
   /* Personalitzacions CSS adicionals */
   body {
       font-family: 'Inter', system-ui, sans-serif;
   }
   .site-header {
       border-bottom: 3px solid #0056b3;
   }
   ```
   > [!WARNING]
   > La línia `Template: astra` ha de coincidir **exactament** amb el nom del directori del tema pare (respectant majúscules i minúscules).

3. Crear el fitxer `/var/www/portal-wordpress/wp-content/themes/astra-child/functions.php`:
   ```php
   <?php
   // Cua d'estils del tema pare i del tema fill
   add_action( 'wp_enqueue_scripts', 'ies_carregar_estils_tema_fill' );
   function ies_carregar_estils_tema_fill() {
       wp_enqueue_style( 'parent-style', get_template_directory_uri() . '/style.css' );
       wp_enqueue_style( 'child-style', get_stylesheet_uri(), array( 'parent-style' ) );
   }
   ```
