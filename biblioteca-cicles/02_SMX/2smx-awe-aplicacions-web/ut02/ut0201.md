Un **CMS** (*Content Management System* o Sistema de Gestió de Continguts) és una aplicació web que permet crear, editar, organitzar i publicar contingut multimèdia a Internet sense requerir coneixements avançats de programació web per part dels redactors. **WordPress** és el CMS de codi obert més utilitzat del món, impulsant més del 40% de tots els llocs web globals.

---

## 1. Requeriments del Sistema per a WordPress

Abans de desplegar WordPress en un entorn de producció sobre Linux (Debian/Ubuntu), cal assegurar-se que la pila tecnològica compleix els següents requisits mínims recomanats:

| Component | Versió Mínima Recomanada | Funció en l'Ecosistema | Paquets / Extensions Requerides |
| :--- | :--- | :--- | :--- |
| **Servidor Web** | Apache 2.4 o Nginx 1.20+ | Recepció de peticions HTTP/HTTPS i reescriptura d'URLs | Mòdul `mod_rewrite` habilitat a Apache |
| **Intèrpret PHP** | PHP 8.1 o 8.2+ | Execució de la lògica de negoci del CMS | `php-mysql`, `php-curl`, `php-gd`, `php-mbstring`, `php-xml`, `php-zip`, `php-intl` |
| **Base de Dades** | MariaDB 10.5+ o MySQL 8.0+ | Emmagatzematge persistent de posts, usuaris i opcions | Motor InnoDB i joc de caràcters `utf8mb4` |
| **Memòria RAM PHP** | 256 MB o 512 MB (`memory_limit`) | Processament de temes i connectors complexos | Ajustable en `/etc/php/8.2/apache2/php.ini` |

## 2. Anatomia del Sistema de Fitxers de WordPress

Quan es descarrega i descomprimeix el paquet oficial de WordPress (`tar -xvzf latest.tar.gz`) en el directori arrel del Virtual Host (per exemple `/var/www/wordpress`), trobem una estructura dividida en tres directoris principals i fitxers arrel clau:

```
/var/www/wordpress/
├── index.php               # Punt d'entrada únic que carrega el nucli de WordPress
├── wp-config.php           # FITXER CLAU: Credencials de BD, claus secretes i configuració
├── wp-config-sample.php    # Plantilla de configuració que s'utilitza durant la instal·lació
├── wp-activate.php         # Activació d'usuaris en instal·lacions multisite
├── wp-cron.php             # Execució de tasques programades (entrades, actualitzacions)
├── wp-login.php            # Pàgina oficial d'autenticació i accés al panell
├── wp-admin/               # Directori del tauler de control d'administració (Dashboard)
├── wp-includes/            # Llibreries auxiliars, API interna i funcions del nucli (Core)
└── wp-content/             # DIRECTORI D'USUARI: Tot el contingut generat o personalitzat
    ├── plugins/            # Extensions i connectors instal·lats
    ├── themes/             # Temes visuals i plantilles de disseny
    ├── uploads/            # Imatges, documents i arxius multimèdia pujats per usuaris
    └── languages/          # Fitxers de traducció (.mo i .po)
```

> [!IMPORTANT]
> Mai s'han de modificar fitxers dins de `wp-admin` o `wp-includes`. Qualsevol canvi en aquests directoris se sobreescriurà durant les actualitzacions del nucli. Totes les personalitzacions es fan a `wp-content` o a través de connectors.

## 3. El Fitxer de Configuració Mestra: `wp-config.php`

El fitxer `wp-config.php` connecta el programari amb el servidor de base de dades i estableix la seguretat criptogràfica:

```php
<?php
// 1. Configuració de la Base de Dades
define( 'DB_NAME', 'wp_corporatiu' );
define( 'DB_USER', 'usuari_wp' );
define( 'DB_PASSWORD', 'ContrasenyaSegura.2026!' );
define( 'DB_HOST', 'localhost' );
define( 'DB_CHARSET', 'utf8mb4' );
define( 'DB_COLLATE', '' );

// 2. Claus úniques d'autenticació i salts (generades per api.wordpress.org/secret-key/1.1/salt/)
define('AUTH_KEY',         'x8#9zL@...cadena_aleatoria_unica...');
define('SECURE_AUTH_KEY',  'bK2$1vQ...cadena_aleatoria_unica...');
define('LOGGED_IN_KEY',    'pT7!mZ8...cadena_aleatoria_unica...');
define('NONCE_KEY',        'wR5^yN3...cadena_aleatoria_unica...');

// 3. Prefix de les taules (mesura bàsica contra atacs SQLi basats en prefixos coneguts)
$table_prefix = 'wp_corp_';

// 4. Mode de depuració (desactivat en entorns de producció)
define( 'WP_DEBUG', false );

// 5. Rutes absolutes
if ( ! defined( 'ABSPATH' ) ) {
    define( 'ABSPATH', __DIR__ . '/' );
}
require_once ABSPATH . 'wp-settings.php';
```

## 4. Estructura de la Base de Dades Relacional

WordPress empra un model de dades extremadament eficient basat en un esquema de 12 taules principals (amb el prefix configurat):

1. **`wp_posts`**: La taula central on s'emmagatzemen articles de blog, pàgines estàtiques, elements multimèdia (adjunts), menús de navegació i revisions.
2. **`wp_postmeta`**: Magatzem clau-valor de metadades associades als posts (imatges destacades, camps personalitzats, configuració de SEO).
3. **`wp_users` i `wp_usermeta`**: Comptes d'usuari registrats, credencials xifrades amb `phpass`/`bcrypt` i capacitats o rols associats.
4. **`wp_options`**: Opcions globals del lloc (URL del lloc, títol, tema actiu, configuració dels connectors).
5. **`wp_terms`, `wp_term_taxonomy`, `wp_term_relationships`**: Sistema de taxonomia per a categoritzar i etiquetar posts.
6. **`wp_comments` i `wp_commentmeta`**: Comentaris rebuts, moderació i dades d'aprovació.

---

## 5. Activitat Pràctica Guiada: Verificació de Requeriments en Servidor Debian

1. Instal·lar els mòduls de PHP requerits per WordPress:
   ```bash
   sudo apt update
   sudo apt install -y apache2 mariadb-server php php-mysql php-curl php-gd php-mbstring php-xml php-zip php-intl libapache2-mod-php
   ```
2. Habilitar el mòdul de reescriptura d'URLs a Apache:
   ```bash
   sudo a2enmod rewrite
   sudo systemctl restart apache2
   ```
3. Crear un fitxer de prova `info.php` a `/var/www/html/` per comprovar la càrrega del mòdul `mysqli` i la memòria assignada (`phpinfo();`), i eliminar-lo en acabar per motius de seguretat.
