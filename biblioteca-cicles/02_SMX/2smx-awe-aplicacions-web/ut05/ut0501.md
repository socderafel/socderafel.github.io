L'ofimàtica clàssica instal·lada a l'ordinador local (com Microsoft Office o LibreOffice desktop) ha evolucionat cap a solucions d'edició integrada en el propi navegador web. Aquestes eines permeten que múltiples usuaris editen simultàniament un document de text, un full de càlcul o una presentació de diapositives veient els canvis i els cursors dels companys en temps real.

---

## 1. El Protocol WOPI: El Pont entre Fitxers i l'Editor Web

Com es connecta un servidor d'arxius (com Nextcloud o SharePoint) amb un motor d'edició ofimàtica web? Mitjançant l'estàndard **WOPI** (*Web Application Open Platform Interface*):

```
[ NAVEGADOR DE L'USUARI ]
       │  1. Obre document .docx
       v
[ SERVIDOR D'ARXIUS (Nextcloud) ] ── 2. Sol·licita sessió WOPI ──> [ SERVIDOR D'EDICIÓ (ONLYOFFICE / Collabora) ]
       │                                                                  │
       │ <────── 3. Retorna token d'accés segur JWT i URL de l'editor ────┘
       v
[ IFRAME AMB L'EDITOR WEB AL NAVEGADOR ]
       │  4. Canvis d'edició simultanis en temps real (WebSockets)
       v
[ SERVIDOR D'EDICIÓ ] ─────── 5. Desa el fitxer actualitzat ───────> [ SERVIDOR NEXTCLOUD ]
```

### Com Funciona WOPI?
1. L'usuari fa clic sobre un arxiu `.docx`, `.xlsx` o `.pptx` a Nextcloud.
2. Nextcloud crea un token d'accés temporal xifrat i redirigeix l'iframe cap al servidor de documents.
3. El servidor de documents utilitza el protocol WOPI (peticions REST) per demanar el fitxer binari a Nextcloud (`GetFile`), el processa i el mostra al navegador.
4. Quan els usuaris fan canvis, el servidor de documents sincronitza la sessió i envia la nova versió a Nextcloud mitjançant `PutFile`.

## 2. Comparativa: ONLYOFFICE vs Collabora Online

Dues grans solucions de codi obert lideren l'ofimàtica web corporativa sobirana:

| Paràmetre | ONLYOFFICE Document Server | Collabora Online (CODE) |
| :--- | :--- | :--- |
| **Model de Renderització** | **Renderització en el Client:** El navegador executa JavaScript/HTML5 Canvas amb la màxima fidelitat visual a formats Microsoft Office. | **Renderització en el Servidor:** El servidor executa una instància virtual de LibreOffice i envia mosaics d'imatges (*tiles*) al client. |
| **Consum de Recursos** | Baix consum de CPU i ample de banda al servidor (el pes del càlcul el suporta el PC de l'usuari). | Major consum de CPU i ample de banda al servidor en haver de renderitzar els mosaics en temps real. |
| **Fidelitat de formats** | Compatibilitat nativa excel·lent amb formats OOXML (`.docx`, `.xlsx`, `.pptx`). | Compatibilitat nativa nativa amb formats OpenDocument (`.odt`, `.ods`, `.odp`) de LibreOffice. |
| **Mode fora de línia** | Fàcilment extensible amb aplicacions d'escriptori híbrides. | Requereix connexió continuada al servidor CODE. |

---

## 3. Seguretat en WOPI: Tokens JWT (*JSON Web Tokens*)

Per evitar que servidors externs no autoritzats puguen injectar o robar documents en edició:
- Totes les comunicacions entre el servidor de fitxers i el servidor ofimàtic van signades amb un **Secret Compartit JWT**.
- Si la signatura del token no coincideix amb la clau secreta configurada a ambdós extrems, la connexió es rebutja de manera immediata (error HTTP 403 Forbidden).
