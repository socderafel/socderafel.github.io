# 3.4 Models de Control d'Accés i Autorització (DAC, MAC, RBAC)

Un cop un usuari ha demostrat la seua identitat legítima, el subsistema de seguretat ha de decidir quines operacions (llegir, escriure, executar o esborrar) té autorització per a dur a terme sobre cada recurs del sistema. Aquesta política es formalitza mitjançant **Models de Control d'Accés**.

---

## 1. Els Tres Models Clàssics de Control d'Accés

```
                     Models de Control d'Accés
           ┌─────────────────────┼─────────────────────┐
           ▼                     ▼                     ▼
          DAC                   MAC                  RBAC
     (Discrecional)        (Obligatori)         (Basat en Rols)
  [Propietari decideix]  [Etiquetes Seguretat]   [Grups i Funcions]
```

### A. DAC (*Discretionary Access Control* - Control Discrecional)
- El creador o propietari (*owner*) del recurs (fitxer, carpeta) té el control absolut sobre ell i decideix lliurement a quins altres usuaris atorga o denega permisos.
- **Implementació:** Els permisos estàndard d'arxius en sistemes operatius d'escriptori com Windows o GNU/Linux per defecte.
- **Inconvenient:** Si un empleat s'equivoca i concedeix permís de lectura a tothom (`Everyone` o `777`), el sistema ho permet sense oposició.

### B. MAC (*Mandatory Access Control* - Control Obligatori)
- Els usuaris **no poden** modificar els permisos dels seus propis fitxers. Una autoritat centralitzada de seguretat assigna **nivells de classificació** als subjectes i etiquetes als objectes (per exemple: *Públic*, *Confidencial*, *Secret*, *Top Secret*).
- El sistema operatiu aplica regles matemàtiques estrictes (com el model Bell-LaPadula: *«no llegir cap amunt, no escriure cap avall»*).
- **Implementació:** Sistemes militars, mòduls **SELinux** a Linux o AppArmor.

### C. RBAC (*Role-Based Access Control* - Control Basat en Rols)
- El model estàndard en xarxes corporatives. Els permisos no s'assignen individualment a cada persona, sinó a **Rols o Grups de Treball** que reflecteixen la seua funció laboral (ex: *Grup-Comptabilitat*, *Grup-Tècnics*, *Grup-Professors*).
- Quan un treballador s'incorpora o canvia de departament, l'administrador simplement l'afegeix o l'elimina del grup corresponent, heretant automàticament els permisos adequats.

---

## 2. El Principi de Mínim Privilegi (*Least Privilege*)

Un dels axiomes més crítics de la ciberseguretat:
> **A cada usuari, programa o procés del sistema només se li han de concedir els privilegis estrictament necessaris per a acomplir la seua tasca legítima, i durant el temps mínim indispensable.**

- Mai s'ha de treballar en el dia a dia com a usuari administrador (`root` a Linux o `Administrador` a Windows).
- Per a tasques que requereixen elevació puntual, s'utilitza la comanda `sudo` a Linux o el Control de Comptes d'Usuari (**UAC**) a Windows.
- Si un usuari comú és infectat per un malware, el dany quedarà confinat a la seua carpeta personal i no podrà destruir el sistema operatiu complet.
