# 7.5 Clients Softphone, Proves de Trucada i Diagnòstic

Un cop configurada la centraleta Asterisk, els usuaris necessiten dispositius terminals per a realitzar i rebre trucades. Aquests terminals poden ser maquinari dedicat (**Hardphones**, telèfons IP d'escriptori com Yealink o Grandstream) o programari instal·lat a l'ordinador o smartphone (**Softphones**).

---

## 1. Clients Softphone de Referència

| Programari | Plataformes Suportades | Característiques Destacades |
| :--- | :--- | :--- |
| **MicroSIP** | Windows (portable i ultra-lleuger) | Codi obert, consum de recursos mínim, suport complet de còdecs (G.711, Opus, Speex) i xifratge TLS/SRTP. |
| **Linphone** | Linux, Windows, macOS, Android, iOS | Multiplataforma, interfície moderna, suport de trucades de vídeo HD i xifratge d'extrem a extrem ZRTP. |
| **Zoiper** | Windows, Linux, macOS, mòbils | Molt popular en entorns corporatius, suport de codis QR per a auto-provisionament ràpid. |

---

## 2. Paràmetres de Connexió en MicroSIP

Per a connectar un client MicroSIP a la centraleta Asterisk desplegada a l'aula o empresa:

1. **Nom del compte (*Account Name*):** Nom descriptiu (Ex: `Recepció 101`).
2. **Servidor SIP (*SIP Server*):** Adreça IP o nom de domini del servidor Asterisk (Ex: `192.168.10.10` o `pbx.iesmestreesteve.es`).
3. **Usuari SIP (*Username*):** Número d'extensió configurat (Ex: `101`).
4. **Domini (*Domain*):** Mateixa IP o domini del servidor (`192.168.10.10`).
5. **Usuari de login (*Login*):** El mateix identificador d'usuari (`101`).
6. **Contrasenya (*Password*):** La clau configurada a la secció `auth` de `pjsip.conf`.
7. Si el registre és correcte, la barra d'estat inferior de MicroSIP mostrarà un indicador verd amb la paraula **En línia (*Online*)**.

---

## 3. Anàlisi i Diagnòstic de Fluxos amb Wireshark

Wireshark és l'eina definitiva per a resoldre problemes de telefonia IP (*troubleshooting*). Mitjançant el menú especial **Telephony → VoIP Calls**, Wireshark detecta automàticament totes les trucades que circulen per la interfície de xarxa:

```
          Client A (192.168.10.50)           Servidor PBX (192.168.10.10)
                     │                                   │
                     │ ──── SIP INVITE ────────────────► │
                     │ ◄─── SIP 100 Trying ───────────── │
                     │ ◄─── SIP 180 Ringing ──────────── │
                     │ ◄─── SIP 200 OK ───────────────── │
                     │ ──── SIP ACK ───────────────────► │
                     │                                   │
                     │ ◄════ Bidirectional RTP Streams ═►│ (Àudio G.711 / Opus)
                     │                                   │
                     │ ──── SIP BYE ───────────────────► │
                     │ ◄─── SIP 200 OK ───────────────── │
```

1. **Comprovació de Senyalització SIP:**
   - **Filtre de captura Wireshark:** `sip`
   - Permet verificar si els missatges `INVITE` arriben al servidor, si hi ha errors d'autenticació (`401 Unauthorized` o `403 Forbidden`) o si el destinatari està ocupat (`486 Busy Here`).

2. **Comprovació del Flux d'Àudio RTP (Símptoma de Trucada Muda):**
   - **Filtre de captura Wireshark:** `rtp`
   - El problema més habitual en telefonia IP és la **trucada d'un sol sentit (*one-way audio*)** o la **trucada muda**: la trucada connecta i sona, però cap interlocutor escolta l'altre. Això sol produir-se quan el tallafocs permet el port de senyalització SIP (5060) però bloqueja el rang de ports UDP multimèdia d'RTP (10000-20000).
   - Mitjançant **Telephony → RTP → RTP Streams → Play Streams**, l'administrador pot escoltar la gravació exacta dels paquets transmesos per a auditar la qualitat del so i descartar talls de xarxa.
