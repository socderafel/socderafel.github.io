La seguretat basada únicament en nom d'usuari i contrasenya és feble: els usuaris trien contrasenyes curtes i els servidors connectats a Internet reben milers d'atacs de força bruta cada hora. El mètode d'autenticació professional més segur i recomanat a OpenSSH és l'**autenticació basada en parells de claus asimètriques (*Public Key Authentication*)**.

---

## 1. Fonament Criptogràfic: Clau Privada vs Clau Pública

L'usuari genera a la seua màquina client dues claus matemàticament vinculades:

```
[ MÀQUINA CLIENT (Portàtil de l'Administrador) ]
├── CLAU PRIVADA (id_ed25519): Es queda secreta al client, mai s'envia per la xarxa!
│                              (Es protegeix amb una frase de pas o Passphrase).
│
└── CLAU PÚBLICA (id_ed25519.pub): Es copia lliurement al servidor remot!
                                   │
                                   v
[ SERVIDOR REMOT (Debian) ] ──── S'afegeix a: ~/.ssh/authorized_keys
```

### Com Funciona l'Autenticació Criptogràfica?
1. El client es connecta i diu: *"Vull entrar com a usuari joan"*.
2. El servidor consulta el fitxer `~/.ssh/authorized_keys` del compte de `joan`.
3. El servidor genera un repte aleatori (*challenge*), el xifra amb la **Clau Pública** de l'usuari i l'envia al client.
4. L'únic ordinador de l'univers capaç de desxifrar aquest repte és aquell que posseeix la **Clau Privada** corresponent.
5. El client el desxifra amb la seua clau privada i retorna la solució. El servidor comprova que és correcta i **permet l'accés instantani sense que cap contrasenya haja viatjat per la xarxa**!

---

## 2. Generació del Parell de Claus amb `ssh-keygen`

En el sistema client (Linux, macOS o Windows amb PowerShell):

```bash
# Generar clau amb l'algorisme modern d'alta seguretat i corbes el·líptiques Ed25519:
ssh-keygen -t ed25519 -C "admin_ies_2026"

# (Alternativa clàssica RSA de 4096 bits):
# ssh-keygen -t rsa -b 4096
```

L'assistent demanarà:
- On desar la clau (prémer Retorn per acceptar la ruta per defecte `~/.ssh/id_ed25519`).
- Frase de pas (*Passphrase*): Una contrasenya per xifrar la clau privada local al disc dur del client.

---

## 3. Còpia de la Clau Pública al Servidor amb `ssh-copy-id`

Per instal·lar la clau pública al compte de l'usuari remot de manera automatitzada:

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub alumne1@192.168.10.10
```
La comanda es connecta demanant la contrasenya per última vegada, crea la carpeta `~/.ssh/` al servidor amb permisos `700`, afegeix la clau a `~/.ssh/authorized_keys` amb permisos `600` i tanca la sessió. A partir d'aquest moment, la connexió s'inicia sense demanar cap contrasenya de servidor!

---

## 4. Desactivació Total de l'Inici per Contrasenya (*Passwordless*)

Un cop verificat que la clau pública funciona, procedim al blindatge final del servidor:
A `/etc/ssh/sshd_config`:
```ini
# Desactivar l'autenticació per contrasenya convencional
PasswordAuthentication no

# Desactivar contrasenyes buides
PermitEmptyPasswords no

# Mantenir activa l'autenticació per clau pública
PubkeyAuthentication yes
```

Reiniciar el servei: `sudo systemctl restart ssh`. A partir d'ara, qualsevol atacant que intente un atac de força bruta rebrà l'error immediat `Permission denied (publickey)`, fent el servidor immune a atacs de diccionari!
