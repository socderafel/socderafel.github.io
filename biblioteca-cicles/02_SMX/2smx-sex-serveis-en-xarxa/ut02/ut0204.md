A més de conèixer la IP d'un nom de màquina (resolució directa), els serveis de seguretat i servidors de correu necessiten fer l'operació contrària: donada una adreça IP, esbrinar quin és el seu nom oficial certificat (**Resolució Inversa**). D'altra banda, per evitar que la xarxa caiga si el servidor DNS s'apaga, és obligatori configurar un **Servidor DNS Secundari (*Slave*)** que mantinga una rèplica exacta de les dades.

---

## 1. El Domini Especial de Resolució Inversa: `in-addr.arpa`

Com que l'adreçament IP s'organitza de major a menor jerarquia de xarxa (de classe a amfitrió) mentre que els dominis es llegeixen de menor a major (de subdomini a TLD), a la resolució inversa **els octets de l'adreça de xarxa s'escriuen en ordre invers**:

- Si la nostra xarxa local és `192.168.10.0/24`:
- S'inverteixen els 3 octets de xarxa: `10.168.192`
- S'afegeix el domini arrel d'adreçament invers: **`.in-addr.arpa`**
- El nom complet de la zona inversa és: **`10.168.192.in-addr.arpa`**

---

## 2. Configuració de la Zona Inversa a Bind9

A `/etc/bind/named.conf.local`:
```ini
zone "10.168.192.in-addr.arpa" {
    type master;
    file "/etc/bind/db.192.168.10";
    allow-transfer { 192.168.10.3; };
};
```

Creem el fitxer `/etc/bind/db.192.168.10`:
```ini
$TTL    86400
@       IN      SOA     ns1.iesrafael.local. admin.iesrafael.local. (
                        2026110301      ; Serial
                        28800           ; Refresh
                        7200            ; Retry
                        2419200         ; Expire
                        86400 )         ; Negative Cache TTL
;
@       IN      NS      ns1.iesrafael.local.
@       IN      NS      ns2.iesrafael.local.

; REGISTRES DE PUNTER INVERS (PTR)
1       IN      PTR     router.iesrafael.local.
2       IN      PTR     ns1.iesrafael.local.
3       IN      PTR     ns2.iesrafael.local.
10      IN      PTR     server.iesrafael.local.
```

> [!NOTE]
> La línia `10 IN PTR server.iesrafael.local.` significa que la IP `192.168.10.10` correspon al nom de màquina `server.iesrafael.local.`.

---

## 3. Desplegament del Servidor DNS Secundari (Esclau)

En un segon servidor Linux (`192.168.10.3`) instal·lem Bind9 i declarem les mateixes zones, però indicant que és de tipus esclau (`type slave`):

A `/etc/bind/named.conf.local` del **Servidor Esclau**:
```ini
zone "iesrafael.local" {
    type slave;
    file "/var/cache/bind/db.iesrafael.local"; // Es desa automàticament
    masters { 192.168.10.2; };                // IP del Servidor Mestre
};

zone "10.168.192.in-addr.arpa" {
    type slave;
    file "/var/cache/bind/db.192.168.10";
    masters { 192.168.10.2; };
};
```

---

## 4. El Mecanisme de Transferència de Zona (*AXFR / IXFR*)

Com es comuniquen el Mestre i l'Esclau?
1. L'administrador fa un canvi al fitxer de zona del Mestre, incrementa el **Serial** i reinicia Bind9.
2. El Mestre envia un missatge de notificació ràpida (**DNS NOTIFY**) a tots els servidors esclaus de la zona.
3. L'esclau rep l'avís, comprova el seu propi Serial i, en veure que és inferior, inicia una connexió **TCP pel port 53** sol·licitant una **Transferència de Zona (AXFR)**.
4. El fitxer es descarrega i l'esclau comença a respondre consultes immediatament amb les dades actualitzades.
