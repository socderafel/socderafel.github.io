# 🌐 1.1 Arquitectura Client-Servidor i el Protocol DHCP

En una xarxa local corporativa o domèstica amb desenes o centenars de dispositius (ordinadors de sobretaula, portàtils, telèfons mòbils, impressores de xarxa i dispositius IoT), configurar manualment a cada equip l'adreça IP, la màscara de subxarxa, la passarel·la per defecte i els servidors DNS és inviable i font constant de conflictes d'adreces duplicades. El protocol **DHCP** (*Dynamic Host Configuration Protocol*) resol aquesta problemàtica automatitzant l'entrega i el control centralitzat dels paràmetres de xarxa.

---

## 1. El Model d'Adreçament: Estàtic vs Dinàmic

| Criteri | Adreçament Manual (Estàtic) | Adreçament Automàtic (DHCP) |
| :--- | :--- | :--- |
| **Configuració** | Introduïda manualment a cada terminal per l'administrador | Sol·licitada i rebuda automàticament en arrencar l'equip |
| **Risc d'error** | Alt (possibilitat de duplicar IPs o equivocar la màscara/DNS) | Nul (el servidor manté una taula de concessions lliures de col·lisió) |
| **Mobilitat** | Inexistent (cal reconfigurar l'equip si canvia de subxarxa o despatx) | Total (l'equip obté la IP adequada de la nova subxarxa en connectar-se) |
| **Cas d'ús ideal** | Servidors, encaminadors, impressores de xarxa i switches gestionables | Equips clients d'oficina, aules d'informàtica i dispositius Wi-Fi |

---

## 2. Ports i Transport del Protocol DHCP

DHCP funciona sobre la capa de transport utilitzant el protocol no orientat a connexió **UDP** (*User Datagram Protocol*):
- **Port UDP 67:** Port de destí on escolta el **Servidor DHCP**.
- **Port UDP 68:** Port d'origen i destí on escolta el **Client DHCP**.

Com que un client que s'acaba d'engegar no té adreça IP configurada ni coneix quina és la IP del servidor de la xarxa, les primeres comunicacions s'emeten obligatòriament mitjançant **difusió (*Broadcast*)**:
- Adreça IP d'origen: `0.0.0.0`
- Adreça IP de destí: `255.255.255.255`
- Adreça MAC de destí: `FF:FF:FF:FF:FF:FF`

---

## 3. El Cicle de Negociació DORA (Discover, Offer, Request, Acknowledge)

La negociació bàsica d'una concessió (*lease*) DHCP entre un client i un servidor segueix estrictament quatre fases conegudes per l'acrònim **DORA**:

```
[ CLIENT DHCP ]                                               [ SERVIDOR DHCP ]
       │                                                              │
       ├──── 1. DHCPDISCOVER (Broadcast UDP 67: "Busque servidor") ──>│
       │                                                              │
       │<─── 2. DHCPOFFER (Unicast/Broadcast: "T'oferisc la IP .50") ─┤
       │                                                              │
       ├──── 3. DHCPREQUEST (Broadcast: "Accepte l'oferta de .50") ──>│
       │                                                              │
       │<─── 4. DHCPACK (Unicast/Broadcast: "Confirmat! És teua") ────┤
       │                                                              │
   [ CONFIGURAT ]                                                [ CONCESSIÓ DESADA ]
```

### Anàlisi Detallada de les Fases DORA:
1. **DHCPDISCOVER:** El client s'inicia i envia un missatge de difusió general preguntant si hi ha algun servidor DHCP disponible a la xarxa local.
2. **DHCPOFFER:** Un o més servidors DHCP responen oferint una adreça IP disponible del seu rang, la màscara, el temps de concessió i la seua pròpia IP com a identificador del servidor.
3. **DHCPREQUEST:** El client tria una de les ofertes rebudes (generalment la primera que li ha arribat) i transmet un missatge en difusió informant a tots els servidors de quina oferta ha acceptat. D'aquesta manera, els altres servidors alliberen les seues ofertes no triades.
4. **DHCPACK (Acknowledgment):** El servidor escollit confirma formalment la concessió, envia tots els paràmetres addicionals (passarel·la, DNS, nom de domini) i registra la vinculació entre l'adreça MAC del client i la IP concedida a la seua base de dades.

---

## 4. Renovació de la Concessió: T1, T2 i DHCPRELEASE

Una adreça IP atorgada per DHCP no és perenne; té una vigència temporal anomenada **Temps de Concessió (*Lease Time*)**:
- **Temporitzador T1 (50% del temps):** Quan transcorre la meitat del temps de concessió, el client envia un missatge **DHCPREQUEST directe per Unicast** al servidor que li va donar la IP demanant renovar el lloguer. Si el servidor respon amb un **DHCPACK**, el comptador es reinicia al 100%.
- **Temporitzador T2 (87.5% del temps):** Si el servidor original no respon al 50% (està apagat o caigut), el client espera fins al 87.5% i aleshores emet un **DHCPREQUEST en difusió (Broadcast)** demanant a qualsevol altre servidor de la xarxa que li prorrogue o n'assigne una altra.
- **Expiració (100%):** Si arriba al 100% sense resposta, el client ha d'alliberar immediatament la IP i tornar a començar el cicle DORA des de zero.
- **DHCPRELEASE:** Quan un equip s'apaga de manera ordenada o l'usuari executa `ipconfig /release` o `dhclient -r`, s'envia un missatge al servidor per alliberar la IP immediatament perquè puga ser utilitzada per un altre dispositiu.
