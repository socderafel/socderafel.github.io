El protocol **FTP** (*File Transfer Protocol* o Protocol de Transferència de Fitxers) és un dels serveis més veterans d'Internet (RFC 959). La seua missió fonamental és permetre la transferència bidireccional fiable d'arxius (pujada i descàrrega) entre equips heterogenis a través de la xarxa, independentment del sistema operatiu que utilitze cadascun.

---

## 1. El Model Arquitectònic de Doble Canal

A diferència de protocols com HTTP o SSH, que gestionen totes les seues accions sobre una única connexió TCP, FTP utilitza de manera simultània **dos canals de comunicació independents**:

```
[ CLIENT FTP ]                                                     [ SERVIDOR FTP ]
       │                                                                  │
       ├════════ CANAL DE CONTROL (Comandes: TCP Port 21) ═══════════════>│ (Obert tota la sessió)
       │         - Autenticació (USER, PASS)                              │
       │         - Navegació de carpetes (CWD, PWD)                       │
       │         - Petició de transferència (LIST, RETR, STOR)            │
       │                                                                  │
       │◄ - - - - CANAL DE DADES (Flux de fitxers o llistats) - - - - - - ┤ (S'obre i tanca per cada arxiu)
```

1. **Canal de Control (Port TCP 21):** S'estableix des de l'inici de la sessió i roman obert tot el temps. S'utilitza exclusivament per enviar comandes de text pla (`USER`, `PASS`, `LIST`, `RETR`, `STOR`, `QUIT`) i rebre codis d'estat numèrics del servidor (ex: `220 Service ready`, `230 User logged in`, `530 Login incorrect`).
2. **Canal de Dades:** És una connexió independent que **s'obre exclusivament quan cal transferir un arxiu o llistar el contingut d'un directori**, i es tanca tan bon punt finalitza dita transferència.

---

## 2. FTP en Mode Actiu (*Active Mode*)

En el mode actiu clàssic, **és el servidor qui pren la iniciativa d'obrir la connexió de dades cap al client**:

```
[ CLIENT FTP (Port 1050) ] ── 1. PORT 1051 (Canal Control) ──> [ SERVIDOR FTP (Port 21) ]
[ CLIENT FTP (Port 1051) ] ◄── 2. TCP SYN (Des del Port 20) ── [ SERVIDOR FTP (Port 20) ]
```

1. El client es connecta des d'un port efímer (ex: `1050`) al port 21 del servidor.
2. Quan el client demana un fitxer, obre un port local (ex: `1051`) i envia al servidor la comanda `PORT` indicant la seua pròpia IP i el port `1051`.
3. **El problema:** El servidor FTP intenta connectar-se des del seu port TCP 20 cap a l'adreça i port del client (`1051`).
4. Si el client està darrere d'un router amb **NAT** o d'un tallafocs personal (la situació del 99% dels usuaris actuals), **el tallafocs bloqueja la connexió entrant del servidor**, impedint la transferència del fitxer!

---

## 3. FTP en Mode Passiu (*Passive Mode - PASV*)

Per resoldre les limitacions de tallafocs i NAT, es va desenvolupar el **Mode Passiu**: en aquesta modalitat, **és el client qui inicia SEMPRE tant la connexió de control com la de dades**:

```
[ CLIENT FTP (Port 1050) ] ── 1. Envia comanda PASV ──────────> [ SERVIDOR FTP (Port 21) ]
[ CLIENT FTP (Port 1050) ] ◄── 2. Respon amb Port X (ex: 40005) ─ [ SERVIDOR FTP (Port 21) ]
[ CLIENT FTP (Port 1051) ] ── 3. TCP SYN cap al Port 40005 ───> [ SERVIDOR FTP (Port 40005) ]
```

1. El client envia per la connexió de control la comanda `PASV`.
2. El servidor obre un port efímer del seu propi rang passiu (per exemple el port `40005`) i respon al client indicant-li la seua IP i eixe número de port.
3. El client inicia una connexió de dades sortint cap al port `40005` del servidor.
4. Com que és una connexió **sortint** iniciada pel client, els tallafocs de la xarxa local i els encaminadors NAT la permeten sense cap problema.

> [!IMPORTANT]
> El Mode Passiu és l'estàndard absolut en l'actualitat. L'administrador d'un servidor FTP d'empresa ha de definir un rang concret de ports passius al programari (ex: de 40000 a 40100) i obrir aquests ports al tallafocs del servidor.
