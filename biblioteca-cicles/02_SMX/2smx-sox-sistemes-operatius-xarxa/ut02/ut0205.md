# 2.5 Replicació de Dominis, Controladors Secundaris i Rols FSMO

En una empresa real, tindre un únic controlador de domini és un risc crític: si eixe únic servidor pateix una fallada elèctrica o de maquinari, **cap empleat podrà iniciar sessió, ni accedir als arxius, ni resoldre noms DNS**. Per garantir l'alta disponibilitat i la tolerància a fallades, és indispensable comptar com a mínim amb **dos controladors de domini**.

---

## 1. Model de Replicació Multi-Mestre (*Multi-Master Replication*)

Active Directory utilitza un model de replicació multi-mestre:
- Qualsevol controlador de domini pot processar lectures i escriptures a la base de dades (per exemple, canviar la contrasenya d'un usuari al DC1 o crear un usuari nou al DC2).
- Els canvis es repliquen automàticament entre tots els controladors de domini mitjançant el procés **KCC** (*Knowledge Consistency Checker*), que genera una topologia de replicació òptima en anell o malla.
- En cas de conflicte (dues modificacions simultànies sobre el mateix atribut), s'aplica la regla de la marca de temps més recent (*Last-Writer-Wins*).

---

## 2. Operacions de Mestre Únic: Els 5 Rols FSMO

Tot i que la majoria d'operacions són multi-mestre, hi ha certes tasques tan crítiques que no poden admetre modificacions concurrents perquè podrien corrompre el domini. Aquestes operacions s'assignen a un únic servidor mitjançant els anomenats **Rols FSMO** (*Flexible Single Master Operations*):

```
+-------------------------------------------------------------------------+
|                         ELS 5 ROLS FSMO D'ACTIVE DIRECTORY              |
+-------------------------------------------------------------------------+
|                                                                         |
|  ROLS A NIVELL DE BOSC (1 sol servidor per a tot el bosc):              |
|  1. Mestre d'Esquema (Schema Master):                                   |
|     L'únic autoritzat a modificar l'estructura de classes i atributs.   |
|  2. Mestre de Noms de Domini (Domain Naming Master):                    |
|     Controla l'addició o eliminació de dominis dins del bosc.           |
|                                                                         |
|  ROLS A NIVELL DE DOMINI (1 servidor per a cada domini):                |
|  3. Mestre de RID (RID Master):                                         |
|     Assigna blocs d'identificadors relatius (RIDs) a cada DC perquè     |
|     puguen crear nous usuaris/equips amb SIDs únics.                    |
|  4. Emulador de PDC (Primary Domain Controller Emulator):               |
|     - Servidor de temps de referència authoritative (NTP).              |
|     - Processa immediatament canvis de contrasenya i bloquejos de compte|
|     - Compatibilitat amb clients antics i edició principal de GPOs.     |
|  5. Mestre d'Infraestructura (Infrastructure Master):                   |
|     Actualitza referències a objectes d'altres dominis (grups creuats). |
|                                                                         |
+-------------------------------------------------------------------------+
```

---

## 3. Comprovació i Transferència de Rols FSMO

Podem esbrinar quin controlador de domini té cadascun dels 5 rols FSMO mitjançant la consola o per comanda:

```powershell
# Comprovar els 5 rols FSMO per PowerShell
Get-ADForest | Select-Object SchemaMaster, DomainNamingMaster
Get-ADDomain | Select-Object RidMaster, PDCEmulator, InfrastructureMaster

# Mitjançant l'eina tradicional de símbol del sistema
netdom query fsmo
```

Si necessitem retirar o apagar el primer servidor per manteniment, podem transferir ordenadament els rols al segon controlador de domini:

```powershell
# Transferència ordenada de rols cap a SRV-DC02
Move-ADDirectoryServerOperationMasterRole -Identity "SRV-DC02" -OperationMasterRole PDCEmulator, RIDMaster, InfrastructureMaster
```

---

## 4. El Catàleg Global (*Global Catalog - GC*)

El **Catàleg Global** és una partició especial que conté una còpia completa de tots els objectes del seu propi domini i una còpia parcial (només els atributs més consultats com nom, correu i pertinença a grups) de tots els objectes de la resta de dominis del bosc.
- És imprescindible perquè els usuaris puguen iniciar sessió (permet comprovar la seua pertinença a Grups Universals).
- En dominis d'una sola seu, és una bona pràctica marcar **tots els controladors de domini com a servidors de Catàleg Global**.
