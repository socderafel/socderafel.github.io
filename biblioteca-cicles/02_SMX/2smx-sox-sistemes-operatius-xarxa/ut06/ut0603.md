# 6.3 Integració de Samba com a Servidor Membre d'un Domini Active Directory

En una empresa real, gestionar usuaris locals a Linux amb `smbpasswd` és ineficient si ja disposem d'un controlador de domini Windows Server amb tots els usuaris donats d'alta a l'Active Directory.

La configuració més potent i elegant és convertir el servidor Linux en un **Servidor Membre del Domini (*Domain Member Server*)**:
- El servidor Linux comparteix carpetes mitjançant Samba.
- Quan un usuari de Windows intenta accedir (`\\srv-linux\projectes`), el servidor Samba consulta automàticament al Controlador de Domini d'Active Directory mitjançant Kerberos i LDAP.
- L'usuari accedeix amb les seues credencials corporatives sense necessitat de crear cap compte d'usuari a Linux.

---

## 1. Components de la Integració: Winbind i SSSD

Hi ha dos enfocaments principals per a unir Samba com a membre de domini:

1. **Winbind (`winbindd`):** El component històric de Samba. Fa de pont entre el sistema d'autenticació de Linux (PAM/NSS) i Active Directory.
2. **SSSD (*System Security Services Daemon*):** L'enfocament modern recomanat en distribucions com Ubuntu i Red Hat. Permet emmagatzematge en memòria cau de credencials fora de línia, integració amb Kerberos i gestió simplificada mitjançant **`realmd`**.

```
+-------------------------------------------------------------------------+
|                  ARQUITECTURA D'UN SERVIDOR MEMBRE SAMBA                |
+-------------------------------------------------------------------------+
|                                                                         |
|  [ Client Windows 10/11 ]                                               |
|        |                                                                |
|        | 1. Petició SMB (tiquet Kerberos de domini)                     |
|        v                                                                |
|  [ Servidor Linux Membre - Samba ]                                      |
|  +-------------------------------------------------------------------+  |
|  | Samba (smbd) <---> SSSD / Winbind <---> idmap (SID -> UID)        |  |
|  +-------------------------------------------------------------------+  |
|        |                                                                |
|        | 2. Valida credencials i pertinença a grups via LDAP/Kerberos   |
|        v                                                                |
|  [ Controlador de Domini Windows Server (SRV-DC01) ]                    |
|                                                                         |
+-------------------------------------------------------------------------+
```

---

## 2. Procés d'Unió amb `realmd` i Configuració de `smb.conf`

```bash
# 1. Unir el servidor Linux al domini Active Directory
sudo realm join -U Administrator iesrafael.local
```

A `/etc/samba/smb.conf`, configurem el mode de seguretat `ADS` (*Active Directory Services*):

```ini
[global]
   workgroup = IESRAFAEL
   security = ADS
   realm = IESRAFAEL.LOCAL
   winbind use default domain = true

   # Mapatge de SIDs a UIDs de Linux mitjançant idmap
   idmap config * : backend = tdb
   idmap config * : range = 3000-7999
   idmap config IESRAFAEL : backend = rid
   idmap config IESRAFAEL : range = 10000-999999

   # Suport d'atributs estesos i ACLs de Windows
   vfs objects = acl_xattr
   map acl inherit = yes
   store dos attributes = yes

[departaments]
   path = /srv/samba/departaments
   read only = no
   # Permet accés als membres del grup de seguretat del domini 'GG_Professors'
   valid users = @"IESRAFAEL\GG_Professors"
```

---

## 3. Verificació d'Identitats Creuades

Un cop reiniciat el servei, podem comprovar que Linux "veu" els usuaris d'Active Directory:

```bash
# Comprovar que el domini reconeix un usuari d'Active Directory a Linux
id jgarcia@iesrafael.local

# Obtenir informació d'usuaris del domini
getent passwd "jgarcia"
```
