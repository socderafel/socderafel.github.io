# 5.2 Registres d'Esdeveniments (Logs) i Diagnòstic d'Incidències

Quan un servei deixa de funcionar, un disc dur comença a donar errors de lectura o es produeix un intent d'accés no autoritzat a la xarxa, el sistema operatiu deixa una constància escrita inalterable de l'incident en els seus **registres d'esdeveniments (*Logs*)**. Saber llegir, filtrar i interpretar aquests registres és l'habilitat principal que diferencia un tècnic competent.

---

## 1. El Visualitzador d'Esdeveniments a Windows Server (`eventvwr.msc`)

A Windows Server, tots els esdeveniments es centralitzen al **Visualitzador d'esdeveniments (*Event Viewer*)**. Els registres principals de Windows són:

```
+-------------------------------------------------------------------------+
|                  REGISTRES PRINCIPALS DE WINDOWS SERVER                 |
+-------------------------------------------------------------------------+
|                                                                         |
|  1. APLICACIÓ (Application):                                            |
|     Incidències i avisos generats pels programes i serveis instal·lats  |
|     (ex: fallada de connexió a una base de dades SQL).                  |
|                                                                         |
|  2. SEGURETAT (Security):                                               |
|     Auditoria d'accessos. Registra inicis de sessió reeixits i fallits, |
|     canvis de permisos i accessos a fitxers protegits.                  |
|                                                                         |
|  3. SISTEMA (System):                                                   |
|     Esdeveniments del propi nucli del sistema operatiu, controladors    |
|     de dispositius, targetes de xarxa i fallades de disc.               |
|                                                                         |
|  4. SERVEIS DE DIRECTORI (Directory Service) i SERVIDOR DNS:            |
|     Específics dels controladors de domini. Registren problemes de      |
|     replicació d'AD DS i fallades en la resolució de noms.              |
|                                                                         |
+-------------------------------------------------------------------------+
```

### Nivells de Gravetat d'un Esdeveniment:
- ℹ️ **Informació (*Information*):** Funcionament normal del sistema (ex: un servei s'ha iniciat correctament).
- ⚠️ **Advertència (*Warning*):** Problema que no és greu ara mateix però podria ser-ho en el futur (ex: poc espai en disc).
- ❌ **Error (*Error*):** Fallada important en un servei o funció (ex: un servei no ha pogut arrancar).
- 🛑 **Crític (*Critical*):** Fallada molt greu que ha provocat una caiguda del sistema o pèrdua de dades.

---

## 2. Codis d'Identificador d'Esdeveniment Clau (*Event ID*) a Windows

En ciberseguretat i administració de sistemes, certs números d'identificador s'aprenen de memòria:
- **Event ID 4624:** Inici de sessió d'usuari reeixit.
- **Event ID 4625:** **Intent fallit d'inici de sessió** (clau per a detectar atacs de força bruta).
- **Event ID 4720:** Creació d'un nou compte d'usuari.
- **Event ID 4726:** Eliminació d'un compte d'usuari.
- **Event ID 4740:** **Compte d'usuari bloquejat** per massa intents fallits de contrasenya.

---

## 3. Registres del Sistema en Linux Server (`/var/log`) i `journalctl`

En sistemes Linux, la informació de registre es gestiona sota el directori `/var/log`:

```bash
# Fitxers de log tradicionals en Ubuntu/Debian
/var/log/syslog         # Missatges generals del sistema
/var/log/auth.log       # Intents d'autenticació, inicis de sessió i ús de sudo
/var/log/dmesg          # Missatges de diagnòstic del nucli d'arrancada
```

En distribucions modernes gestionades per `systemd`, l'eina definitiva és **`journalctl`**:

```bash
# 1. Veure els registres del sistema en temps real (seguiment en calent)
journalctl -f

# 2. Veure els errors generats des de l'última arrancada del sistema
journalctl -b -p err

# 3. Filtrar els registres d'un servei específic (ex: servei SSH)
journalctl -u ssh -n 50
```
