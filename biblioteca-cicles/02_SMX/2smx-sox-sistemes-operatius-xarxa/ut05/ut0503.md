# 5.3 Automatització de Tasques i Programació

Un bon administrador de sistemes automatitza totes aquelles tasques repetitives o que s'han d'executar fora de l'horari laboral (de matinada per a no afectar el rendiment dels empleats), tals com còpies de seguretat, neteja de registres vells, buidat de directoris temporals i comprovacions de seguretat.

---

## 1. El Programador de Tasques de Windows (`taskschd.msc`)

A Windows Server, l'eina encarregada és el **Programador de tasques (*Task Scheduler*)**:
- Una tasca programada es compon de:
  - **Desencadenadors (*Triggers*):** Defineixen *quan* s'executa la tasca (segons una programació horària com *Tots els dies a les 02:00 AM*, o en ocórrer un esdeveniment, o en iniciar sessió).
  - **Accions (*Actions*):** Defineixen *què* s'executa (iniciar un programa com `powershell.exe`, amb arguments com `-ExecutionPolicy Bypass -File C:\Scripts\backup.ps1`).
  - **Condicions i Configuració:** Per exemple: *Executar només si l'equip està inactiu*, o *Executar tant si l'usuari ha iniciat sessió com si no* (utilitzant el compte de servei `SYSTEM`).

```powershell
# Creació d'una tasca programada per PowerShell
$Action = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-File C:\Scripts\neteja_temp.ps1"
$Trigger = New-ScheduledTaskTrigger -Daily -At "03:00AM"
Register-ScheduledTask -TaskName "NetejaTemporals" -Action $Action -Trigger $Trigger -User "SYSTEM"
```

---

## 2. Programació de Tasques en Linux amb Cron (`crontab`)

En sistemes Linux, el servei estàndard és el dimoni **cron**:
- Cada usuari (i l'administrador root) disposa del seu propi fitxer de planificació, que s'edita mitjançant:
  ```bash
  crontab -e
  ```

### La Sintaxi Clau dels 5 Camps de Cron:
```
+-------------------------------------------------------------------------+
|                  SINTAXI DELS 5 CAMPS DE CRONTAB                        |
+-------------------------------------------------------------------------+
|                                                                         |
|  *   *   *   *   *   comanda_a_executar                                 |
|  -   -   -   -   -                                                      |
|  |   |   |   |   |                                                      |
|  |   |   |   +------- Dia de la setmana (0 - 6, on 0 és diumenge)       |
|  |   |   +----------- Mes de l'any (1 - 12)                             |
|  |   +--------------- Dia del mes (1 - 31)                              |
|  +------------------- Hora del dia (0 - 23)                             |
|  +------------------- Minut de l'hora (0 - 59)                          |
|                                                                         |
+-------------------------------------------------------------------------+
```

### Exemples d'Ús Reals:
```bash
# Executar un script de còpia de seguretat tots els dies a les 02:30 de la matinada:
30 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1

# Executar una comprovació cada 15 minuts:
*/15 * * * * /usr/local/bin/check_services.sh

# Executar el dia 1 de cada mes a les 00:00:
0 0 1 * * /usr/local/bin/informe_mensual.sh
```

---

## 3. Temporitzadors de `systemd` (*systemd timers*)

En distribucions modernes amb `systemd`, els **temporitzadors (*systemd timers*)** estan substituint progressivament a cron per a serveis crítics:
- Es crea un fitxer de servei (`meu_servei.service`) i un fitxer de temporitzador associat (`meu_servei.timer`).
- **Avantatges:** Millor integració amb el registre (`journalctl`), capacitat de controlar dependències de serveis i major precisió temporal.
