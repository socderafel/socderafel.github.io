# 5.4 Gestió d'Actualitzacions i Pegats de Seguretat

El parxejat del programari és la mesura preventiva més eficaç contra ciberatacs. La immensa majoria d'intrusions aprofiten vulnerabilitats conegudes per a les quals els fabricants ja havien publicat una actualització que l'organització encara no havia instal·lat.

Tanmateix, en un entorn de producció amb centenars d'ordinadors, **mai no s'ha de deixar que cada màquina es descarregue i instal·le actualitzacions de forma autònoma i aleatòria** des d'Internet. Això col·lapsaria l'amplada de banda de la connexió a Internet de l'empresa i podria provocar que un pegat defectuós trenque les aplicacions crítiques del negoci.

---

## 1. Gestió Centralitzada d'Actualitzacions a Windows: WSUS

A les xarxes corporatives de Microsoft s'utilitza el rol **WSUS (*Windows Server Update Services*)**:

```
+-------------------------------------------------------------------------+
|                  ARQUITECTURA DE FUNCIONAMENT DE WSUS                   |
+-------------------------------------------------------------------------+
|                                                                         |
|  [ Servidors de Microsoft Update a Internet ]                           |
|                         |                                               |
|                         v (Es descarrega una sola vegada)               |
|  [ SERVIDOR LOCAL WSUS ]                                                |
|  - Emmagatzema localment els pegats aprovats.                           |
|  - L'administrador aprova o rebutja actualitzacions segons convinga.    |
|                         |                                               |
|                         +-----------------------+                       |
|                         |                       |                       |
|                         v                       v                       |
|                  [ Grup Pilot ]          [ Producció ]                  |
|                  (5% d'equips de         (Resta d'equips de l'empresa,  |
|                   prova per avaluar       un cop provat el pegat durant |
|                   estabilitat)            7-14 dies)                    |
|                                                                         |
+-------------------------------------------------------------------------+
```

### Configuració dels Clients mitjançant GPO:
Mitjançant una Directiva de Grup vincular a l'arrel del domini:
- `Configuració de l'equip -> Plantilles administratives -> Components de Windows -> Windows Update`.
- **Directiva:** *Especificar la ubicació del servei d'actualització de Microsoft en la intranet*.
- S'introdueix l'adreça del servidor WSUS local (ex: `http://srv-wsus.iesrafael.local:8530`).
- Els clients deixen de consultar a Internet i descarreguen els pegats exclusivament des de la xarxa local a velocitat de Gigabit.

---

## 2. Gestió d'Actualitzacions a Linux Server

En servidors Linux (com Ubuntu o Debian), el parxejat de seguretat es pot automatitzar mitjançant el paquet **`unattended-upgrades`**:

```bash
# 1. Instal·lar el servei d'actualitzacions desateses
sudo apt update
sudo apt install -y unattended-upgrades update-notifier-common

# 2. Habilitar el servei
sudo dpkg-reconfigure -plow unattended-upgrades
```

Al fitxer `/etc/apt/apt.conf.d/50unattended-upgrades`:
- Es configura perquè **només instal·le automàticament els pegats de seguretat** (`${distro_codename}-security`), evitant canvis de versió majors que podrien alterar dependències d'aplicacions web o bases de dades.
- Es pot configurar perquè si cal reiniciar el servidor pel nucli (*reboot required*), ho faça automàticament a una hora convinguda (ex: a les 04:00 AM):
  ```
  Unattended-Upgrade::Automatic-Reboot "true";
  Unattended-Upgrade::Automatic-Reboot-Time "04:00";
  ```
