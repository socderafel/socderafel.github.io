# 1.5 Virtualització de Servidors i Rols Bàsics en Laboratori

En l'actualitat, la pràctica totalitat dels sistemes operatius en xarxa s'executen sobre entorns virtualitzats o plataformes de computació en el núvol. Per a l'aprenentatge pràctic dels Sistemes Operatius en Xarxa, és imprescindible construir un **laboratori virtual d'aprenentatge** aïllat i coherent.

---

## 1. Tipus d'Hipervisors per a Servidors

La virtualització es recolza en el component anomenat **hipervisor** (*Virtual Machine Monitor* o VMM):

```
+-------------------------------------------------------------------------+
|                  ARQUITECTURA DELS HIPERVISORS                          |
+-------------------------------------------------------------------------+
|                                                                         |
|  [ HIPERVISOR TIPUS 1 (Bare-Metal) ]   [ HIPERVISOR TIPUS 2 (Hosted) ]   |
|  +---------------------------------+   +-----------------------------+  |
|  | Màquines Virtuals (VMs)         |   | Màquines Virtuals (VMs)     |  |
|  +---------------------------------+   +-----------------------------+  |
|  | Hipervisor (Proxmox, ESXi, KVM) |   | Hipervisor (VirtualBox, VMW)|  |
|  +---------------------------------+   +-----------------------------+  |
|  | Maquinari Físic (Servidor)      |   | Sistema Operatiu Amfitrió   |  |
|  +---------------------------------+   +-----------------------------+  |
|                                        | Maquinari Físic (PC/Portàtil|  |
|                                        +-----------------------------+  |
+-------------------------------------------------------------------------+
```

1. **Hipervisors Tipus 1 (Nadius o *Bare-Metal*):** S'instal·len directament sobre el maquinari físic del servidor, sense cap sistema operatiu per sota. Ofereixen el màxim rendiment, latència mínima i aïllament professional (exemples: Proxmox VE, VMware ESXi, Microsoft Hyper-V Server, KVM).
2. **Hipervisors Tipus 2 (Allotjats o *Hosted*):** S'executen com una aplicació convencional sobre un sistema operatiu amfitrió (com Windows 11 o Ubuntu Desktop). Són perfectes per a laboratoris docents a l'aula (exemples: Oracle VirtualBox, VMware Workstation).

---

## 2. Modes de Xarxa Virtual en el Laboratori

L'elecció correcta de la manera en què les targetes de xarxa virtuals es connecten entre si és clau per a evitar conflictes amb la xarxa del centre educatiu o de l'empresa:

| Mode de Xarxa Virtual | Com funciona? | Comunicació amb altres VMs | Comunicació amb Internet | Cas d'ús típic en laboratori |
| :--- | :--- | :--- | :--- | :--- |
| **Pont (*Bridged Adapter*)** | La VM apareix com un equip físic més connectat al switch de l'aula. | Sí, i amb tota la xarxa física real. | Sí, directament a través del router físic. | Perillós en laboratoris si s'activen servidors DHCP virtuals (conflicte d'IPs a l'aula). |
| **Xarxa Interna (*Internal Network*)** | Crea un commutador virtual privat aïllat exclusivament per a les VMs. | Sí, només entre VMs que comparteixen el mateix nom de xarxa interna. | No (completament aïllades). | **Ideal per al laboratori de SOX** (evita interferir amb la xarxa real). |
| **Xarxa NAT (*NAT Network*)** | Proporciona una xarxa privada entre VMs amb sortida a Internet mitjançant NAT. | Sí, entre les VMs connectades a la mateixa xarxa NAT. | Sí, a través de la IP de l'amfitrió. | Perfecte per a actualitzar paquets (`apt`, `Windows Update`) sense exposar servidors. |
| **Només Amfitrió (*Host-Only*)** | Comunica les màquines virtuals entre si i amb la màquina física amfitriona. | Sí. | No. | Accés còmode per SSH o RDP des del PC físic cap a les VMs. |

## 3. Topologia del Laboratori de SOX

Per a superar les pràctiques d'aquest mòdul, construirem un entorn amb tres màquines virtuals interconnectades en una xarxa privada:

```
+-------------------------------------------------------------------------+
|                  TOPOLOGIA DEL LABORATORI CORPORATIU                    |
+-------------------------------------------------------------------------+
|                                                                         |
|     [ SRV-DC01 ]                 [ SRV-LINUX ]           [ CLI-WIN10 ]  |
|  Windows Server 2022          Ubuntu Server 24.04        Windows 10 Pro |
|    Controlador Domini           Servidor Membre          Client Domini  |
|      IP: 192.168.10.10            IP: 192.168.10.20       IP: Dinàmica  |
|                                                                         |
|         |                              |                       |        |
|         +------------------------------+-----------------------+        |
|                                        |                                |
|                        [ Commutador Virtual Privat ]                    |
|                        Xarxa NAT / Interna: 192.168.10.0/24             |
|                                                                         |
+-------------------------------------------------------------------------+
```

## 4. Clonació i Ús d'Eines de Generalització (Sysprep)

Quan virtualitzem, sovint creem una màquina base model (*Template*) i la clonem per a no repetir la instal·lació:
- Si clonem directament una màquina Windows, les dues màquines tindran el mateix identificador de seguretat (**SID** - *Security Identifier*). Si intentem unir les dues màquines al mateix domini Active Directory, es produirà un conflicte greu de seguretat.
- Abans de clonar un sistema Windows model, cal executar **Sysprep** (`C:\Windows\System32\Sysprep\sysprep.exe`), marcant l'opció **Generalitzar (*Generalize*)** i apagant l'equip. Això elimina el SID antic i genera un SID completament únic en la pròxima arrancada.
