# 4.8 Arquitectura del Nucli (*Kernel*) del Sistema Operatiu

El **nucli** (*kernel*) és el cor del sistema operatiu. Segons com estiguen organitzats els serveis essencials (gestió de memòria, planificador de CPU, sistema de fitxers, controladors de maquinari) respecte a l'espai privilegiat de la CPU, distingim tres grans tipus d'arquitectures:

---

## 🏛️ Les Tres Grans Arquitectures de Nucli

```
[1. NUCLI MONOLÍTIC]        [2. MICROKERNEL]             [3. NUCLI HÍBRID]
+----------------------+     +----------------------+     +----------------------+
| Mode Usuari (Ring 3) |     | Mode Usuari (Ring 3) |     | Mode Usuari (Ring 3) |
| - Shell / Apps       |     | - Shell / Apps       |     | - Shell / Apps       |
|                      |     | - Filesystem Server  |     | - Subsistemes Win32  |
|                      |     | - Device Drivers     |     |                      |
+----------------------+     +----------------------+     +----------------------+
========================     ========================     ========================
| Mode Nucli (Ring 0)  |     | Mode Nucli (Ring 0)  |     | Mode Nucli (Ring 0)  |
| - Scheduler          |     | - Scheduler mínim    |     | - Scheduler & MMU    |
| - MMU (Memòria)      |     | - IPC bàsic          |     | - Device Drivers     |
| - Filesystem         |     | - Gestió d'interrup. |     | - Filesystem (NTFS)  |
| - Drivers de tot     |     |                      |     | - GDI / Subsistema GUI|
+----------------------+     +----------------------+     +----------------------+
  Ex: GNU/Linux, BSD          Ex: Minix, QNX, Fuchsia       Ex: Windows NT, macOS
```

---

## 📊 Taula Comparativa d'Arquitectures de Nucli

| Característica | Nucli Monolític (GNU/Linux) | Microkernel (Minix, QNX) | Nucli Híbrid (Windows NT / macOS) |
| :--- | :--- | :--- | :--- |
| **Ubicació dels drivers** | Mode Nucli (Ring 0) com a mòduls dinàmics (`.ko`). | Mode Usuari (Ring 3) com a serveis aïllats. | Mode Nucli (Ring 0) per a màxim rendiment gràfic. |
| **Rendiment** | **Màxim:** La comunicació interna és directa per crides a funcions en memòria. | Menor: Requereix intercanvi continu de missatges IPC entre Ring 0 i Ring 3. | Molt alt: Combina estructura modular amb execució a Ring 0. |
| **Tolerància a fallades** | Si un controlador falla a Ring 0, provoca un *Kernel Panic*. | **Excel·lent:** Si cau el controlador del disc, es reinicia el servei en mode usuari sense caure el sistema. | Si falla un driver crític a Ring 0, es produeix una pantalla blava (BSOD). |
| **Exemples reals** | Linux (Ubuntu, Debian, Red Hat), FreeBSD. | QNX (automoció i sistemes mèdics en temps real), Minix 3. | Windows 11 / Windows 10 (nucli NT), macOS / iOS (nucli XNU). |

## 🧩 Mòduls Dinàmics del Nucli en Linux

Tot i ser monolític, el nucli Linux és altament **modular**. No cal recompilar el nucli complet per afegir suport per a un nou perifèric:
- Els controladors es compilen com a fitxers amb extensió `.ko` (*Kernel Object*).
- Es carreguen i descarreguen dinàmicament a la memòria del nucli segons les necessitats:

```bash
# Llistar tots els mòduls del nucli carregats actualment a la RAM
lsmod

# Obtenir informació tècnica detallada d'un mòdul (ex: controlador e1000 de xarxa)
modinfo e1000

# Carregar un mòdul manualment a la memòria
sudo modprobe bonding

# Descarregar un mòdul del nucli de forma segura
sudo modprobe -r bonding
```
