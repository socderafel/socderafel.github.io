# 4.5 Instal·lació de GNU/Linux i Doble Arrancada (Dual Boot Windows + Linux)

En molts entorns professionals i acadèmics és necessari que un mateix equip informàtic puga arrencar tant amb **Microsoft Windows** com amb una distribució **GNU/Linux** (com Ubuntu Desktop). Aquesta configuració rep el nom de **Doble Arrancada** o **Dual Boot**.

Si es realitza de forma ordenada seguint les bones pràctiques d'administració de sistemes, ambdós sistemes conviuran de manera totalment pacífica compartint la mateixa partició ESP i seleccionant el sistema desitjat en cada arrencada mitjançant el gestor **GRUB 2**.

---

## 1. La Regla d'Or: Primer Windows, Després GNU/Linux

En configurar un equip amb Dual Boot, l'ordre d'instal·lació és crucial:

```
PAS 1: Instal·lar Windows (Crea partició ESP, MSR i NTFS)
PAS 2: Desactivar 'Inici Ràpid' (Fast Startup) a Windows
PAS 3: Reduir la partició C: per deixar espai lliure no assignat
PAS 4: Instal·lar Ubuntu Linux a l'espai alliberat (Configura GRUB 2 automàticament)
```

### Per què aquest ordre estricte?
1. **El comportament de Windows Boot Manager:** Si s'instal·la Linux en primer lloc i després Windows, l'instal·lador de Windows sobreescriu l'ordre d'arrancada de la memòria NVRAM per posar-se ell en primer lloc, ignorant per complet la presència de Linux.
2. **L'assistent de Linux és respectuós:** En canvi, els instal·ladors moderns de Linux (com l'assistent d'Ubuntu) estan programats per detectar automàticament la partició de Windows mitjançant la utilitat `os-prober`, afegint una entrada al menú de GRUB sense alterar els fitxers de Microsoft.

---

## 2. El Perill del "Fast Startup" (Inici Ràpid) de Windows

Abans de tocar qualsevol partició o instal·lar Linux, el tècnic de SMX **ha de desactivar obligatòriament l'Inici Ràpid de Windows**:

* **Com funciona l'Inici Ràpid?** Quan l'usuari fa clic a *"Apaga l'equip"*, Windows 10/11 en realitat no s'apaga del tot; tanca les sessions d'usuari i **hiberna el nucli del sistema** escrivint el seu estat al fitxer `hiberfil.sys`.
* **Per què és perillós per a Linux?** En estar en estat d'hibernació, Windows deixa el sistema de fitxers NTFS marcat amb un senyal de bloqueig (*dirty flag*). Si Linux intenta muntar aquest volum per llegir o escriure arxius, es pot produir una **corrupció irreversible de dades**.

### Com desactivar-lo al taller:
* **Per línia d'ordres (CMD com a administrador):**
  ```cmd
  powercfg -h off
  ```
  *(Aquesta ordre desactiva completament la hibernació i allibera diversos gigabytes d'espai a la unitat C:).*
* **Gràficament:** *Tauler de control -> Opcions d'energia -> Trieu el comportament dels botons d'encesa -> Canvia la configuració no disponible actualment -> Desmarca "Activa l'inici ràpid"*.

---

## 3. Preparació de l'Espai des de l'Administrador de Discs

1. Obre la utilitat `diskmgmt.msc` en Windows.
2. Fes clic amb el botó dret sobre el volum principal **`C:`** i selecciona **Redueix el volum... (Shrink Volume)**.
3. Tria la quantitat d'espai a alliberar (recomanat per a pràctiques d'SMX: entre **40.000 MB** i **80.000 MB**, és a dir, uns 40-80 GB).
4. El resultat serà una regió marcada en negre com a **Espai no assignat**. Deixa-la sense formatar; l'instal·lador d'Ubuntu s'encarregarà de crear-hi les particions ext4.

---

## 4. Instal·lació d'Ubuntu Desktop i Particionament Manual

En arrencar des del USB d'Ubuntu triem l'opció *"Prova o instal·la Ubuntu"*. En arribar a la pantalla de tipus d'instal·lació, és molt recomanable triar **"Més opcions" (Particionament manual)** per comprendre què passa exactament al disc:

```
+----------------+----------------+---------------------+-------------------+
| ESP (FAT32)    | Windows (NTFS) | Partició Arrel /    | Àrea Swap         |
| 100 MB         | 150 GB         | ext4 (60 GB)        | 4 GB (o swapfile) |
+----------------+----------------+---------------------+-------------------+
```

1. **La partició ESP existent:**
   - Localitza la partició de 100 MB de tipus `efi` (creada prèviament per Windows).
   - Fes doble clic sobre ella i selecciona: *Utilitza com a: Partició del sistema EFI*.
   - ⚠️ **MOLT IMPORTANT:** **NO marques la casella "Formatar"**. Si la formates, esborraràs el carregador de Windows (`bootmgfw.efi`). Només volem que s'hi afija el carregador `grubx64.efi`.
2. **La partició arrel (`/`):**
   - Selecciona l'espai lliure no assignat i prem el botó `+`.
   - Sistema de fitxers: **ext4 transaccional**.
   - Punt de muntatge: **`/`** (arrel del sistema).
   - Mida: la pràctica totalitat de l'espai disponible.
3. **Àrea d'intercanvi (Swap):** En instal·lacions modernes d'Ubuntu, el sistema crea automàticament un fitxer `/swapfile` dins de la partició arrel, de manera que ja no és imprescindible crear una partició física de swap dedicada a menys que es vulga hibernar el sistema.

---

## 5. El Menú GRUB 2 i Resolució d'Incidències Post-Instal·lació

Un cop finalitzada la instal·lació i reiniciat l'equip, la placa base carregarà el gestor **GRUB 2**, presentant una pantalla similar a:

```
                           GNU GRUB versió 2.06
 * Ubuntu
   Opcions avançades per a Ubuntu
   Windows Boot Manager (a /dev/nvme0n1p1)
   Configuració del microprogramari UEFI
```

### Què fer si l'equip arrenca directament a Windows ignorant Linux?
De vegades, certes BIOS d'HP, Acer o Lenovo mantenen rígidament Windows en la primera posició de la memòria NVRAM:
1. **Solució des de la UEFI:** Accedeix a la configuració UEFI (`F2`/`Del`) -> Secció *Boot Options* -> Mou l'entrada `ubuntu` per damunt de `Windows Boot Manager`.
2. **Solució des de Windows (CMD com a administrador):**
   ```cmd
   bcdedit /set {bootmgr} path \EFI\ubuntu\shimx64.efi
   ```
   Això indica a la placa base que execute directament el gestor segur d'Ubuntu, que serà qui donarà l'opció de triar Windows.
