# 4.1 Firmware del Sistema: BIOS Heretada vs UEFI Modern i Secure Boot

Abans que qualsevol sistema operatiu (siga Windows, GNU/Linux o macOS) puga prendre el control dels recursos del computador, la placa base executa un programari de molt baix nivell emmagatzemat en un xip de memòria no volàtil (ROM / Flash EEPROM): el **firmware del sistema** o **microprogramari**.

Aquest component és la primera línia d'execució en encendre l'ordinador. Durant dècades hem conegut aquest microprogramari com a **BIOS**, però els sistemes actuals han migrat per complet cap a l'estàndard modern **UEFI**. Comprendre les seues diferències és indispensable per a qualsevol tècnic de SMX abans d'iniciar una instal·lació.

---

## 1. La Seqüència d'Inicialització Inicial: El POST

En prémer el botó d'encesa el processador es troba en un estat bàsic (mode real de 16 bits en x86) i comença a executar la instrucció situada en una adreça de memòria fixa coneguda com a **Reset Vector** (típicament `0xFFFFFFF0` en arquitectures x86/x64). 

En aquest instant s'inicia el **POST (Power-On Self-Test)**:
1. **Verificació elèctrica i d'integritat:** Comprovació dels voltatges bàsics i integritat dels registres de la CPU.
2. **Detecció i prova de la memòria RAM:** S'escaneja la memòria instal·lada i es verifiquen els primers bancs. Si falla, la placa emet senyals acústics (bips d'error) o codis numèrics a la pantalla de diagnòstic LED de la placa (codis POST).
3. **Inicialització del bus i controladors perifèrics:** Detecció del bus PCIe, controladora gràfica integrada o dedicada, controladors SATA/NVMe, busos USB i teclat.
4. **Localització del dispositiu d'arrancada (Boot Order):** Segons la prioritat configurada (Disc NVMe, Unitat USB, Xarxa PXE), el firmware cerca el codi inicial de càrrega del sistema.

---

## 2. BIOS Heretada (Legacy BIOS): Història i Limitacions Crítiques

La **BIOS (Basic Input/Output System)** va ser dissenyada per IBM a principi dels anys 80. Encara que va permetre l'explosió dels PC compatibles, presentava colls d'ampolla arquitectònics insalvables per als equips moderns:

* **Mode Real de 16 bits:** La BIOS s'executa en mode de 16 bits i només pot adreçar de forma directa **1 MB de memòria RAM**. Això limita severament la complexitat i la velocitat del codi d'inicialització.
* **Espai de càrrega minúscul (446 bytes):** La BIOS busca el primer sector del disc dur (el sector 0, conegut com a **MBR**). Dels 512 bytes del sector, només **446 bytes** estan reservats per al codi d'arrancada executable (la resta és per a la taula de particions de 64 bytes i la signatura de 2 bytes `0x55AA`). Aquest espai era tan reduït que calia recórrer a malabarismes i etapes múltiples (etapa 1, etapa 1.5, etapa 2 de GRUB).
* **Interfície arcaica:** Mode text exclusiu en blau/gris, controlat únicament pel teclat, sense suport directe de ratolí ni resolucions d'alta definició.
* **Sense controladors moderns ni xarxa avançada:** La BIOS no entén de sistemes de fitxers moderns; només llegeix sectors físics en cru (LBA).

---

## 3. UEFI (Unified Extensible Firmware Interface)

Per a superar aquestes limitacions, un consorci d'empreses líders (Intel, AMD, Microsoft, Apple, AMI, Phoenix) va crear l'estàndard **UEFI**. No és simplement una "BIOS bonica amb ratolí", sinó un **mini sistema operatiu independent** que resideix a la placa base:

| Característica | BIOS Heretada (Legacy) | UEFI Modern |
| :--- | :--- | :--- |
| **Arquitectura de CPU** | 16 bits (mode real) | 32 bits o 64 bits natiu |
| **Límit de memòria adreçable** | 1 MB de RAM | Fins a 16 Exabytes de RAM |
| **Esquema de particions obligatori** | MBR (màx. 2,2 TB per unitat) | GPT (fins a 9,4 Zettabytes) |
| **Comprensió de Sistemes de Fitxers** | Cap (llegeix sectors en cru) | Sí, natiu per a **FAT32** (i FAT16/FAT12) |
| **Ubicació del Carregador** | Sector 0 MBR (446 bytes) | Fitxers executables `.efi` a la partició ESP |
| **Interfície d'usuari** | Text pla 80x25, només teclat | Gràfica d'alta resolució, ratolí i multillenguatge |
| **Diagnòstic i Xarxa** | Molt primitiu o inexistent | Pila de xarxa completa (IPv4/IPv6, HTTP, PXE) |
| **Seguretat d'Arrancada** | Inexistent (vulnerable a Bootkits) | **Secure Boot** amb verificació criptogràfica |

---

## 4. Secure Boot: La Cadena de Confiança Criptogràfica

Un dels avanços més decisius d'UEFI és **Secure Boot** (Arrancada Segura). Històricament, el programari maliciós més perillós eren els anomenats **Bootkits** o **Rootkits de firmware**: virus que sobreescrivien el sector MBR o el carregador de Windows per a carregar-se en memòria **abans** que el propi antivirus o el nucli del sistema operatiu s'iniciaren, fent-se completament invisibles.

Secure Boot atura aquest vector d'atac mitjançant una **cadena de confiança asimètrica (claus públiques/privades)**:

```
[ Platform Key (PK) ] -> [ Key Exchange Key (KEK) ] -> [ Signatures Database (db) ]
                                                                   |
                                          Verifica la signatura de:
                                          - bootx64.efi
                                          - kernel.sys / vmlinuz
                                          - Controladors de baix nivell
```

1. **La base de dades `db` (Allowed Signatures):** Conté els certificats i les empremtes hash de tots els binaris permesos per a arrancar. Microsoft signa el carregador de Windows (`bootx64.efi`) i també signa carregadors intermedis per a distribucions GNU/Linux reconegudes (com el projecte **Shim** d'Ubuntu, Debian, Fedora i Red Hat).
2. **La base de dades `dbx` (Forbidden Signatures):** És una llista negra revocada. Si es descobreix una vulnerabilitat en un carregador signat del passat, el fabricant o Microsoft afegeix el hash a la `dbx` per evitar que un atacant faça servir aquest carregador antic per executar codi arbitrari.
3. **Què passa si falla la signatura?** El firmware bloqueja l'execució immediatament i mostra un missatge d'error vermell: *"Secure Boot Violation: Invalid signature detected"*.

> ⚠️ **Atenció al Taller de SMX:** En equips de clients o pràctiques d'aula on calga arrancar eines de diagnòstic basades en Linux antic, Clonezilla sense signar o instal·lar controladors propietaris de targetes Wi-Fi/GPU que no estan signats, el tècnic ha d'accedir a la configuració UEFI i **desactivar temporalment Secure Boot**. En finalitzar, s'ha de reactivar sempre que siga possible.

---

## 5. El Mode CSM (Compatibility Support Module)

Quan una placa base UEFI rep una unitat de disc antic particionada en MBR, o un pendrive instal·lador dissenyat per a BIOS de 16 bits, no pot arrencar-lo en mode UEFI pur. 

Per a mantenir compatibilitat cap arrere, les plaques incorporen el mode **CSM (Compatibility Support Module)**:
* Quan s'activa CSM, la UEFI emula les interrupcions clàssiques `INT 10h`, `INT 13h` de la BIOS de 16 bits i llegeix el sector MBR tradicional.
* **Per què desactivar CSM avui dia?**
  1. **Requisit de Windows 11:** Windows 11 exigeix de forma estricta arrencar en mode **UEFI pur amb Secure Boot habilitat i TPM 2.0**. Si la màquina està en mode CSM/Legacy, l'instal·lador de Windows 11 mostrarà l'error: *"Aquest equip no compleix els requisits mínims del sistema"*.
  2. **Fast Boot:** L'arrancada ràpida de la placa queda desactivada en mode CSM, ja que ha de carregar mòduls d'emulació antics.
  3. **Discs de més de 2 TB:** Un disc de 4 TB configurat amb CSM i MBR només aprofitarà 2,2 TB; els restants 1,8 TB quedaran com a espai perdut inaccessible.
