# 4.3 La Seqüència d'Arrancada (Boot Process), Partició ESP i Gestors (GRUB 2 i Windows BCD)

L'arrancada d'un ordinador és un procés encadenat per fases conegut tècnicament com a **Bootstrapping** (agafar-se per les pròpies botes per alçar-se). Com que en encendre l'equip la memòria RAM està completament buida, el maquinari ha de seguir un camí estricte i seqüencial per transferir el control des del microprogramari de la placa base fins al nucli (*kernel*) del sistema operatiu.

En aquesta secció analitzarem com ha canviat aquest procés amb l'arribada d'UEFI, com s'organitza la partició **ESP**, i com funcionen els dos gestors d'arrancada més utilitzats: **Windows Boot Manager (BCD)** i **GRUB 2**.

---

## 1. El Camí d'Arrancada: BIOS Clàssica vs UEFI Moderna

```
FLUX TRADICIONAL (BIOS Legacy + MBR):
[ Botó Encesa ] -> [ POST ] -> [ Llegeix Sector 0 (MBR) ] -> [ Cerca Partició Activa ] -> [ VBR ] -> [ NTLDR / GRUB Stage 1 ] -> [ Nucli SO ]

FLUX MODERN (UEFI + GPT):
[ Botó Encesa ] -> [ POST ] -> [ Consulta NVRAM (BootOrder) ] -> [ Accedeix a Partició ESP (FAT32) ] -> [ Executa .efi ] -> [ Gestor (GRUB2 / BCD) ] -> [ Kernel SO ]
```

### El canvi de paradigma fonamental
En els sistemes antics amb BIOS, el microprogramari no sabia què era un sistema de fitxers ni una carpeta. Només demanava a la controladora de disc llegir els primers 512 bytes del disc físic. Si aquest sector contenia un error, tota la cadena es trencava.

En canvi, **UEFI entén de forma nativa el sistema de fitxers FAT32**. La placa base pot obrir carpetes, llegir fitxers i executar binaris compilats específicament per a l'arquitectura del processador (fitxers amb extensió `.efi`).

---

## 2. La Partició ESP (EFI System Partition)

La **Partició del Sistema EFI (ESP)** és una partició especial i independent del sistema operatiu situada en un disc particionat en GPT:

* **Format de fitxers:** Ha d'estar formatada obligatòriament en **FAT32** (o FAT16 per a mitjans molt xicotets). La UEFI inclou el controlador FAT integrat en el seu propi xip ROM.
* **Mida recomanada:** Normalment entre **100 MB** (estàndard de Windows) i **512 MB** (recomanat en entorns Linux o arrencades múltiples per allotjar diversos binaris i imatges de diagnòstic).
* **Identificador GUID:** Té el tipus únic `C12A7328-F81F-11D2-BA4B-00A0C93EC93B`. En eines com `fdisk` es marca com a tipus `EFI System`.

### Estructura típica de fitxers dins de l'ESP
Quan es munta la partició ESP (en Linux habitualment a `/boot/efi`), trobem una jerarquia neta i organitzada:

```
/boot/efi/
└── EFI/
    ├── Boot/
    │   └── bootx64.efi          <-- Carregador fallback universal (per defecte)
    ├── Microsoft/
    │   └── Boot/
    │       ├── bootmgfw.efi     <-- Windows Boot Manager
    │       └── BCD              <-- Base de dades de configuració d'arrancada
    └── ubuntu/
        ├── shimx64.efi          <-- Signat per Microsoft per a Secure Boot
        ├── grubx64.efi          <-- Binari de GRUB 2
        └── mmx64.efi            <-- Gestor de claus MOK (Machine Owner Key)
```

> 💡 **Fallback `bootx64.efi`:** Si una unitat USB o un disc no té una entrada registrada a la memòria NVRAM de la placa base, la UEFI busca automàticament la ruta estàndard `/EFI/Boot/bootx64.efi` en la partició FAT32. Així és com funcionen els pendrives d'instal·lació.

---

## 3. El Gestor de Windows: Windows Boot Manager i el Magatzem BCD

En Windows (a partir de Vista i mantingut en Windows 10/11), el procés d'arrancada es gestiona mitjançant dos elements:
1. **`bootmgfw.efi` (Windows Boot Manager):** L'aplicació executable UEFI que mostra el menú d'arrencada si hi ha múltiples versions de Windows o opcions de recuperació.
2. **El BCD (Boot Configuration Data):** Un fitxer de base de dades estructurat en format de registre binari que substitueix l'antic `boot.ini`. Conté els identificadors GUID dels sistemes instal·lats, les rutes als controladors i els paràmetres de depuració.

### Eines d'administració de BCD al taller
* **`bcdedit.exe`:** Eina de línia d'ordres avançada executada com a administrador.
  ```cmd
  # Veure totes les entrades del magatzem BCD actual
  bcdedit /enum

  # Configurar el temps d'espera del menú d'arrancada a 5 segons
  bcdedit /timeout 5

  # Habilitar el menú d'opcions avançades clàssic (F8)
  bcdedit /set {default} bootmenupolicy legacy
  ```
* **`msconfig`:** Utilitat gràfica de configuració del sistema (pestanya *Arrencada*) per seleccionar el sistema per defecte o arrencar en mode segur.

---

## 4. El Gestor de GNU/Linux: GRUB 2 (GRand Unified Bootloader)

**GRUB 2** és el gestor d'arrancada per excel·lència en l'ecosistema Linux. És modular, extremadament flexible i capaç de reconèixer automàticament particions de Windows, Linux, macOS o BSD.

### Fitxers clau de GRUB 2
* **`/etc/default/grub`:** El fitxer de configuració que **sí** que ha d'editar l'administrador:
  ```bash
  GRUB_DEFAULT=0              # Arrenca la primera entrada de la llista
  GRUB_TIMEOUT=10             # Espera 10 segons abans d'arrencar
  GRUB_DISTRIBUTOR="Ubuntu"
  GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"  # Amaga missatges del kernel
  GRUB_DISABLE_OS_PROBER=false # Habilita la detecció d'altres SO com Windows
  ```
* **`/boot/grub/grub.cfg`:** El fitxer de configuració final que llegeix el gestor durant l'arrancada. **Mai s'ha d'editar manualment**, ja que és sobreescrit automàticament.
* **`sudo update-grub`:** Comanda en Ubuntu/Debian que executa l'script `grub-mkconfig -o /boot/grub/grub.cfg`, escaneja els nuclis instal·lats i crida a `os-prober` per detectar particions de Windows.

### La comanda `efibootmgr` en Linux
Permet consultar i modificar les variables de la memòria **NVRAM** de la placa base directament des de la terminal:
```bash
# Llistar l'ordre d'arrancada de la UEFI
sudo efibootmgr

# Canviar l'ordre d'arrancada perquè arrenque primer Ubuntu (0002) i després Windows (0000)
sudo efibootmgr -o 0002,0000,0001
```
