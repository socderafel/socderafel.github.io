# 4.2 Esquemes de Particionament: MBR vs GPT

Perquè un disc físic o unitat d'estat sòlid (SSD SATA o NVMe) puga allotjar sistemes de fitxers i sistemes operatius, el seu espai d'adreces de blocs lògics (**LBA - Logical Block Addressing**) s'ha de dividir en regions independents anomenades **particions**.

L'esquema que defineix com s'emmagatzema la informació sobre la ubicació, mida i tipus d'aquestes particions rep el nom de **taula de particions**. En el món del maquinari x86/x64 coexisteixen dos estàndards fonamentals: el clàssic **MBR** i el modern **GPT**.

---

## 1. MBR (Master Boot Record): Estructura i Límit Matemàtic de 2,2 TB

L'estàndard **MBR** es va introduir l'any 1983 amb PC-DOS 2.0. Resideix exclusivament en el **primer sector físic del disc** (Sector 0, LBA 0), el qual té una mida exacta de **512 bytes**:

```
+-----------------------------------+--------------------+-----------+
| Codi d'arrancada executable (IPL) | Taula Particions   | Magic byte|
|              446 bytes            | 64 bytes (4 x 16B) |  2 bytes  |
+-----------------------------------+--------------------+-----------+
 0                                   446                  510         512
```

### Anatomia dels 512 bytes del sector MBR
1. **Bootstrap Code (446 bytes):** Codi màquina de 16 bits que la BIOS executa per buscar quina de les 4 particions està marcada com a *activa* (Bootable) i saltar al seu sector VBR.
2. **Taula de particions (64 bytes):** Només disposa d'espai per a **4 entrades** de 16 bytes cadascuna. Per això un disc MBR només pot tindre:
   - Fins a **4 particions primàries**.
   - O bé **3 particions primàries + 1 partició estesa** (la qual serveix de contenidor per a un nombre indefinit de *particions lògiques* mitjançant estructures EBR enllaçades).
3. **Signatura d'arrancada (2 bytes):** La paraula hexadecimal `0x55AA` (en bytes: `0x55` i `0xAA`). Si aquests 2 bytes finals no contenen aquest valor exacte, la BIOS considera que el disc no és arrencable.

### El per què del límit matemàtic de 2,19 TB (2,2 TB)
En la taula de 16 bytes de cada partició MBR, el camp que emmagatzema el nombre total de sectors de la partició i el sector d'inici utilitza números enters de **32 bits**:

$$	ext{Sectors màxims adreçables} = 2^{32} = 4.294.967.296 	ext{ sectors}$$

Com que cada sector tradicional mesura **512 bytes**:

$$	ext{Capacitat màxima} = 4.294.967.296 	imes 512 	ext{ bytes} = 2.199.023.255.552 	ext{ bytes} pprox 2,199 	ext{ TB} pprox 2 	ext{ TiB}$$

> 🔴 **Conseqüència Tècnica:** Si connectes un disc dur modern de 4 TB, 8 TB o 16 TB inicialitzat en MBR, el sistema operatiu només podrà aprofitar els primers 2,2 TB. Els gigabytes restants quedaran com a espai no assignat i inutilitzable.

---

## 2. GPT (GUID Partition Table): L'Arquitectura de Nova Generació

L'esquema **GPT** forma part de l'estàndard UEFI i resol de soca-rel totes les vulnerabilitats i límits de MBR:

```
LBA 0      -> [ Protective MBR ] (Compatibilitat i protecció anti-esborrat)
LBA 1      -> [ Capçalera GPT Primària ] (Header amb GUID del disc i CRC32)
LBA 2..33  -> [ Taula d'Entrades de Particions Primàries ] (128 entrades)
LBA 34..N  -> [ PARTICIÓ 1 ] [ PARTICIÓ 2 ] [ PARTICIÓ 3 ] ... (Dades)
Final disc -> [ Còpia de Seguretat de les Entrades GPT ]
Últim LBA  -> [ Capçalera GPT Secundària (Backup Header) ]
```

### Característiques Clau de GPT
* **Identificadors Únics Universals (GUID / UUID):** Cada disc i cada partició tenen un identificador de 128 bits únic al món (ex: `EBD0A0A2-B9E5-4433-87C0-68B6B72699C7` per a particions de dades bàsiques de Windows).
* **Mínim de 128 particions primàries:** L'especificació reserva 32 sectors de 512 bytes (16.384 bytes). Com que cada entrada de partició ocupa 128 bytes, suporta $16.384 / 128 = 128$ particions per defecte, sense necessitat de particions esteses ni lògiques.
* **Adreçament de 64 bits (9,4 Zettabytes):** Amb camps de 64 bits, la capacitat màxima teòrica és de $2^{64} 	imes 512 	ext{ bytes} pprox 9,4 	imes 10^{21} 	ext{ bytes}$ (9,4 ZB).
* **Protective MBR (LBA 0):** En el sector 0, GPT escriu un MBR fictici amb una única partició de tipus `0xEE` que cobreix tot el disc. Si un sistema operatiu o utilitat antiga (com un instal·lador de Windows XP) llegeix el disc, veu aquesta partició i no sobreescriu el contingut pensant que el disc està buit.
* **Redundància i Integritat amb CRC32:** GPT guarda una còpia idèntica de la capçalera i de les taules al final físic del disc. A més, inclou sumes de comprovació **CRC32**. Si un sector defectuós danya la capçalera primària, la UEFI restaura automàticament la taula des del backup final.

---

## 3. Taula Comparativa Definitiva: MBR vs GPT

| Paràmetre | MBR (Master Boot Record) | GPT (GUID Partition Table) |
| :--- | :--- | :--- |
| **Estàndard associat** | BIOS Legacy (1983) | UEFI (Modern) |
| **Ubicació de la taula** | Només al Sector 0 (LBA 0) | Al principi (LBA 1-33) i al final del disc (Backup) |
| **Mecanisme de recuperació** | Cap (si el sector 0 es danya, es perd la taula) | Automàtic mitjançant còpia de seguretat i CRC32 |
| **Nombre màxim de particions** | 4 primàries (o 3 primàries + 1 estesa) | 128 primàries en sistemes operatius estàndard |
| **Mida màxima de disc** | 2,2 TB (amb sectors de 512 bytes) | 9,4 ZB (Zettabytes) |
| **Identificació de particions** | Codis hexadecimals de 1 byte (ex: `0x07`, `0x83`) | GUIDs de 128 bits |
| **Compatibilitat Windows 11** | No admès com a disc de sistema | **Obligatori per al disc d'arrancada** |

## 4. Gestió Pràctica al Taller: Ordres en Windows i GNU/Linux

### En GNU/Linux: Comprovar el tipus de taula
Amb la comanda `lsblk` o `fdisk`:
```bash
# Mostrar discs i esquema de particionament (pttype: dos=MBR, gpt=GPT)
lsblk -o NAME,SIZE,TYPE,FSTYPE,PTTYPE,MOUNTPOINT

# Consultar el disc complet amb fdisk
sudo fdisk -l /dev/sda
# O bé utilitzar parted
sudo parted -l
```

### En Windows: Comprovar i convertir amb DISKPART
Per a equips nous o discs que s'han de preparar abans d'instal·lar:
```cmd
diskpart
DISKPART> list disk
# Si la columna 'Gpt' té un asterisc (*), el disc és GPT. Si està buida, és MBR.

DISKPART> select disk 0
DISKPART> clean
DISKPART> convert gpt
DISKPART> exit
```

### Migració sense pèrdua de dades: `MBR2GPT`
En equips amb Windows 10 que volen actualitzar a Windows 11 sense formatejar, Microsoft inclou l'eina oficial `mbr2gpt.exe`:
```cmd
# 1. Validar que el disc compleix els requisits (màx 3 particions primàries, espai lliure)
mbr2gpt /validate /allowFullOS

# 2. Convertir el disc de MBR a GPT i crear la partició ESP automàticament
mbr2gpt /convert /allowFullOS
```
*En reiniciar l'ordinador, el tècnic ha d'entrar a la UEFI i canviar immediatament el mode de Legacy/CSM a UEFI pur.*
