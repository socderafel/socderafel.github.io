Un ordinador modern és un conjunt extremadament complex de circuits electrònics que executen milions d'instruccions per segon. Perquè aquest sistema siga comprensible, programable i segur, s'organitza en **capes d'abstracció jeràrquiques**. Cada capa ofereix serveis a la capa immediatament superior, amagant els detalls tècnics i la complexitat del maquinari subjacent.

---

## 🏛️ Model Jeràrquic de Capes d'un Sistema Informàtic

En qualsevol estació de treball (siga un ordinador amb Windows 11 o una màquina amb Ubuntu Linux), l'estructura funcional s'organitza de dalt a baix en cinc nivells clarament definits:

```
  ┌────────────────────────────────────────────────────────────────────────┐
  │ 5. APLICACIONS D'USUARI: Navegador web, LibreOffice, IDEs, Jocs       │
  ├────────────────────────────────────────────────────────────────────────┤
  │ 4. INTERFÍCIE D'USUARI: Entorn gràfic (GUI / Desktop) o Intèrpret CLI  │
  ├────────────────────────────────────────────────────────────────────────┤
  │ 3. INTERFÍCIE DE CRIDES AL SISTEMA (Syscalls): open, read, fork, write │
  ├────────────────────────────────────────────────────────────────────────┤
  │ 2. NUCLI DEL SISTEMA OPERATIU (Kernel) i Controladors de Dispositiu    │
  ├────────────────────────────────────────────────────────────────────────┤
  │ 1. FIRMWARE DEL SISTEMA: BIOS Heretada / Firmware UEFI modern          │
  ├────────────────────────────────────────────────────────────────────────┤
  │ 0. MAQUINARI FÍSIC: CPU (ALU, registres), RAM, Busos PCIe, Disc NVMe   │
  └────────────────────────────────────────────────────────────────────────┘
```

1. **Maquinari físic (Capa 0):** L'electrònica digital, processador, xips de memòria RAM, controladors d'interrupció i perifèrics d'E/S.
2. **Firmware del sistema (Capa 1):** Codi gravat en memòria no volàtil (ROM/Flash SPI) de la placa base que inicialitza el maquinari durant el POST (*Power-On Self-Test*) i llança el gestor d'arrancada.
3. **Nucli (Kernel) del SO (Capa 2):** El cor del sistema operatiu. Resideix permanentment a la memòria RAM principal i té el control absolut de la CPU i els perifèrics físics.
4. **Interfície de Crides al Sistema (*Syscalls*, Capa 3):** Porta d'accés estandarditzada i protegida que permet a les aplicacions normals demanar serveis al nucli (per exemple, escriure en un fitxer o obrir un sòcol de xarxa).
5. **Espai d'usuari (Capes 4 i 5):** Inclou els serveis d'usuari, les biblioteques de sistema (*glibc* en Linux, *Win32 API* en Windows), els intèrprets d'ordres (*Bash*, *PowerShell*) i les aplicacions finals.

## 🛡️ Anells de Protecció de la CPU: Ring 0 vs Ring 3

L'arquitectura dels processadors x86 i x86-64 implementa mecanismes de seguretat basats en maquinari anomenats **anells de protecció** (*Protection Rings* o nivells de privilegi). La CPU impedeix que el programari d'un nivell menys privilegiat execute instruccions crítiques d'un nivell superior:

```
                          ANELLS DE PRIVILEGI DE LA CPU
                     ┌───────────────────────────────────┐
                     │            RING 3                 │
                     │         (Mode Usuari)             │
                     │   Aplicacions, GUI, Shells        │
                     │   Accés molt restringit           │
                     │   ┌───────────────────────────┐   │
                     │   │          RING 1 & 2       │   │
                     │   │   (Històric / Drivers)    │   │
                     │   │   ┌───────────────────┐   │   │
                     │   │   │      RING 0       │   │   │
                     │   │   │   (Mode Kernel)   │   │   │
                     │   │   │   Nucli del SO    │   │   │
                     │   │   │   Accés Total     │   │   │
                     │   │   └───────────────────┘   │   │
                     │   └───────────────────────────┘   │
                     └───────────────────────────────────┘
```

* **Ring 0 (Mode Kernel o Mode Privilegiat):**
  - El processador pot executar qualsevol instrucció del seu joc d'ordres (com ara deshabilitar interrupcions `CLI`, canviar taules de pàgines de memòria `CR3` o accedir directament a ports d'E/S).
  - Ací s'executa exclusivament el **nucli del sistema operatiu** i els seus **controladors de dispositiu**.
  - Si un controlador comença a escriure en una zona de memòria errònia en Ring 0, provoca una fallada fatal que col·lapsa tot l'equip: una **Pantalla Blava de la Mort** (*BSOD*) en Windows o un **Kernel Panic** en Linux.

* **Ring 3 (Mode Usuari o Mode No Privilegiat):**
  - S'hi executen totes les aplicacions d'usuari (Google Chrome, LibreOffice, jocs, consoles de terminals).
  - Tenen prohibit accedir directament als xips de memòria d'altres processos o comunicar-se directament amb el disc dur o la targeta de xarxa.
  - Si una aplicació intenta executar una instrucció no permesa o accedir a una adreça de memòria que no li pertany, la CPU genera una excepció per fallada de segmentació (*Segmentation Fault* en Linux o *Access Violation 0xC0000005* en Windows) i el sistema operatiu finalitza immediatament només eixe programa, mantenint intacte i segur el funcionament de la resta de l'equip.

## 📞 La Interfície de Crides al Sistema (Syscalls)

Quan una aplicació que s'executa en Mode Usuari (Ring 3) necessita guardar un document al disc, no pot enviar ordres directament al controlador SATA o NVMe. Ha de sol·licitar-ho al nucli mitjançant una **crida al sistema** (*System Call* o *Syscall*):

```
  APLICACIÓ (Ring 3)        BIBLIOTECA C / API          NUCLI / KERNEL (Ring 0)
  ──────────────────        ──────────────────          ───────────────────────
   my_file.write(...)  ──>    write() en glibc   ──>     Instrucció SYSCALL
                                                         Canvi de mode a Ring 0
                                                                   │
                                                                   ▼
                                                         sys_write() al nucli
                                                         Verifica permisos i disc
                                                         Comunica amb el disc NVMe
                                                                   │
                                                                   ▼
   Retorn d'èxit      <──   Retorn de control   <──     Instrucció SYSRET
   (Contingut desat)        Canvi de mode a Ring 3
```

Aquest mecanisme de **canvi de context** (*Context Switch*) garanteix:
- **Seguretat:** El nucli valida si l'usuari que ha llançat el programa té permisos de lectura o escriptura sobre eixe fitxer abans de tocar el disc físic.
- **Portabilitat:** El programador no necessita saber si el disc dur és un SSD Western Digital, un disc HDD Seagate o una unitat USB; el nucli s'encarrega d'unificar l'accés.

## 🧩 Tipus d'Arquitectures de Nucli: Monolític, Microkernel i Híbrid

Els sistemes operatius s'han dissenyat segons tres grans filosofies de construcció interna del seu nucli:

| Característica | Nucli Monolític (*Monolithic*) | Microkernel (*Micro-nucli*) | Nucli Híbrid (*Hybrid*) |
| :--- | :--- | :--- | :--- |
| **Exemples reals** | **GNU/Linux**, FreeBSD | **MINIX 3**, QNX, GNU Hurd | **Windows NT** (10/11), macOS (XNU) |
| **Ubicació dels serveis** | Nucli, controladors, gestió de fitxers i xarxes s'executen TOTS en **Ring 0**. | Només la planificació bàsica de CPU i comunicació entre processos (IPC) en **Ring 0**; la resta s'executa en **Ring 3**. | Combina la rapidesa del nucli monolític amb una certa modularitat de microkernel. Serveis clau en **Ring 0**. |
| **Rendiment** | **Màxim.** Les crides internes no requereixen canvis continus de context entre Ring 0 i Ring 3. | **Inferior.** Gran sobrecàrrega per pas continu de missatges (*IPC*) entre servidors d'usuari. | **Molt alt.** Estructurat per subsistemes ràpids. |
| **Robustesa davant fallades** | Si un controlador falla en Ring 0, pot col·lapsar tot el nucli (*Kernel Panic*). | Si un controlador de disc o xarxa falla, cau com un procés d'usuari i es pot reiniciar sense apagar l'equip. | Equilibrat; incorpora mecanismes de recuperació de controladors gràfics en mode usuari (*WDDM*). |
| **Modularitat dinàmica** | Alta mitjançant mòduls carregables (*LKM* via `modprobe`). | Màxima per naturalesa (processos servidors independents). | Alta mitjançant controladors dinàmics `.sys`. |

## 🔌 Gestió de Controladors de Dispositiu (*Device Drivers*)

Un controlador és una peça de programari que tradueix les instruccions generals del nucli a les comandes electròniques específiques que entén un model de xip o perifèric concret:

* **En GNU/Linux:**
  - Els controladors es denominen mòduls carregables del nucli (*Loadable Kernel Modules* - **LKM**, amb extensió `.ko`).
  - Es poden carregar o descarregar de la memòria en calent sense necessitat de reiniciar el sistema.
  - Ordres essencials de consola:
    - `lsmod`: Llista tots els mòduls de controladors actualment carregats a la memòria del nucli.
    - `modinfo <nom>`: Mostra l'autor, descripció, paràmetres i llicència d'un mòdul.
    - `sudo modprobe <nom>`: Carrega un mòdul juntament amb totes les seues dependències.
    - `sudo modprobe -r <nom>`: Descarrega un mòdul de la memòria del nucli de forma segura.

* **En Microsoft Windows:**
  - Es tracta de controladors binaris (fitxers `.sys` acompanyats d'un fitxer descriptor d'instal·lació `.inf`).
  - Windows exigeix que tots els controladors de 64 bits estiguen **signats digitalment per Microsoft** (*Driver Signature Enforcement*) per evitar la injecció de rootkits o programari espia al Ring 0.
  - Es gestionen gràficament des del **Administrador de dispositius** (`devmgmt.msc`) o des de consola mitjançant la utilitat `pnputil.exe`.
