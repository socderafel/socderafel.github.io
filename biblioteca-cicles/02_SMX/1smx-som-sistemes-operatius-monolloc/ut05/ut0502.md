# 5.2 Gestió d'Usuaris, Grups i Permisos POSIX en GNU/Linux

Des dels seus orígens en UNIX a finals dels anys 60, **GNU/Linux** ha estat concebut des de la seua arrel com un **sistema operatiu multiusuari i multitasca real**. Això significa que múltiples persones i serveis poden interactuar amb la màquina alhora, de forma totalment aïllada i protegida.

Per garantir que cap usuari puga espiar, alterar o destruir la feina d'un altre (ni comprometre l'estabilitat del sistema), Linux implementa un model de seguretat estricte basat en **identificadors numèrics (UID/GID)** i una matriu de **permisos d'accés POSIX**.

---

## 1. El Model d'Usuaris i els Fitxers del Sistema

En Linux, cada compte d'usuari està associat a un número enter anomenat **UID (User ID)**:
* **UID 0:** És el superusuari **`root`** (l'administrador absolut). Té permisos totals per llegir, escriure o esborrar qualsevol fitxer sense restriccions.
* **UIDs 1 a 999:** Reservats per a comptes del sistema i dimonis de servei (com `www-data`, `mysql`, `systemd-resolve`). Aquests usuaris no tenen inici de sessió interactiu (`/usr/sbin/nologin`).
* **UIDs 1000 en endavant:** Usuaris humans ordinaris creats per l'administrador (el primer usuari que es crea durant la instal·lació rep típicament el UID 1000).

```
/etc/passwd   --> Dades públiques del compte (nom, UID, GID, home, shell)
/etc/shadow   --> Hashes xifrats de les contrasenyes (només llegible per root)
/etc/group    --> Definició dels grups de sistema i els seus membres
/etc/sudoers  --> Privilegis d'administració per a l'ordre sudo
```

### Anatomia d'una línia a `/etc/passwd`
Si fem `head -n 1 /etc/passwd` veurem quelcom com:
`root:x:0:0:root:/root:/bin/bash`
1. `root`: Nom del compte d'usuari.
2. `x`: Indica que la contrasenya està emmagatzemada de forma segura al fitxer xifrat `/etc/shadow`.
3. `0`: UID de l'usuari.
4. `0`: GID del grup primari.
5. `root`: Camp de comentari o nom complet (GECOS).
6. `/root`: Directori d'inici (*home*).
7. `/bin/bash`: Shell per defecte en iniciar sessió.

### Ordres essencials de gestió al taller
```bash
# Crear un nou usuari amb el seu directori /home i shell bash
sudo useradd -m -s /bin/bash anna

# Assignar o canviar la contrasenya de l'usuari
sudo passwd anna

# Crear un grup de treball
sudo groupadd professors

# Afegir l'usuari 'anna' al grup secundari 'professors' i al grup 'sudo'
sudo usermod -aG professors,sudo anna

# Eliminar un usuari i esborrar de forma neta tot el seu directori home
sudo userdel -r anna
```

## 2. El Model de Permisos POSIX (UGO)

Quan executem l'ordre `ls -l` a la terminal, obtenim una cadena de 10 caràcters a la primera columna que defineix els permisos exactes del recurs:

```
- r w x r - x r - -   1 alumne departament 4096 març 10 11:30 script.sh
│ └──┬──┘ └──┬──┘ └──┬──┘
│    │       │       └── OTHERS (Altres usuaris del sistema)
│    │       └────────── GROUP (Membres del grup 'departament')
│    └────────────────── USER (L'usuari propietari 'alumne')
└─────────────────────── Tipus de fitxer: '-' (ordinari), 'd' (directori), 'l' (enllaç)
```

### Valors dels permisos: La suma octal
Cada triplet es compon de 3 drets bàsics:
* **Lectura (`r` - Read):** Valor numèric **4**. Permet obrir i visualitzar el fitxer (o llistar fitxers si és una carpeta).
* **Escriptura (`w` - Write):** Valor numèric **2**. Permet modificar o esborrar el fitxer (o crear/eliminar fitxers si és una carpeta).
* **Execució (`x` - eXecute):** Valor numèric **1**. Permet executar un programa/script (o travessar i entrar a una carpeta amb `cd`).
* **Sense permís (`-`):** Valor numèric **0**.

Per calcular el permís d'un recurs se sumen els valors de cada grup:
* `r w x` = 4 + 2 + 1 = **7** (Control total)
* `r - x` = 4 + 0 + 1 = **5** (Lectura i execució, no modificable)
* `r w -` = 4 + 2 + 0 = **6** (Lectura i escriptura, no executable)
* `r - -` = 4 + 0 + 0 = **4** (Només lectura)
* `- - -` = 0 + 0 + 0 = **0** (Sense accés)

## 3. Ordres de Modificació: `chmod` i `chown`

### Canvi de permisos amb `chmod`
Podem utilitzar la notació numèrica octal o la simbòlica:
```bash
# Notació Octal clàssica
chmod 755 script.sh    # Propietari rwx (7), Grup r-x (5), Altres r-x (5)
chmod 644 document.txt # Propietari rw- (6), Grup r-- (4), Altres r-- (4)
chmod 700 clau_privada # Propietari rwx (7), ningú més té accés (00)

# Notació Simbòlica (u=user, g=group, o=others, a=all; + afegir, - llevar, = fixar)
chmod +x script.sh     # Afegeix permís d'execució a tothom
chmod g-w fitxer.conf  # Lleva el permís d'escriptura al grup
chmod o=r informe.pdf  # Fixa exactament només lectura per a la resta d'usuaris
```

### Canvi de propietari i grup amb `chown`
```bash
# Canviar el propietari a 'anna'
sudo chown anna document.txt

# Canviar propietari i grup alhora (usuari:grup)
sudo chown anna:professors document.txt

# Aplicar el canvi de forma recursiva a tota una carpeta i el seu contingut
sudo chown -R anna:professors /dades/projecte/
```

## 4. Permisos Especials Avançats: SUID, SGID i Sticky Bit

Per a resoldre necessitats de seguretat que el model estàndard no cobreix, Linux afegeix un quart dígit octal a l'esquerra:

| Permís Especial | Valor Octal | Posició en `ls -l` | Significat Pràctic |
| :--- | :---: | :---: | :--- |
| **SUID** (Set User ID) | **4xxx** | `-rwsr-xr-x` (s a User) | El fitxer s'executa sempre amb els privilegis del **propietari del fitxer**, no de l'usuari que el llança (ex: `/usr/bin/passwd` és propietat de root per poder escriure a `/etc/shadow`). |
| **SGID** (Set Group ID) | **2xxx** | `drwxrwsr-x` (s a Group) | En un directori compartit, qualsevol fitxer nou que es cree hereta automàticament el grup propietari del directori, facilitant el treball en equip. |
| **Sticky Bit** | **1xxx** | `drwxrwxrwt` (t a Others) | En un directori comú com `/tmp`, qualsevol usuari pot crear fitxers, però **només el propietari del fitxer (o root) pot esborrar-lo**. Evita que usuaris maliciosos eliminen la feina aliena. |
