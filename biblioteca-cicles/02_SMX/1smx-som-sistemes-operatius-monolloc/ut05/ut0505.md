# 5.5 Manteniment, Còpies de Seguretat, Imatges i Resolució d'Avaries

En la professió informàtica hi ha una dita inqüestionable: *«Els discs durs i SSDs no es divideixen entre els que fallen i els que no, sinó entre els que ja han fallat i els que estan a punt de fallar»*.

Un tècnic de SMX no només ha de saber muntar i instal·lar màquines, sinó dissenyar plans de protecció de dades (estratègia 3-2-1), clonar sistemes complets amb eines d'imatge de disc com **Clonezilla**, i retornar a la vida un equip l'arrancada del qual ha quedat danyada (reparació de **BCD** en Windows i rescat de **GRUB 2** mitjançant `chroot` en Linux).

---

## 1. La Regla d'Or de les Còpies de Seguretat: L'Estratègia 3-2-1

Qualsevol empresa o professional que vulga sobreviure a atacs de Ransomware, avaries mecàniques o errors humans catastròfics ha d'aplicar de forma estricta la regla **3-2-1**:

```
[ 3 CÒPIES ] ──> 1 Dades de Producció actives + 2 Còpies de Seguretat
      │
[ 2 SUPORTS ] ──> Utilitzar 2 tipus de tecnologia diferents (ex: SSD intern + Servidor NAS / Disc extern)
      │
[ 1 OFFSITE ] ──> Mantenir 1 còpia fora de les instal·lacions (al núvol xifrat o en una segona seu)
```

### Tipus de Còpies de Seguretat
* **Còpia Completa (Full Backup):** Copia el 100% de les dades seleccionades.
  - *Avantatge:* La restauració és immediata i requereix un únic conjunt de dades.
  - *Inconvenient:* Triga molt de temps i consumeix una gran quantitat d'emmagatzematge.
* **Còpia Incremental:** Només emmagatzema els fitxers que s'han creat o modificat **des de l'última còpia** (siga aquesta completa o incremental).
  - *Avantatge:* És la més ràpida d'executar i ocupa molt poc espai.
  - *Inconvenient:* Per a restaurar cal la còpia completa inicial més **totes** les incrementals intermèdies ordenades en el temps.
* **Còpia Diferencial:** Emmagatzema tots els fitxers modificats **des de l'última còpia completa**.
  - *Avantatge:* Per a restaurar només es necessiten dos elements: la còpia completa base i l'última diferencial.

## 2. Eines d'Empaquetament i Sincronització al Taller

### A. L'empaquetador `tar` en Linux
Permet agrupar milers de fitxers en un únic arxiu contenidor conservant els permisos POSIX, i comprimir-lo amb gzip:
```bash
# Crear un arxiu comprimit .tar.gz (c=create, z=gzip, v=verbose, f=file)
tar -czvf copia_usuaris_2026.tar.gz /home/alumne/Dades

# Visualitzar el contingut sense descomprimir
tar -tzvf copia_usuaris_2026.tar.gz

# Restaurar i extreure el contingut en una carpeta de destí (x=extract)
tar -xzvf copia_usuaris_2026.tar.gz -C /recuperacio/
```

### B. La sincronització intel·ligent amb `rsync`
A diferència de la comanda `cp` (que copia tot sempre de zero), **`rsync`** compara origen i destí i **només transfereix els blocs que han canviat**, convertint-se en l'eina de rèplica per excel·lència:
```bash
# Sincronitzar la carpeta de projectes cap a un disc extern USB muntat
# -a: mode arxiu (preserva propietaris, grups, permisos, dates i enllaços)
# -v: mostra el detall per pantalla
# -z: comprimeix durant la transmissió
# --delete: esborra a la còpia els fitxers que s'hagen eliminat a l'origen
rsync -avz --delete /var/www/html/ /media/usb/backup_web/
```

## 3. Clonació i Imatges de Disc amb Clonezilla

Quan en un centre educatiu o empresa s'han de preparar 30 ordinadors idèntics per a una nova aula d'informàtica, instal·lar-los un a un és impensable. S'instal·la i configura un **equip mestre (Golden Image)** i es clona mitjançant **Clonezilla**:

* **Device-to-Image:** Guarda una còpia fidel de tot el disc dur (incloses les particions GPT, l'ESP i el sistema operatiu) en una carpeta de xarxa (servidor NFS/Samba) o disc extern USB.
* **Device-to-Device:** Clona directament un disc físic vell a un disc físic nou connectat al mateix equip (ideal per a actualitzacions d'un disc dur mecànic HDD a un SSD NVMe ultraràpid).

## 4. Resolució d'Avaries d'Arrancada (Disaster Recovery)

### Reparació del Carregador de Windows (BCD)
Quan Windows mostra la pantalla blava d'avaria d'arrancada (*Error 0xc000000f o BCD Missing*):
1. Arrenca l'ordinador des del USB d'instal·lació de Windows.
2. A la pantalla inicial selecciona *"Reparar l'equip"* -> *Resolució de problemes* -> *Símbol del sistema*.
3. Executa les comandes de diagnòstic i reconstrucció:
   ```cmd
   bootrec /fixmbr
   bootrec /fixboot
   bootrec /rebuildbcd
   sfc /scannow /offbootdir=c:\ /offwindir=c:\windows
   ```

### Rescat de GRUB 2 en Linux mitjançant Live USB i `chroot`
Si una actualització de Windows o un error en la partició fa desaparèixer el menú de GRUB, podem reinstal·lar-lo des d'un Live USB d'Ubuntu:
```bash
# 1. Obtenir privilegis de superusuari
sudo su

# 2. Identificar la partició arrel (ex: /dev/sda2) i la partició ESP (ex: /dev/sda1)
lsblk

# 3. Muntar el sistema al directori temporal /mnt
mount /dev/sda2 /mnt
mount /dev/sda1 /mnt/boot/efi

# 4. Enllaçar els directoris especials del maquinari del Live USB al sistema muntat
for i in /dev /dev/pts /proc /sys /run; do mount -B $i /mnt$i; done

# 5. Executar chroot per 'entrar' al Linux instal·lat al disc rígid
chroot /mnt

# 6. Reinstal·lar el carregador GRUB a la unitat de disc i actualitzar el menú
grub-install /dev/sda
update-grub

# 7. Eixir i reiniciar
exit
reboot
```
