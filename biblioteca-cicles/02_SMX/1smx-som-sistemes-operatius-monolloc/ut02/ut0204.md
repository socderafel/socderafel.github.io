La memòria RAM és l'espai de treball ràpid on la CPU necessita tindre el codi i les dades per poder operar. No obstant això, en els primers sistemes informàtics, els programes s'havien de carregar en blocs físics contigus; si un programa creixia o la memòria s'omplia de forats dispersos, el sistema es bloquejava.

La solució d'enginyeria que va revolucionar la informàtica és la **memòria virtual amb paginació**, una tecnologia que fa creure a cada programa que disposa de tota la memòria de l'ordinador per a ell sol de manera contínua i privada.

---

## 🗺️ Adreces Lògiques (Virtuals) vs Adreces Físiques

Quan una aplicació s'executa, fa referència a **adreces virtuals o lògiques** que van des de `0x00000000` fins al límit del seu espai assignat. La CPU disposa d'un coprocessador especialitzat anomenat **MMU** (*Memory Management Unit*) que tradueix cada adreça virtual a una **adreça física** real dels mòduls de memòria DDR4/DDR5:

```
                            TRADUCCIÓ D'ADRECES AMB MMU
     PROGRAMA D'USUARI              UNITAT MMU                 MEMÒRIA RAM FÍSICA
  ┌─────────────────────┐      ┌──────────────────┐          ┌─────────────────────┐
  │ Adreça Virtual      │      │ Consulta TLB /   │          │ Adreça Física Real  │
  │ 0x0040A120          │ ───► │ Taula de Pàgines │ ───────► │ 0x7FA01120          │
  └─────────────────────┘      └──────────────────┘          └─────────────────────┘
```

Aquest desacoblament aporta dos grans avantatges:
1. **Protecció i aïllament:** El procés A no pot llegir ni corrompre la memòria del procés B, perquè les seues taules de traducció apunten a marcs físics completament independents.
2. **Ubicació no contigua:** Un programa de 100 MB es pot allotjar repartit en trossos xicotets per tota la memòria RAM sense necessitat de trobar un bloc buit continu de 100 MB.

---

## 📄 Paginació: Pàgines i Marcs de Pàgina

La paginació divideix els dos espais de memòria en blocs de mida idèntica:

* **Pàgina virtual (Page):** Bloc de mida fixa de l'espai virtual del procés. En arquitectures x86 i x86-64 la mida universal estàndard és de **4 KiB (4.096 bytes)**.
* **Marc de pàgina (Page Frame):** Bloc físic de la mateixa mida (4 KiB) a la memòria RAM real.

```
          ESPAI VIRTUAL DEL PROCÉS                     MEMÒRIA RAM FÍSICA
        ┌──────────────────────────────┐              ┌───────────────────┐
        │ Pàgina Virtual 0 (Codi)      │ ───────────► │ Marc Físic 12     │
        ├──────────────────────────────┤              ├───────────────────┤
        │ Pàgina Virtual 1 (Dades)     │ ───────────► │ Marc Físic 4      │
        ├──────────────────────────────┤              ├───────────────────┤
        │ Pàgina Virtual 2 (Pila/Heap) │ ───┐         │ Marc Físic 28     │
        └──────────────────────────────┘   │          ├───────────────────┤
                                           │          │ Marc Físic 4      │ ◄── Pàgina 1
                                           │          └───────────────────┘
                                           └────────► [ DESAT A LA SWAP ]
                                                      (No està a la RAM)
```

### L'accelerador TLB (Translation Lookaside Buffer)
Com que consultar la Taula de Pàgines a la RAM per a cada lectura de memòria duplicaria el temps d'accés, la CPU integra una memòria cau ultra-ràpida d'adreces anomenada **TLB**. Si l'adreça està al TLB (*TLB Hit*), la traducció és pràcticament instantània (en menys d'un cicle de rellotge).

---

## ⚠️ La Fallada de Pàgina (Page Fault)

Quan un programa intenta llegir una adreça d'una pàgina que no es troba carregada en cap marc de la RAM física (el seu bit de presència a la taula és `0`), el maquinari genera una excepció anomenada **Fallada de Pàgina** (*Page Fault*):

```
                       CICLE D'UNA FALLADA DE PÀGINA (PAGE FAULT)
  1. La CPU intenta accedir a la pàgina virtual ──────────────────────────────────────┐
                                                                                      │
  2. La MMU detecta que el Bit de Presència = 0 ──► Genera interrupció (Page Fault)   │
                                                              │                       │
  3. El Nucli del SO pren el control en Ring 0 ◄──────────────┘                       │
     Comprova si l'adreça és legítima o un error d'accés (Segmentation Fault)          │
                                                                                      │
  4. El Nucli busca la pàgina a l'espai de Swap o al disc d'emmagatzematge            │
                                                                                      │
  5. Es reserva un Marc Físic buit a la RAM (o s'expulsa una altra pàgina amb LRU)    │
                                                                                      │
  6. Es llig la pàgina del disc i es copia al marc de RAM                             │
                                                                                      │
  7. S'actualitza la Taula de Pàgines (Bit Presència = 1)                             │
                                                                                      │
  8. El nucli reprèn la instrucció original del programa com si res haguera passat ───┘
```

El programa d'usuari mai s'adona que la pàgina estava al disc; simplement nota un xicotet retard de mil·lisegons mentre el disc llegeix les dades.

---

## 🔄 Algorismes de Reemplaçament de Pàgines

Quan la memòria RAM física està al 100% i ocorre una fallada de pàgina, el sistema operatiu ha d'expulsar una pàgina existent cap a la Swap per alliberar un marc físic. Els principals criteris són:

| Algorisme | Mecanisme | Avantatges / Inconvenients |
| :--- | :--- | :--- |
| **FIFO (First-In, First-Out)** | Expulsa la pàgina que fa més temps que està carregada a la RAM. | Molt fàcil d'implementar, però pateix de l'**Anomalia de Belady** (afegir més marcs de RAM física pot provocar paradoxalment més fallades de pàgina). |
| **LRU (Least Recently Used)** | Expulsa la pàgina que fa més temps que no s'ha utilitzat (menys referenciada recentment). | **Excel·lent rendiment.** S'acosta molt al comportament òptim teòric, però requereix suport de maquinari per comptar temps d'accés. |
| **Rellotge (*Clock / Second Chance*)** | Pàgines en cua circular amb un bit de referència. Si el bit és 1, li dona una segona oportunitat (posa bit a 0); si és 0, l'expulsa. | És l'algorisme utilitzat a la pràctica per la seua gran eficiència i baix consum de CPU. |

---

## 🧩 Fragmentació Interna vs Fragmentació Externa

* **Fragmentació Externa (Eliminada per la paginació):** Ocorre quan hi ha prou espai lliure total a la memòria, però està fragmentat en buits xicotets no contigus. Gràcies a la paginació, aquest problema **desapareix completament**, ja que qualsevol marc de 4 KiB lliure pot allotjar qualsevol pàgina.
* **Fragmentació Interna:** Si un procés només necessita 1.000 bytes de dades, el SO li ha d'assignar una pàgina sencera de 4.096 bytes. Els 3.096 bytes restants de la pàgina queden desaprofitats dins d'eixe bloc.
