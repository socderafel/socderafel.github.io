En un ordinador modern hi ha desenes o centenars de processos llestos per executar-se a la memòria RAM, però només disposem d'un nombre limitat de nuclis de CPU físics (per exemple, 4, 8 o 16 nuclis). El component del nucli que decideix quin procés utilitza la CPU en cada mil·lisegon s'anomena **planificador de la CPU** (*CPU Scheduler* o *Dispatcher*).

---

## 🎯 Criteris de Rendiment d'un Bon Planificador

Un bon algorisme de planificació ha d'optimitzar simultàniament diverses mètriques tècniques:

* **Aprofitament de la CPU (CPU Utilization):** Mantindre el processador ocupat el 100% del temps possible, evitant cicles buits.
* **Rendiment (Throughput):** Nombre de processos que completen la seua execució per unitat de temps (per minut o per segon).
* **Temps de retorn (Turnaround Time):** Temps total des que el procés entra al sistema fins que finalitza completament.
* **Temps d'espera (Waiting Time):** Quantitat de temps que el procés passa assegut a la cua de preparats (*Ready*) sense rebre CPU.
* **Temps de resposta (Response Time):** Temps des que l'usuari fa una acció (un clic o tecla) fins que el sistema comença a respondre.

---

## ⚖️ Planificació No Expulsiva vs Expulsiva (Preemptive)

Els algorismes es divideixen en dues grans famílies:

```
                          TIPUS DE PLANIFICACIÓ DE LA CPU
  ┌───────────────────────────────────┬───────────────────────────────────┐
  │     NO EXPULSIVA (Cooperativa)    │       EXPULSIVA (Apropiativa)     │
  ├───────────────────────────────────┼───────────────────────────────────┤
  │ Un procés obté la CPU i manté el  │ La CPU incorpora un temporitzador │
  │ control de manera ininterrompuda  │ electrònic de maquinari. Quan     │
  │ fins que finalitza o decideix     │ s'esgota la seua franja de temps, │
  │ voluntàriament alliberar-la fent  │ la CPU genera una interrupció i   │
  │ una operació d'E/S lenta.         │ desallotja el procés a la força.  │
  │                                   │                                   │
  │ Risc: Si un procés té un bucle    │ Avantatge: Cap programa pot       │
  │ infinit ('while true'), bloqueja  │ monopolitzar ni congelar l'equip. │
  │ tot el sistema. (Ex: Windows 3.1) │ (Ex: Windows 11, Linux, macOS).   │
  └───────────────────────────────────┴───────────────────────────────────┘
```

---

## 📚 Els Principals Algorismes de Planificació

### 1. FCFS (First-Come, First-Served / FIFO)
És l'algorisme més senzill: el primer procés que arriba a la cua és el primer que s'atén completament (no expulsiu).

* **L'efecte comboi (Convoy Effect):** Si arriba primer un procés llarg que necessita 30 segons de càlcul intensiu i darrere arriben 10 processos interactius xicotets de 10 mil·lisegons (com moure el cursor o escriure un caràcter), tots els processos curts queden congelats esperant que el gegant acabe. El temps mitjà d'espera es dispara.

---

### 2. SJF (Shortest Job First - Primer el Treball Més Curt)
S'analitza la cua de processos preparats i s'assigna la CPU al procés que té la **ràfega de CPU més curta**.

* **Propietat matemàtica:** Està demostrat que SJF produeix el **temps mitjà d'espera mínim absolut** de tots els algorismes possibles.
* **Inconvenient real:** En un sistema monolloc d'escriptori és impossible conèixer amb antelació quant de temps necessitarà un programa de càlcul abans d'executar-lo. S'utilitza en entorns de processament per lots (*batch*) amb temps estimats.

---

### 3. Round Robin (RR - Torn Rotatori amb Quàntum)
És el mecanisme vertebral de tots els sistemes operatius multitasca moderns de temps compartit (*Time-Sharing*).

El nucli defineix una unitat de temps xicoteta anomenada **quàntum** o ranura temporal (*Time Quantum*, típicament de **10 a 50 mil·lisegons**). Els processos s'organitzen en una cua circular:

```
                            CICLE ROUND ROBIN AMB QUÀNTUM
                      ┌───────────────────────────────────────┐
                      │  Cua Circular de Preparats: [P1, P2, P3]
                      └──────────────────┬────────────────────┘
                                         │
                                         ▼
                                ┌─────────────────┐
                                │ Execució a CPU  │
                                │   (Quàntum q)   │
                                └────────┬────────┘
                                         │
                      ┌──────────────────┴──────────────────┐
                      │                                     │
           ¿Ha acabat el procés?                 ¿Ha expirat el quàntum q?
           ┌──────────┴──────────┐               ┌──────────┴──────────┐
           │                     │               │                     │
          SÍ                    NO              SÍ                    NO
           │                     │               │                     │
           ▼                     ▼               ▼                     ▼
        Finalitza         Es bloqueja per E/S   Expulsió per rellotge  Continua
        (Surt)            (Cua d'espera)        (Torna a la cua)       execució
```

#### El dilema de la mida del Quàntum ($q$):
* **Si $q$ és massa gran (ex: 2.000 ms):** El sistema perd fluïdesa interactiva i es comporta de facto com un FCFS; el ratolí i les finestres es noten travades.
* **Si $q$ és massa xicotet (ex: 0,1 ms):** El processador passarà més temps desant i restaurant PCBs en canvis de context (*Context Switch Overhead*) que no fent treball útil.
* **Regla pràctica:** Entre el 70% i el 80% de les ràfegues de CPU dels processos haurien de ser més curtes que el quàntum seleccionat.

---

### 4. Cues Multinivell amb Retroalimentació (MLFQ)
Els sistemes operatius moderns (com el *Completely Fair Scheduler* - **CFS** de Linux o el planificador de Windows) utilitzen múltiples cues prioritàries:
- Els processos interactius que fan molta E/S i gasten poc quàntum (el ratolí, el terminal, l'editor de text) es mantenen a les **cues de prioritat màxima**.
- Els processos de càlcul matemàtic massiu que esgoten el seu quàntum sense fer E/S es degraden automàticament cap a **cues inferiors amb quàntums més llargs**.
- S'aplica un mecanisme d'**envelliment** (*Aging*): si un procés de baixa prioritat passa massa temps sense rebre CPU, la seua prioritat s'eleva progressivament per evitar la **inanició** (*Starvation*).

---

## 🧮 Exemple Pràctic: Càlcul de Temps Mitjà d'Espera (Gantt)

Imaginem 3 processos que arriben a l'instant $t = 0$:

| Procés | Temps de Ràfega de CPU |
| :---: | :---: |
| **P1** | 24 ms |
| **P2** | 3 ms |
| **P3** | 3 ms |

### Cas A: Algorisme FCFS (Ordre P1 -> P2 -> P3)
```
  Diagrama de Gantt:
  ┌─────────────────────────────────────────────────┬──────┬──────┐
  │                       P1                        │  P2  │  P3  │
  └─────────────────────────────────────────────────┴──────┴──────┘
  0                                                 24     27     30 ms
```
* Temps d'espera de P1: $0\text{ ms}$
* Temps d'espera de P2: $24\text{ ms}$
* Temps d'espera de P3: $27\text{ ms}$
* **Temps Mitjà d'Espera:** $\frac{0 + 24 + 27}{3} = \frac{51}{3} = \mathbf{17\text{ ms}}$

### Cas B: Algorisme SJF (Ordre P2 -> P3 -> P1)
```
  Diagrama de Gantt:
  ┌──────┬──────┬─────────────────────────────────────────────────┐
  │  P2  │  P3  │                       P1                        │
  └──────┴──────┴─────────────────────────────────────────────────┘
  0      3      6                                                 30 ms
```
* Temps d'espera de P2: $0\text{ ms}$
* Temps d'espera de P3: $3\text{ ms}$
* Temps d'espera de P1: $6\text{ ms}$
* **Temps Mitjà d'Espera:** $\frac{0 + 3 + 6}{3} = \frac{9}{3} = \mathbf{3\text{ ms}}$ (Més de 5 vegades més ràpid!).
