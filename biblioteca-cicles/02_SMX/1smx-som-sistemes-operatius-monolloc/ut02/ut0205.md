Un disc dur magnètic o una unitat d'estat sòlid (SSD NVMe) és només una seqüència massiva de sectors físics sense estructura. El **sistema de fitxers** (*File System*) és l'estructura lògica de dades que el sistema operatiu construeix sobre una partició per organitzar, nomenar, indexar, protegir i localitzar els fitxers de manera eficient.

En el món dels sistemes monolloc conviuen dues grans filosofies d'indexació: el model basat en **Inodes** propi de l'estàndard UNIX/Linux (**ext4**) i el model basat en la **Master File Table (MFT)** de Microsoft Windows (**NTFS**).

---

## 🐧 El Sistema d'Inodes en GNU/Linux (ext4)

En GNU/Linux i sistemes UNIX, un fitxer no és una entitat única indivisible, sinó que es divideix en dues parts: les **metadades** (informació sobre el fitxer) i les **dades reals** (el contingut).

L'estructura de dades que conté les metadades s'anomena **Inode** (*Index Node* o node d'índex). Cada fitxer i directori té un número d'Inode únic dins de la seua partició:

```
                            ESTRUCTURA D'UN INODE EN EXT4
  ┌─────────────────────────────────────────────────────────────────────────────┐
  │ METADADES DE L'INODE (ex: Inode #10425):                                    │
  │ • Tipus de fitxer (regular, directori, enllaç simbòlic...)                 │
  │ • Mida exacta en bytes                                                      │
  │ • Propietari (UID) i Grup (GID)                                             │
  │ • Permisos d'accés POSIX (rwxr-xr--)                                        │
  │ • Marques de temps: atime (accés), mtime (modificació), ctime (canvi)       │
  │ • Comptador d'enllaços durs (Link Count)                                    │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ PUNTERS DE BLOCS DE DADES:                                                  │
  │ • 12 Punters Directes ──────────────► [Bloc 101] [Bloc 102] ... [Bloc 112]  │
  │ • 1 Punter Indirecte Simple ────────► [Taula amb 1.024 punters a blocs]     │
  │ • 1 Punter Indirecte Doble  ────────► [Taula a 1.024 taules indirectes]     │
  │ • 1 Punter Indirecte Triple ────────► [Permet fitxers de fins a 16 TiB]     │
  └─────────────────────────────────────────────────────────────────────────────┘
```

> [!IMPORTANT]
> **Què NO conté un Inode?**
> Un Inode **mai conté el nom del fitxer ni el contingut de les dades**.
> El nom del fitxer s'allotja a la taula del **directori pare**, el qual és simplement una llista de parelles: `[Nom del fitxer -> Número d'Inode]`.

### Enllaços Durs (Hard Links) vs Enllaços Simbòlics (Soft / Symlinks):
* **Enllaç Dur (`ln fitxer.txt copia_dura.txt`):** Crea una nova entrada de directori amb un altre nom que **apunta exactament al mateix número d'Inode**. Si s'esborra el fitxer original, les dades continuen intactes perquè el comptador d'enllaços de l'Inode passa de 2 a 1.
* **Enllaç Simbòlic (`ln -s fitxer.txt acces_directe.txt`):** Crea un nou Inode propi el contingut del qual és exclusivament la ruta de text cap a l'arxiu original (similar a un accés directe de Windows). Si s'esborra l'arxiu de destí, l'enllaç queda trencat (*dangling link*).

Comandes d'inspecció d'Inodes a la terminal:
```bash
# Veure el número d'inode dels fitxers
ls -li

# Informació forense completa d'un Inode
stat document.pdf
```

## 🪟 La Taula MFT (Master File Table) en Windows NTFS

El sistema de fitxers **NTFS** (*New Technology File System*) utilitzat per Windows estructura tota la partició al voltant d'una base de dades relacional anomenada **MFT** (*Master File Table*).

La MFT és un fitxer especial ocult (`$MFT`) format per registres de mida fixa d'exactament **1.024 bytes (1 KiB)**. Cada fitxer o directori del disc té associat un registre dins de la MFT:

```
                      REGISTRE DE LA TAULA MFT (1.024 BYTES)
  ┌─────────────────────────────────────────────────────────────────────────────┐
  │ ENCAPÇALAMENT DEL REGISTRE MFT (Número de seqüència, estat actiu/inactiu)   │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ ATRIBUT $STANDARD_INFORMATION: Marques de temps (creació, canvi), atributs   │
  │                                de fitxer (només lectura, ocult, sistema).   │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ ATRIBUT $FILE_NAME: Nom del fitxer (suport complet Unicode UTF-16).         │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ ATRIBUT $DATA: Dades reals del fitxer                                       │
  │                                                                             │
  │ Cas A (Fitxer Resident <= 700 bytes):                                       │
  │   El contingut del fitxer es guarda DIRECTAMENT DINS de la MFT!             │
  │   No cal gastar cap clúster del disc (accés instantani ultra-ràpid).        │
  │                                                                             │
  │ Cas B (Fitxer No Resident > 700 bytes):                                     │
  │   Conté una llista de punters ('Data Runs') cap als clústers del disc.      │
  └─────────────────────────────────────────────────────────────────────────────┘
```

### Funcions Avançades Nativament Suportades per NTFS:
1. **Registre de Transaccions (Journaling):** Guarda un registre de tots els canvis pendents en el fitxer `$LogFile`. Si l'ordinador pateix una fallada de corrent elèctric sobtada, durant l'arrencada el sistema recupera la consistència en segons sense haver de fer una comprovació completa del disc (*chkdsk*).
2. **Llistes de Control d'Accés (ACL):** Seguretat d'usuaris a nivell d'arxiu o carpeta amb permisos detallats (Lectura, Escriptura, Modificació, Control Total).
3. **Compressió Nativa i Xifratge EFS:** Permet comprimir carpetes al vol o xifrar fitxers confidencials amb claus públiques d'usuari.
4. **Fitxers Residents:** Els arxius molt xicotets no malgasten clústers de disc.

## 📊 Taula Comparativa de Sistemes de Fitxers Monolloc

| Sistema de Fitxers | Desenvolupador / SO | Mida Màxima de Fitxer | Mida Màxima de Volum | Journaling | Ús Professional Típic |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **FAT32** | Microsoft (1996) | **4 GiB** (límit rígid) | 2 TB (o 16 TB teòrics) | No | Dispositius antics, memòries USB petites, partició UEFI ESP. |
| **exFAT** | Microsoft (2006) | **16 EiB** | **128 PiB** | No | **El millor format per a llapis USB i discs externs compartits entre Windows, Linux i Mac.** |
| **NTFS** | Microsoft (1993) | **16 TiB** | **8 PiB** | **Sí** | Partició del sistema de **Windows 10 / 11**. |
| **ext4** | Comunitat Linux (2008) | **16 TiB** | **1 EiB** | **Sí** | Partició principal de la gran majoria de distribucions **GNU/Linux**. |
| **Btrfs** | Oracle / Linux | **16 EiB** | **16 EiB** | Copy-on-Write (CoW) | Distribucions modernes (Fedora, openSUSE) amb suport de snapshots natius. |
