Una de les tasques més crítiques del sistema operatiu és la **gestió de processos**. Cada vegada que fas doble clic en una icona d'escriptori o executes una ordre en una terminal, es posa en marxa una estructura viva que competeix amb centenars d'altres tasques per obtindre cicles de processador i memòria.

---

## 🆚 Programa vs Procés: La Diferència Fonamental

Sovint s'utilitzen com a sinònims en el llenguatge col·loquial, però en ciències de la computació són conceptes radicalment diferents:

```
  ┌─────────────────────────────────────┬─────────────────────────────────────┐
  │         PROGRAMA (Entitat Passiva)  │         PROCÉS (Entitat Activa)     │
  ├─────────────────────────────────────┼─────────────────────────────────────┤
  │ Un conjunt d'instruccions en codi   │ Un programa carregat en memòria RAM │
  │ màquina desat al disc d'emmagat-    │ en ple estat d'execució, amb el seu │
  │ zematge secundari (fitxer `.exe` en │ propi espai d'adreces, registres de │
  │ Windows o binari ELF en Linux).     │ CPU, pila (stack) i recursos d'E/S. │
  │                                     │                                     │
  │ Exemple: `/usr/bin/firefox` al disc │ Exemple: 3 instàncies actives de    │
  │ (ocupa espai de disc, però no gasta │ Firefox consumint 850 MB de RAM i   │
  │ CPU ni memòria RAM).                │ 12% de processador.                 │
  └─────────────────────────────────────┴─────────────────────────────────────┘
```

Un mateix programa pot donar lloc a múltiples processos diferents executant-se de manera simultània i independent.

## 🔄 Cicle de Vida i Diagrama d'Estats d'un Procés

Al llarg de la seua existència, un procés passa per diversos estats gestionats pel nucli del sistema operatiu:

```
                            DIAGRAMA D'ESTATS D'UN PROCÉS
                                  ┌───────────────┐
                                  │      NOU      │
                                  │  (Admissió)   │
                                  └───────┬───────┘
                                          │
                                          ▼
                                  ┌───────────────┐
                   ┌─────────────►│   PREPARAT    │◄──────────────┐
                   │              │    (Ready)    │               │
                   │              └───────┬───────┘               │
                   │ Temporitzador        │ Planificador          │ Fi d'E/S o
                   │ (Fi de Quàntum)      │ (Assigna CPU)         │ Esdeveniment
                   │                      ▼                       │
                   │              ┌───────────────┐               │
                   └──────────────┤  EN EXECUCIÓ  │               │
                                  │   (Running)   │               │
                                  └───────┬───────┘               │
                                          │                       │
                                          │ Sol·licita E/S        │
                                          │ o bloqueig            │
                                          ▼                       │
                                  ┌───────────────┐               │
                                  │   BLOQUEJAT   │───────────────┘
                                  │   (Waiting)   │
                                  └───────────────┘
                                          │
                                          │ Finalització (exit)
                                          ▼
                                  ┌───────────────┐
                                  │   TERMINAT    │
                                  │ (Zombie/Exit) │
                                  └───────────────┘
```

1. **Nou (New):** El procés s'està creant a la memòria a partir del fitxer binari de disc.
2. **Preparat (Ready):** El procés té tot el que necessita a la memòria RAM per funcionar, però està esperant que la CPU quede lliure en la cua de planificació.
3. **En execució (Running):** La CPU està executant activament les instruccions d'aquest procés en aquest instant precís.
4. **Bloquejat o en espera (Waiting / Blocked):** El procés no pot continuar encara que la CPU estiga completament lliure, perquè està esperant una operació externa lenta (per exemple, que l'usuari prema una tecla, que arribe un paquet de xarxa o que el disc NVMe acabe de llegir un sector).
5. **Terminat (Terminated):** El procés ha completat la seua execució o ha estat avortat. Allibera la seua memòria, però manté el seu codi de sortida a la taula de processos fins que el procés pare el recull (fase *Zombie*).

## 📋 El Bloc de Control de Procés (PCB - Process Control Block)

Perquè el sistema operatiu puga suspendre un procés en execució, donar torn a un altre i reprendre el primer exactament on s'havia quedat sense perdre cap dada, el nucli manté una fitxa tècnica a la memòria anomenada **PCB** (*Process Control Block* o `task_struct` en Linux):

```
                        ESTRUCTURA DEL PCB A LA MEMÒRIA DEL NUCLI
  ┌─────────────────────────────────────────────────────────────────────────────┐
  │ IDENTIFICACIÓ: PID (Process ID: 4102), PPID (Parent ID: 1045), UID/GID      │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ ESTAT ACTUAL: Preparat (Ready), En Execució (Running), Bloquejat (Waiting)  │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ COMPTADOR DE PROGRAMA (PC): Adreça de la següent instrucció a executar      │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ REGISTRES DE LA CPU: Còpia exacta de RAX, RBX, RCX, RDX, RBP, RSP (Pila)    │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ GESTIÓ DE MEMÒRIA: Punter a la Taula de Pàgines virtuals (registre CR3)    │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ INFORMACIÓ DE PLANIFICACIÓ: Prioritat dinàmica, valor 'nice' (-20 a 19)    │
  ├─────────────────────────────────────────────────────────────────────────────┤
  │ TAULA D'ARXIUS OBERTS: Descriptors de fitxer actius (stdin=0, stdout=1...) │
  └─────────────────────────────────────────────────────────────────────────────┘
```

Quan ocorre un **canvi de context** (*Context Switch*), la CPU desa ràpidament tots els valors dels seus xips al PCB del procés que ix i carrega els valors desats al PCB del procés nou entrant. Aquesta operació es produeix centenars de vegades cada segon.

---

## 🧵 Processos vs Fils d'Execució (*Threads*)

Un **fil d'execució** (*Thread* o procés lleuger) és la unitat bàsica més xicoteta a la qual un sistema operatiu pot assignar temps de CPU:

* **Procés pesant:** Té el seu propi espai de memòria virtual completament aïllat. La comunicació entre dos processos diferents (IPC) requereix crides al sistema lentes.
* **Fils d'un mateix procés:**
  - Comparteixen el mateix espai d'adreces de memòria, les mateixes variables globals i els mateixos fitxers oberts.
  - Cada fil té el seu propi comptador de programa (*PC*), el seu joc de registres i la seua pròpia **pila** (*stack*).
  - Un navegador modern executa un fil per a la interfície d'usuari, un altre fil per descodificar el vídeo de YouTube i un tercer fil per carregar la descàrrega en segon pla; tot dins del mateix procés sense bloquejar la finestra.

## 💻 Inspecció i Control de Processos per Consola

### En GNU/Linux (Bash):
```bash
# Llistar tots els processos detallats amb el seu PID i consum de CPU/RAM
ps aux

# Veure l'arbre jeràrquic de processos pare-fill (PPID -> PID)
pstree -p

# Monitor en temps real interactiu
top   # o 'htop' si està instal·lat

# Finalitzar un procés rebel pel seu PID enviant el senyal SIGTERM (15) o SIGKILL (9)
kill -15 4102   # Tancament net i ordenat
kill -9 4102    # Tancament forçós immediat pel nucli
```

### En Microsoft Windows (PowerShell):
```powershell
# Llistar els 10 processos que més CPU consumeixen
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10 Id, ProcessName, CPU, WorkingSet

# Finalitzar un procés bloquejat pel seu identificador (PID)
Stop-Process -Id 4102 -Force
```
