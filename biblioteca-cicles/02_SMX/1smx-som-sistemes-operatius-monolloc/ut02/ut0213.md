# 2.13 Sistemes Transaccionals i Sistemes de Fitxers amb Journaling

Un tall sobtat de corrent elèctric o un bloqueig del sistema mentre s'està escrivint informació a disc pot deixar el sistema de fitxers en un estat d'incoherència greu (per exemple, un fitxer que s'ha marcat com a creat al directori però que no té els blocs de dades assignats a l'espai lliure). Els sistemes moderns solucionen aquest problema mitjançant el **Journaling** (registre per diari transaccional).

---

## 📖 El Mecanisme de Journaling

El *journaling* funciona de manera anàloga a una transacció bancària:

```
[1. Preparació]        El SO rep la petició d'escriure o modificar un fitxer.
       │
       ▼
[2. Diari / Journal]   El SO registra l'operació planejada en una zona especial de disc (el diari).
       │
       ▼
[3. Commit al Diari]   Es marca al diari que la transacció és completa i atòmica.
       │
       ▼
[4. Escriptura Real]   S'actualitzen les estructures definitives del sistema de fitxers (inodos / dades).
       │
       ▼
[5. Alliberament]      S'esborra la transacció del diari (checkpointing).
```

### ⚡ Què passa si s'apaga l'ordinador durant l'escriptura?
- **Amb sistemes antics (FAT32, ext2 sense diari):**
  A l'arrencada cal analitzar tot el disc complet bloc a bloc per detectar inconsistències, un procés lent que pot trigar hores en discos de gran capacitat.
- **Amb sistemes amb Journaling (ext4, NTFS, XFS):**
  A l'arrencada, el sistema només llegeix el xicotet fitxer de diari:
  - Si la transacció estava a mitges (abans del *commit*), es descarta completament (*rollback*).
  - Si la transacció estava confirmada però no s'havia plasmat a disc, s'aplica immediatament (*replay*). El sistema es recupera en pocs segons!

## 🛠️ Eines de Comprovació i Reparació d'Integritat

| Sistema Operatiu | Comandament | Ús habitual |
| :--- | :--- | :--- |
| **Microsoft Windows** | `chkdsk C: /f /r` | Analitza el volum NTFS, repara errors lògics (`/f`) i localitza sectors defectuosos intentant recuperar dades (`/r`). Requereix reiniciar el sistema per a desmuntar el volum `C:`. |
| **GNU/Linux** | `fsck -y /dev/sdb1` | Comprova el sistema de fitxers ext4 (`File System Consistency Check`). **Compte:** Mai s'ha d'executar `fsck` sobre una partició que estiga muntada en mode lectura/escriptura, ja que podria corrompre les dades. |
