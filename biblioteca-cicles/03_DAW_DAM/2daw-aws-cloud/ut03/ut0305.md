## El Dilema de l'Administració en Subxarxes Privades

Com s'administra un servidor Linux que conté dades crítiques i està ubicat a una subxarxa privada sense adreça IP pública ni ruta cap a l'Internet Gateway?

Exposar el port SSH (22) o RDP (3389) a Internet públic suposa sotmetre el servidor a milers d'intents d'atac de força bruta automatitzats diàriament. Per resoldre aquest repte s'utilitzen dues arquitectures clau:

---

## 1. El Host Bastió (*Bastion Host / Jump Box*)

Un **Host Bastió** és una instància EC2 especialment endurida (*hardened*) que es col·loca a la **subxarxa pública**:
- **Té IP pública:** És l'únic servidor que admet connexions SSH des de l'exterior.
- **Accés restringit:** El seu Security Group només permet el port 22 des de la IP pública estàtica de l'oficina o casa de l'administrador (`la.teua.ip/32`), mai des de tot Internet (`0.0.0.0/0`).
- **Mecanisme de salt (*Jump*):** L'administrador es connecta primer al Bastió per SSH, i des d'aquest bastió obre una segona sessió SSH cap a la IP privada interna del servidor de la subxarxa privada.
- **Agent Forwarding:** Tècnica d'SSH que permet utilitzar la clau privada local de l'administrador per saltar al segon servidor sense haver de deixar mai la clau privada desada físicament al Bastió.

---

## 2. L'Alternativa Moderna: AWS Systems Manager (SSM) Session Manager

L'ús de Hosts Bastió, tot i ser un clàssic, presenta desavantatges: costa diners mantenir el bastió encès, cal gestionar claus SSH i cal tenir un port obert a Internet.

L'arquitectura moderna recomanada per AWS és **AWS Systems Manager Session Manager**:
- **Sense ports oberts:** Permet obrir una terminal Bash interactiva al navegador o a l'AWS CLI **sense necessitat d'obrir el port 22 SSH** ni tenir adreça IP pública a cap instància!
- **Com funciona?** La instància EC2 executa un agent petit (`amazon-ssm-agent`) que es comunica cap a fora amb l'API d'AWS mitjançant HTTPS (port 443).
- **Seguretat IAM:** L'accés no es controla amb claus `.pem` privades, sinó amb les credencials corporatives d'IAM.
- **Auditoria total:** Totes les comandes que l'administrador tecleja a la consola es poden enregistrar i guardar en un fitxer de registre xifrat a Amazon S3 o CloudWatch Logs.
