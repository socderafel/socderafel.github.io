## Subxarxes i Zones de Disponibilitat

Mentre que una VPC s'estén per tota una regió, **cada subxarxa individual ha d'estar assignada estrictament a una única Zona de Disponibilitat (AZ)**.
- Una subxarxa mai pot travessar múltiples AZs.
- Per a aconseguir alta disponibilitat (*Multi-AZ*), cal crear com a mínim dues subxarxes bessones en dues AZs diferents.

---

## Arquitectura de Dues Capes: Subxarxes Públiques vs Privades

En desenvolupament d'aplicacions web, la millor pràctica d'enginyeria és la segmentació de seguretat en múltiples capes (*multi-tier architecture*):

```
+---------------------------------------------------------------------------------+
|                                 AMAZON VPC                                      |
|                                                                                 |
|   +------------------------------------+   +------------------------------------+
|   |         ZONA DE DISP. A (AZ-a)     |   |         ZONA DE DISP. B (AZ-b)     |
|   |                                    |   |                                    |
|   |  [ Subxarxa Pública 10.0.1.0/24 ]  |   |  [ Subxarxa Pública 10.0.2.0/24 ]  |
|   |   - Balancejador de Càrrega (ALB)  |   |   - Balancejador de Càrrega (ALB)  |
|   |   - Servidors Web Frontend         |   |   - Servidors Web Frontend         |
|   |   - RUTA DIRECTA A L'IGW           |   |   - RUTA DIRECTA A L'IGW           |
|   +------------------------------------+   +------------------------------------+
|                      |                                        |                 |
|   +------------------------------------+   +------------------------------------+
|   |  [ Subxarxa Privada 10.0.11.0/24 ] |   |  [ Subxarxa Privada 10.0.12.0/24 ] |
|   |   - Servidors d'Aplicacions Backend|   |   - Servidors d'Aplicacions Backend|
|   |   - Base de Dades MySQL (Primària) |   |   - Base de Dades MySQL (Rèplica)  |
|   |   - SENSE ACCÉS DIRECTE DES D'EXT. |   |   - SENSE ACCÉS DIRECTE DES D'EXT. |
|   +------------------------------------+   +------------------------------------+
+---------------------------------------------------------------------------------+
```

## Què fa que una Subxarxa siga «Pública» o «Privada»?

En AWS, no hi ha cap casella que diga "aquesta subxarxa és pública". La diferència depèn exclusivament de la seua **Taula d'Encaminament (*Route Table*)**:

| Tipus de Subxarxa | Taula d'Encaminament Associada | IP Pública de les Instàncies | Ús Recomanat |
| :--- | :--- | :--- | :--- |
| **Subxarxa Pública** | Té una ruta explícita `0.0.0.0/0` apuntant directament cap a un **Internet Gateway (IGW)**. | Sí, les instàncies reben una adreça IPv4 pública accessible des d'Internet. | Balancejadors de càrrega elàstics (ALB), servidors web perimetrals, servidors Bastió. |
| **Subxarxa Privada** | **NO** té ruta cap a l'Internet Gateway (apunta a un dispositiu NAT o només té la ruta local `10.0.0.0/16 local`). | No reben mai IPv4 pública; només tenen adreça IP privada. Són invisibles a Internet. | Bases de dades (Amazon RDS), servidors d'aplicació backend, sistemes de pagament. |
