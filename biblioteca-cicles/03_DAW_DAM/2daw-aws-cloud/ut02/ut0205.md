## Necessitat de l'Arquitectura Multicompte

A mesura que una empresa creix, utilitzar un únic compte d'AWS per a totes les tasques esdevé un greu perill:
- Un error d'un programador en proves podria esborrar la base de dades de producció.
- La facturació es barreja i costa saber quant gasta cada departament.
- La superfície d'atac és massiva.

La solució professional recomanada per AWS és utilitzar una **estratègia de múltiples comptes**: un compte per a *Desenvolupament*, un per a *Staging/Preproducció*, un per a *Producció* i un altre per a *Auditories i Seguretat*.

---

## AWS Organizations i Jerarquia d'Unitats Organitzatives (OU)

**AWS Organizations** és un servei de gestió de comptes que permet consolidar múltiples comptes sota una estructura centralitzada:

```
               +--------------------------------------+
               |        Compte de Gestió (Root)       |
               +--------------------------------------+
                                  |
                +-----------------+-----------------+
                |                                   |
    +-----------------------+           +-----------------------+
    |  OU_Desenvolupament   |           |     OU_Produccio      |
    +-----------------------+           +-----------------------+
        |               |                   |               |
+---------------+---------------+   +---------------+---------------+
| Compte Dev 1  | Compte Dev 2  |   | Compte Prod 1 | Compte Prod 2 |
+---------------+---------------+   +---------------+---------------+
```

### Beneficis Clau d'AWS Organizations
1. **Facturació Consolidada (*Consolidated Billing*):** Es rep una única factura mensual amb tots els costos unificats i es comparteixen descomptes per volum de dades entre tots els comptes.
2. **Aprovisionament automatitzat:** Possibilitat de crear nous comptes en segons mitjançant APIs.
3. **Control centralitzat de permisos:** Aplicació de regles globals a nivell d'empresa.

---

## Polítiques de Control de Serveis (SCP - *Service Control Policies*)

Les **SCP** són barreres de contenció (*guardrails*) que estableixen els **permisos màxims que els comptes d'una OU poden exercir**:
- Una SCP mai concedeix permisos per si mateixa; actua com un filtre superior o sostre de seguretat.
- Fins i tot si un administrador té `AdministratorAccess` dins d'un compte de desenvolupament, si una SCP bloqueja una acció a nivell d'Organització, l'administrador NO podrà executar-la!

Exemple pràctic de SCP:
- **Prohibir l'ús de regions fora d'Europa:** Garanteix el compliment legal del RGPD impedint que ningú pugui crear servidors als EUA o Àsia per error.
- **Impedir la desactivació de registres:** Evita que qualsevol usuari pugui aturar el servei d'auditoria AWS CloudTrail.
