## Fonaments d'AWS Identity and Access Management (IAM)

**AWS IAM** és el servei global gratuït que controla l'autenticació (*qui ets*) i l'autorització (*què pots fer*) sobre tots els recursos del teu compte d'AWS.

```
+-----------------------------------------------------------------+
|                    COMPONENTS PRINCIPALS D'IAM                  |
+-------------------+--------------------+------------------------+
|   Usuari IAM      |     Grup IAM       |        Rol IAM         |
|                   |                    |                        |
| - Identitat       | - Col·lecció       | - Identitat assumible  |
|   humana o servei |   d'usuaris        |   sense credencials    |
| - Contrasenya     | - Simplifica       |   permanents           |
|   de consola      |   l'assignació de  | - Per a instàncies EC2,|
| - Access Keys     |   polítiques de    |   Lambdas o usuaris    |
|   per a la CLI    |   seguretat        |   federats             |
+-------------------+--------------------+------------------------+
```

---

## 1. Usuaris IAM (*IAM Users*)
- Representen una persona física (per exemple: `joan.garcia`) o una aplicació externa que interactua amb AWS.
- **Tipus d'accés:**
  - **Accés a la Consola de Gestió d'AWS:** Requereix nom d'usuari, contrasenya i codi MFA obligatori.
  - **Accés Programàtic (CLI / SDK / API):** Utilitza un parell de claus d'accés: **Access Key ID** (clau pública) i **Secret Access Key** (contrasenya privada d'accés). Mai s'han de pujar claus secretes a repositoris GitHub públics!

---

## 2. Grups IAM (*IAM Groups*)
- Una agrupació lògica d'usuaris que comparteixen les mateixes responsabilitats professionals (per exemple: `Grup_Administradors`, `Grup_Desenvolupadors_Frontend`, `Grup_Auditoria_Seguretat`).
- **Important:** Un grup només conté usuaris; no pot contenir altres grups (no admet aniuament).
- L'assignació de permisos s'ha de fer sempre al **grup**, mai a usuaris individuals, seguint les bones pràctiques d'enginyeria.

---

## 3. Rols IAM (*IAM Roles*)
A diferència d'un usuari, un rol no té credencials estàtiques permanents (ni contrasenya ni claus d'accés fixes). Està dissenyat per a ser **assumit temporalment** per qualsevol entitat que ho necessiti:
- **Serveis d'AWS:** Una instància EC2 necessita escriure fitxers a un bucket S3. S'assigna un Rol IAM a la instància (*Instance Profile*) i l'SDK d'AWS rep automàticament claus temporals que roten cada poques hores sense que el programador haja d'escriure cap credencial al codi!
- **Accés entre comptes (*Cross-Account Access*):** Permet a un administrador del compte de Desenvolupament assumir temporalment un rol al compte de Producció per auditar una incidència.
- **Federació d'identitats:** Treballadors que inicien sessió amb el seu compte de Google Workspace o Active Directory corporatiu.
