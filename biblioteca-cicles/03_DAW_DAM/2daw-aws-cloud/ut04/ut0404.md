## Autenticació Asimètrica mitjançant Parells de Claus (*Key Pairs*)

A diferència dels servidors locals on se sol utilitzar un usuari i contrasenya per entrar, **a les instàncies Linux d'AWS l'autenticació per contrasenya està desactivada per defecte per raons de seguretat**.
S'utilitza criptografia de clau pública:
- **Clau pública:** AWS la injecta automàticament dins del fitxer `~/.ssh/authorized_keys` de l'usuari predeterminat del sistema (com `ec2-user` o `ubuntu`) durant el primer llançament.
- **Clau privada (`.pem`):** L'usuari la descarrega un sol cop en crear-la a la consola d'AWS i l'ha de custodiar de forma ultra segura al seu equip local. AWS no guarda mai una còpia de la clau privada!

### Ajust Obligatori de Permisos en Linux / macOS:
El client OpenSSH rebutjarà immediatament connectar-se si el fitxer de clau privada té permisos massa oberts (com 777 o 644):
```bash
# Donar permís de lectura exclusiu al propietari (error: Permissions 0644 are too open!)
chmod 400 el-meu-parell-de-claus.pem

# Connexió SSH al servidor
ssh -i el-meu-parell-de-claus.pem ubuntu@54.216.45.12
```

## El Servei de Metadades d'Instància (IMDS)

Tota instància EC2 té accés a una adreça IP interna especial de xarxa enllaç-local (*link-local*): **`http://169.254.169.254/latest/meta-data/`**.
Aquesta adreça no passa per Internet i permet a la instància consultar informació sobre ella mateixa: la seua adreça IP privada, la seua IP pública, el seu ID d'instància, la regió i, especialment, **les credencials temporals del seu Rol IAM**.

### La Revolució de Seguretat d'IMDSv2
- **Vulnerabilitat d'IMDSv1:** Qualsevol petició simple HTTP `GET` obtenia les dades. Si l'aplicació web patia una vulnerabilitat de falsificació de peticions del costat del servidor (SSRF), un atacant podia enganyar el servidor web perquè fes un GET a `169.254.169.254` i robar les claus temporals de seguretat d'AWS!
- **Protecció d'IMDSv2:** Requereix una petició orientada a sessió en dos passos mitjançant un token temporal amb el mètode `PUT`:

```bash
# Pas 1: Obtenir un token de sessió de 6 hores (21600 segons)
TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")

# Pas 2: Utilitzar el token a la capçalera per llegir les metadades
curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id
```
