Per a provar exhaustivament funcions amb desenes de combinacions de dades (com l'algoritme de validació d'un DNI o d'un correu electrònic), escriure 20 mètodes `@Test` pràcticament idèntics és ineficient i genera codi duplicat. La solució professional són les **proves parametritzades**. A més, per saber quin percentatge del nostre codi ha sigut realment avaluat pels tests, s'utilitzen eines d'anàlisi de **cobertura de codi (*Code Coverage*)**.

---

## 🎯 Proves Parametritzades (`@ParameterizedTest`)

Permeten executar el mateix mètode de prova múltiples vegades injectant valors d'un joc de dades:

```java
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;
import org.junit.jupiter.params.provider.ValueSource;
import static org.junit.jupiter.api.Assertions.*;

class ValidadorTest {

    // Proveïdor simple de valors:
    @ParameterizedTest
    @ValueSource(strings = {"654112233", "677889900", "962881100"})
    void testTelefonsValids(String telefon) {
        assertTrue(Validador.esTelefonValid(telefon));
    }

    // Proveïdor múltiple CSV (entrada1, entrada2, resultat esperat):
    @ParameterizedTest(name = "Test {index}: {0} + {1} = {2}")
    @CsvSource({
        "1,   1,   2",
        "5,   3,   8",
        "-2,  5,   3",
        "0,   0,   0"
    })
    void testSumesMultiples(int n1, int n2, int esperat) {
        assertEquals(esperat, Calculadora.sumar(n1, n2));
    }
}
```

## 📊 Cobertura de Codi (*Code Coverage*) i JaCoCo

La **cobertura de codi** és una mètrica percentual que reflecteix quina proporció de sentències, branques i mètodes de l'aplicació s'han executat durant la bateria de proves.

### Eines i Integració
- **JaCoCo (Java Code Coverage):** El plugin estàndard en Maven i Gradle.
- Genera un informe visual en HTML amb colors:
  - 🟢 **Verd:** Línia de codi totalment coberta per tests.
  - 🟡 **Groc:** Branca parcialment coberta (ex: es va provar el `true` d'un `if`, però mai el `false`).
  - 🔴 **Vermell:** Línia de codi mai executada pels tests.

---

## 🏗️ El Patró AAA (Arrange, Act, Assert)

Tota bona prova unitària ha d'estructurar-se en tres blocs clarament diferenciats:
1. **Arrange (Preparar):** Instanciar objectes, inicialitzar variables i preparar l'estat.
2. **Act (Actuar):** Executar el mètode concret que volem provar.
3. **Assert (Verificar):** Comprovar mitjançant assercions que el resultat és exactament l'esperat.
