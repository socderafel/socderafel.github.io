El **provar programari (*Software Testing*)** és el procés d'executar un programa amb la intenció explícita de trobar defectes. Lluny de ser una tasca d'última hora abans d'entregar, el *testing* professional és una disciplina metòdica que acompanya tot el cicle de vida.

---

## ⚠️ La Distinció Clau: Error vs. Defecte vs. Fallada

Segons l'estàndard IEEE 610.12 i el glossari oficial ISTQB:

```
┌────────────────────────────────────────────────────────┐
│  ERROR HUMÀ (Mistake / Error)                          │
│  Una acció humana equivocada comesa per un analista o  │
│  programador (ex: un malentès d'un requeriment o una   │
│  badada de càlcul mental).                             │
└───────────────────────────┬────────────────────────────┘
                            ▼
┌────────────────────────────────────────────────────────┐
│  DEFECTE / FALTA (Defect / Bug)                        │
│  La manifestació de l'error introduïda físicament en   │
│  el codi font o documentació (ex: un '<' erroni).      │
└───────────────────────────┬────────────────────────────┘
                            ▼
┌────────────────────────────────────────────────────────┐
│  FALLADA (Failure)                                     │
│  La desviació observable en temps d'execució entre el  │
│  comportament real del programa i el comportament      │
│  esperat pel client (ex: el caixer no dóna els diners).│
└────────────────────────────────────────────────────────┘
```

> **IMPORTANT:** Un defecte pot romandre latent al codi durant anys sense provocar mai cap fallada, fins que un usuari introdueix la combinació de dades precisa que activa eixa línia de codi defectuosa.

---

## 🪜 Els Quatre Nivells de Prova

1. **Proves Unitàries (*Unit Testing*):** Verifiquen la unitat mínima de codi aïllada (un mètode, una funció o una classe individual). Són automatitzades pels propis desenvolupadors amb eines com JUnit.
2. **Proves d'Integració (*Integration Testing*):** Verifiquen que múltiples mòduls, serveis o capes (com la connexió entre la lògica de negoci i la base de dades PostgreSQL) funcionen coordinadament sense errors d'interfície.
3. **Proves de Sistema (*System Testing*):** Verifiquen el sistema complet integrat en un entorn el més semblant possible al de producció, incloent proves no funcionals (rendiment, càrrega, seguretat).
4. **Proves d'Acceptació (*Acceptance Testing*):** Executades directament pel client o usuaris finals (proves Alfa a l'empresa desenvolupadora, proves Beta en entorn real) per validar si el producte compleix les expectatives del negoci abans del pagament final.
