Les **Eines CASE (*Computer-Aided Software Engineering*)** són aplicacions informàtiques dissenyades per a donar suport automatitzat a qualsevol de les activitats del cicle de vida del desenvolupament de programari. Permeten als equips d'enginyeria reduir tasques manuals tedioses, transformar automàticament models de disseny UML en codi executable (**Enginyeria Directa**) i reconstruir l'arquitectura de projectes heretats a partir del codi font existent (**Enginyeria Inversa**), assolint la sincronització bidireccional contínua (**Round-Trip**).

---

## 15.1 Concepte i Classificació de les Eines CASE

L'objectiu principal d'una eina CASE és augmentar la productivitat, millorar la qualitat del programari i garantir que la documentació tècnica es manté coherent amb el codi real.

### Classificació segons la fase del cicle de vida:
1. **Upper CASE (CASE Superior / Front-End):**
   - Donen suport a les primeres etapes del cicle de vida: captura de requisits, anàlisi del sistema i disseny conceptual de l'arquitectura.
   - Funcionalitats: Editors de diagrames UML (classes, casos d'ús, seqüència), diagrames entitat-relació (ER) de bases de dades i diccionaris de dades.
   - Exemples: **Visual Paradigm**, **StarUML**, **Modelio**, **Draw.io**.
2. **Lower CASE (CASE Inferior / Back-End):**
   - Donen suport a les etapes finals: codificació, compilació, proves automatitzades i manteniment.
   - Funcionalitats: Generadors automàtics de codi font, entorns integrats de desenvolupament (IDEs), depuradors i suites de proves com JUnit.
3. **Integrated CASE (I-CASE / CASE Integrat):**
   - Plataformes que integren eines Upper i Lower sota un repositori comú de metadades, cobrint tot el cicle de vida des de l'anàlisi de requisits fins al desplegament en producció.

---

## 15.2 Enginyeria Directa (*Forward Engineering*)

L'**enginyeria directa** és el procés automàtic de traduir un model gràfic d'alt nivell d'abstracció (com un diagrama de classes UML) en l'esquelet de codi font d'un llenguatge de programació específic (Java, C++, C#, Python).

### Com transforma l'eina CASE el model UML a Java:
1. Cada rectangle del diagrama es converteix en un fitxer `.java`.
2. Els atributs privats amb tipus es tradueixen a camps `private` amb els seus mètodes d'accés *getters* i *setters*.
3. Les relacions d'herència (`◁───`) afegeixen la clàusula `extends NomSuperclasse`.
4. Les realitzacions d'interfície (`◁····`) afegeixen `implements NomInterficie`.
5. Les associacions amb multiplicitat `0..*` o `1..*` es converteixen automàticament en col·leccions:
   ```java
   private java.util.List<LiniaComanda> linies = new java.util.ArrayList<>();
   ```

---

## 15.3 Enginyeria Inversa (*Reverse Engineering*)

L'**enginyeria inversa** és el procés oposat: pren un programa ja existent (codi font `.java`, arxius `.class` compilats o esquemes SQL) i n'extreu automàticament una representació a un nivell d'abstracció superior (diagrames UML de classes o de paquets).

### Quan s'utilitza l'enginyeria inversa?
- **Auditoria de programari heretat (*Legacy Code*):** Quan s'arriba a una empresa amb milers de línies de codi antic sense cap documentació o amb documentació desactualitzada.
- **Avaluació de l'arquitectura real:** Per a comprovar si els programadors estan respectant el disseny original o han creat dependències circulars ocultes.
- **Incorporació de nous membres a l'equip:** Permet als nous desenvolupadors visualitzar l'esquelet del sistema en minuts en lloc de llegir milers de línies de fitxers.

> [!NOTE]
> L'enginyeria inversa pot extreure fàcilment relacions d'herència i associacions entre classes analitzant les variables del codi font. No obstant això, **no pot distingir amb total certesa entre agregació i composició**, ja que la propietat semàntica de destrucció coincident depèn de la lògica dinàmica de l'aplicació.

---

## 15.4 Enginyeria d'Anada i Tornada (*Round-Trip Engineering*)

La **sincronització Round-Trip** és la combinació perfecta d'enginyeria directa i inversa treballant en temps real:
- Si un arquitecte modifica una classe al diagrama UML afegint un nou atribut o canviant una relació, l'eina CASE actualitza automàticament el fitxer Java a l'IDE.
- Si un programador afig un nou mètode directament a l'editor de Java, l'eina CASE reflecteix el nou mètode al diagrama UML de forma instantània.
Açò resol definitivament el problema històric de la documentació que queda obsoleta en quant el codi comença a evolucionar.

## 📝 Quadern d'Activitats Pràctiques i Reptes de Laboratori

### Bloc A: Fonaments, Dimensionament i Anàlisi de Rendiment

#### Exercici 1: Anàlisi de Traducció en Enginyeria Directa
Observa el següent diagrama de classes UML descrit textualment:
- Interfície `Imprimible` amb l'operació `+ imprimir() : void`.
- Classe abstracta `Document` amb atribut `- id : int` i mètode abstracte `+ getMida() : int`.
- Classe `Informe` que hereta de `Document` i implementa `Imprimible`. Conté una associació de composició `1` a `1..*` amb `Pagina`.

1. Escriu l'esquelet complet de codi Java que generarà una eina CASE per a la classe `Informe.java`.
2. Com ha traduït l'eina la relació de composició cap a `Pagina`? Quin tipus de col·lecció s'ha creat?

#### Exercici 2: Limitacions de l'Enginyeria Inversa sobre codi compilat
Una empresa ha perdut el codi font original d'un mòdul i només disposa dels fitxers binaris `.class`.
S'utilitza una eina d'enginyeria inversa per a reconstruir el model UML:
1. Podrà l'eina recuperar els noms de les classes, mètodes i tipus de dades dels atributs?
2. Podrà recuperar els comentaris de l'autor o les explicacions narratives que hi havia al codi font original? Per què?
3. Podrà determinar si un enllaç entre dues classes és una agregació o una simple associació? Justifica la resposta.

#### Exercici 3: Càlcul d'estalvi de temps en generació automàtica
En un projecte empresarial de $80\text{ classes}$:
- Un programador triga una mitjana de $18\text{ minuts}$ per classe en escriure a mà la definició, imports, atributs, constructors buits, getters, setters i col·leccions d'associació.
- Una eina CASE genera els 80 fitxers d'esquelet a partir del model UML en només $15\text{ segons}$.
1. Calcula les hores totals de treball manual que requeriria codificar els esquelets a mà.
2. Quant de temps humà net s'estalvia l'equip de desenvolupament utilitzant enginyeria directa?

### Bloc B: Reptes Pràctics de Laboratori i Taller / Comandes

#### Repte 1: Enginyeria Directa amb una Eina CASE (Model -> Codi)
- **Objectiu:** Dibuixar un model de dades i generar l'esquelet de classes Java automàticament.
- **Procediment de taller:**
  1. Obre una eina CASE (Visual Paradigm Community, StarUML o el complement PlantUML/Mermaid a l'IDE).
  2. Dissenya un model amb 3 classes: `Client`, `Compte` i `Moviment`.
  3. Estableix una associació $1 \rightarrow *$ entre `Client` i `Compte`, i una composició $1 \rightarrow *$ entre `Compte` i `Moviment`.
  4. Executa l'assistent de **Generació de Codi Java (*Generate Code*)**.
  5. Inspecciona els fitxers Java generats i comprova que l'encapsulament i els mètodes s'han creat correctament.

#### Repte 2: Enginyeria Inversa a l'IDE (Codi -> Model UML)
- **Objectiu:** Extreure el diagrama de classes d'un paquet Java existent sense dibuixar cap línia manual.
- **Procediment de taller:**
  1. Obre un projecte Java amb múltiples classes a IntelliJ IDEA o Eclipse.
  2. Fes clic dret sobre el paquet principal `com.empresa.model` i selecciona l'opció de menú:
     - En IntelliJ: **Diagrams -> Show Diagram (Ctrl+Alt+U)**.
     - En Eclipse: Utilitzant el connector ObjectAid o Papyrus.
  3. Visualitza el diagrama generat automàticament: comprova com l'eina ha detectat les fletxes d'herència i els atributs dels camps privats.
  4. Exporta el diagrama en format d'imatge PNG o SVG.

#### Repte 3: Sincronització Round-Trip en temps real
- **Objectiu:** Experimentar com un canvi al codi actualitza el diagrama i viceversa.
- **Procediment de taller:**
  1. Amb el diagrama de classes obert a la pantalla dividida, afig un nou atribut `private double límitCredit;` directament al fitxer de codi Java.
  2. Guarda el fitxer i comprova com l'atribut apareix automàticament al compartiment de la classe al diagrama UML.
  3. Afig una nova operació des del diagrama i comprova com l'IDE crea la signatura del mètode al fitxer de codi.
