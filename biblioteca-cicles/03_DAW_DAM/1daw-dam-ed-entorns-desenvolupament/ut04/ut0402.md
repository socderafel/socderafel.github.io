El diagrama gràfic de casos d'ús només ofereix una visió a vista d'ocell (*bird's-eye view*). Per a poder programar i verificar el sistema, cada cas d'ús s'ha de documentar amb una **especificació narrativa estructurada**, redactada en un llenguatge clar i entenedor tant per al client com per als desenvolupadors.

---

## 📋 Plantilla Estàndard d'Especificació Narrativa

Vegem l'exemple formal per al cas d'ús **CU-01: Retirar Efectiu del Caixer**:

| Camp de la Plantilla | Contingut de l'Especificació |
| :--- | :--- |
| **Identificador i Nom** | **CU-01: Retirar Efectiu d'un Caixer Automàtic** |
| **Actor Principal** | Client del Banc |
| **Actors Secundaris** | Sistema Central d'Autorització Bancària (Host) |
| **Descripció Breu** | El client utilitza la seua targeta per retirar diners en efectiu del seu compte corrent. |
| **Precondicions** | El caixer disposa de bitllets físics suficients i connexió de xarxa amb el banc central. |
| **Postcondicions d'Èxit** | Els diners són lliurats al client, el saldo del compte és debitat i s'imprimeix un rebut. |
| **Flux Principal (d'Èxit)** | 1. El client introdueix la targeta al lector.<br>2. El sistema sol·licita el codi PIN secret.<br>3. El client tecleja el PIN.<br>4. El sistema valida el PIN amb el banc central.<br>5. El sistema mostra el menú d'imports disponibles.<br>6. El client selecciona la quantitat desitjada.<br>7. El sistema verifica que el compte disposa de saldo suficient.<br>8. El sistema expulsa la targeta.<br>9. El client recull la targeta.<br>10. El sistema lliura l'efectiu i el comprovant. |
| **Fluxos Alternatius** | **4a. PIN incorrecte:** El sistema avisa de l'error i permet 2 intents més. Si s'esgoten, la targeta queda retinguda.<br>**7a. Saldo insuficient:** El sistema mostra un missatge d'avís i retorna al pas 5 per triar un import menor o cancel·lar. |
| **Excepcions** | **E1:** Fallada elèctrica o pèrdua de comunicació amb el banc: la targeta és expulsada immediatament i es registra la fallada en el log del caixer. |
