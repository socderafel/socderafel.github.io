L'automatització és la màxima de l'enginyeria del programari moderna. Des de les primeres eines d'enginyeria assistida per ordinador (**CASE - Computer-Aided Software Engineering**) fins a les modernes canonades d'**Integració Contínua i Desplegament Continu (CI/CD)**, la tecnologia permet construir solucions fiables amb intervenció humana mínima en les tasques repetitives.

---

## 🧰 Classificació de les Eines CASE

Les eines CASE són aplicacions que automatitzen o donen suport a una o més fases del cicle de vida:

1. **Upper CASE (Fases inicials):** Donen suport a la planificació, captura de requeriments i modelat conceptual (ex: eines de diagramació UML, disseny E/R de bases de dades).
2. **Lower CASE (Fases finals):** Donen suport a la generació de codi, proves automatitzades, depuració i documentació (ex: compiladors, generadors de codi, JUnit).
3. **Integrated CASE (I-CASE):** Cobreixen de manera unificada tot el cicle de vida des de l'anàlisi fins al manteniment sota un únic repositori central de metadades.

---

## 🚀 Integració Contínua (CI) i GitHub Actions

La **Integració Contínua (Continuous Integration - CI)** és una pràctica de desenvolupament on els membres de l'equip integren el seu codi de manera molt freqüent (diverses vegades al dia) en el repositori principal. Cada integració és verificada de manera automàtica per un servidor que compila el projecte i executa tots els tests.

### Exemple de Flux de Treball a GitHub Actions (`.github/workflows/ci.yml`)
```yaml
name: Java CI amb Maven

on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - uses: actions/checkout@v4
    
    - name: Configurar JDK 21
      uses: actions/setup-java@v4
      with:
        java-version: '21'
        distribution: 'temurin'
        cache: maven

    - name: Construir i passar tests amb Maven
      run: mvn clean verify
```

Si algun desenvolupador puja un commit que fa fallar un sol test de JUnit, **GitHub Actions marca el commit en vermell (❌)** i bloqueja automàticament la fusió del Pull Request, evitant que cap codi defectuós arribe a producció.
