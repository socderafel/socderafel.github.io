## 📌 20.1 Marc Normatiu i Pautes de Recuperació Competencial Extraordinària

La convocatòria extraordinària ofereix a l'estudiant l'oportunitat de demostrar l'assoliment dels **Resultats d'Aprenentatge (RA)** que no van ser superats durant el període d'avaluació contínua ordinària.

### Principis Pedagògics de la Recuperació
1. **Avaluació competencial individualitzada:** La recuperació se centra en les competències concretes pendents d'assolir segons l'informe d'avaluació ordinària (RA1 a RA6).
2. **Caràcter pràctic i aplicat:** La prova extraordinària consta de dues parts interconnectades:
   - **Part A (Projecte Integral Tècnic):** Desenvolupament d'una aplicació de programari completa que evidencie el domini de totes les fases del cicle de vida.
   - **Part B (Defensa Tècnica i Prova Pràctica Individual):** Resolució de supòsits pràctics i sessió de depuració en viu davant el tribunal/docent.

---

## 📌 20.2 Projecte Integral de Desenvolupament: Requeriments i Arquitectura

Per superar la convocatòria extraordinària, l'alumnat ha de desenvolupar el projecte de programari complet **"SmartFleet — Sistema de Gestió de Flotes i Logística de Vehicles"**.

```
+----------------------------------------------------------------------------------------------------+
|                         ARQUITECTURA DEL PROJECTE INTEGRAL "SMARTFLEET"                            |
+----------------------------------------------------------------------------------------------------+
|                                                                                                    |
|  [ MODELAT UML ]  ================>  [ IMPLEMENTACIÓ JAVA ]  ===============>  [ QA & JUNIT 5 ]   |
|  - Diagrama Classes                  - Capa de Domini / Entitats              - Proves Unitàries   |
|  - Diagrama Seqüència                - Gestors de Negoci                      - Tests Paramètrics  |
|  - Diagrama Casos d'Ús               - Control d'Excepcions Personalitzades   - Cobertura > 80%    |
|                                                                                                    |
|                                         |                                                          |
|                                         v                                                          |
|                         [ GESTIÓ & REFACTORING AMB GIT ]                                           |
|                         - Branques: main, develop, feature/*                                       |
|                         - Conventional Commits: feat, fix, test, docs                              |
|                         - Documentació Javadoc generada en HTML                                    |
+----------------------------------------------------------------------------------------------------+
```

### Requeriments del Domini SmartFleet
1. **Jerarquia de Vehicles:** Classe abstracta `Vehicle` (matrícula, marca, model, quilometratge, estat) de la qual hereten `Furgoneta` (capacitat de càrrega en kg) i `Camió` (nombre d'eixos i tacògraf).
2. **Rutes de Transport:** Una `Ruta` té un codi, origen, destí, distància en km i té assignat exactament un `Vehicle` i un `Conductor`.
3. **Manteniment Preventiu:** Cada vehicle té associat un registre històric d'operacions de `Manteniment` (composició). Si el quilometratge supera els 15.000 km des de l'última revisió, el sistema ha de bloquejar l'assignació de noves rutes llançant una excepció `VehicleNoOperatiuException`.
4. **Càlcul d'Eficiència:** El gestor de flota ha de calcular el cost total operatiu per quilòmetre recorregut en funció del tipus de vehicle i del combustible consumit.

## 📌 20.4 Guia de Defensa Tècnica i Avaluació Oral

La defensa presencial del projecte dura **20 minuts** i segueix l'estructura següent:

### Fase 1: Exposició de l'Arquitectura (5 minuts)
- Presentació del diagrama de classes UML.
- Justificació de les relacions escollides (per què herència vs composició, gestió de multiplicitats).
- Explicació del patró de disseny aplicat per a la gestió de rutes.

### Fase 2: Demostració i Execució de Proves (5 minuts)
- Execució en viu de la suite completa de tests de JUnit 5 des de l'IDE.
- Mostra de l'informe de cobertura de **JaCoCo**, demostrant el compliment del llindar del 80%.

### Fase 3: Prova de Depuració en Directe (*Live Debugging*) (10 minuts)
- El docent/tribunal introdueix una anomalia o fallada lògica intencionada en una de les classes de negoci (ex: fallada en el càlcul del desgast de furgonetes).
- L'estudiant ha de:
  1. Configurar els punts de ruptura (*breakpoints*) adients.
  2. Executar el projecte en mode depuració (*Debug*).
  3. Inspeccionar les variables locals i la pila de crides (*Call Stack*).
  4. Localitzar la línia exacta de l'error, esmenar-lo i verificar la correcció executant novament la suite de proves unitàries.

## 📝 Quadern d'Activitats Pràctiques i Reptes de Laboratori

### 📋 Bloc A: Anàlisi Tècnica i Càlculs de Qualitat Extraordinària

#### Exercici 20.1: Càlcul de Recuperació Parcial per Resultats d'Aprenentatge
Un estudiant té pendents d'assolir els següents Resultats d'Aprenentatge segons l'acta ordinària:
- $\text{RA3}$ (Modelat Estructural UML): ponderació en l'assignatura $15\%$.
- $\text{RA5}$ (Disseny i Execució de Proves): ponderació en l'assignatura $35\%$.
- Els altres RA (RA1, RA2, RA4, RA6) estan superats amb una mitjana consolidada de $6.8$ sobre 10 (representant el $50\%$ restant de la matèria).

A la convocatòria extraordinària, l'estudiant obté un $8.0$ a la part de modelat UML ($\text{RA3}$) i un $7.5$ a la prova de JUnit i cobertura ($\text{RA5}$).
1. Calculeu la nova qualificació final global de l'estudiant ($N_F$):
   $$N_F = (0.50 \times 6.8) + (0.15 \times \text{RA3}) + (0.35 \times \text{RA5})$$
2. Verifiqueu si la qualificació final supera el llindar d'aprovat ($N_F \ge 5.0$) i classifiqueu-la segons l'escala oficial (Aprovat, Notable, Excel·lent).

#### Exercici 20.2: Càlcul del Retorn d'Inversió en Proves (ROI de Qualitat)
Una empresa de programari avalua el retorn de la inversió en l'automatització de proves unitàries amb JUnit 5 versus proves manuals:
- **Cost de desenvolupament de la suite de proves:** $T_\text{tests} = 60\text{ hores}$ a un cost de $35\text{ €/hora}$.
- **Cost de correcció d'un defecte en fase de proves primerenques:** $C_\text{primerenc} = 50\text{ €/defecte}$.
- **Cost de correcció d'un defecte si s'escapa a producció:** $C_\text{producció} = 650\text{ €/defecte}$.
- Durant el període d'auditoria, la suite automàtica detecta i evita que $18$ defectes greus arriben a producció.

1. Calculeu l'estalvi econòmic net generat per la suite de proves:
   $$\text{Estalvi Brut} = 18 \times (C_\text{producció} - C_\text{primerenc})$$
2. Calculeu el **ROI de Qualitat** en percentatge:
   $$\text{ROI} = \frac{\text{Estalvi Brut} - \text{Cost de Desenvolupament}}{\text{Cost de Desenvolupament}} \times 100$$

#### Exercici 20.3: Càlcul de l'Esforç de Halstead i Mantenibilitat
Per a un mètode de càlcul d'itineraris d'SmartFleet, s'han comptabilitzat els següents operadors i operands de Halstead:
- Operadors únics ($n_1$): $8$
- Operands únics ($n_2$): $12$
- Total d'operadors ($N_1$): $34$
- Total d'operands ($N_2$): $28$

1. Calculeu la **Longitud del Programa** ($N = N_1 + N_2$) i el **Vocabulari** ($n = n_1 + n_2$).
2. Calculeu el **Volum de Halstead** ($V$):
   $$V = N \times \log_2(n)$$
3. Calculeu la **Dificultat** ($D$) i l'**Esforç** ($E$):
   $$D = \frac{n_1}{2} \times \frac{N_2}{n_2}, \quad E = D \times V$$
   Interpreteu si el nivell d'esforç obtingut indica una rutina fàcilment mantenible o candidata a refactorització immediata.

### 💻 Bloc B: Reptes Pràctics en Entorn de Desenvolupament

#### Repte 20.1: Implementació de l'Arquitectura Base d'SmartFleet
1. Creeu un repositori Git local anomenat `smartfleet-project` amb estructura estàndard Maven (`src/main/java`, `src/test/java`, `pom.xml`).
2. Definiu el model de classes complet amb:
   - Classe abstracta `Vehicle` amb atributs encapsulats i mètode abstracte `public abstract double calcularCostManteniment(double kms)`.
   - Classes derivades `Furgoneta` i `Camió` que implementen el càlcul específic segons el seu desgast per eixos o càrrega.
   - Classe `GestorFlota` que manté una col·lecció de vehicles i gestiona les operacions d'alta, baixa i assignació de rutes.
3. Creeu commits atòmics en branques de Git per a cada subsistema (`feature/vehicles`, `feature/gestor-flota`).

#### Repte 20.2: Suite Exhaustiva de Proves i Cobertura JaCoCo (>80%)
1. Creeu la classe de test `GestorFlotaTest` amb JUnit 5.
2. Dissenyeu bateries de proves per comprovar:
   - Validació de dades correctes en crear vehicles.
   - Llançament de `VehicleNoOperatiuException` quan un vehicle supera el límit de quilòmetres sense revisió.
   - Càlcul correcte dels costos de flota utilitzant `@ParameterizedTest` amb almenys 4 jocs de prova diferents.
3. Configureu el plugin `jacoco-maven-plugin` al fitxer `pom.xml`.
4. Executeu `mvn clean verify` i obriu l'informe `target/site/jacoco/index.html`. Verifiqueu que tant **Instruction Coverage** com **Branch Coverage** superen el llindar del 80%.

#### Repte 20.3: Documentació Tècnica Javadoc i Auditoria SonarLint
1. Documenteu totes les classes i mètodes públics d'SmartFleet amb comentaris Javadoc estàndard:
   - Incloeu descripció clara del propòsit de cada mètode.
   - Etiqueteu tots els paràmetres amb `@param`.
   - Etiqueteu el valor de retorn amb `@return`.
   - Documenteu les excepcions llançades amb `@throws`.
2. Genereu la documentació HTML completa mitjançant l'ordre `mvn javadoc:javadoc` o la funció de l'IDE.
3. Executeu una anàlisi amb SonarLint sobre tot el projecte i assegureu-vos d'obtenir zero defectes crítics o bloquejadors.
