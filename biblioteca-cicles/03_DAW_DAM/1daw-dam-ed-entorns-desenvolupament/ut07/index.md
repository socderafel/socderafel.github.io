Les **proves pràctiques d'avaluació tècnica** formen part tant del procés formatiu acadèmic en cicles formatius com dels processos de selecció i promoció professional en la indústria tecnològica (*Coding Challenges*). En aquesta unitat s'estableix una metodologia rigorosa per a abordar exercicis tècnics complexos, diagnosticar i solucionar errors crítics d'execució en temps real, optimitzar l'eficiència dels algorismes i aplicar barems d'autoavaluació i coavaluació competencial.

---

## 7.1 Metodologia per a la resolució de problemes tècnics de desenvolupament

Quan un desenvolupador s'enfronta a un repte pràctic o examen tècnic, l'error més comú és començar a teclejar codi de forma precipitada. Els enginyers sènior segueixen un protocol estructurat en 4 fases:

1. **Comprensió i anàlisi dels requisits:** Llegir detingudament l'enunciat, identificar les condicions d'entrada, els tipus de dades admesos i els casos extrems (*Edge Cases*: col·leccions buides, nombres negatius, valors nuls).
2. **Disseny conceptual de la solució:** Plantejar l'enfocament algorítmic en paper o pseudocodi, calculant la complexitat temporal estimada ($O(n)$) abans d'implementar.
3. **Implementació modular i neta:** Codificar en xicotets mètodes amb responsabilitat única, aplicant noms expressius i respectant l'encapsulament de classes.
4. **Validació immediata amb valors límit:** Executar el depurador o redactar casos de prova amb valors límit abans de considerar la tasca finalitzada.

## 7.2 Diagnòstic i resolució de fallades crítiques comunes

En els exercicis d'avaluació en Java solen aparèixer patrons d'error clàssics:

### 1. Referències nul·les (`NullPointerException`)
Es produeix en intentar invocar un mètode o accedir a un atribut sobre una variable que apunta a `null`.
```java
// ERROR TÍPIC:
String nom = null;
if (nom.equals("admin")) { ... } // Llança NullPointerException

// SOLUCIÓ DEFENSIVA RECOMANADA:
if ("admin".equals(nom)) { ... } // Mai falla encara que nom siga null
```

### 2. Pèrdua de precisió en càlculs monetaris
Utilitzar tipus de coma flotant primitius (`float` o `double`) per a càlculs econòmics genera errors d'arrodoniment a causa de la representació en binari IEEE 754:
```java
// PROBLEMA:
double total = 0.1 + 0.2; // Resultat: 0.30000000000000004

// SOLUCIÓ PROFESSIONAL: Utilitzar BigDecimal
BigDecimal preu = new BigDecimal("0.1");
BigDecimal totalCorrecte = preu.add(new BigDecimal("0.2")); // 0.3 exacte
```

### 3. Modificació concurrent de col·leccions (`ConcurrentModificationException`)
Es produeix en eliminar elements d'un `ArrayList` mentre s'itera amb un bucle `for-each`:
```java
// ERROR:
for (Client c : llista) {
    if (c.esMoros()) llista.remove(c); // Llança ConcurrentModificationException
}

// SOLUCIÓ RECOMANADA (Java 8+):
llista.removeIf(Client::esMoros);
```

## 7.3 Eficiència algorítmica: Notació Gran O ($O$)

L'avaluació d'un programa no sols mesura si funciona correctament, sinó també **com d'eficientment gestiona el temps i la memòria**:

| Complexitat | Nom | Comportament amb $N = 1.000.000$ | Exemple Típic |
| :---: | :--- | :--- | :--- |
| **$O(1)$** | Temps Constant | $\approx 1\text{ operació}$ | Accés a element d'array per índex |
| **$O(\log N)$** | Temps Logarítmic | $\approx 20\text{ operacions}$ | Cerca binària en llista ordenada |
| **$O(N)$** | Temps Lineal | $\approx 1.000.000\text{ operacions}$ | Recorregut simple d'un bucle |
| **$O(N \log N)$** | Quasilineal | $\approx 20.000.000\text{ operacions}$ | Algorismes d'ordenació eficients (MergeSort) |
| **$O(N^2)$** | Temps Quadràtic | $\approx 10^{12}\text{ operacions (Col·lapse!)}$ | Bucles niats manuals (BubbleSort) |

## 📝 Quadern d'Activitats Pràctiques i Reptes de Laboratori

### Bloc A: Fonaments, Dimensionament i Anàlisi de Rendiment

#### Exercici 1: Anàlisi de complexitat temporal i colls d'ampolla
Un programador dissenya un mètode per comprovar si en una llista de $N$ usuaris hi ha elements duplicats:
- **Algorisme A (Bucles niats):**
  ```java
  for (int i = 0; i < N; i++) {
      for (int j = i + 1; j < N; j++) {
          if (usuaris.get(i).equals(usuaris.get(j))) return true;
      }
  }
  ```
- **Algorisme B (Estructura HashSet):**
  ```java
  Set<Usuari> unics = new HashSet<>();
  for (Usuari u : usuaris) {
      if (!unics.add(u)) return true;
  }
  ```

1. Quina és la complexitat temporal asimptòtica $O$ de l'Algorisme A i de l'Algorisme B?
2. Si una operació individual de comparació triga $10\text{ nanosegons}$ ($10^{-8}\text{ s}$), calcula el temps d'execució aproximat de tots dos algorismes per a una base de dades de $N = 100.000\text{ usuaris}$.
3. És acceptable l'Algorisme A en un examen tècnic de rendiment professional?

#### Exercici 2: Auditoria de codi i detecció de defectes en una prova pràctica
Analitza el següent fragment de codi d'un exercici d'avaluació:

```java
public class GestorBanc {
    public static double calcularInteres(double capital, int mesos) {
        double resultat;
        try {
            resultat = capital / mesos;
        } catch (Exception e) {
            // No fa res
        }
        return resultat; // <-- Compila? Què passa si capital és 0 o mesos és 0?
    }
}
```

1. Identifica els **3 problemes crítics** de codi d'aquest mètode (compilació, captura buida d'excepcions i divisió per zero en coma flotant).
2. Per què bloquejar o "empassar-se" excepcions amb un bloc `catch` buit es considera una de les pitjors pràctiques en enginyeria de programari?
3. Refactoritza el mètode perquè siga robust, retorni una excepció adequada (`IllegalArgumentException`) i valide els paràmetres d'entrada.

#### Exercici 3: Càlcul de qualificació ponderada en una avaluació tècnica
Un barem oficial de correcció tècnica avalua 4 dimensions amb les següents ponderacions:
- $D_1$: Correcció Funcional (passa tots els tests bàsics): $40\%$.
- $D_2$: Robustesa i Casos Límit (gestió d'entrades buides i excepcions): $25\%$.
- $D_3$: Eficiència i Estructures de Dades adequades: $20\%$.
- $D_4$: Codi Net, Nomenclatura i Encapsulament: $15\%$.

- Un aspirant obté les següents puntuacions sobre 10: $D_1 = 9.0$, $D_2 = 4.0$, $D_3 = 8.0$, $D_4 = 7.5$.
1. Calcula la qualificació final ponderada sobre 10 de l'aspirant:
   $$\text{Nota Final} = (D_1 \times 0.40) + (D_2 \times 0.25) + (D_3 \times 0.20) + (D_4 \times 0.15)$$
2. Si la convocatòria exigeix una nota mínima de $5.0$ en cadascuna de les 4 dimensions de manera independent per a aprovar, l'aspirant està aprovat o suspès? Què indica açò sobre la importància de provar els casos límit?

### Bloc B: Reptes Pràctics de Laboratori i Taller / Comandes

#### Repte 1: Desenvolupament d'un Algorisme d'Inventari amb Cerca Binària
- **Objectiu:** Implementar una solució tècnica òptima que supere una prova pràctica de rendiment.
- **Enunciat:** Donada una classe `Article` amb `codi` (enter únic) i `preu`, implementa una col·lecció que permeta cercar un article pel seu codi amb complexitat logarítmica $O(\log n)$ en una llista ordenada de $50.000$ articles.
- **Requisits de prova:**
  1. Si l'article existeix, retorna el seu preu.
  2. Si l'article no existeix, retorna un valor opcional (`Optional<Double>`) buit sense llançar cap excepció.
  3. Comprova la solució contrarellotge en l'IDE.

#### Repte 2: Depuració contrarellotge d'un simulador bancari amb 3 bugs ocults
- **Objectiu:** Localitzar tres defectes mitjançant el depurador en menys de 20 minuts.
- **Defectes a localitzar:**
  1. Un bucle `while` amb condició d'aturada que no s'assoleix mai a causa d'un decrement omès.
  2. Una comparació de cadenes amb `==` en lloc d'`.equals()`.
  3. Un accés a un mapa `HashMap` que retorna `null` i s'intenta convertir a enter primitiu provocant una fallada de desempaquetament (*Unboxing NullPointerException*).

#### Repte 3: Desenvolupament d'un Harness de Proves per a Coavaluació
- **Objectiu:** Crear una classe de prova ràpida que verifique les solucions desenvolupades per altres companys.
- **Instruccions:**
  1. Dissenya un mètode `testAutomatitzat()` que execute 10 crides amb entrades típiques i entrades límit.
  2. Imprimeix per consola un informe d'avaluació detallant: nombre de tests superats, temps d'execució en mil·lisegons i llista de fallades detectades.
