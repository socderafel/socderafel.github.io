## 1. Concepte de Recursivitat en Programació

La **recursivitat** és una tècnica algorítmica on un mètode es resol **cridant-se a si mateix** sobre una instància més menuda o simplificada del mateix problema. Es fonamenta en el principi d'inducció matemàtica.

Tot mètode recursiu correcte ha de constar obligatòriament de dues parts inseparables:
1. **Cas Base (Condició de Parada):** L'estat més simple del problema que es pot resoldre de forma immediata i directa sense fer cap nova crida recursiva.
2. **Pas Recursiu (Descomposició):** La reducció del problema actual en un subproblema de menor grandària que acoste progressivament l'execució cap al cas base.

---

## 2. Exemple Canònic: El Càlcul del Factorial ($N!$)

Per definició matemàtica:
$$0! = 1 \quad (	ext{Cas Base})$$
$$N! = N 	imes (N - 1)! \quad 	ext{per a } N > 0 \quad (	ext{Pas Recursiu})$$

```java
public class AlgorismesRecursius {

    /**
     * Calcula el factorial d'un número de forma recursiva.
     */
    public static long factorial(int n) {
        // 1. Clàusula de Guàrdia / Control d'error
        if (n < 0) {
            throw new IllegalArgumentException("El número no pot ser negatiu.");
        }
        
        // 2. Cas Base: 0! = 1 i 1! = 1
        if (n <= 1) {
            return 1;
        }

        // 3. Pas Recursiu: N * factorial(N - 1)
        return n * factorial(n - 1);
    }
}
```

### Què passa a la Pila de Crides (*Call Stack*) durant `factorial(3)`?
1. S'apila `factorial(3)` $ightarrow$ espera el resultat de `factorial(2)`.
2. S'apila `factorial(2)` $ightarrow$ espera el resultat de `factorial(1)`.
3. S'apila `factorial(1)` $ightarrow$ arriba al **Cas Base** i retorna `1`.
4. Es desapila `factorial(1)`, `factorial(2)` calcula $2 	imes 1 = 2$ i es desapila.
5. `factorial(3)` calcula $3 	imes 2 = 6$ i finalitza l'execució.

## 3. Recursivitat vs Iteració: Avantatges i Desavantatges

| Criteri | Enfocament Recursiu | Enfocament Iteratiu (Bucles `for` / `while`) |
| :--- | :--- | :--- |
| **Claredat de Codi** | Molt més natural i elegant per a problemes com arbres (DOM, XML), sistemes de fitxers de directoris i grafs. | Pot requerir bucles complexos i piles auxiliars manuals. |
| **Consum de Memòria** | **Alt:** Cada crida crea un nou marc de pila (*Stack Frame*); risc de `StackOverflowError` si la profunditat és gran. | **Molt baix:** Reutilitza les mateixes variables locals en temps constant $O(1)$ de memòria auxiliar. |
| **Rendiment de CPU** | Lleugerament inferior per l'overhead de la invocació contínua de mètodes. | Màxim rendiment directe per a operacions seqüencials. |
