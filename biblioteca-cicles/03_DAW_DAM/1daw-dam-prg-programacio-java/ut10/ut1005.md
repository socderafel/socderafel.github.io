## Què és la Serialització?

La **serialització** és el procés de convertir l'estat complet d'un objecte viu (incloent tots els seus atributs i els altres objectes als quals fa referència en el seu graf de memòria) en una seqüència de bytes que pot ser emmagatzemada en un fitxer a disc o transmesa per xarxa.

El procés invers, reconstruir l'objecte a la memòria RAM des del flux de bytes, s'anomena **deserialització**.

```
Objecte al Heap ===[ObjectOutputStream]===> Fitxer d'objectes (.ser / .bin)
Fitxer a disc  ===[ObjectInputStream] ====> Objecte reconstruït al Heap
```

---

## El Marcador `java.io.Serializable`

Perquè els objectes d'una classe puguen ser serialitzats, la classe ha d'implementar la interfície `java.io.Serializable`. Es tracta d'una **interfície marcadora** (*marker interface*): no conté cap mètode, simplement indica a la JVM que autoritza la persistència de l'estat intern.

```java
import java.io.Serializable;

public class Client implements Serializable {
    // 1. Identificador de versió de la classe
    private static final long serialVersionUID = 1L;

    private String nif;
    private String nom;

    // 2. Camp exclòs de la serialització per motius de seguretat
    private transient String clauAccés;

    public Client(String nif, String nom, String clau) {
        this.nif = nif;
        this.nom = nom;
        this.clauAccés = clau;
    }
}
```

---

## Escriptura i Lectura d'Objectes

Utilitzem les classes de flux avançades `ObjectOutputStream` i `ObjectInputStream`:

```java
// Guardar objectes al disc
Client c = new Client("12345678Z", "Laura", "secreta123");
try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("client.ser"))) {
    oos.writeObject(c);
    System.out.println("Client guardat amb èxit.");
}

// Recuperar l'objecte des del disc
try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("client.ser"))) {
    Client recuperat = (Client) ois.readObject();
    System.out.println("Client recuperat: " + recuperat.getNom());
}
```

---

## El Paper de `serialVersionUID`

Quan una classe es compila, Java li assigna un hash de versió calculat a partir dels seus camps i mètodes. Si canviem un atribut de la classe i intentem carregar un fitxer que es va gravar amb la versió anterior, es produirà una excepció `InvalidClassException`.

Declarar explícitament un identificador `private static final long serialVersionUID = 1L;` permet als desenvolupadors mantindre el control de compatibilitat entre diferents versions de l'aplicació.
