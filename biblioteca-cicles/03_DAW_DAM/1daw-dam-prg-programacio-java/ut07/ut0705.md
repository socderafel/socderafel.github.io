## Gestió de Memòria en Java: Stack vs Heap

Comprendre com la JVM distribueix la memòria és clau per a tot desenvolupador Java:

```
PILA D'EXECUCIÓ (Stack Memory)          MEMÒRIA DINÀMICA (Heap Memory)
+-----------------------------+         +-------------------------------+
| Marc de main():             |         |                               |
|   int x = 42                |         |  Objecte Persona @0x7f4a:     |
|   Persona p = @0x7f4a ------>--------->   nom: "Anna"                 |
|                             |         |   edat: 21                    |
+-----------------------------+         +-------------------------------+
```

1. **Memòria de Pila (*Stack*):**
   - Ràpida, organitzada en marcs de crida de mètodes (*frames*).
   - Emmagatzema variables primitives locals (`int`, `boolean`, `double`) i les **referències (adreces)** que apunten als objectes del Heap.
   - S'allibera automàticament quan el mètode finalitza la seua execució.
2. **Memòria Dinàmica (*Heap*):**
   - Emmagatzema tots els **objectes creats amb l'operador `new`** i els seus atributs d'instància.
   - Compartida per tota l'aplicació.

## Cicle de Vida i Recollidor de Fem (*Garbage Collector*)

Quan un objecte deixa de tindre cap referència viva que apunte cap a ell (perquè la variable local ha eixit del seu àmbit o s'ha reassignat a `null`), l'objecte es converteix en **inaccessible**.

El **Garbage Collector (GC)** és un procés en segon pla de la JVM que detecta automàticament aquests objectes inabastables i allibera la seua memòria al Heap, evitant les fuites de memòria típiques de llenguatges sense recol·lector.

```java
Persona p1 = new Persona("Joan"); // Instància 1 creada
Persona p2 = new Persona("Marta"); // Instància 2 creada

p1 = p2; // p1 ara apunta a la Instància 2!
// La Instància 1 ("Joan") queda òrfena de referències: serà recollida pel GC.
```

## La Importància de Redefinir `toString()`

En Java, totes les classes hereten de la classe base `java.lang.Object`. El mètode `toString()` per defecte retorna una cadena gens informativa: `NomClasse@CodiHashHexadecimal` (ex: `Persona@6a6824be`).

És una regla fonamental de desenvolupament sobreescriure `@Override public String toString()` per a oferir una representació textual clara de l'estat intern de l'objecte:

```java
public class Persona {
    private String nom;
    private int edat;

    public Persona(String nom, int edat) {
        this.nom = nom;
        this.edat = edat;
    }

    @Override
    public String toString() {
        return "Persona{nom='" + nom + "', edat=" + edat + "}";
    }
}
```

Quan executem `System.out.println(p);`, Java crida automàticament al mètode `p.toString()`.
