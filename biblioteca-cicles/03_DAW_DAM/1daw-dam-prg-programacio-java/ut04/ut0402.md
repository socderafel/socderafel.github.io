## 1. El Dogma de Java: Tot es Passa Estrictament PER VALOR

En molts llibres i manuals antics existeix una confusió greu que afirma erròniament que «els primitius es passen per valor i els objectes es passen per referència». **Aquesta afirmació és totalment falsa en Java**:

> [!IMPORTANT] Llei Universal de Java
> **En Java, ABSOLUTAMENT TOT el pas de paràmetres es realitza PER VALOR.**  
> El que s'envia a un mètode és **sempre una còpia del valor** emmagatzemat a la variable local de la pila cridant.

La diferència de comportament rau exclusivament en **què és el que guarda la variable**:
- Si la variable és de **tipus primitiu**, el seu valor a la pila és el **número pur**.
- Si la variable és de **tipus objecte (referència)**, el seu valor a la pila és la **direcció de memòria (punter d'adreça)** que apunta a l'objecte allotjat al Heap.

---

## 2. Pas de Tipus Primitius: Còpia Aïllada del Valor

Quan passem un tipus primitiu a un mètode, es copia el seu valor numèric en un nou marc de pila (*stack frame*). Qualsevol modificació sobre eixe paràmetre dins del mètode **no té absolutament cap efecte** sobre la variable original:

```java
public class DemostracioPrimitius {
    public static void incrementar(int numero) {
        numero = numero + 10; // Modifica la còpia local de la pila!
        System.out.println("Dins del mètode: " + numero); // Imprimeix 15
    }

    public static void main(String[] args) {
        int edat = 5;
        incrementar(edat);
        System.out.println("Al main després de cridar: " + edat); // Imprimeix 5 (INALTERAT!)
    }
}
```

---

## 3. Pas de Referències a Objectes: Còpia de la Referència

Quan passem un objecte (com un array o una instància de classe):
1. Es copia el valor de la variable cridant, que és **la direcció de memòria** que apunta a l'objecte al Heap.
2. Com que tant la variable original com el paràmetre del mètode tenen dues còpies de la **mateixa adreça**, ambdues apunten al **mateix objecte físic en el Heap**.
3. Si el mètode **muta l'estat intern de l'objecte** (ex: `vector[0] = 99`), el canvi es veurà reflectit en l'original.
4. Però si el mètode **intenta reassignar la referència a un nou objecte** (`vector = new int[5]`), **l'original NO canvia**, demostrant que la referència mateixa es va passar per valor!

```java
public class DemostracioObjectes {
    public static void modificarArray(int[] valors) {
        valors[0] = 999; // MUTA l'objecte compartit al Heap!
        valors = new int[]{1, 2, 3}; // REASSIGNA la còpia de la referència (només afecta localment)
    }

    public static void main(String[] args) {
        int[] notes = {10, 20, 30};
        modificarArray(notes);
        System.out.println(notes[0]); // Imprimeix 999 (estat intern mutat)
        System.out.println(notes.length); // Imprimeix 3 (la reassignació a new int[3] NO va afectar a notes!)
    }
}
```
