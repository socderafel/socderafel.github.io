## La Vulnerabilitat d'Injecció SQL (*SQL Injection*)

La **Injecció SQL** ha liderat històricament el rànquing OWASP Top 10 de vulnerabilitats més crítiques de seguretat en aplicacions. Ocorre quan es construeixen ordres SQL concatenant text introduït per l'usuari amb la interfície simple `Statement`:

```java
// CODI VULNERABLE I ALTAMENT PERILLÓS (MAI S'HA D'UTILITZAR!)
Statement stmt = connexio.createStatement();
String sql = "SELECT * FROM usuaris WHERE user = '" + inputUsuari + "' AND pass = '" + inputPass + "'";
ResultSet rs = stmt.executeQuery(sql);
```

Si un atacant introdueix en el camp d'usuari: `' OR '1'='1' --`  
La sentència compilada pel motor SQL serà:
```sql
SELECT * FROM usuaris WHERE user = '' OR '1'='1' --' AND pass = '...'
```
La condició `'1'='1'` és sempre vertadera i el doble guió `--` anul·la la comprovació de la contrasenya com un comentari, donant accés immediat amb privilegis d'administrador!

---

## La Solució Definitiva: `PreparedStatement`

La interfície **`PreparedStatement`** elimina d'arrel la injecció SQL gràcies al mecanisme de **consultes parametritzades**:
1. La consulta s'envia prèviament al motor de base de dades amb caràcters d'interrogació `?` (*placeholders*).
2. El motor **precompila l'arbre de sintaxi SQL** abans d'incorporar les dades.
3. Els paràmetres s'envien de forma separada amb mètodes tipats (`setString()`, `setInt()`, `setDouble()`).
4. El motor tracta els valors **estrictament com a dades literals**, fent absolutament impossible que un caràcter de cometa o ordre SQL s'execute com a codi.

```java
String sql = "SELECT * FROM usuaris WHERE user = ? AND pass = ?";

try (PreparedStatement ps = connexio.prepareStatement(sql)) {
    // Els índexs dels paràmetres comencen en 1 (NO en 0!)
    ps.setString(1, inputUsuari);
    ps.setString(2, inputPass);

    try (ResultSet rs = ps.executeQuery()) {
        if (rs.next()) {
            System.out.println("Accés concedit.");
        } else {
            System.out.println("Credencials incorrectes.");
        }
    }
}
```

## Execució d'Operacions DML: `executeUpdate()`

Per a sentències `INSERT`, `UPDATE` o `DELETE`, s'utilitza `executeUpdate()`, que retorna el nombre exacte de files afectades a la base de dades:

```java
String sql = "UPDATE productes SET preu = ?, estoc = ? WHERE id = ?";
try (PreparedStatement ps = connexio.prepareStatement(sql)) {
    ps.setDouble(1, 49.99);
    ps.setInt(2, 120);
    ps.setInt(3, 105);

    int filesAfectades = ps.executeUpdate();
    System.out.println("Files modificades: " + filesAfectades);
}
```
