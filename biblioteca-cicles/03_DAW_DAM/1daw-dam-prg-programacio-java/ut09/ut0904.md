## Llançament Explícit d'Excepcions: `throw`

Quan un mètode detecta que no es compleixen les precondicions necessàries per a realitzar la seua tasca, utilitza la sentència **`throw`** seguida d'una instància d'un objecte d'excepció per a interrompre el flux normal:

```java
public void retirarDiners(double quantitat) {
    if (quantitat <= 0) {
        throw new IllegalArgumentException("La quantitat a retirar ha de ser estrictament positiva.");
    }
    if (quantitat > this.saldo) {
        throw new IllegalStateException("Saldo insuficient per a completar la retirada.");
    }
    this.saldo -= quantitat;
}
```

---

## Propagació d'Excepcions: la Clàusula `throws`

Quan un mètode pot generar una **excepció comprovada (*checked*)** però la seua responsabilitat no és solucionar-la sinó delegar-la al mètode cridador superior, ha d'indicar-ho en la seua capçalera utilitzant **`throws`**:

```java
// Delegació de responsabilitat: qui cride a carregarConfiguracio haurà de gestionar FileNotFoundException
public Properties carregarConfiguracio(String ruta) throws FileNotFoundException, IOException {
    Properties prop = new Properties();
    try (FileInputStream fis = new FileInputStream(ruta)) {
        prop.load(fis);
    }
    return prop;
}
```

---

## Encadenament d'Excepcions (*Exception Chaining*)

Quan capturem una excepció tècnica de baix nivell (com `SQLException`) en una capa d'accés a dades, és una pràctica d'enginyeria recomanada embolcallar-la dins d'una excepció de domini d'alt nivell (com `ServeiUsuariException`) sense perdre la causa original. Això s'anomena **encadenament**:

```java
try {
    connexioBBDD.executarSQL("...");
} catch (SQLException e) {
    // Es passa 'e' com a causa en el constructor de la nova excepció
    throw new RepositoriException("Error en accedir a les dades fiscals", e);
}
```
