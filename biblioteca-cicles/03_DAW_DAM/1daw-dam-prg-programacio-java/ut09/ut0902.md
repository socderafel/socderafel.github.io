## Anatomia del Bloc `try-catch-finally`

El mecanisme estàndard per a gestionar anomalies en temps d'execució consta de tres seccions complementàries:

```java
try {
    // 1. Codi susceptible de fallar o llançar una excepció
    int resultat = 100 / divisor;
    System.out.println("Resultat: " + resultat);
} catch (ArithmeticException e) {
    // 2. Codi de recuperació específic davant la fallada
    System.err.println("Error matemàtic: " + e.getMessage());
} finally {
    // 3. Codi de neteja que s'executa SEMPRE de manera garantida
    System.out.println("Operació completada.");
}
```

---

## Múltiples Blocs `catch` i Ordre de Jerarquia

Un sol bloc `try` pot estar acompanyat de diversos blocs `catch` per a gestionar diferents tipus d'excepcions.

> **Regla Crítica de Jerarquia:** Els blocs `catch` s'avaluen en **ordre seqüencial de dalt a baix**. S'han de col·locar **primer les subclasses més específiques** i **després les superclasses més generals**. Si es col·locara un `catch (Exception e)` abans d'un `catch (IOException e)`, el codi no compilaria per ser unreachable code!

```java
try {
    // Operacions de fitxers i parseig de dades
} catch (FileNotFoundException e) {
    System.err.println("El fitxer físic no s'ha trobat.");
} catch (IOException e) {
    System.err.println("Error general d'entrada/eixida.");
} catch (Exception e) {
    System.err.println("Qualsevol altra fallada no prevista: " + e.getMessage());
}
```

---

## La Clàusula Multi-catch (Java 7+)

Si el tractament de recuperació per a dues o més excepcions que no tenen relació directa d'herència entre elles és exactament el mateix, es poden agrupar en un sol bloc utilitzant l'operador `|`:

```java
try {
    processarDades();
} catch (NumberFormatException | NullPointerException e) {
    // Gestió conjunta per a ambdues fallades
    System.err.println("Dada numèrica o referència no vàlida: " + e.getMessage());
}
```
