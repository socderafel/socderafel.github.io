## Per Què Crear Excepcions Personalitzades?

Encara que Java compta amb dotzenes d'excepcions estàndards, en aplicacions empresarials és essencial definir **excepcions pròpies del domini de negoci**. Això permet:
1. Donar un significat clar i precís a l'error dins del vocabulari de l'aplicació (`ComandaJaEnviadaException`, `ProducteEsgotatException`).
2. Afegir camps d'estat propis per a facilitar la recuperació (com el codi de client afectat o la data límit superada).
3. Permetre als consumidors de la biblioteca capturar exactament eixe error específic sense atrapar altres problemes no relacionats.

---

## Com Definir una Excepció Pròpia

Per a crear una excepció personalitzada només cal crear una classe que herete de:
- **`Exception`:** Si volem que siga una **excepció comprovada (*checked*)**.
- **`RuntimeException`:** Si volem que siga **no comprovada (*unchecked*)** (molt habitual en desenvolupament modern de serveis i APIs REST).

```java
public class SaldoInsuficientException extends Exception {
    private final double saldoActual;
    private final double importDemanat;

    // Constructor bàsic amb missatge descriptiu
    public SaldoInsuficientException(String missatge) {
        super(missatge);
        this.saldoActual = 0;
        this.importDemanat = 0;
    }

    // Constructor avançat amb dades de domini per a auditoria
    public SaldoInsuficientException(String missatge, double saldoActual, double importDemanat) {
        super(missatge + " [Saldo disponible: " + saldoActual + " €, Demanat: " + importDemanat + " €]");
        this.saldoActual = saldoActual;
        this.importDemanat = importDemanat;
    }

    // Constructor per a encadenament amb causa original
    public SaldoInsuficientException(String missatge, Throwable causa) {
        super(missatge, causa);
        this.saldoActual = 0;
        this.importDemanat = 0;
    }

    public double getSaldoActual() { return saldoActual; }
    public double getImportDemanat() { return importDemanat; }
}
```

## Decàleg de Bones Pràctiques en Gestió d'Errors

1. **Mai silencies excepcions:** No deixes blocs `catch` buits ni et limites a imprimir missatges sense prendre decisions.
2. **Reutilitza abans de crear:** Si un error encaixa perfectament en `IllegalArgumentException` o `IllegalStateException`, fes servir les classes estàndards de la JDK.
3. **Proporciona missatges descriptius:** Inclou en el missatge el valor concret que ha provocat l'error (per exemple: `"El valor del port ha de ser entre 1 i 65535. Valor rebut: " + port`).
4. **Allibera sempre els recursos:** Usa sempre `try-with-resources`.
5. **No uses excepcions per a controlar el flux normal:** Les excepcions tenen un cost elevat de rendiment en la creació de la traça de pila (*stack trace*). No les faces servir com a substituts de condicions `if/else`.
