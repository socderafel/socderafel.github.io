# 5.4 Classes i mètodes abstractes (abstract)

En determinades ocasions, és possible que necesites definir una classe que represente un concepte el suficientement abstracte com perquè mai vagen a existir instàncies d'ella (objectes). *Tindria això sentit*? *Què utilitat podria tindre*?

Imagina una aplicació per a un centre educativo que utilitze les classes d'exemple `Alumno` i `Profesor`, totes dues subclases de `Persona`. És més que probable que eixa aplicació mai arribe a necessitar objectes de la classe `Persona`, ja que serien massa genérics com per a poder ser utilitzats (no contendrían suficient informació específica). Podrías arribar llavors a la conclusió de que la classe `Persona` ha resultat d'utilitat com classe base per a construir altres classes que hereden d'ella, però no com una classe instanciable de la qual vagen a existir objectes. A aquest tipus de classes es els anomena classes abstractes.

> **📌 A tindre en compte**
> 

> En alguns casos pot resultar útil disposar de classes que **mai seran instanciades**, sinó que **proporcionen un** marco o **model a seguir pels seus classes derivades** dins d'una jerarquia d'herència. Són les classes abstractes.

La possibilitat de declarar classes abstractes és una de les característiques més útils dels llenguatges orientats a objectes, ja que permeten donar unes línies generals de com és una classe sense tindre que implementar tots els seus mètodes o implementant solament alguns d'ells. Açò resulta especialment útil quan les distintes classes derivades deban proporcionar els mateixos mètodes indicats en la classe base abstracta, però la seua implementació siga específica per a cada subclase. 

Imagina que estàs treballant en un entorn de manipulació d'objectes gràfics i necesitas treballar amb *línies*, *cercles*, *rectangles*, etc. Aquests objectes tindran en comú alguns atributs que representen la seua estat (*ubicació*, *color del contorno*, *color de farciment*, etc.) i alguns mètodes que modelen el seu comportament (*dibuixar*, *emplenar amb un color*, *escalar*, *desplazar*, *rotar*, etc.). Alguns d'ells seran comuns per a tots ells (per exemple la *ubicació* o el *desplazament*) i no obstant això altres (com per exemple *dibuixar*) necesitarán una implementació específica depenent del tipus d'objecte. Però, en qualsevol cas, tots ells necessiten eixos mètodes (tant un *cercle* com un *rectangle* necessiten el mètode *dibuixar*, encara que es lleven a cabo de manera diferent). En aquest cas resultaría molt útil disposar d'una classe abstracta objecte gràfic on es definirían les línies generals (alguns atributs concrets comuns, alguns mètodes concrets comuns implementats i alguns mètodes genérics comuns sense implementar) d'un objecte gràfic i més avant, segons es vagen definint classes especialitzades (*línies*, *cercles*, *rectangles*), es aniran concretant en cada subclase aquells mètodes que es dejaron sense implementar en la classe abstracta.

## 1. Declaració d'una classe abstracta

Ja has vist que una classe abstracta és una classe que no es pot instanciar, és a dir, que no es poden crear objectes a partir d'ella. La idea és permetre que altres classes deriven d'ella, proporcionant un model genéric i alguns mètodes d'utilitat general. Les classes abstractes es declaran mitjançant el modificador `abstract`:

```java
[modificador_acceso] abstract class nombreClase [herencia] [interfaces] {
  ...
}
```

> **📌 A tindre en compte**
> 

> Una classe pot contindre en el seu interior mètodes declarats com `abstract` (mètodes per als quals només es indica la capçalera, però no es proporciona la seua implementació). En tal cas, la classe haurà de ser necessàriament també `abstract`. Eixos mètodes hauran de ser posteriorment implementats en els seus classes derivades.

D'altra banda, una classe també pot contindre mètodes totalment implementats (no abstractes), els quals seran heretats pels seus classes derivades i podran ser utilitzats sense necessitat de definirlos (ja que ja estan implementats).

Quan trabatges amb classes abstractes has de tindre en compte:

- Una classe abstracta només pot usar-se per a crear noves classes derivades. No es pot fer un `new` d'una classe abstracta. Es produciría un error de compilació.

- Una classe abstracta pot contindre mètodes totalment definits (no abstractes) i mètodes sense definir (mètodes abstractes).

<details markdown="1">

<summary>💡 Exemple 4.01: Revisa amb cura el següent exemple</summary>

Basándote en la jerarquia de classes d'exemple (`Persona`, `Alumno`, `Profesor`), que ja has utilitzat en altres ocasions, modifica el que consideres oportuno perquè `Persona` siga, a partir d'ara, una classe abstracta (no instanciable) i les altres dos classes sigan sent classes derivades d'ella, però sí instanciables.

**Solució**  

En aquest cas l'únic que hi hauria que fer és afegir el modificador `abstract` a la classe `Persona`. El resta de la classe permanecería igual i les classes `Alumno` i `Profesor` no tendrían porqué sufrir cap modificació.

```java
public abstract class Persona {
    protected String nombre;
    protected String apellidos;
    protected LocalDate fechaNacimiento;
    ...
}
```

A partir d'ara no podran existir objectes de la classe `Persona`. El compilador generaría un error.

</details>

<details markdown="1">

<summary>💡 Classes abstractes en la API</summary>

Localitza en la API de Java algun exemple de classe abstracta.

Existeixen una gran quantitat de classes abstractes en la API de Java. Ací tens un parell d'exemples:

- La classe `AbstractList`:

```java
public abstract class AbstractList<E> extends AbstractCollection<E> implements List<E> {
    // ...

    // Métodos abstractos
    public abstract E get(int index);
    public abstract int size();
}
```

De la que heredan classes instanciable com `Vector` o `ArrayList`.
  
  

- La classe `AbstractSequentialList`:

```java
public abstract class AbstractSequentialList<E> extends AbstractList<E>{
    // ...

    // Métodos abstractos
    public abstract ListIterator<E> listIterator(int index);
}
```

Aquesta classe hereda de `AbstractList`, i d'aquesta hereda la classe `LinkedList`.    

</details>

## 2. Mètodes abstractes

Un mètode abstracte és un mètode declarat en una classe per al qual eixa classe no proporciona la implementació.   
  
Si una classe disposa de, almenys, un mètode abstracte es diu que és una classe abstracta.   

> **📌 Implementar mètodes abstractes heretats**
> 

> Tota classe que herede (siga subclase) d'una classe abstracta ha d'implementar tots els mètodes abstractes del seu superclase o bé volverlos a declarar com abstractes (i per tant també seria abstracta).

Per a declarar un mètode abstracte en Java s'utilitza el modificador `abstract`. És un mètode de la qual implementació no es defineix, sinó que es declara únicament el seu interfície (capçalera) perquè el seu cos siga implementat més avant en una classe derivada.

Un mètode es declara com abstracte mitjançant l'ús del modificador `abstract` (com en les classes abstractes):

```java
[modificador_acceso] abstract <tipo> <nombreMetodo> ([parámetros]) [excepciones];
```

> **📌 A tindre en compte**
> 

> Quan una classe conté un mètode abstracte ha de declarar-se com abstracta obligatòriament.

Imagina que tens una classe `Empleado` genérica per a diversos tipus d'empleat i tres classes derivades: `EmpleadoFijo` (té un salario fix més certs complementos), `EmpleadoTemporal` (salario fix més altres complementos diferents) i `EmpleadoComercial` (una part de salario fix i unes comisions per cada operació). La classe `Empleado` podria contindre un mètode abstracte `calcularNomina`, ja que saps que es mètode serà necessari per a qualsevol tipus d'empleat (tot empleat cobra una nómina). No obstant això el càlcul en sí de la nómina serà diferent si es tracta d'un empleat fix, un empleat temporal o un empleat comercial, i serà dins de les classes especialitzades de `Empleado` (`EmpleadoFijo` ̧ `EmpleadoTemporal`, `EmpleadoComercial`) on es implementen de manera específica el càlcul de les mateixes.

Has de tindre en compte al treballar amb mètodes abstractes:

- Un mètode abstracte implica que la classe a la que pertany ha de ser abstracta, però això no significa que tots els mètodes d'eixa classe tinguen que ser abstractes.

- Un mètode abstracte no pot ser privat (no es podria implementar, atès que les classes derivades no tendrían accés a ell).

- Els mètodes abstractes no poden ser estátics, ja que els mètodes estátics no poden ser redefinits (i els mètodes abstractes necessiten ser redefinits).

<details markdown="1">

<summary>💡 Exemple 4.02: Revisa amb cura el següent exemple</summary>

Basándote en la jerarquia de classes `Persona`, `Alumno`, `Profesor`, crea un mètode abstracte anomenat `mostrarDatos` per a la classe `Persona`. Depenent del tipus de persona (*alumne* o *professor*) el mètode `mostrarDatos` haurà de mostrar uns o altres dades personals (caldrà fer implementacions específiques en cada classe derivada).
  
  
Una vegada fet açò, implementa completament les tres classes (amb tots els seus atributs i mètodes) i utilízalas en un xicotet programa d'exemple que creu un objecte de tipus `Alumno` i un altre de tipus `Profesor`, els rellene amb informació i mostre eixa informació en la pantalla a través del mètode mostrar.
  
  

**Solució**  

Atès que el mètode `mostrarDatos` no va a ser implementat en la classe `Persona`, serà declarat com abstracte i no es incluirá la seua implementació:

```java
protected abstract void mostrarDatos ();
```

Recorda que el simple fet de que la classe `Persona` continga un mètode abstracte fa que la classe siga abstracta (i haurà d'indicar-se com tal en la seua declaració): 

```java
public abstract class Persona {
...
```

En el cas de la classe `Alumno` caldrà fer una implementació específica del mètode `mostrarDatos` i el mateix per al cas de la classe `Profesor`.

1) Mètode `mostrarDatos` per a la classe `Alumno`:

```java
@Override
public void mostrarDatos() {
    DateTimeFormatter formatoFecha = DateTimeFormatter.ofPattern("dd/MM/yyyy");
    String stringFecha = formatoFecha.format(this.fechaNacimiento);

    System.out.printf ("%-18s%s\n", "Nombre:", this.nombre);
    System.out.printf ("%-18s%s\n", "Apellidos:", this.apellidos);
    System.out.printf ("%-18s%s\n", "Fecha nacimiento:", stringFecha);
    // A continuación mostramos la información "especializada" de esta subclase
    System.out.printf ("%-18s%s\n", "Grupo:", this.grupo);
    System.out.printf ("%-18s%-5.2f\n", "Nota media:", this.notaMedia);    
}
```

2) Mètode `mostrarDatos` per a la classe `Profesor`:

```java
@Override
public void mostrarDatos() {
    DateTimeFormatter formatoFecha = DateTimeFormatter.ofPattern("dd/MM/yyyy");
    String stringFecha = formatoFecha.format(this.fechaNacimiento);

    System.out.printf ("%-18s%s\n", "Nombre:", this.nombre);
    System.out.printf ("%-18s%s\n", "Apellidos:", this.apellidos);
    System.out.printf ("%-18s%s\n", "Fecha nacimiento:", stringFecha);
    // A continuación mostramos la información "especializada" de esta subclase
    System.out.printf ("%-18s%s\n", "Especialidad:", this.especialidad);
    System.out.printf ("%-18s%-7.2f €\n", "Salario:", this.salario);
}
```

3) Un xicotet programa d'exemple d'ús del mètode mostrar en aquestes dos classes podria ser:

```java
import java.time.LocalDate;

public class EjemploUso {

    public static void main(String[] args) {
        // Declaración de objetos
        Alumno alumno;
        Profesor profesor;

        // Creación de objetos (llamada a constructores)
        alumno = new Alumno("Juan", "Torres", LocalDate.of(1990, 10, 6), "1DAW", 7.5);

        profesor = new Profesor("Antonio", "Campos", LocalDate.of(1970, 8, 15), "Informatica", 1750);

        // Utilización del método mostrar
        alumno.mostrarDatos();
        System.out.println();
        profesor.mostrarDatos();
    }
}
```

```java

## 3. Classes i mètodes finals

En unitats anteriors has vist el modificador `final`, encara que només l'has utilitzat per ara per a atributs i variables (per exemple per a declarar atributs constants, que una vegada que prenen un valor ja no poden ser modificats). Però aquest modificador també pot ser utilitzat amb classes i amb mètodes (amb un comportament que no és exactament igual, encara que pot trobar-se certa analogía: **no es permet heredar o no es permet redefinir**).

### 3.1. Classes final

Una classe declarada com `final` no pot ser heredada, és a dir, no pot tindre classes derivades. La jerarquia de classes a la que pertany acaba en ella (no tindrà classes hijas):

```java
[modificador_acceso] final class nombreClase [herencia] [interfaces]
```

### 3.2. Mètodes final

Un mètode també pot ser declarat com `final`, en tal cas, eixe mètode no podrà ser redefinido en una classe derivada:

```java
[modificador_acceso] final <tipo> <nombreMetodo> ([parámetros]) [excepciones]
```

Si intentas redefinir un mètode `final` en una subclase es producirá un error de compilació.

Distints contextos en els que pot aparèixer el modificador `final`:

| Lloc | Funció |
| --- | --- |
| Com modificador de classe. | La classe no pot tindre subclases. |
| Com modificador d'atribut. | L'atribut no podrà ser modificat una vegada que tome un valor. Serveix per a definir constants. |
| Com modificador al declarar un mètode | El mètode no podrà ser redefinido en una classe derivada. |
| Com modificador al declarar una variable referència. | Una vegada que la variable tome un valor referència (un objecte), no es podrà canviar. La variable sempre apuntará al mateix objecte, la qual cosa no vol dir que eixe objecte no puga ser modificat internament a través dels seus mètodes. Però la variable no podrà apuntar a un altre objecte diferent. |
| Com modificador en un paràmetre d'un mètode | El valor del paràmetre (ja siga un tipus primitiu o una referència) no podrà modificar-se dins del codi del mètode. |

Vegem un exemple de cada possibilitat:

<details markdown="1">

<summary>💡 Exemple 4.03: Modificador d'una classe</summary>

```java
public final class ClaseSinDescendencia { // Clase "no heredable"
...
}
```

</details>

<details markdown="1">

<summary>💡 Exemple 4.04: Modificador d'un atribut</summary>

```java
public class ClaseEjemplo {
// Valor constante conocido en tiempo de compilación
final double PI = 3.14159265;
```

// Valor constant conegut solament en temps d'ejecució
final int SEMILLA = (int) Math.random()*10+1;
    ...
}
```

</details>

<details markdown="1">

<summary>💡 Exemple 4.05: Modificador d'un mètode</summary>

```java
public final metodoNoRedefinible (int parametro1) { // Mètode "no redefinible"
    ...
}
```

</details>

<details markdown="1">

<summary>💡 Exemple 4.06: Modificador en una variable referència</summary>

```java
// Referència constant: sempre es apuntará al mateix objecte Alumne
// recién creat, encara que aquest objecte puga sufrir modificacions.
final Alumne PRIMER_ALUMNO = new Alumne ("Pepe", "Torres", 9.55);
```

// Si la variable no es una referencia (tipo primitivo), 
// sería una constante más (como un atributo constante).
final int NUMERO_DIEZ = 10; // Valor constante (dentro del ámbito de vida de la variable)
```

</details>

<details markdown="1">

<summary>💡 Exemple 4.07: Modificador en un paràmetre d'un mètode</summary>

```java
void metodoConParametrosFijos (final int par1, final int par2) {
    // Los parámetros "par1" y "par2" no podrán
    // sufrir modificaciones aquí dentro
    ...
}
```

</details>
