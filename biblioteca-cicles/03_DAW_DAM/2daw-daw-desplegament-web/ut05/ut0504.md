## Arquitectura de Proxy Invers (*Reverse Proxy*)

Un **proxy directe (*Forward Proxy*)** s'ubica al costat dels clients (per exemple, a una xarxa educativa o d'oficina) per a controlar i filtrar la seua eixida cap a Internet. 
En canvi, un **proxy invers (*Reverse Proxy*)** s'ubica davant d'un o diversos servidors web o d'aplicacions interns (backend), actuant com a punt d'entrada únic per a tots els usuaris d'Internet.

```
 [ Clients Internet ]  (HTTPS - Port 443 Públic)
          |
          v
 +---------------------------------------------------+
 |         PROXY INVERS (Nginx / HAProxy)           |
 |  - Punt únic d'entrada públic                     |
 |  - Terminació TLS/SSL                             |
 |  - Memòria cau estàtica (Caching)                 |
 |  - Tallafoc d'aplicació web bàsic (WAF / Rate-limit)|
 +---------------------------------------------------+
     |                      |                     |
     | (HTTP 3000)          | (HTTP 8000)         | (HTTP 8080)
     v                      v                     v
 [ Node.js / Express ]  [ Python / FastAPI ]  [ Java / Tomcat ]
 (Servidors interns privats - No exposats directament a Internet)
```

### Beneficis decisius d'un Proxy Invers
1. **Seguretat i Ocultació:** Els servidors interns escolten en ports privats (`127.0.0.1` o IPs de xarxa privada) i no són accessibles directament des d'Internet.
2. **Terminació TLS (*SSL Termination*):** El certificat TLS s'instal·la exclusivament al proxy invers. El proxy desxifra el trànsit i el distribueix internament per HTTP pur, reduint el consum de CPU dels backends.
3. **Optimització de Recursos:** Nginx pot servir els arxius estàtics (imatges, CSS, JS) directament i derivar al backend només les peticions d'API dinàmiques.

## Configuració de Proxy Invers amb Nginx

A `/etc/nginx/sites-available/reverse-proxy.conf`:

```nginx
server {
    listen 80;
    server_name portal.empresa.val;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name portal.empresa.val;

    ssl_certificate /etc/letsencrypt/live/portal.empresa.val/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/portal.empresa.val/privkey.pem;

    # Recursos estàtics servits directament pel proxy invers
    location /static/ {
        alias /var/www/portal/static/;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    # Desviament cap al servidor d'aplicacions (ex. Node.js al port 3000)
    location / {
        proxy_pass http://127.0.0.1:3000;
        
        # Preservació de capçaleres HTTP crítiques
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Suport per a WebSockets si l'aplicació ho requereix
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

## HAProxy com a Passarel·la d'Alt Rendiment

**HAProxy** (*High Availability Proxy*) és una altra opció de referència de codi obert quan es busca una solució especialitzada en commutació de capa 4 (TCP) i capa 7 (HTTP) a escala massiva de peticions concurrents.
