## Fonaments del Balanceig de Càrrega (*Load Balancing*)

Quan el volum d'usuaris concurrents d'una aplicació web supera la capacitat d'un únic servidor, l'escalabilitat vertical (afegir més CPU i RAM) arriba ràpidament a límits físics i econòmics. L'**escalabilitat horitzontal** consisteix a afegir més servidors idèntics (nodes) en paral·lel, i utilitzar un **balancejador de càrrega** per a repartir les peticions entre ells.

---

## Configuració de Grups `upstream` en Nginx

Nginx defineix els clústers de servidors mitjançant el bloc `upstream`:

```nginx
upstream clúster_aplicacio {
    # Algorisme per defecte: Round-Robin (repartiment seqüencial equitatiu)
    server 192.168.10.11:8080 weight=3 max_fails=3 fail_timeout=10s;
    server 192.168.10.12:8080 weight=1 max_fails=3 fail_timeout=10s;
    server 192.168.10.13:8080 backup;  # Només rep trànsit si els principals cauen
}

server {
    listen 80;
    server_name app.empresa.val;

    location / {
        proxy_pass http://clúster_aplicacio;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### Algorismes de Balanceig Disponibles
1. **Round-Robin (per defecte):** Distribueix les peticions una a una cíclicament entre tots els servidors disponibles.
2. **Ponderat (*Weighted Round-Robin*):** Mitjançant el paràmetre `weight=N`, assigna major proporció de càrrega als servidors amb maquinari més potent.
3. **Menys Connexions (*least_conn*):** Envia la nova petició al servidor que té menys connexions actives en eixe instant (ideal per a peticions llargues o informes feixucs).
4. **IP Hash (*ip_hash*):** Aplica una funció hash a l'adreça IP del client per a dirigir sempre el mateix visitant al mateix node (garanteix persistència de sessions locals).

## Memòria Cau HTTP de Proxy (*Proxy Caching*)

Una altra funció clau del balancejador de càrrega és la **memòria cau de contingut**. Si milers d'usuaris consulten la mateixa portada o catàleg de productes, el proxy invers pot guardar la resposta generada pel backend en memòria RAM/disc i retornar-la directament durant els següents minuts sense molestar la base de dades ni el backend.

```nginx
# Declaració de la ruta de cau a nivell global (http context)
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=MEU_CACHE:10m max_size=1g inactive=60m use_temp_path=off;

server {
    ...
    location / {
        proxy_cache MEU_CACHE;
        proxy_cache_valid 200 302 10m;  # Guarda respostes correctes durant 10 minuts
        proxy_cache_valid 404 1m;        # Guarda errors 404 durant 1 minut
        add_header X-Cache-Status $upstream_cache_status; # Retorna HIT, MISS o BYPASS
        proxy_pass http://clúster_aplicacio;
    }
}
```
