## La Revolució de Nginx i el Problema C10K

A finals dels anys 90, els servidors web patien greus problemes per gestionar més de 10.000 connexions concurrents simultànies (el conegut com a **Problema C10K**). Els servidors clàssics creaven un procés o un fil per cada connexió, esgotant ràpidament la memòria i causant un col·lapse pel cost de canvi de context (*context switching*) de la CPU.

L'any 2004, Igor Sysoev va dissenyar **Nginx** (pronunciat *Engine-X*):
- **Arquitectura orientada a esdeveniments (*Event-Driven Architecture*):** No crea un procés per connexió.
- Disposa d'un **Procés Mestre (*Master Process*)** que gestiona la configuració i privilegis, i un o diversos **Processos Treballadors (*Worker Processes*)**, generalment un per cada nucli físic de CPU.
- Cada *worker* gestiona milers de connexions de forma completament asíncrona i no bloquejant mitjançant mecanismes com `epoll` a Linux.

```
+-------------------------------------------------------+
|                    ARQUITECTURA DE NGINX              |
+-------------------------------------------------------+
|              [ Procés Mestre (Master) ]               |
|            (Llegeix configuració, port 80)            |
|                           │                           |
|         +-----------------+-----------------+         |
|         ▼                                   ▼         |
| [ Worker Process 1 ]              [ Worker Process 2 ]|
|  (Bucle epoll asíncron)            (Bucle epoll asíncron)|
|  - Connexió #1                     - Connexió #3      |
|  - Connexió #2                     - Connexió #4      |
|  (fins a 10.000+ connexions)       (fins a 10.000+)   |
+-------------------------------------------------------+
```

## Estructura de Configuració de Nginx: Blocs `server` i `location`

A Nginx no hi ha fitxers XML ni directives Apache; s'utilitza una sintaxi estructurada per blocs delimitats per claus `{}`:

```nginx
# /etc/nginx/sites-available/el-meu-lloc.conf
server {
    listen 80;
    listen [::]:80;
    
    server_name www.elmeulloc.com elmeulloc.com;
    root /var/www/elmeulloc/html;
    index index.html index.htm index.php;

    # Gestió de fitxers estàtics amb memòria cau
    location ~* \.(jpg|jpeg|png|gif|ico|css|js)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    # Bloqueig de fitxers ocults de Git o entorn
    location ~ /\. {
        deny all;
    }

    # Regla principal per a aplicacions modernes SPA (React, Vue, Laravel)
    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }
}
```

---

## La Directiva `location` i l'Ordre de Precedència

La directiva `location` determina com respon Nginx a les diferents rutes de la URL:
1. **Coincidència exacta (`=`):** `location = /login { ... }` (màxima prioritat).
2. **Prefix amb prioritat (`^~`):** Si coincideix, atura la cerca d'expressions regulars.
3. **Expressió regular sensible a majúscules (`~`):** `location ~ \.php$ { ... }`.
4. **Expressió regular insensible a majúscules (`~*`):** `location ~* \.(png|jpg)$ { ... }`.
5. **Prefix estàndard (sense modificador):** `location /imatges/ { ... }`.

### Comandes d'Administració de Nginx:
- `sudo nginx -t`: **Comprova la sintaxi dels fitxers abans de reiniciar**.
- `sudo systemctl reload nginx`: Recarrega configuracions en calent sense perdre cap connexió activa.
