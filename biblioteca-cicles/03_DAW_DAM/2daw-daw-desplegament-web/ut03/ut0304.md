## El Repte del Desplegament de Node.js en Producció

En entorns de desenvolupament local, n'hi ha prou amb executar `node server.js` al terminal per arrencar una aplicació Express o NestJS. Tanmateix, en un servidor de producció real:
1. Si l'administrador tanca la sessió SSH, el procés de Node.js mor immediatament.
2. Si es produeix una excepció no capturada (`uncaughtException`), el procés cau i la web queda fora de servei.
3. Node.js s'executa sobre un únic fil de CPU; si el servidor té 8 nuclis, els altres 7 romanen completament ociosos.

Per a resoldre aquests tres problemes crítics s'utilitza un **Gestor de Processos en Producció** com **PM2 (Process Manager 2)**.

---

## Què és PM2 i Quines Funcionalitats Aporta?

**PM2** és el gestor de processos en producció per a aplicacions Node.js més utilitzat a la indústria web:
- **Execució en segon pla com a dimoni:** Manté l'aplicació executant-se de forma resident i permanent.
- **Autosanció automàtica (*Auto-Restart*):** Si l'aplicació pateix una fallada o excepció greu, PM2 la reinicia en pocs mil·lisegons sense intervenció humana.
- **Mode Clúster sense canvis de codi:** Aprofita tots els nuclis de la CPU llançant múltiples processos i balancejant les connexions d'entrada.
- **Persistència en reiniciar la màquina:** S'integra amb `systemd` perquè les aplicacions arrenquin automàticament després d'un reinici del servidor.

```bash
# Instal·lació global mitjançant npm
sudo npm install -g pm2

# Llançar l'aplicació en mode clúster aprofitant tots els nuclis
pm2 start app.js -i max --name "el-meu-backend"

# Monitoritzar l'estat, consum de memòria i CPU en temps real
pm2 list
pm2 monit

# Veure registres combinats
pm2 logs

# Guardar la llista de processos actuals i vincular amb systemd
pm2 save
pm2 startup
```

## Fitxers d'Ecosistema: `ecosystem.config.js`

Per a projectes professionals no s'executen comandes soltes de terminal; es defineix un fitxer de configuració estructurat:

```javascript
module.exports = {
  apps: [
    {
      name: 'api-botiga',
      script: './dist/main.js',
      instances: 'max',
      exec_mode: 'cluster',
      env_production: {
        NODE_ENV: 'production',
        PORT: 3000,
        DATABASE_URL: 'mysql://user:pass@localhost:3306/db'
      },
      max_memory_restart: '300M', // Si supera 300 MB per fuita, reinicia
      error_file: './logs/err.log',
      out_file: './logs/out.log'
    }
  ]
};
```
