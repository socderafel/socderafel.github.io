## Evolució dels Models d'Integració Web-Aplicació

A les albors de la web, els servidors només podien lliurar fitxers HTML estàtics desats prèviament al disc. Per permetre la creació de pàgines dinàmiques generades en temps d'execució es van desenvolupar diversos models de comunicació entre el servidor web i el codi d'aplicació:

```
1. Model CGI Clàssic (1993):
   [Servidor Web] --(fork procés nou per petició)--> [Script Perl/C] (lent i pesat)

2. Model Mòdul Integrat (1997 - mod_php):
   [Servidor Web (Apache)] <--- [Mòdul PHP integrat en memòria del servidor]

3. Model FastCGI Persistent (Modern):
   [Servidor Web (Nginx/Apache)] --(Socket UNIX / TCP)--> [Piscina de Processos Persistents PHP-FPM]

4. Model Servidors d'Aplicació Autònoms amb Proxy Invers (Actual):
   [Nginx (Reverse Proxy)] --(Proxy HTTP/WS)--> [Node.js / Gunicorn / Tomcat]
```

---

## 1. El Model CGI (*Common Gateway Interface*)
- **Mecanisme:** Especificació estàndard que permet al servidor web passar la petició HTTP a un programa extern mitjançant **variables d'entorn** (`REQUEST_METHOD`, `QUERY_STRING`, `REMOTE_ADDR`) i rebre la sortida estàndard (*stdout*) com a resposta.
- **Fallada crítica:** Cada petició requereix que el nucli execute una crida `fork()` per crear un procés del sistema nou, carregar l'intèrpret, executar l'script i morir. Si arriben 500 peticions en un segon, el servidor crea 500 processos simultanis, exhaurint la memòria RAM i causant la caiguda del servidor.

---

## 2. El Protocol FastCGI
- **Solució al problema CGI:** En comptes de crear i destruir processos contínuament, FastCGI utilitza un **conjunt de processos persistents (*pool*)** que s'inicien una sola vegada i es mantenen vius a la memòria principal en espera de feina.
- Quan arriba una petició HTTP, el servidor web la multiplexa sobre una connexió persistent (mitjançant un socket UNIX de domini local o un socket de xarxa TCP) cap a un dels processos lliures de la piscina, que processa el codi i retorna el resultat ràpidament sense cap cost de creació de procés.

---

## 3. Especificacions Modernes: Servlets (Java), WSGI/ASGI (Python) i Racks (Ruby)

Per evitar que cada servidor web haja d'escriure codi específic per a cada llenguatge de programació, cada ecosistema ha creat un estàndard unificat d'interfície:
- **Java Servlets:** Especificació de Sun/Oracle on les classes Java implementen la interfície `HttpServlet`, gestionades per un contenidor com Apache Tomcat.
- **PEP 3333 (WSGI - *Web Server Gateway Interface*):** Estàndard universal en Python que connecta servidors web com Gunicorn o uWSGI amb frameworks com Django o Flask.
- **ASGI (*Asynchronous Server Gateway Interface*):** Evolució asíncrona de WSGI dissenyada per a suportar WebSockets i protocols asíncrons amb FastAPI.
