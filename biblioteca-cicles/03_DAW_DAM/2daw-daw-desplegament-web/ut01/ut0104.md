## Fonaments d'Alta Disponibilitat (High Availability - HA)

L'**Alta Disponibilitat** és la característica d'una arquitectura de sistemes dissenyada per garantir un nivell òptim de rendiment operatiu i continuïtat de servei durant un període determinat, fins i tot quan alguns dels seus components individuals fallen de manera imprevista.

Per aconseguir alta disponibilitat cal complir tres principis d'enginyeria:
1. **Eliminació de Punts Únics de Fallada (SPOF):** Duplicació física de tots els elements crítics (servidors, xarxes, alimentació, discs).
2. **Detecció precoç de fallades:** Monitorització contínua mitjançant comprovacions de salut (*Health Checks*).
3. **Commutació transparent per error (*Failover*):** Capacitat de desviar el trànsit d'un node defectuós a un node sa en temps real sense intervenció humana.

---

## Arquitectures de Clúster: Actiu-Passiu vs Actiu-Actiu

Quan s'agrupen múltiples servidors per cooperar com una sola unitat lògica (*clúster*):

```
+-----------------------------------------------------------------+
|                    MODELS DE CLÚSTER EN ALTA DISPONIBILITAT      |
+------------------------------------+----------------------------+
|        Clúster Actiu - Passiu      |     Clúster Actiu - Actiu  |
|          (Failover Clàssic)        |      (Balanceig de Càrrega)|
|                                    |                            |
| [Node A: Actiu] (Serveix trànsit)  | [Node A] (Serveix el 50%)  |
|        │                           |    ▲                       |
|        ▼ (Heartbeat)               |    │                       |
| [Node B: Passiu] (En espera freda) | [Balancejador de Càrrega]  |
|                                    |    │                       |
| Si A mor, B s'encén i assumeix la  |    ▼                       |
| seua IP virtual (VRRP / Keepalived)| [Node B] (Serveix el 50%)  |
+------------------------------------+----------------------------+
```

- **Actiu-Passiu:** Ideal per a recursos que no admeten escriptura concurrent fàcilment (com el node mestre d'una base de dades relacional). El segon node roman en espera fins que el primer falla.
- **Actiu-Actiu:** Ideal per a la capa web frontend i servidors d'aplicacions sense estat. Tots els nodes atenen usuaris simultàniament, multiplicant la capacitat de càrrega i oferint redundància immediata.

---

## Algorismes de Balanceig de Càrrega

El balancejador distribueix les peticions entrants entre els nodes del clúster segons diferents estratègies:
- **Round Robin:** Distribueix les peticions de forma estrictament rotativa i seqüencial (Servidor 1, Servidor 2, Servidor 3, Servidor 1...).
- **Weighted Round Robin:** Assigna un pes a cada servidor segons la seua potència física de maquinari (per exemple, un servidor amb pes 3 rep tres vegades més peticions que un amb pes 1).
- **Least Connections:** Envia la nova petició al servidor que té menys connexions actives en aquest moment (ideal per a peticions llargues o descàrregues de fitxers).
- **IP Hash:** Calcula un hash de l'adreça IP del client per enviar sempre el mateix usuari al mateix servidor (mecanisme bàsic de persistència de sessió).
