## El Model Fonamental Client-Servidor a la Web

El funcionament de la World Wide Web es fonamenta en el patró d'arquitectura distribuïda **Client-Servidor**:
- **Client (User Agent):** Generalment un navegador web (Chrome, Firefox, Safari) o una aplicació mòbil que formula sol·licituds de servei.
- **Servidor:** Un procés o conjunt de processos que escolten permanentment en un port de xarxa (ports estàndard `80` per a HTTP i `443` per a HTTPS), processen la petició rebuda i retornen una resposta estructurada.

```
+----------------+      Peticio HTTP (GET /index.html)     +----------------+
|                | -------------------------------------> |                |
|  Client Web    |                                        |  Servidor Web  |
|  (Navegador)   | <------------------------------------- |  (Apache/Nginx)|
+----------------+      Resposta HTTP (200 OK + HTML)      +----------------+
```

## El Protocol de Comunicació: HTTP/1.1, HTTP/2 i HTTP/3

L'evolució del protocol de transferència d'hipertext ha transformat la velocitat i eficiència de desplegament:

| Protocol | Any | Transport | Característiques Clau |
| :--- | :---: | :---: | :--- |
| **HTTP/1.1** | 1999 | TCP | Connexions persistents (*Keep-Alive*), però pateix de bloqueig en cap de línia (*Head-of-Line Blocking*): cada recurs requereix una petició seqüencial o múltiples connexions TCP concurrents (màxim 6 per domini). |
| **HTTP/2** | 2015 | TCP | **Multiplexació binària:** Totes les peticions i respostes viatgen de forma concorrent sobre una única connexió TCP. Compressió de capçaleres (*HPACK*) i *Server Push*. |
| **HTTP/3** | 2022 | **QUIC (UDP)** | Substitueix TCP pel protocol QUIC basat en UDP. Elimina completament el bloqueig en cap de línia en xarxes inestables (com xarxes mòbils 4G/5G) i xifratge TLS 1.3 integrat per defecte en la capa de transport. |

## El Cicle Petició-Resposta (*Request-Response Cycle*)

Quan un usuari tecleja una URL com `https://www.ieslluissimarro.org/cursos` al navegador:
1. **Resolució DNS:** El client consulta els servidors de noms per traduir el nom de domini a una adreça IP pública.
2. **Negociació TCP / TLS Handshake:** S'estableix la connexió TCP (tres vies: SYN, SYN-ACK, ACK) i es negocia el canal criptogràfic TLS intercanviant certificats digitals i claus de sessió simètriques.
3. **Enviament de la Petició HTTP:** El client envia el mètode (`GET`, `POST`, `PUT`, `DELETE`), la ruta, les capçaleres (*Headers*: `User-Agent`, `Cookie`, `Accept`) i el cos opcional (*Body*).
4. **Processament al Servidor:** El servidor web processa la petició, executa codi dinàmic si cal (PHP, Python, Node) i consulta bases de dades.
5. **Retorn de la Resposta HTTP:** Retorna un codi d'estat (`200 OK`, `301 Redirect`, `404 Not Found`, `500 Internal Error`), capçaleres de resposta (`Content-Type`, `Set-Cookie`) i el document o dades JSON.
