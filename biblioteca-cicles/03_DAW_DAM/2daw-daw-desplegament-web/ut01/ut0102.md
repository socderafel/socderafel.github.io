## El Concepte de Capes i Desacoblament

En enginyeria de programari i desplegament web, una **capa (*tier*)** és una divisió lògica i física de la infraestructura on cada nivell té una responsabilitat clarament definida i només es comunica amb les seues capes adjacents mitjançant interfícies ben definides (APIs o protocols de xarxa).

---

## 1. Arquitectura de Dues Capes (*Client-Server 2-Tier*)
- **Estructura:** Client pesant (*fat client*) connectat directament al Gestor de Base de Dades.
- **Inconvenients:** Seguretat pèssima (el client té la cadena de connexió directa a la base de dades), manteniment costós i escalabilitat pràcticament nul·la per a la web.

---

## 2. Arquitectura de Tres Capes (*3-Tier Architecture*)
És l'estàndard clàssic sobre el qual s'han construït la majoria d'aplicacions web empresarials:

```
[ CAPA 1: PRESENTACIÓ ]      Navegador Web / Client Lleuger
           │                 (HTML, CSS, JavaScript, React, Vue)
           ▼ HTTP / HTTPS
[ CAPA 2: NEGOCI / APP ]     Servidor Web + Servidor d'Aplicacions
           │                 (Apache, Nginx + PHP-FPM, Spring Boot, Node.js)
           ▼ Protocol SQL
[ CAPA 3: DADES / BBDD ]     Servidor de Base de Dades
                             (MySQL, PostgreSQL, Oracle, MongoDB)
```

1. **Capa de Presentació:** S'executa al dispositiu de l'usuari final. S'encarrega exclusivament de renderitzar la interfície gràfica i recollir interaccions.
2. **Capa de Negoci (Lògica d'Aplicació):** S'executa en servidors d'aplicacions protegits. Processa les regles de negoci, valida permisos, autentica usuaris i realitza els càlculs.
3. **Capa de Dades:** Emmagatzema i garanteix la persistència, integritat transaccional (ACID) i seguretat de les dades de negoci.

---

## 3. Arquitectures N-Capes (*Multi-Tier*)
A mesura que les aplicacions creixen per atendre milions de peticions, la capa d'aplicació i de dades se subdivideix en noves capes especialitzades:
- **Capa de Proxy Invers i Balanceig:** (Nginx, HAProxy, AWS ALB) rep les peticions externes i gestiona el xifratge TLS.
- **Capa d'Acceleració i Memòria Cau (*Caching*):** (Redis, Memcached, Varnish) manté en memòria RAM les dades i pàgines més consultades per evitar peticions innecessàries a la base de dades.
- **Capa de Cuetes i Missatgeria Asíncrona:** (RabbitMQ, Apache Kafka, Amazon SQS) desacobla tasques pesades (com l'enviament de milers d'emails o processament de factures) per a ser processades en segon pla per treballadors (*workers*).
