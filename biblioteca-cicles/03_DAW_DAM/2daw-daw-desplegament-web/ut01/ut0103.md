## El Paradigma Monolític Tradicional

En una **arquitectura monolítica**, tota la lògica d'aplicació s'empaqueta i s'executa com una única unitat de programari cohesionada:
- **Exemple típic:** Una aplicació desenvolupada amb Laravel, Django o Spring Boot on el catàleg de productes, el carret de la compra, la passarel·la de pagaments, la gestió d'usuaris i les notificacions comparteixen el mateix codi font i la mateixa base de dades.
- **Avantatges:** Senzillesa inicial de desenvolupament, facilitat per fer proves locals i desplegament inicial ràpid (un sol fitxer `.jar` o directori de codi).
- **Inconvenients:** A mesura que el projecte creix, el codi esdevé complex i difícil de mantenir (*deute tècnic*). Si una part de l'aplicació falla (per exemple, una fuita de memòria al mòdul d'informes), **cau l'aplicació sencera**. A més, per escalar cal duplicar tot el monòlit complet.

---

## L'Arquitectura de Microserveis

En una **arquitectura de microserveis**, l'aplicació es descompon en una col·lecció de serveis menuts, independents, autònoms i feblement acoblats:
- Cada microservei gestiona una única capacitat de negoci (*Single Responsibility Principle*).
- Cada servei té la seua **pròpia base de dades independent** (per evitar dependències d'esquema).
- Es comuniquen a través de la xarxa mitjançant protocols lleugers com **APIs RESTful (JSON sobre HTTP)** o **gRPC**.
- Poden estar programats en llenguatges diferents (poliglots): el servei de catàleg en PHP, el servei d'autenticació en Go i el motor de recomanacions en Python.

---

## Contenidors de Programari: La Tecnologia Docker

Desplegar microserveis directament sobre sistemes operatius tradicionals provocava el clàssic conflicte de dependències (*«A la meua màquina funciona!»*). Els **contenidors Docker** resolen aquest problema empaquetant el codi font juntament amb totes les seues dependències, biblioteques i configuracions en una unitat lleugera i aïllada:

```
+-----------------------------------+     +-----------------------------------+
|         MÀQUINES VIRTUALS         |     |        CONTENIDORS DOCKER         |
+-----------------------------------+     +-----------------------------------+
| [App 1]   [App 2]   [App 3]       |     | [App 1]   [App 2]   [App 3]       |
| (Libs)    (Libs)    (Libs)        |     | (Libs)    (Libs)    (Libs)        |
| [SO Guest][SO Guest][SO Guest]    |     +-----------------------------------+
| (Gbs de mida, arrencada lenta)    |     |          Motor Docker             |
+-----------------------------------+     +-----------------------------------+
|            Hipervisor             |     |      Sistema Operatiu Host        |
+-----------------------------------+     +-----------------------------------+
|       Maquinari Físic             |     |       Maquinari Físic             |
+-----------------------------------+     +-----------------------------------+
```

### Avantatges dels Contenidors en el Desplegament:
1. **Lleugeresa extrema:** Comparteixen el nucli (*kernel*) del sistema operatiu amfitrió, ocupant megabytes en comptes de gigabytes.
2. **Arrencada gairebé instantània:** S'inicien en pocs mil·lisegons o segons.
3. **Portabilitat absoluta:** Una imatge de Docker s'executa amb idèntic comportament a l'equip portàtil del desenvolupador, al servidor de proves i al clúster de producció (Kubernetes / AWS ECS).
