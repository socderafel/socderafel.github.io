## Enjaulament d'Usuaris (*Chroot Jail*)

Quan un desenvolupador web o client es connecta per FTP, per defecte podria navegar per l'arbre de directoris del sistema operatiu (`/etc`, `/var`, `/tmp`, `/usr`), visualitzant fitxers de configuració sensibles. L'operació d'**enjaulament** (*chroot*) canvia l'arrel aparent del sistema de fitxers per a la sessió de l'usuari, fent que la seua carpeta personal (per exemple `/var/www/elmeulloc`) siga interpretada com el directori `/`. L'usuari queda confinat i és incapaç d'accedir a directoris superiors mitjançant `cd ..`.

### Configuració del Chroot a vsftpd
A `/etc/vsftpd.conf`:
```ini
chroot_local_user=YES
chroot_list_enable=NO
```

### El Dilema del *Writable Root* i Solucions
Per a evitar atacs d'evasió de gàbia (*chroot escape*), les versions modernes de vsftpd bloquegen la connexió amb l'error `500 OOPS: vsftpd: refusing to run with writable root inside chroot()` si l'usuari té permís d'escriptura en el seu directori arrel enjaulat.

Hi ha dues solucions vàlides:
1. **Opció de Directiva (més senzilla):**
   ```ini
   allow_writeable_chroot=YES
   ```
2. **Estructura Recomanada de Directoris (bona pràctica):**
   Fer que l'arrel de l'usuari siga de lectura exclusiva de `root`, i crear un subdirectori interior (`public_html` o `upload`) amb permisos per a l'usuari:
   ```bash
   sudo chown root:root /home/usuari_web
   sudo chmod 755 /home/usuari_web
   sudo mkdir /home/usuari_web/public_html
   sudo chown usuari_web:usuari_web /home/usuari_web/public_html
   ```

## Usuaris Locals vs Usuaris Virtuals

En un servidor web que allotja desenes d'aplicacions o múltiples clients (entorn d'allotjament virtual), crear un compte d'usuari Linux local a `/etc/passwd` per a cadascun representa un risc de seguretat considerable:
- Els usuaris locals podrien intentar connectar-se per SSH.
- Poden consumir recursos del sistema o executar binaris.

### Concepte d'Usuaris Virtuals
Els **usuaris virtuals** només existeixen dins de la base de dades d'autenticació del servei FTP (gestionada mitjançant PAM - *Pluggable Authentication Modules*, bases de dades Berkeley DB, fitxers de text pla o bases de dades MySQL/MariaDB).
Tots els usuaris virtuals s'associen (*mapegen*) a un únic usuari sense privilegis del sistema (per exemple `ftpsecure` o `www-data`), assignant a cadascun un directori arrel i permisos independents.

```
 [ Client FTP: 'client1' ] ---> [ Autenticació PAM / DB ] ---> Valida credencials
                                                                        |
                                         +------------------------------+
                                         v
 [ Mapeig al sistema operatiu ] ----> Executat com a usuari 'www-data' (UID 33)
                                      Enjaulat a: /var/www/vhosts/client1/
```
