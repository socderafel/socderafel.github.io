## Introducció a la Transferència de Fitxers en Xarxa

En el cicle de vida del desenvolupament i manteniment de plataformes web, la pujada i sincronització de fitxers (codi font PHP/Python/Node.js, fulls d'estil CSS, scripts JavaScript, imatges i vídeos) requereix mecanismes de xarxa especialitzats. El protocol originari d'Internet per a aquesta finalitat és el **FTP** (*File Transfer Protocol*, definit a la RFC 959 l'any 1985). Malgrat la seua longevitat, la seua arquitectura de doble canal continua sent la base teòrica per a comprendre els serveis de transferència actuals.

```
       +------------------------------------------------+
       |               CLIENT FTP                       |
       +------------------------------------------------+
           | (Port dinàmic client)  | (Port dades client)
           |                        |
           | Canal Control (TCP 21) | Canal Dades (TCP 20 / dinàmic)
           | Comandes i respostes   | Llistats de carpetes i fitxers
           v                        v
       +------------------------------------------------+
       |               SERVIDOR FTP                     |
       +------------------------------------------------+
```

### Arquitectura de Doble Canal

A diferència d'HTTP o SSH, que empren un únic flux TCP bidireccional per a comandes i dades, FTP utilitza dos canals separats:
1. **Canal de Control (Port TCP 21 al servidor):** Es manté obert durant tota la sessió d'usuari. Transmet en text pla (en FTP clàssic) comandes com `USER`, `PASS`, `LIST`, `RETR`, `STOR` i codis de resposta numèrics (com `220 Service ready`, `230 User logged in`, `550 Permission denied`).
2. **Canal de Dades:** S'obre i es tanca de manera efímera per a cada operació que implique transmissió d'informació (enviar el contingut d'un directori amb `LIST`, descarregar un fitxer amb `RETR` o pujar-lo amb `STOR`).

## Modes de Connexió: Actiu vs Passiu

La determinació de quina màquina (client o servidor) inicia la connexió TCP del canal de dades defineix els dos modes operatius de FTP:

### 1. Mode Actiu (*Active Mode* o `PORT`)
- **Procediment:**
  1. El client estableix la connexió de control cap al port 21 del servidor des d'un port local dinàmic (ex. port N = 51234).
  2. Quan cal transferir dades, el client obre un segon port local a l'espera (N+1 = 51235) i envia pel canal de control la comanda `PORT client_ip,port_high,port_low`.
  3. **El servidor és qui s'inicia cap al client:** Des del port 20 d'origen, el servidor llança una connexió TCP entrant cap a la IP i port indicats pel client.
- **La problemàtica del NAT:** Si el client es troba darrere d'un encaminador domèstic o corporatiu amb NAT (*Network Address Translation*), la connexió entrant procedent del port 20 del servidor serà rebutjada pel tallafoc del client, ja que no respon a cap sol·licitud prèvia de sortida coneguda.

### 2. Mode Passiu (*Passive Mode* o `PASV`)
- **Procediment:**
  1. El client obre la connexió de control cap al port 21 del servidor.
  2. Quan cal transferir dades, el client envia la comanda `PASV`.
  3. El servidor obre un port dinàmic aleatori d'un rang predefinit (per exemple, entre 40000 i 40100) i respon al client amb el codi `227 Entering Passive Mode (IP, port)`.
  4. **El client és qui inicia la connexió de dades:** El client es connecta cap a la IP i port passiu del servidor. Com que totes dues connexions són sortints des de la perspectiva del client, els tallafocs i encaminadors NAT permeten el trànsit sense problemes.

## Evolució cap a Canals Xifrats: FTPS i SFTP

| Característica | FTP Estàndard | FTPS (FTP sobre TLS) | SFTP (SSH File Transfer) |
| :--- | :--- | :--- | :--- |
| **Protocol Base** | RFC 959 (FTP) | RFC 4217 (FTP + TLS/SSL) | RFC 4251 (OpenSSH) |
| **Canals TCP** | Doble canal (21 control + dades) | Doble canal (21 xifrat + dades xifrades) | **Canal Únic (Port TCP 22)** |
| **Xifratge** | Cap (text pla vulnerable a sniffer) | TLS 1.2 / TLS 1.3 | Criptografia SSH (AES/ChaCha20) |
| **Ports de Dades** | Port 20 o rangs dinàmics | Rangs dinàmics xifrats (PASV) | Multiplexat dins la sessió SSH |
| **Facilitat Tallafoc** | Complexa darrere de NAT | Requereix obrir rang de ports passius | **Òptima (només el port 22)** |
| **Autenticació** | Usuaris del sistema / virtuals | Usuaris + Certificat X.509 opcional | Claus asimètriques ED25519 o clau/pass |
