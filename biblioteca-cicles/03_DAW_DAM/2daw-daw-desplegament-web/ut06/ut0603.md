## Conceptes Fonamentals de CI/CD

- **Integració Contínua (*Continuous Integration* - CI):** Pràctica de desenvolupament en què els membres d'un equip integren el seu codi de manera molt freqüent en un repositori compartit. Cada integració dispara automàticament un procés de construcció (*build*) i una bateria de tests automatitzats per a detectar errades al més prompte possible.
- **Lliurament Continu (*Continuous Delivery* - CD):** Automatitza la preparació d'artefactes validats llestos per a ser posats en producció en qualsevol moment amb un clic.
- **Desplegament Continu (*Continuous Deployment* - CD):** Tot canvi que supera satisfactòriament les etapes de la canonada de CI es desplega directament i automàticament a l'entorn de producció sense intervenció humana manual.

## Estructura d'un Flux de Treball a GitHub Actions

Els fluxos de treball (*workflows*) es defineixen en fitxers declaratius YAML ubicats al directori `.github/workflows/`:

Exemple de `.github/workflows/deploy.yml`:
```yaml
name: Canonada de CI/CD per a Aplicació Web

on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Descarregar Codi Font
        uses: actions/checkout@v4

      - name: Configurar Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Instal·lar Dependències
        run: npm ci

      - name: Executar Linter i Tests
        run: |
          npm run lint
          npm test

  deploy:
    needs: test  # Només s'executa si la fase de 'test' ha estat un èxit!
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - name: Descarregar Codi Font
        uses: actions/checkout@v4

      - name: Construir Projecte
        run: |
          npm ci
          npm run build

      - name: Desplegar al Servidor via SSH i Rsync
        uses: easingthemes/ssh-deploy@main
        env:
          SSH_PRIVATE_KEY: ${{ secrets.SERVER_SSH_KEY }}
          REMOTE_HOST: ${{ secrets.SERVER_HOST }}
          REMOTE_USER: ${{ secrets.SERVER_USER }}
          SOURCE: "dist/"
          TARGET: "/var/www/elmeulloc/"
          ARGS: "-avz --delete"
```

## Bones Pràctiques de Seguretat en CI/CD

1. **Mai commitejar credencials en clar:** Utilitzar sempre **Repository Secrets** o gestors de secrets com HashiCorp Vault.
2. **Immutabilitat i Traçabilitat:** Utilitzar versions fixades d'accions (`uses: actions/checkout@v4` o sha de commit).
3. **Principi de Privilegi Mínim:** L'usuari SSH de desplegament (`deployer`) no ha de ser `root`; només ha de tindre permisos d'escriptura a la carpeta de publicació `/var/www/`.
