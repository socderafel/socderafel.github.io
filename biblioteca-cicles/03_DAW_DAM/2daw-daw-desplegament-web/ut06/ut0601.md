## Git com a Base del Desplegament Web

El sistema de control de versions distribuït **Git** no és només una eina de seguiment de codi font per a programadors, sinó la font única de veritat (*Single Source of Truth*) per a tota la infraestructura i el desplegament d'aplicacions web. Tota modificació en producció ha de tindre el seu origen en un commit traçable, signat i aprovat mitjançant revisió de parells (*Code Review*).

---

## Models de Flux de Treball en Equip

### 1. Model GitFlow Clàssic
Estructura amb branques de llarga durada dissenyada per a cicles de llançament planificats:
- `main` / `master`: Conté el codi en producció. Cada commit és una versió llançada amb etiqueta (*tag*).
- `develop`: Branca d'integració on convergeixen les noves funcionalitats acabades.
- `feature/*`: Branques temporals per al desenvolupament de funcionalitats individuals creades des de `develop`.
- `release/*`: Branques de preparació per a estabilitzar una nova versió (ajustos de números de versió, correcció d'últimes errades).
- `hotfix/*`: Branques d'emergència creades directament des de `main` per a solucionar vulnerabilitats crítiques en producció.

### 2. Model Trunk-Based Development
Model modern, àgil i àmpliament adoptat en entorns d'alt rendiment DevOps i desplegament continu:
- Una única branca principal activa (`main` o *trunk*).
- Branques de funcionalitat de vida molt curta (*short-lived feature branches*, menys de 24-48 hores).
- Integracions molt freqüents recolzades en bateries exhaustives de proves automàtiques (CI).
- Ús de commutadors de funcionalitats (*Feature Flags*) per a desplegar codi a producció sense activar-lo encara per als usuaris finals.

---

## Etiquetatge (*Tags*) i Versionament Semàntic (SemVer)

Els desplegaments a producció s'identifiquen mitjançant etiquetes que segueixen l'estàndard **Semantic Versioning (MAJOR.MINOR.PATCH)**:
- **MAJOR:** Canvis incompatibles que trenquen la retrocompatibilitat de l'API.
- **MINOR:** Noves funcionalitats que mantenen la compatibilitat amb versions anteriors.
- **PATCH:** Correccions d'errors que no afegeixen noves funcionalitats.

```bash
# Creació d'etiqueta anotada de versió
git tag -a v1.4.0 -m "Llançament de la versió 1.4.0 amb nou mòdul de pagaments"

# Publicació de les etiquetes al repositori remot
git push origin v1.4.0
```
