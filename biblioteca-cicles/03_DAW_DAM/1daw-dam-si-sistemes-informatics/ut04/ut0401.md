## Què és un Sistema de Fitxers (*Filesystem*)?

Un disc dur sense formatar és només una seqüència massiva de sectors de bytes en brut. Un **sistema de fitxers** és l'estructura lògica i el conjunt d'algorismes que el sistema operatiu utilitza per a organitzar, anomenar, assignar espai, trobar i securitzar els fitxers i directoris físics a la unitat.

---

## Unitat d'Assignació: El Clúster o Bloc

L'espai d'un sistema de fitxers es divideix en trossos de mida fixa anomenats **blocs (en Linux) o clústers (en Windows)**, típicament de **4096 bytes (4 KB)**:
- Un fitxer que ocupa 500 bytes gastarà físicament un clúster sencer de 4 KB (els 3596 bytes restants es perden per **fragmentació interna**).
- Un fitxer de 9 KB necessitarà 3 clústers (12 KB reservats).
- La mida de clúster és configurable en formatar: mides menudes (1 KB o 2 KB) redueixen el malbaratament d'espai per a milions de fitxers petits; mides grans (16 KB o 64 KB) maximitzen la velocitat per a servidors de vídeo o bases de dades massives.

---

## Metadades i Estructures Internes: Inodes vs MFT

```
SISTEMA EXT4 (Linux)                          SISTEMA NTFS (Windows)
+-----------------------------------+         +-----------------------------------+
| Taula d'Inodes:                   |         | Master File Table (MFT):          |
| - Inode 1042:                     |         | - Registre 1024 (1 KB per fitxer):|
|   * Mida en bytes                 |         |   * Nom del fitxer                |
|   * Propietari (UID) i Grup (GID) |         |   * Atributs de seguretat (ACLs)  |
|   * Permisos (rwxr-xr--)          |         |   * Marques temporals (MAC)       |
|   * Marques de temps (atime, mtime|         |   * Llista de clústers de dades   |
|   * Punter als blocs de dades     |         |   * Dades petites (Residentes MFT)|
|   (El nom del fitxer es guarda al |         +-----------------------------------+
|    directori pare, NO a l'inode!) |
+-----------------------------------+
```

En Linux, cada fitxer o carpeta està representat per un número d'**inode** únic (`ls -i`).

---

## El Mecanisme de Registre Diari (*Journaling*)

Els sistemes de fitxers moderns com **NTFS**, **ext4**, **XFS** o **Btrfs** implementen *Journaling*:
1. Abans de modificar cap dada al disc, el sistema operatiu escriu un registre atòmic de la transacció en una àrea especial protegida del disc anomenada **Journal**.
2. Posteriorment, s'escriuen les dades reals a les seues ubicacions definitives.
3. Un cop completat amb èxit, la transacció es marca com a completada (*commit*).
4. Si es produeix un tall elèctric just enmig de l'escriptura, en arrencar el sistema operatiu només ha de consultar el Journal per a refer o descartar la transacció interrompuda, recuperant la integritat en fracció de segons sense risc de corrupció de la taula de fitxers.
