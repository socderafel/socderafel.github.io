## Planificació de Tasques Periòdiques: El Dimoni Cron

En sistemes Linux i servidors Unix, el dimoni **`crond` (o `cron`)** s'executa contínuament en segon pla despertant-se cada minut per a comprovar si hi ha tasques programades per a executar.
Cada usuari del sistema té la seua pròpia taula de tasques planificades editable mitjançant la comanda:
```bash
# Editar la taula de cron de l'usuari actual
crontab -e

# Llistar les tasques programades de l'usuari actual
crontab -l

# Editar la taula d'un altre usuari (requereix privilegis d'administrador)
sudo crontab -u www-data -e
```

### Sintaxi Temporal dels 5 Camps de Cron
Una línia de crontab es defineix amb 5 camps temporals seguits de la comanda a executar:

```
 *     *     *     *     *     comanda_a_executar
 |     |     |     |     |
 |     |     |     |     +---- Dia de la setmana (0 - 7, on 0 i 7 són Diumenge)
 |     |     |     +---------- Mes de l'any (1 - 12)
 |     |     +---------------- Dia del mes (1 - 31)
 |     +---------------------- Hora del dia (0 - 23)
 +---------------------------- Minut de l'hora (0 - 59)
```

Exemples pràctics:
- `0 3 * * * /scripts/backup_bbdd.sh`: Tots els dies de l'any a les 03:00 de la matinada.
- `*/15 * * * * /usr/bin/python /check_api.py`: Cada 15 minuts de forma contínua.
- `0 8 1 * * /scripts/informe_mensual.sh`: El dia 1 de cada mes a les 08:00 del matí.

## Gestió Moderna de Registres amb Systemd-Journald

En les distribucions Linux modernes basades en `systemd`, el servei centralitzat **`systemd-journald`** recull els esdeveniments del nucli, serveis del sistema i aplicacions en un format binari indexat d'alta velocitat.

```bash
# Visualitzar tots els registres del sistema
journalctl

# Seguir en temps real els registres (equivalent a tail -f)
journalctl -f

# Filtrar els missatges generats exclusivament pel servei Apache
journalctl -u apache2.service

# Filtrar esdeveniments per nivell de severitat (des d'error fins a emergència)
journalctl -p err..emerg

# Registres des de l'última arrencada del sistema
journalctl -b
```

## El Dimoni Tradicional Rsyslog i la Rotació de Logs (`logrotate`)

Molts serveis tradicionals continuen escrivint els seus esdeveniments en fitxers de text pla sota la jerarquia `/var/log/` mitjançant el dimoni **`rsyslog`**:
- `/var/log/syslog` o `/var/log/messages`: Registre genèric del sistema.
- `/var/log/auth.log` o `/var/log/secure`: Registre d'autenticacions (inicis de sessió, intents fallits SSH, ús de `sudo`).

### La Utilitat Logrotate
Si un servidor d'alt trànsit escriu milions de línies de registre, el disc dur s'ompliria en pocs dies. La utilitat **`logrotate`** automatitza el manteniment:
- Talla periòdicament el registre actual (per exemple, diàriament o setmanalment).
- Comprimeix els registres antics amb `gzip` (`fitxer.log.1.gz`).
- Manté un nombre màxim de versions històriques i esborra automàticament les més antigues.
