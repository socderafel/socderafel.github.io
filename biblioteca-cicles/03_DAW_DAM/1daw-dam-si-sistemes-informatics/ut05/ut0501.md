## La Necessitat dels Models de Comunicació en Capes

La transmissió de dades entre ordinadors a través del món és un problema d'enginyeria extraordinàriament complex. Per a fer-lo abordable, s'utilitza una **arquitectura en capes**: cada capa resol una responsabilitat específica i ofereix serveis a la capa immediatament superior, desacoblant completament els detalls del maquinari físic de la lògica de les aplicacions d'usuari.

---

## Comparativa: Model OSI vs Model TCP/IP

```
MODEL DE REFERÈNCIA OSI (ISO)                 ARQUITECTURA PRÀCTICA TCP/IP (IETF)
+-----------------------------+               +-----------------------------------+
| 7. Capa d'Aplicació         |               |                                   |
+-----------------------------+               |  4. Capa d'Aplicació              |
| 6. Capa de Presentació      | =============>|  - Protocols: HTTP, HTTPS, SSH,   |
+-----------------------------+               |    DNS, DHCP, FTP, SMTP           |
| 5. Capa de Sessió           |               |                                   |
+-----------------------------+               +-----------------------------------+
| 4. Capa de Transport        | =============>|  3. Capa de Transport             |
| - Fiabilitat, ports d'origen/destí          |  - Protocols: TCP (fiable) i UDP  |
+-----------------------------+               +-----------------------------------+
| 3. Capa de Xarxa            | =============>|  2. Capa d'Internet               |
| - Direccionament lògic (IP) i encaminament   |  - Protocols: IPv4, IPv6, ICMP    |
+-----------------------------+               +-----------------------------------+
| 2. Capa d'Enllaç de Dades   | =============>|  1. Capa d'Accés a la Xarxa       |
| - Trametes, adreces físiques MAC, control   |  - Tecnologies: Ethernet (802.3), |
+-----------------------------+               |    Wi-Fi (802.11), Fibra òptica   |
| 1. Capa Física (Senyals, bits, cables)      |                                   |
+---------------------------------------------+-----------------------------------+
```

## El Procés d'Encapsulament de Dades

Quan enviem un missatge (per exemple una petició HTTP des d'un navegador), la informació descendeix per la pila de protocols afegint capçaleres de control (*Headers*):

1. **Capa d'Aplicació:** Genera les dades originals del missatge (`Dades`).
2. **Capa de Transport:** Afegeix la capçalera de transport amb els **ports d'origen i destí** (ex: port 443 per a HTTPS). La PDU resultant s'anomena **Segment (en TCP)** o **Datagrama (en UDP)**.
3. **Capa d'Internet (Xarxa):** Afegeix la capçalera IP amb les **adreces IP d'origen i destí**. La PDU s'anomena **Paquet (*Packet*)**.
4. **Capa d'Accés a Xarxa (Enllaç):** Afegeix la capçalera d'enllaç amb les **adreces físiques MAC d'origen i destí** i una cua (*Trailer*) de comprovació d'errors (FCS / CRC32). La PDU s'anomena **Trama (*Frame*)**.
5. **Capa Física:** Converteix la trama en un tren de **bits binaris** (senyals elèctrics, llum o ones de ràdio).

En el receptor es produeix el procés invers simètric de **desencapsulament**.
