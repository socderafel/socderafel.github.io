La **captura dels errors** és necessària perquè el programa o script que s'execute puga continuar.

A l'hora de programar des del punt de vista del gestor, per mitjà de procediments/funcions, podem realitzar **dos aproximacions** diferents a la gestió d'errors:

- **Capturar les excepcions** que es puguen donar i enviar un missatge al programa client (per mitjà d'un paràmetre d'eixida o un valor concret retornat amb un `SELECT`). En aquest cas, el tractament de l'error el gestionarem **dins del procediment/funció** del gestor.

- **No capturar excepcions** i que siga el programa client el que gestione les mateixes. En aquest cas, fins i tot, podem ser nosaltres mateixos els que **provoquemos una excepció** dins del codi del procediment/funció.

Podria donar-se una combinació de les dos aproximacions.

> **📌 Treballar directament contra MySQL**
> 

> Si treballem directament contra el gestor MySQL **sense fer ús d'un programa client**, llamarem directament als procediments/funcions, per la qual cosa el normal seria **intentar capturar nosaltres les excepcions** perquè l'ejecució dels scripts no es parase si es produjera algun error.

## **Declaració d'excepcions**

Quan capturamos excepcions, podrem capturar:

- **Errors i excepcions definides pel SGBD** (per exemple, `DUPLICATE ENTRY FOR KEY`, que es produeix quan intentem afegir dos files amb la mateixa clau primària).

- **Excepcions creades pel usuari** (per exemple, llançar una excepció quan es intente afegir un animal amb una alçària negativa).

En qualsevol dels dos casos, cada excepció va a estar associada a un **número ja predefinido pel gestor**. Per a fer més llegible el maneig d'excepcions, podem associar aquest número a un **nom d'excepció** i després controlar la captura per aquest nom i no pel número associat.

Per exemple, el codi d'error a l'intentar esborrar una taula que no existeix és el **1051**. Dins d'un procediment podrem capturar aquesta excepció i declarar `no_existe_tabla` quan es produïsca l'error 1051:

```sql
DECLARE no_existe_tabla CONDITION FOR 1051;
```

### **Error Code i SQLState Code**

En la llista de missatges d'error apareixen dos tipus d'errors associats a cada missatge:

- **Error Code**: són números específics de MySQL que no valen per a altres gestors.

- **SQLState Code**: cadena de 5 dígitos basat en ANSI SQL i ODBC i per tant els seus codis són *estandarditzats*.

Emprar un o un altre va a dependre del nostre programa client. En el cas de voler donar un nom a l'excepció emprant el **SQLState**, la sintaxi canvia:

```sql
DECLARE no_existe_tabla CONDITION FOR SQLSTATE '42S02';
```

Alguns codis d'error de MySQL:

| Error Number | Symbol | SQLSTATE | Message |
| --- | --- | --- | --- |
| 1006 | ER_CANT_CREATE_DB | HY000 | Can't create database '%s' (errno: %d - %s) |
| 1007 | ER_DB_CREATE_EXISTS | HY000 | Can't create database '%s'; database exists |
| 1022 | ER_DUP_KEY | 23000 | Can't write; duplicate key in table '%s' |
| 1049 | ER_BAD_DB_ERROR | 42000 | Unknown database '%s' |
| 1050 | ER_TABLE_EXISTS_ERROR | 42S01 | Table '%s' already exists |
| 1051 | ER_BAD_TABLE_ERROR | 42S02 | Unknown table '%s' |
| 1052 | ER_NON_UNIQ_ERROR | 23000 | Column '%s' in %s is ambiguous |

## **Lanzant excepcions: SIGNAL**

Amb **`SIGNAL`** podrem llançar excepcions personalitzades, d'aquesta manera podrem realitzar **validacions de negoci**, com per exemple *el pes dels animals ha de ser major a 0*. Sent la següent sintaxi:

```sql
SIGNAL condition_value
[SET signal_information_item [, signal_information_item] ...]
```

- **`condition_value`**: pot ser un valor de `SQLSTATE` (una cadena literal de 5 caràcters) o un `condition_name` que fa referència a una condició prèviament definida amb `DECLARE ... CONDITION`.

- **`signal_information_item`**: elements d'informació de la condició que es poden establir, com `MESSAGE_TEXT`, `MYSQL_ERRNO`, entre altres.

- El valor de SQLSTATE **no ha de començar amb `'00'`**, ja que aquests indiquen èxit i no són vàlids per a un error. Per a señalar un valor genéric de SQLSTATE s'utilitza **`'45000'`**, que significa *excepció definida pel usuari no manejada*.

- La clàusula `SET` és opcional i permet establir múltiples elements d'informació de la condició:

  - **`MESSAGE_TEXT`**: missatge que es mostrarà a l'usuari.

  - **`MYSQL_ERRNO`**: número d'error específic de MySQL.

  - Altres elements com `SCHEMA_NAME`, `TABLE_NAME`, `COLUMN_NAME`, etc., per a proporcionar més context.

> **📌 Exemple 1. SIGNAL directe**
> 

```sql
DELIMITER $$
CREATE PROCEDURE ejemplo (valor INT)
BEGIN
    IF valor < 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'El valor no puede ser negativo',
            MYSQL_ERRNO = 1001;
    END IF;
END$$
DELIMITER ;
```

> **📌 Exemple 2. Condició amb nom**
> 

```sql
DELIMITER $$
CREATE PROCEDURE ejemplo (valor INT)
BEGIN
    DECLARE condicion_negativa CONDITION FOR SQLSTATE '45000';

    IF valor < 0 THEN
        SIGNAL condicion_negativa
        SET MESSAGE_TEXT = 'El valor no puede ser negativo';
    END IF;
END$$
DELIMITER ;
```

## **Manejant excepcions: DECLARE HANDLER**

Per a añadirle un comportament a la gestió d'errors, necessitem declarar un **manejador d'errors** en el nostre codi, mitjançant `DECLARE HANDLER`, sentència que té la següent sintaxi:

```sql
DECLARE handler_action HANDLER
FOR condition_value [, condition_value] ...
statement
```

- **`handler_action`**: què fer quan ocorre la condició.

  - **`CONTINUE`**: continua l'ejecució amb la següent instrucció.

  - **`EXIT`**: ix del bloc `BEGIN ... END` on està el manejador.

  - **`UNDO`**: (no implementat en MySQL, es accepta però no té efecte).

- **`condition_value`**: la condició a manejar.

  - Codis `SQLSTATE` com `'02000'` (sense resultats).

  - Codis d'error específics de MySQL.

  - Paraules clau com:

    - **`SQLEXCEPTION`**: qualsevol error.

    - **`SQLWARNING`**: advertencias (com truncament).

    - **`NOT FOUND`**: sense resultats (per exemple, en un `SELECT ... INTO` que no troba res).

  - Condicions nombrades amb `DECLARE ... CONDITION`.

- **`statement`**: la instrucció a executar quan ocorre la condició.

Els manejadors es asocian mitjançant `FOR` a codis d'error, estats de SQL (els quals són cadenes i per tant van entre cometes) i les condicions predefinides:

> **📌 Exemples de manejadors**
> 

```sql
-- Manejar un error genérico: evita que el procedimiento se detenga por completo si ocurre un error.
DECLARE CONTINUE HANDLER FOR SQLEXCEPTION
SET @error = 'Ocurrió un error';

-- Manejar un resultado no encontrado. Común en bucles LOOP que leen datos fila a fila con cursores.
DECLARE CONTINUE HANDLER FOR NOT FOUND
SET done = TRUE;

-- Con SQLSTATE
DECLARE EXIT HANDLER FOR SQLSTATE '23000'
SET @error = 'Violación de restricción UNIQUE';
```

### **Exemple sobre la BBDD CIRC**

Controlar si es produeix un error a l'inserir un animal amb pista o atracció inexistente:

> **📌 Procediment amb manejador**
> 

```sql
DELIMITER $$
CREATE PROCEDURE insertarAnimal_Handler(
    IN nom VARCHAR(50),
    IN tipo VARCHAR(9),
    IN anhos INT,
    IN peso FLOAT,
    IN estatura FLOAT,
    IN atraccion VARCHAR(50),
    IN pista VARCHAR(50)
)
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    SELECT 'Error al insertar el animal: posiblemente una clave foránea no existe' AS mensaje;

    INSERT INTO ANIMALES (NOMBRE, TIPO, ANHOS, PESO, ESTATURA, NOMBRE_ATRACCION, NOMBRE_PISTA)
    VALUES (nom, tipo, anhos, peso, estatura, atraccion, pista);

    SELECT 'Animal insertado correctamente' AS mensaje;
END $$
DELIMITER ;

CALL insertarAnimal_Handler('León Rojo', 'felino', 5, 200, 1.5, 'Atracción Falsa', 'Pista 1');
```

## **Exercicis resolts**

### **Exercici 1**

Crea un procediment de nom `animales_Delete` que donat el nom d'un animal, l'esborre. Abans haurà d'esborrar totes les taules relacionades. En el cas que l'animal tinga **menys de 2 anys** no estarà permitido borrar-lo i llançarà una excepció (el codi d'error per a excepcions definides pel usuari és el **45000**) amb el text: *No és possible donar de baixa a animals amb menys de dos anys*. En el cas que l'animal **no existisca**, haurà de llançar una excepció amb el text *'Eixe animal no existeix'* i un **ErrorCode 1643**.

> **📌 Nota**
> 

> Aquest procediment esborra les dades de diverses taules, per la qual cosa necessitaríem fer ús d'una **transacció**.

> **📌 Solució**
> 

```sql
USE CIRCO;
DROP PROCEDURE IF EXISTS animales_delete;
DELIMITER $$
CREATE PROCEDURE animales_delete(p_nombreAnimal VARCHAR(50))
COMMENT 'Da de baja un animal siempre que su edad sea superior a 2 años'
bloque_proc:BEGIN
    DECLARE v_anos TINYINT DEFAULT -1;

    SELECT anhos
    INTO v_anos
    FROM ANIMALES
    WHERE nombre = p_nombreAnimal;

    CASE
        WHEN v_anos = -1 THEN
            SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = 'Ese animal no existe',
                MYSQL_ERRNO = 1643;
            -- LEAVE bloque_proc; NO HACE FALTA YA QUE SIGNAL HACE SALIR DEL PROCEDIMIENTO
        WHEN v_anos < 2 THEN
            SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = 'No se puede dar de baja a animales con menos de dos años';
            -- LEAVE bloque_proc; NO HACE FALTA YA QUE SIGNAL HACE SALIR DEL PROCEDIMIENTO
        ELSE BEGIN END;
    END CASE;

    -- BORRAMOS LOS ANIMALES. Necesitaríamos una transacción.
    DELETE FROM ANIMALES_ARTISTAS
    WHERE nombre_animal = p_nombreAnimal;

    DELETE FROM ANIMALES
    WHERE nombre = p_nombreAnimal;
END$$
DELIMITER ;

CALL animales_delete('no_existe');   -- Devuelve el código 1643
CALL animales_delete('Berni');       -- No cumple que la edad sea superior a 2 años.
CALL animales_delete('Princesa2');   -- Lo da de baja de todas las tablas
```

### **Exercici 2**

Crea un procediment de nom `animales_addArtista` al que es li passe el **nom d'un animal** i el **nif d'un artista** i asigne el cuidador a l'animal. Haurà de comprovar que l'animal i l'artista existeixen. En cas que no, haurà de llançar una excepció amb el **ErrorCode 1643** i text *'L'animal no existeix'* o *'L'artista no existeix'*.

> **📌 Solució**
> 

```sql
USE CIRCO;
DROP PROCEDURE IF EXISTS animales_addArtista;
DELIMITER $$
CREATE PROCEDURE animales_addArtista(p_nombreAnimal VARCHAR(50), p_nif CHAR(9))
COMMENT 'Asigna un nuevo artista a un animal.'
bloque_proc:BEGIN
    IF (SELECT COUNT(*) FROM ANIMALES WHERE nombre = p_nombreAnimal) = 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Ese animal no existe',
            MYSQL_ERRNO = 1643;
        -- LEAVE bloque_proc; NO HACE FALTA YA QUE SIGNAL HACE SALIR DEL PROCEDIMIENTO
    END IF;

    IF (SELECT COUNT(*) FROM ARTISTAS WHERE nif = p_nif) = 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Ese artista no existe',
            MYSQL_ERRNO = 1643;
        -- LEAVE bloque_proc; NO HACE FALTA YA QUE SIGNAL HACE SALIR DEL PROCEDIMIENTO
    END IF;

    INSERT INTO ANIMALES_ARTISTAS (nombre_animal, nif_artista)
    VALUES (p_nombreAnimal, p_nif);
END$$
DELIMITER ;

CALL animales_addArtista('no_existe', '11111111A');
CALL animales_addArtista('Princesa1', 'no_existe');
CALL animales_addArtista('Leo', '33333333C'); -- Si lanzamos dos veces esta orden, MySQL lanzará una excepción de clave duplicada.
```

### **Exercici 3**

Crea un procediment de nom `animales_add` que afegeix un nou animal. En cas d'intentar donar d'alta un animal amb el **mateix nom**, captura l'excepció i fes que el procediment retorne (amb un select) **-1**. En cas que l'alta siga correcta, que retorne **0**. En el cas que el nom de la pista o de l'atracció **no existisca**, captura l'excepció i retorna el valor **-2**.

> **📌 Pistes**
> 

> - Treballa amb **noms d'excepcions** en compte d'amb els números associats: `ex_claveDuplicada`, `ex_pista_atracc_no_existe`.

> - Per a saber el número d'excepció que has de capturar, **provoca el fallada i anota el número**.

> **📌 Solució**
> 

```sql
USE CIRCO;
DROP PROCEDURE IF EXISTS animales_add;
DELIMITER $$
CREATE PROCEDURE animales_add(p_nombreAnimal VARCHAR(50), p_tipo VARCHAR(9), p_anos TINYINT,
                              p_peso FLOAT, p_estatura FLOAT, p_atraccion VARCHAR(50), p_pista VARCHAR(50))
COMMENT 'Añade un nuevo animal.'
BEGIN
    DECLARE ex_claveDuplicada CONDITION FOR 1062;
    DECLARE ex_pista_atracc_no_existe CONDITION FOR 1452;

    DECLARE EXIT HANDLER FOR ex_claveDuplicada
    BEGIN
        SELECT -1;
    END;

    DECLARE EXIT HANDLER FOR ex_pista_atracc_no_existe
    BEGIN
        SELECT -2;
    END;

    INSERT INTO ANIMALES (nombre, tipo, anhos, peso, estatura, nombre_atraccion, nombre_pista)
    VALUES (p_nombreAnimal, p_tipo, p_anos, p_peso, p_estatura, p_atraccion, p_pista);

    SELECT 0;
END$$
DELIMITER ;

CALL animales_add('Leo', 'León', 3, 230, 1.34, NULL, NULL);                    -- Clave duplicada
CALL animales_add('Leo2', 'León', 3, 230, 1.34, 'NO EXISTE', NULL);            -- Atracción que no existe
CALL animales_add('Leo2', 'León', 3, 230, 1.34, 'El gran felino', 'SUPER');    -- Todo correcto
```

> **📌 Nota**
> 

> Com el procediment només va a tindre una ordre `INSERT`, no fa falta fer que salga del mateix al producir-se l'excepció. Fijar-se que **no es produeix una excepció** en l'anomenada al procediment, per la qual cosa l'ejecució amb ordres posteriors seguiría.

### **Exercici 4**

Crea un procediment de nom `artistas_add` que afegeix un nou artista. S'ha de comprovar si el **nif existeix**. Aquesta comprovació es farà **capturant l'excepció corresponent**. En cas d'error, s'enviarà en un **paràmetre d'eixida** el valor **-1**. Si tot està correcte s'enviarà el valor **0**.

> **📌 Pistes**
> 

> - Crea un nom d'excepció: `ex_artista_duplicado`.

> - Al costat de les dades de l'artista s'ha d'enviar el **nom d'un animal** (ha d'estar prèviament donat d'alta) que va a cuidar l'artista.

> - S'ha d'anomenar al mètode `animales_addArtista` (creat prèviament) i **capturar la possible excepció** que lance aquest mètode emprant el SQLSTATE. Si l'animal no existeix ha d'enviar en el paràmetre d'eixida el valor **-2**.

> - Crea un nom d'excepció: `ex_animal_no_existe`. Qualsevol excepció que es produïsca ha de fer que es salga del procediment.

> **📌 Solució**
> 

```sql
USE CIRCO;
DROP PROCEDURE IF EXISTS artistas_add;
DELIMITER $$
CREATE PROCEDURE artistas_add(p_nif CHAR(9), p_apellidos VARCHAR(100), p_nombre VARCHAR(50),
                              p_nifJefe CHAR(9), p_nombreAnimal VARCHAR(50), OUT p_resultado TINYINT)
COMMENT 'Añade un nuevo artista.'
BEGIN
    DECLARE ex_artista_duplicado CONDITION FOR 1062;
    DECLARE ex_animal_no_existe CONDITION FOR SQLSTATE '45000';

    DECLARE EXIT HANDLER FOR ex_artista_duplicado
        SET p_resultado = -1;

    DECLARE EXIT HANDLER FOR ex_animal_no_existe
        SET p_resultado = -2;

    INSERT INTO ARTISTAS (nif, apellidos, nombre, nif_jefe)
    VALUES (p_nif, p_apellidos, p_nombre, p_nifJefe);

    CALL animales_addArtista(p_nombreAnimal, p_nif);

    SET p_resultado = 0;
END$$
DELIMITER ;

CALL artistas_add('11111111A', 'Orten Sanlat', 'Cristina', NULL, 'Leo', @resultado); -- Devuelve -1 => Clave primaria duplicada
SELECT @resultado;

CALL artistas_add('11111122F', 'Orten Sanlat', 'Cristina', '92828822A', 'Leo', @resultado); -- Devuelve 0 => Nif jefe no existe pero el trigger lo cambia por NULL
SELECT @resultado;

CALL artistas_add('11111144F', 'Jiménez Royal', 'Lucas', NULL, 'Leo_NO_EXISTE', @resultado); -- Devuelve -2 => Animal no existe PERO al no estar en una transacción, el artista se ha añadido
SELECT @resultado;
```

> **📌 Transaccions**
> 

> Aquest mètode és un candidato per a realitzar una **transacció** ja que va a afectar a dos taules (va a afegir dos files).

> **📌 Resum**
> 

> - Podem **capturar excepcions** (enviant un codi al client) o **dejar-les que les gestione el programa client**.

> - `DECLARE ... CONDITION FOR` assigna un **nom** a un codi d'error (`Error Code`) o `SQLSTATE`.

> - **`SIGNAL`** llança excepcions personalitzades (`SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '...'`).

> - **`DECLARE ... HANDLER`** defineix què fer ante una condició: `CONTINUE` o `EXIT`.

> - Condicions predefinides: `SQLEXCEPTION`, `SQLWARNING` i `NOT FOUND`.

> - El codi 45000 és la *excepció definida pel usuari*.
