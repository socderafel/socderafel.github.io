# 1.2 Introducció a les Bases de Dades i Objectius

La evolución lógica de los problemas derivados del uso de los fitxers fue estandarizar el acceso a la información, de manera que un disseny físic específico servía para todas las aplicaciones de una organización.
Este nuevo enfoque se centró en los datos más que en el proceso; és a dir, el emmagatzematge de los datos se estructuraba independientemente de las aplicaciones que las iban a utilizar. També se eliminó la redundancia y se favoreció la transferencia de información entre aplicaciones. Apareció el concepto de base de dades.

## **Conceptos**

- **Base de dades**: Es una colección de datos relacionados lógicamente entre sí, con una definición y descripción comunes y que están estructurados de una determinada manera. Es un conjunto estructurado de datos que representa entidades y sus interrelaciones, almacenados con la mínima redundancia y posibilitando el acceso a ellos eficientemente por parte de diversas aplicaciones y usuaris.

- També almacena una descripción de estos datos. Se denomina metadato, se almacena en el diccionario de datos o catálogo y es el que permet que exista independencia de datos lógico‐físico.

Una base de dades constará de los siguientes elementos:

- **Entidades**: Objeto real o abstracto con características diferenciadoras de otros, del que se almacena información en la base de dades.

- **Atributos**: Son los datos que se almacenan de la entidad. Cualquier propiedad o característica de una entidad puede ser atributo.

- **Registros**: Donde se almacena la información de cada entidad. Es un conjunto de atributos que contienen los datos que pertenecen a una misma repetición de entidad.

- **Campos**: Donde se almacenan los atributos de cada registre.

## **Uso**.

### **¿Quién las utiliza?**

Existen cuatro tipos de personas que pueden hacer uso de una base de dades: el administrador, los diseñadores de la base de dades, los programadores de aplicaciones y los usuaris finales.

- **Administrador**: Es la persona encargada de la creación o implementación física y las políticas de seguridad y accesos de la base de dades.

- **Diseñador**: Son las personas encargadas de diseñar cómo será la base de dades. Llevarán a cabo la identificación de los datos, las relaciones entre ellos, sus restricciones, etc.

- **Programadores de aplicaciones**: Ofrecerán la posibilidad de realizar consultes de datos, inserción, actualización o eliminación de los mismos por medio de las aplicaciones.

- **Usuario Final**: Son los clientes finales de la base de dades.

## **Ubicación de la información**

Las bases de dades pueden tener un tamaño muy reducido o bien, ser muy voluminosas y complejas. Una BBDD puede necesitar servidores en lugares diferentes, y viceversa, pequeñas bbdd pueden existir como archivos en el disco duro de un único equipo.

- **Discos SATA**: Interfaz de transferencia de datos.

- **Discos SCSI**: Interfaces preparadas para discos duros de gran capacidad de emmagatzematge y velocidad de rotación.

- **RAID**: Se basa en el montaje en conjunto de 2 o más discos duros, formando un bloque de trabajo, para obtener capacidad, mejoras en velocidad o seguridad de emmagatzematge.

- **Sistemas NAS**: Permite compartir la capacidad de emmagatzematge de un Servidor con ordenadores personales o servidores clientes a través de una red.

- **Sistemas SAN**: Se trata de una red concebida para conectar servidores, matrices (arrays) de discos y librerías de soporte.

## **Modelos de BBDD**

Esta es una de las formas de clasificación de las BBDD, que nos indica su organización lógica de la información. Las más utilizadas en estos momentos son:

- 

**Modelo Jerárquico**: Organizan los datos en una estructura en árbol, donde cada nodo tiene un padre y puede tener varios hijos. Es un modelo de datos más antiguo, pero todavía utilizado en ciertos sistemas.

- **Ventajas**: Rápido acceso a datos en sistemas donde las relaciones son naturales en forma de árbol.

- **Desventajas**: Dificultad para manejar relaciones complejas que no encajan en una estructura jerárquica. Escalabilidad limitada.

- 

**Modelo en Red**: Son una evolución de las bases de dades jerárquicas donde un nodo puede tener múltiples padres, formando una red de interconexiones más flexible.

- **Ventajas**: Más flexibilidad que las bases de dades jerárquicas.

- **Desventajas**: Más complejas de gestionar que las bases de dades relacionals. Más difíciles de modelar y mantener.

- 

**Modelo Relacional**: Almacenan los datos en taules que es poden enlazar entre sí mediante claus primàries y foraneas. Utilizan el lenguaje SQL para la gestión de datos.

- **Ventajas**: Soportan transaccions ACID (Atomicidad, Consistencia, Aislamiento, Durabilidad). Son muy estandarizadas y ampliamente utilizadas.

- **Desventajas**: Puede ser menos eficiente para datos no estructurados o semi-estructurados. Escalabilidad vertical limitada.

- 

**Modelo NoSQL**: Incluyen una variedad de modelos de datos diferentes a los relacionales, como documentos, claves-valor, columna ancha y gráficos. Están diseñadas para gestionar grandes volúmenes de datos no estructurados o semi-estructurados.

- **Ventajas**: Muy escalables horizontalmente. Flexibles para datos no estructurados o semi-estructurados.

- **Desventajas**: A menudo no soportan transaccions ACID completas. Menos estandarización e interoperabilidad.
