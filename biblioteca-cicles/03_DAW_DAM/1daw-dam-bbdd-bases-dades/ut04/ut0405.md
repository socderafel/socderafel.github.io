# 4.5 Llenguatge de Control de Dades (DCL): CREATE USER, GRANT i REVOKE

El **Lenguaje de Control de Datos (Data Control Language - DCL)** es el conjunto de instrucciones SQL encargado de gestionar la **seguridad** de una base de dades.

Mientras que el **DDL** define la estructura y el **DML** manipula los datos, el **DCL** controla **quién puede acceder a la información y qué operaciones puede realizar**.

Gracias al DCL es posible:

- Crear usuaris.

- Modificar usuaris.

- Eliminar usuaris.

- Asignar permisos.

- Revocar permisos.

- Gestionar la seguridad de la base de dades.

Objetivo del DCL

El DCL garantiza que **cada usuari solo pueda realizar las operaciones para las que ha sido autorizado**, protegiendo la integridad y confidencialidad de la información.

## **Usuarios**

Antes de asignar permisos es necesario crear los usuaris que accederán al sistema.

Cada usuari dispone de:

- Un nombre.

- Un equipo (host) desde el que puede conectarse.

- Una contraseña.

- Un conjunto de privilegis.

En MySQL un usuari se identifica mediante:

```sql

```

```sql

```

| --- | --- |

Per exemple:

```sql

```

```sql

```

| --- | --- |

o

```sql

```


### **CREATE USER**

La instrucción `CREATE USER` crea un nuevo usuari.

Sintaxis básica

```sql

```

```sql

```

| 1 2 3 | CREATE USER 'nombre_usuari'@'localhost' IDENTIFIED BY 'contraseña'; |
| --- | --- |

Ejemplo: crear el usuari 'profesor'

```sql

```

```sql

```

| 1 2 3 | CREATE USER 'profesor'@'localhost' IDENTIFIED BY 'abc123'; |
| --- | --- |

El usuari podrá conectarse a MySQL utilizando esas credenciales.

Usuarios y permisos

Crear un usuari **no implica que tenga permisos sobre ninguna base de dades**.

### **ALTER USER**

Permite modificar las características de un usuari existente.

Normalmente se utiliza para cambiar la contraseña.

ALTER USER

```sql

```

```sql

```

| 1 2 3 | ALTER USER 'profesor'@'localhost' IDENTIFIED BY 'NuevaContraseña'; |
| --- | --- |

### **DROP USER**

Elimina completamente un usuari.

DROP USER

```sql

```

```sql

```

| 1 2 | DROP USER 'profesor'@'localhost'; |
| --- | --- |

Después de ejecutar esta instrucción el usuari ya no podrá acceder al servidor.

## **Privilegios**

Los privilegis determinan las operaciones que un usuari puede realizar.

Existen privilegis para:

- Consultar datos.

- Insertar registres.

- Modificar información.

- Eliminar registres.

- Crear taules.

- Modificar taules.

- Crear usuaris.

- Administrar el servidor.

Los permisos se gestionan mediante dos instrucciones:

- `GRANT`

- `REVOKE`

Efecto de los cambios de permisos

- Los cambios en los privilegis de **taula y columna** tienen efecto inmediatamente, aunque el usuari ya se encuentre conectado.

- Los cambios a nivel de **base de dades** no tienen efecto hasta que el usuari ejecuta `USE nombre_db;`.

- Los cambios en los privilegis **globales** no tienen efecto hasta que el cliente vuelve a conectarse.

### **GRANT**

La instrucción `GRANT` permet conceder permisos a usuaris o roles.

Sintaxis general

```sql

```

```sql

```

| 1 2 3 4 | GRANT privilegis ON objeto TO usuari; |
| --- | --- |

### **Ejemplo básico**

Conceder todos los permisos sobre una base de dades.

GRANT ALL

```sql

```

```sql

```

| 1 2 3 4 | GRANT ALL ON instituto.* TO 'profesor'@'localhost'; |
| --- | --- |

### **Permiso de consulta**

GRANT SELECT

```sql

```

```sql

```

| 1 2 3 4 | GRANT SELECT ON instituto.* TO 'profesor'@'localhost'; |
| --- | --- |

El usuari únicamente podrá consultar información.

### **Varios permisos simultáneamente**

Es posible conceder varios permisos en una sola instrucción.

GRANT con varios permisos

```sql

```

```sql

```

| 1 2 3 4 5 6 7 | GRANT SELECT, INSERT, UPDATE ON instituto.* TO 'profesor'@'localhost'; |
| --- | --- |

## **Privilegios globales**

Los privilegis globales afectan a **todo el servidor MySQL**.

Para ello se utiliza:

```sql

```

```sql

```

| 1 | ON *.* |
| --- | --- |

Ejemplo:

GRANT a nivel global

```sql

```

```sql

```

| 1 2 3 4 | GRANT SELECT ON *.* TO 'profesor'@'localhost'; |
| --- | --- |

Este usuari podrá consultar cualquier taula de cualquier base de dades.

Varios permisos globales

```sql

```

```sql

```

| 1 2 3 4 | GRANT SELECT, UPDATE ON *.* TO 'profesor'@'localhost'; |
| --- | --- |

Efecto de los permisos globales

Si el usuari ya está conectado cuando se modifica un permiso global, el cambio **no se aplicará** hasta que cierre la sesión y vuelva a conectarse.

El privilegi USAGE

Cuando se crea un usuari nuevo, el único privilegi que posee es **USAGE**, que únicamente permet conectarse al servidor.

## **Privilegios sobre una base de dades**

Es el nivel más utilizado.

Se conceden permisos únicamente sobre una base de dades concreta.

GRANT ALL sobre una base de dades

```sql

```

```sql

```

| 1 2 3 4 | GRANT ALL ON instituto.* TO 'profesor'@'localhost'; |
| --- | --- |

### **Ejemplo**

Permitir consultar e insertar información.

GRANT SELECT, INSERT sobre una base de dades

```sql

```

```sql

```

| 1 2 3 4 5 6 | GRANT SELECT, INSERT ON instituto.* TO 'profesor'@'localhost'; |
| --- | --- |

### **Permisos disponibles**

| Permiso | Función |
| --- | --- |
| SELECT | Consultar datos |
| INSERT | Insertar registres |
| UPDATE | Modificar registres |
| DELETE | Eliminar registres |
| CREATE | Crear taules |
| DROP | Eliminar taules |
| ALTER | Modificar taules |
| REFERENCES | Crear claus foranes |
| EVENT | Gestionar esdeveniments (events) |
| LOCK TABLES | Bloquear taules |

Permisos CREATE, ALTER y DROP

- `CREATE` permet crear taules.

- `DROP` elimina taules.

- `ALTER` modifica una taula (requiere el privilegi `CREATE`).

## **Privilegios sobre procedimientos**

També pueden concederse permisos relacionados con procediments emmagatzemats y funciones.

GRANT sobre rutinas

```sql

```

```sql

```

| 1 2 3 4 5 6 | GRANT CREATE ROUTINE, ALTER ROUTINE ON instituto.* TO 'profesor'@'localhost'; |
| --- | --- |

Rutinas

No existe el permiso `DROP ROUTINE`. Si un usuari posee el permiso `ALTER ROUTINE` puede modificar o borrar una rutina.

## **WITH GRANT OPTION**

Existe un permiso especial denominado **WITH GRANT OPTION**.

Permite que el usuari pueda conceder a otros usuaris los mismos permisos que ha recibido.

Ejemplo con WITH GRANT OPTION

```sql

```

```sql

```

| 1 2 3 4 5 6 7 | GRANT SELECT, INSERT ON instituto.* TO 'profesor'@'localhost' WITH GRANT OPTION; |
| --- | --- |

## **Permisos sobre taules**

En ocasiones únicamente interesa permitir el acceso a una taula concreta.

GRANT sobre una taula

```sql

```

```sql

```

| 1 2 3 4 5 6 | GRANT SELECT, INSERT ON instituto.alumno TO 'profesor'@'localhost'; |
| --- | --- |

En este caso el usuari únicamente podrá trabajar con la taula `alumno`.

Privilegios a nivel de taula

Los privilegis que manejan la estructura de la taula son `CREATE`, `ALTER` y `DROP`. Los que manejan los datos de la taula son `DELETE`, `SELECT`, `UPDATE` e `INSERT`. També existen privilegis para vistes (`CREATE VIEW`, `SHOW VIEW`, `DROP VIEW`), índices (`INDEX`) y disparador (trigger)s (triggers) (`TRIGGER`).

## **Permisos sobre columnes**

MySQL també permet conceder permisos únicamente sobre determinadas columnes.

GRANT sobre columnes

```sql

```

```sql

```

| 1 2 3 4 5 6 | GRANT SELECT(nombre), UPDATE(nombre) ON instituto.alumno TO 'profesor'@'localhost'; |
| --- | --- |

El usuari únicamente podrá consultar y modificar la columna `nombre`.

## **REVOKE**

La instrucción `REVOKE` elimina permisos previamente concedidos.

Su sintaxis es muy similar a `GRANT`.

Sintaxis general

```sql

```

```sql

```

| 1 2 3 4 | REVOKE privilegis ON objeto FROM usuari; |
| --- | --- |

### **Ejemplo**

Eliminar el permiso de inserción.

REVOKE INSERT

```sql

```

```sql

```

| 1 2 3 4 5 | REVOKE INSERT ON instituto.* FROM 'profesor'@'localhost'; |
| --- | --- |

### **Eliminar todos los privilegis**

També es posible eliminar todos los permisos concedidos.

REVOKE ALL PRIVILEGES

```sql

```

```sql

```

| 1 2 3 4 5 | REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'profesor'@'localhost'; |
| --- | --- |

Después de ejecutar esta instrucción el usuari únicamente conservará el privilegi **USAGE**.

## **Buenas prácticas de seguridad**

Recomendaciones

- Concede únicamente los permisos estrictamente necesarios.

- Evita utilizar el usuari `root` para aplicaciones.

- Asigna permisos sobre bases de dades concretas en lugar de privilegis globales.

- Utiliza contraseñas seguras.

- Revisa periódicamente los permisos de los usuaris.

- Elimina los usuaris que ya no sean necesarios.

## **Resumen**

Ideas clave

- El **DCL** controla el acceso a la base de dades mediante usuaris y permisos.

- `CREATE USER`, `ALTER USER` y `DROP USER` permeten gestionar usuaris.

- `GRANT` concede privilegis y `REVOKE` los elimina.

- Los permisos pueden aplicarse a nivel global, de base de dades, de taula o incluso de columna.

- `SHOW GRANTS` permet consultar los privilegis asignados a un usuari.

- Es recomendable aplicar siempre el **principio del mínimo privilegi**, concediendo únicamente los permisos necesarios para realizar cada tarea.
