Una vegada dissenyada l'estructura d'una taula, el següent pas consisteix en seleccionar el **tipus de dada** més adequat per a cada un dels seus atributs. El tipus de dada determina:

- El tipus d'informació que podrà almacenar-se.

- L'espai ocupat en disc.

- El rang de valors permesos.

- Les operacions que podran realitzar-se sobre eixe camp.

Seleccionar correctament el tipus de dada millora el rendiment de la base de dades, redueix l'espai utilitzat i evita errors d'integritat.

## **Classificació dels tipus de dades**

MySQL agrupa els [tipus de dades](https://dev.mysql.com/doc/refman/8.0/en/data-types.html) en cinc grans categories:

- Tipus numèrics.

- Tipus de cadenes de caràcters.

- Tipus de data i hora.

- Tipus espacials.

- Tipus JSON.

### **Tipus de dades numèrics**

Els tipus numèrics permeten emmagatzemar números enters i decimals. La seua elecció dependrà principalment del rang de valors que necessitem emmagatzemar.

#### **Enters**

| Tipus | Ús recomanat | Mida | Rang (amb signe) | Rang (sense signe) |
| --- | --- | --- | --- | --- |
| TINYINT | Valors xicotets, estats, edades | 1 byte | -128 a 127 | 0 a 255 |
| SMALLINT | Quantitats moderades | 2 bytes | -32.768 a 32.767 | 0 a 65.535 |
| MEDIUMINT | Enter mediano | 3 bytes | -8.388.608 a 8.388.607 | 0 a 16.777.215 |
| INT | Identificadors i valors generals | 4 bytes | -2.147.483.648 a 2.147.483.647 | 0 a 4.294.967.295 |
| BIGINT | Grans quantitats o identificadors masivos | 8 bytes | -9.223.372.036.854.775.808 a 9.223.372.036.854.775.807 | 0 a 18.446.744.073.709.551.615 |

Si el número mai serà negatiu pot utilitzar-se el modificador:

```sql
INT UNSIGNED
```

el que permet duplicar el rang positiu disponible.

#### **Números decimals**

Quan és necessari emmagatzemar valors amb decimals, MySQL ofereix diversos tipus.

| Tipus | Ús recomanat | Mida | Rang (amb signe) |
| --- | --- | --- | --- |
| DECIMAL(M,D) | Importes económics, preus i dades que requereixen precisió exacta | Variable | Fins a 65 xifres (30 decimals com a màxim) |
| FLOAT | Medicions aproximades, dades científics amb menor precisió | 4 bytes | ±3,4 × 10³⁸ (≈ 7 xifres significativas) |
| DOUBLE | Càlculs científics o estadístics que requereixen major precisió | 8 bytes | ±1,79 × 10³⁰⁸ (≈ 15 xifres significativas) |

### **Tipus de cadenes de caràcters**

Aquests tipus emmagatzemen text. La principal diferència entre ells reside en el mida màxim i en si ocupen una longitud fixa o variable.

| **Tipus de dada** | **Descripció** |
| --- | --- |
| CHAR(N) | Cadena de caràcters de longitud fixa (**N** caràcters). |
| VARCHAR(N) | Cadena de caràcters de longitud variable (fins a **N** caràcters). |
| TEXT | Cadena de text llarga (fins a **65.535** caràcters). |
| TINYTEXT | Cadena de text corta (fins a **255** caràcters). |
| MEDIUMTEXT | Cadena de text mediana (fins a **16.777.215** caràcters). |
| LONGTEXT | Cadena de text molt llarga (fins a **4.294.967.295** caràcters). |
| BLOB | Emmagatzema dades binaris (fins a **65.535** bytes). |
| TINYBLOB | Emmagatzema dades binaris xicotets (fins a **255** bytes). |
| MEDIUMBLOB | Emmagatzema dades binaris medianos (fins a **16.777.215** bytes). |
| LONGBLOB | Emmagatzema dades binaris molt grans (fins a **4.294.967.295** bytes). |
| BOOLEAN o BOOL | Usat per a valors booleanos (`0` o `1`, `FALSE` o `TRUE`). |

### **Tipus de data i hora**

Permeten emmagatzemar informació temporal.

| Tipus | Format | Exemple | Descripció |
| --- | --- | --- | --- |
| DATE | YYYY-MM-DD | 2005-11-18 | Data en format YYYY-MM-DD. |
| TIME | HH:MM:SS | 08:15:00 | Només el temps en format HH:MM:SS. |
| DATETIME | YYYY-MM-DD HH:MM:SS | 2026-10-15 09:45:30 | Data i hora en format YYYY-MM-DD HH:MM:SS. |
| TIMESTAMP | Marca temporal. YYYY-MM-DD HH:MM:SS | 2026-08-03 17:45:30 | Marca de temps, data i hora amb un rang més limitat (1970-2038). |
| YEAR | YYYY | 2026 | Any en format YYYY. |

### **Tipus espacials**

MySQL incorpora diversos tipus per a treballar amb informació geográfica. Aquests tipus s'utilitzen principalment en aplicacions GIS (Sistemes de Informació Geográfica).

| Tipus | Ús |
| --- | --- |
| POINT | Punt |
| LINESTRING | Línia |
| POLYGON | Polígono |
| GEOMETRY | Geometría genérica |
| GEOGRAPHY | Dades geográfics sobre la Tierra |

### **Tipus JSON**

Des de MySQL 5.7 existeix un tipus específic per a emmagatzemar documents JSON.

> **📌 CREATE TABLE**
> 

```sql
CREATE TABLE productos(
    id INT PRIMARY KEY,
    caracteristicas JSON
);
```

Exemple de contingut:

> **📌 JSON**
> 

```sql
{
"color":"Rojo",
"peso":3.5,
"garantia":true
}
```

El SGBD valida automàticament que el contingut siga un document JSON vàlid.

## **Creació de dominis**

A més de tots els tipus de dades vistos (i alguns més que es ixen de l'abast del curs), en alguns SGBD (per exemple, PostgreSQL sí que el permet, però MySQL no), podem crear els nostres propis tipus de dades o dominis.

> **📌 CREATE DOMAIN**
> 

```sql
CREATE DOMAIN numero_positivo
AS INTEGER
CHECK (VALUE > 0);
```

Mitjançant CREATE TYPE podem definir tipus de dades complexos, com tipus de registres, arrays o tipus compostos de diversos atributs. Per exemple, podem crear un tipus de dada per a emmagatzemar coordenades:

> **📌 CREATE TYPE**
> 

```sql
CREATE TYPE coordenada AS (
    x FLOAT,
    y FLOAT
);
```

## **Enumeracions (ENUM)**

Quan un atribut només pot prendre un conjunt reducido de valors, MySQL permet utilitzar el tipus `ENUM`.

Exemple:

> **📌 CREATE TABLE**
> 

```sql
CREATE TABLE empleado(
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100),
    estado ENUM(
        'Activo',
        'Inactivo',
        'Suspendido'
    ) NOT NULL
);
```

Només podran almacenar-se eixos tres valors. Si es intenta inserir un altre distint, com "Vacacions", MySQL generará un error.

> **📌 Quan utilitzar 'ENUM'?**
> 

> Aquest tipus de dada els utilitzarem quan els valors possibles són molt reducits i canvien molt poc. Com per exemple, l'estat d'una comanda, el sexo d'una persona, el nivell d'accés, els dies de la setmana o els tipus d'usuari.

> No és recomanable utilitzar-lo per a llistes que canvien freqüentment, ja que obligaría a modificar l'estructura de la taula.
