El **Llenguatge de Definició de Dades (DDL)** (*Data Definition Language*) és el conjunt d'instruccions SQL encarregat de crear i modificar l'estructura d'una base de dades.

Amb DDL podem:

- Crear bases de dades.

- Crear taules.

- Definir relacions.

- Crear índexs.

- Modificar l'estructura de les taules.

- Eliminar objectes de la base de dades.

A diferència del DML, el DDL **no manipula les dades**, sinó que treballa sobre l'estructura de la base de dades.

> **📌 DDL**
> 

> Les instruccions DDL modifiquen el **esquema** de la base de dades, no la informació emmagatzemada.

## **Principals instruccions DDL**

| Instrucció | Funció |
| --- | --- |
| `CREATE` | Crear objectes |
| `ALTER` | Modificar objectes |
| `DROP` | Eliminar objectes |
| `RENAME` | Canviar noms |
| `TRUNCATE` | Vaciar una taula |
| `COMMENT` | Afegir comentaris (segons SGBD) |
| `SHOW` | Mostrar objectes |
| `DESCRIBE` | Mostrar l'estructura d'una taula |

## **CREATE DATABASE**

La instrucció `CREATE DATABASE` crea una nova base de dades.

> **📌 Sintaxi bàsica**
> 

```sql
CREATE DATABASE nombre_bd;
```

Normalment també es especifica el **joc de caràcters** i la **col·lació**.

> **📌 CREATE DATABASE amb joc de caràcters i col·lació**
> 

```sql
CREATE DATABASE instituto
CHARACTER SET utf8mb4
COLLATE utf8mb4_general_ci;
```

Una vegada creada, seleccionarem la base de dades amb:

> **📌 Seleccionar la base de dades**
> 

```sql
USE instituto;
```

### **Comprovar les bases de dades existents**

> **📌 Mostrar les bases de dades**
> 

```sql
SHOW DATABASES;
```

### **Exemple complet**

> **📌 Crear la base de dades 'peliculas'**
> 

```sql
CREATE DATABASE peliculas
CHARACTER SET utf8mb4
COLLATE utf8mb4_spanish2_ci;
USE peliculas;
```

## **CREATE TABLE**

Una vegada creada la base de dades podem començar a crear les seues taules.

La instrucció `CREATE TABLE` defineix completament una taula:

- Nom.

- Columnes.

- Tipus de dades.

- Restriccions.

- Claus.

- Motor d'emmagatzematge.

> **📌 Sintaxi general**
> 

```sql
CREATE TABLE nombre_tabla(
    campo tipo,
    campo tipo,
    ...
);
```

### **Estructura general**

> **📌 Estructura completa de CREATE TABLE**
> 

```sql
CREATE TABLE tabla (
    campo1 TIPO
        [NOT NULL]
        [DEFAULT valor]
        [PRIMARY KEY]
        [UNIQUE],
    campo2 TIPO,
    ...

    CONSTRAINT nombre_restriccion ...
)
ENGINE = InnoDB;
```

### **Exemple de creació d'una taula**

> **📌 CREATE TABLE actor**
> 

```sql
CREATE TABLE actor(
    idActor INT PRIMARY KEY,
    nombreActor VARCHAR(30)
        COLLATE utf8mb4_spanish2_ci
        NOT NULL,
    nacionalidadActor INT
        NOT NULL
)
ENGINE = InnoDB
DEFAULT CHARSET = utf8mb4
COLLATE = utf8mb4_spanish2_ci;
```

En aquest exemple:

- `idActor` serà la clau primària.

- `nombreActor` no admet valors nuls.

- Es especifica una col·lació concreta.

- La taula utilitzarà el motor **InnoDB**.

## **Claus primàries (PRIMARY KEY)**

Tota taula ha de disposar d'una **clau primària**.

La seua funció és identificar de forma única cada registre.

Una clau primària:

- No admet valors repetits.

- No admet valors NULL.

- Ha d'identificar unívocament cada fila.

Existeixen 3 formes de definirla depenent de la seua posició o composició.

### **Forma 1: Com propietat de l'atribut**

> **📌 PRIMARY KEY com propietat**
> 

```sql
CREATE TABLE actor(
    idActor INT PRIMARY KEY,
    nombre VARCHAR(30),
    nacionalidad INT
);
```

És la forma més senzilla.

### **Forma 2: Com restricció**

> **📌 PRIMARY KEY com restricció**
> 

```sql
CREATE TABLE actor(
    idActor INT,
    nombre VARCHAR(30),
    nacionalidad INT,
    CONSTRAINT pk_actor
        PRIMARY KEY(idActor)
);
```

Aquesta opció resulta més recomanable perquè permet assignar un nom a la restricció.

### **Clau primària composta**

Quan la clau està formada per diversos atributs:

> **📌 Clau primària composta**
> 

```sql
CREATE TABLE alquiler(
    dni VARCHAR(9),
    codPelicula INT,
    CONSTRAINT pk_alquiler
        PRIMARY KEY(
            dni,
            codPelicula
        )
);
```

## **AUTO_INCREMENT**

En moltes taules resulta convenient utilitzar un identificador numèric que aument automàticament.

Per a això MySQL proporciona la propietat:

> **📌 AUTO_INCREMENT**
> 

```sql
AUTO_INCREMENT
```

> **📌 Exemple amb AUTO_INCREMENT**
> 

```sql
CREATE TABLE empleado(
    id INT AUTO_INCREMENT,
    nombre VARCHAR(100),
    puesto VARCHAR(50),
    CONSTRAINT pk_empleado
        PRIMARY KEY(id)
);
```

Cada nou registre recibirá automàticament un identificador distint.

> **📌 INSERT i comprovació de l'identificador**
> 

```sql
INSERT INTO empleado (nombre, puesto)
VALUES ('Juan Pérez', 'Gerente');

INSERT INTO empleado (nombre, puesto)
VALUES ('Ana López', 'Desarrolladora');
```

| id | nom | posat |
| --- | --- | --- |
| 1 | Juan Pérez | Gerente |
| 2 | Ana López | Desarrolladora |

> **📌 AUTO_INCREMENT**
> 

> L'ús de `AUTO_INCREMENT` simplifica enormement la creació de claus primàries.

## **Restriccions**

Les restriccions permeten garantir la integritat de les dades.

Entre les més habituals trobem:

- PRIMARY KEY

- FOREIGN KEY

- UNIQUE

- NOT NULL

- DEFAULT

- CHECK

### **NOT NULL**

Impedeix que una columna quede buida.

> **📌 NOT NULL**
> 

```sql
nombre VARCHAR(100) NOT NULL
```

Si intentem inserir un registre sense indicar aquest valor:

```sql
ERROR
```

### **DEFAULT**

Permet establir un valor per defecte.

> **📌 DEFAULT**
> 

```sql
estado VARCHAR(20)
DEFAULT 'Pendiente'
```

Si l'usuari no proporciona un valor:

```sql
Pendiente
```

serà emmagatzemat automàticament.

### **UNIQUE**

Impedeix que existisquen valors repetits. Quan en el model relacional marcamos una propietat com **clau única (UK)**, en el model físic la definim amb la propietat `UNIQUE`.

> **📌 Exemple amb UNIQUE**
> 

```sql
CREATE TABLE empleado(
    dni VARCHAR(9),
    nSegSocial VARCHAR(15),
    nombre VARCHAR(40),
    CONSTRAINT pk_empleado
        PRIMARY KEY(dni),
    CONSTRAINT uk_seg_social
        UNIQUE(nSegSocial)
);
```

Una diferència important respecte a la clau primària és que:

- PRIMARY KEY → no admet NULL.

- UNIQUE → sí permet valors NULL (segons el SGBD).

> **📌 Clau única vs clau primària**
> 

> La principal diferència entre una clau primària i una clau única és que **la clau única permet valors nuls**.

### **FOREIGN KEY**

Les claus foranes estableixen relacions entre taules.

Una clau forana sempre fa referència a una **clau primària** d'una altra taula.

> **📌 Exemple amb FOREIGN KEY**
> 

```sql
CREATE TABLE alquiler(
    dni VARCHAR(9),
    codPelicula INT,
    CONSTRAINT pk_alquiler
        PRIMARY KEY(
            dni,
            codPelicula
        ),
    CONSTRAINT fk_cliente
        FOREIGN KEY(dni)
        REFERENCES cliente(dni),
    CONSTRAINT fk_pelicula
        FOREIGN KEY(codPelicula)
        REFERENCES pelicula(cod)
);
```

> **📌 FOREIGN KEY**
> 

> Una **FOREIGN KEY** sempre referència una **PRIMARY KEY** (o una clau única equivalent) d'una altra taula.

### **Propagació de canvis**

Quan una clau primària canvia o desaparece, hem de decidir què ocurrirá amb les claus foranes.

MySQL permet definir aquest comportament mitjançant:

- `ON DELETE`

- `ON UPDATE`

> **📌 Sintaxi general de la propagació**
> 

```sql
[CONSTRAINT [symbol]] FOREIGN KEY
    [index_name] (col_name, ...)
    REFERENCES tabla (col_name, ...)
    [ON DELETE reference_option]
    [ON UPDATE reference_option]

reference_option:
    RESTRICT | CASCADE | SET NULL | NO ACTION | SET DEFAULT
```

#### **NO ACTION**

Impedeix realitzar l'operació.

> **📌 ON DELETE NO ACTION**
> 

```sql
ON DELETE NO ACTION
```

És el comportament per defecte si no indiquem res.

#### **CASCADE**

Propaga automàticament els canvis.

> **📌 ON DELETE CASCADE**
> 

```sql
ON DELETE CASCADE
```

Si s'elimina el registre pare:

- També s'eliminen tots els registres fills.

#### **SET NULL**

> **📌 ON DELETE SET NULL**
> 

```sql
ON DELETE SET NULL
```

La clau forana passa a contindre:

```sql
NULL
```

Perdiéndose la relació existent.

#### **RESTRICT**

No permet eliminar el registre mentre existisquen referències.

> **📌 ON DELETE RESTRICT**
> 

```sql
ON DELETE RESTRICT
```

#### **SET DEFAULT**

Alguns SGBD permeten establir un valor per defecte.

> **📌 ON DELETE SET DEFAULT**
> 

```sql
ON DELETE SET DEFAULT
```

> **📌 SET DEFAULT**
> 

> MySQL actualment **no suporta** `SET DEFAULT`.

### **CHECK**

Permet validar que les dades complisquen determinades condicions.

> **📌 Exemple amb CHECK**
> 

```sql
CREATE TABLE ingreso(
    codigo INT PRIMARY KEY,
    importe DECIMAL(11,2),
    CONSTRAINT ck_importe
        CHECK(
            importe > 0
            AND importe < 8000
        )
);
```

També pot comparar diverses columnes.

> **📌 CHECK comparant dos columnes**
> 

```sql
CHECK(
    importe < importeMax
)
```

## **Índexs**

Els índexs permeten localitzar registres molt més ràpidament.

Funcionen de forma similar a l'índex d'un llibre.

- Sense índex: **Cercar registre** --> **Recórrer tota la taula**

- Amb índex: **Cercar registre** --> **Accés directe**

### **Quan crear un índex?**

Resulta recomanable crear índexs sobre columnes utilitzades freqüentment en:

- `WHERE`

- `ORDER BY`

- `JOIN`

> **📌 Índexs**
> 

> Per a millorar el rendiment, podem crear un índex per a cada columna que s'utilitza en la clàusula `WHERE` o en `ORDER BY`.

### **CREATE INDEX**

La instrucció `CREATE INDEX` s'utilitza per a crear índexs en les nostres taules.

> **📌 Sintaxi bàsica**
> 

```sql
CREATE INDEX nombre_indice
ON tabla(
    columna
);
```

### **Índex únic**

> **📌 CREATE UNIQUE INDEX**
> 

```sql
CREATE UNIQUE INDEX uk_nia
ON alumnado(
    nia
);
```

No permitirá valors duplicats.

### **Avantatges dels índexs**

- Aceleran les consultes.

- Mejoran l'ordenació.

- Redueixen el temps de cerca.

### **Inconvenients**

- Ocupen espai addicional.

- Fan més lentas les insercions i modificacions.

- Han d'utilitzar-se únicament quan siguen necessaris.

> **📌 Resum**
> 

> - `CREATE DATABASE` crea una nova base de dades.

> - `CREATE TABLE` defineix taules i les seues columnes.

> - Tota taula ha de tindre una **PRIMARY KEY**.

> - `AUTO_INCREMENT` genera identificadors automàticament.

> - Les restriccions garanteixen la integritat de les dades.

> - Les **FOREIGN KEY** estableixen relacions entre taules.

> - Els índexs mejoran el rendiment de les consultes.

## **Modificació de l'estructura de les bases de dades (DDL Avançat)**

Fins a ara hem aprendido a crear bases de dades i taules mitjançant la instrucció `CREATE`. No obstant això, una vegada creada una base de dades, és molt habitual que siga necessari modificar la seua estructura per a adaptar-la a noves necessitats.

El llenguatge **DDL** proporciona diverses instruccions que permeten modificar, reanomenar, eliminar o vaciar els distints objectes d'una base de dades.

En aquest apartat estudiarem les següents instruccions:

- `ALTER`

- `DROP`

- `RENAME`

- `TRUNCATE`

### **ALTER TABLE**

La instrucció `ALTER TABLE` permet modificar l'estructura d'una taula ja existent sense necessitat d'eliminar-la i volverla a crear.

Amb ella podem:

- Afegir columnes.

- Eliminar columnes.

- Modificar columnes.

- Afegir restriccions.

- Eliminar restriccions.

- Canviar el nom de columnes (segons el SGBD).

> **📌 Quan utilitzar ALTER?**
> 

> Sempre que siga necessari modificar l'estructura d'una taula sense perdre les dades emmagatzemats.

#### **Sintaxi general**

> **📌 Sintaxi general de ALTER TABLE**
> 

```sql
ALTER TABLE nombre_tabla
acción;
```

Les accions més habituals són:

- `ADD`

- `MODIFY`

- `CHANGE`

- `DROP`

#### **Afegir columnes**

Per a incorporar un nou atribut utilitzarem `ADD COLUMN`.

> **📌 Sintaxi ADD COLUMN**
> 

```sql
ALTER TABLE tabla
ADD COLUMN columna tipo;
```

> **📌 Exemple: afegir un àlies artístic a 'actor'**
> 

```sql
ALTER TABLE actor
ADD COLUMN aliasActor VARCHAR(30);
```

La nova estructura serà:

| idActor | nombreActor | nacionalidadActor | aliasActor |
| --- | --- | --- | --- |
|  |  |  |  |

#### **Afegir diverses columnes**

També és possible afegir diverses columnes en una sola instrucció.

> **📌 Afegir diverses columnes**
> 

```sql
ALTER TABLE actor
ADD COLUMN fechaNacimiento DATE,
ADD COLUMN salario DECIMAL(10,2);
```

#### **Modificar una columna**

Si volem canviar el tipus de dada, el mida o les restriccions d'una columna utilitzarem `MODIFY`.

> **📌 Sintaxi MODIFY**
> 

```sql
ALTER TABLE tabla
MODIFY columna nuevo_tipo;
```

> **📌 Exemple: modificar el mida del cognom d'un alumne**
> 

```sql
ALTER TABLE alumno
MODIFY apellidos VARCHAR(40)
NOT NULL;
```

#### **Modificar diverses propietats**

També és possible modificar simultàniament:

- Tipus de dada.

- Longitud.

- Restriccions.

- Valor per defecte.

> **📌 Exemple: modificar diverses propietats**
> 

```sql
ALTER TABLE empleado
MODIFY salario DECIMAL(12,2)
DEFAULT 1200.00;
```

#### **Eliminar una columna**

Quan un atribut deixa de ser necessari podem eliminar-lo.

> **📌 Sintaxi DROP COLUMN**
> 

```sql
ALTER TABLE tabla
DROP COLUMN columna;
```

> **📌 Exemple: eliminar la columna 'aliasActor'**
> 

```sql
ALTER TABLE actor
DROP COLUMN aliasActor;
```

> **📌 Eliminar una columna**
> 

> A l'eliminar una columna també desaparecen totes les dades emmagatzemats en ella.

#### **Afegir restriccions**

Encara que normalment les restriccions es creen juntament amb la taula, també poden incorporar-se posteriorment mitjançant `ALTER TABLE`.

> **📌 Sintaxi general ADD CONSTRAINT**
> 

```sql
ALTER TABLE tabla
ADD CONSTRAINT nombre
tipo_restriccion;
```

> **📌 Exemple: afegir una clau forana**
> 

```sql
ALTER TABLE empleado
ADD CONSTRAINT fk_oficina
FOREIGN KEY(oficina)
REFERENCES oficina(codigo);
```

Amb aquesta instrucció es estableix la relació entre totes dues taules.

#### **Eliminar restriccions**

També és possible eliminar una restricció existent.

> **📌 Eliminar una clau forana**
> 

```sql
ALTER TABLE empleado
DROP FOREIGN KEY fk_oficina;
```

En MySQL és necessari indicar el nom de la restricció.

### **DROP**

La instrucció `DROP` elimina completament un objecte de la base de dades.

Pot utilitzar-se sobre:

- Bases de dades.

- Taules.

- Índexs.

- Vistes.

- Procediments.

- Triggers.

> **📌 Atenció**
> 

> `DROP` elimina definitivament l'objecte i tota la informació contenida en ell.

#### **DROP DATABASE**

Elimina una base de dades completa.

> **📌 DROP DATABASE**
> 

```sql
DROP DATABASE instituto;
```

Si volem evitar errors quan no existisca:

> **📌 DROP DATABASE IF EXISTS**
> 

```sql
DROP DATABASE IF EXISTS instituto;
```

#### **DROP TABLE**

Elimina completament una taula.

> **📌 DROP TABLE**
> 

```sql
DROP TABLE alumnado;
```

Al fer-ho desaparecen:

- La seua estructura.

- Tots els registres.

- Els seus índexs.

- Les seues restriccions.

#### **DROP INDEX**

També podem eliminar un índex.

> **📌 Sintaxi DROP INDEX**
> 

```sql
DROP INDEX nombre_indice
ON nombre_tabla;
```

> **📌 Exemple: eliminar l'índex únic de 'alumnat'**
> 

```sql
DROP INDEX uk_nia
ON alumnado;
```

En alguns SGBD també és possible indicar:

> **📌 Una altra forma de DROP INDEX**
> 

```sql
DROP INDEX alumnado.uk_nia;
```

### **RENAME**

La instrucció `RENAME` permet canviar el nom de distints objectes de la base de dades.

Els més habituals són:

- Taules.

- Índexs.

#### **Reanomenar una taula**

> **📌 Sintaxi RENAME TABLE**
> 

```sql
RENAME TABLE
nombre_actual
TO
nuevo_nombre;
```

> **📌 Exemple: reanomenar la taula 'actor'**
> 

```sql
RENAME TABLE actor
TO artista;
```

A partir d'eixe moment totes les consultes hauran d'utilitzar el nou nom.

#### **Reanomenar un índex**

En versions recientes de MySQL també és possible canviar el nom d'un índex.

> **📌 Exemple: reanomenar un índex**
> 

```sql
ALTER TABLE alumnado
RENAME INDEX indice_valor_unico_NIA
TO NIA_UK;
```

Açò facilita treballar amb noms més cortos i descriptivos.

### **TRUNCATE**

La instrucció `TRUNCATE` elimina **tots els registres** d'una taula.

> **📌 Sintaxi TRUNCATE**
> 

```sql
TRUNCATE TABLE nombre_tabla;
```

#### **Què ocorre internament?**

Encara que des del punt de vista de l'usuari sembla un esborrat masivo, internament MySQL realitza una operació similar a **DROP TABLE** --> **CREATE TABLE**

Per això `TRUNCATE` pertany al llenguatge **DDL** i no al **DML**.

#### **TRUNCATE vs DELETE**

Totes dues instruccions eliminen registres, però existeixen diferències importants.

| Característica | DELETE | TRUNCATE |
| --- | --- | --- |
| Elimina registres | Sí | Sí |
| Elimina tota la taula | No | No |
| Permet WHERE | Sí | No |
| És més ràpid | No | Sí |
| Reinicia AUTO_INCREMENT | No (habitualment) | Sí |
| Pertany a | DML | DDL |

> **📌 Exemple DELETE**
> 

```sql
DELETE
FROM alumno
WHERE provincia='Valencia';
```

Només elimina alguns registres.

> **📌 Exemple TRUNCATE**
> 

```sql
TRUNCATE TABLE alumno;
```

Elimina tots els registres de la taula.

### **SHOW**

La instrucció `SHOW` permet consultar informació sobre la base de dades.

> **📌 Mostrar les bases de dades**
> 

```sql
SHOW DATABASES;
```

> **📌 Mostrar les taules**
> 

```sql
SHOW TABLES;
```

> **📌 Mostrar la creació d'una taula**
> 

```sql
SHOW CREATE TABLE alumno;
```

> **📌 Mostrar la creació d'una base de dades**
> 

```sql
SHOW CREATE DATABASE instituto;
```

### **DESCRIU**

Permet consultar l'estructura d'una taula.

> **📌 DESCRIU**
> 

```sql
DESCRIBE alumno;
```

o bé

> **📌 DESC**
> 

```sql
DESC alumno;
```

Obtindrem informació com:

- Nom de la columna.

- Tipus de dada.

- Clau primària.

- Valors nuls.

- Valor per defecte.

> **📌 Eixida de DESCRIU**
> 

```sql
+----------+--------------+------+-----+---------+-------+
| Campo    | Tipo         | Null | Key | Default | Extra |
+----------+--------------+------+-----+---------+-------+
| id       | int          | NO   | PRI |         |       |
| nombre   | varchar(100) | NO   |     |         |       |
| telefono | varchar(20)  | YES  |     |         |       |
+----------+--------------+------+-----+---------+-------+
```

## **Resum**

> **📌 Ideas clau**
> 

> - `ALTER TABLE` permet modificar l'estructura d'una taula existent.

> - `ADD`, `MODIFY` i `DROP COLUMN` són les operacions més habituals.

> - `ADD CONSTRAINT` permet afegir restriccions posteriorment.

> - `DROP` elimina completament un objecte de la base de dades.

> - `RENAME` canvia el nom de taules i índexs.

> - `TRUNCATE` elimina tots els registres d'una taula de forma molt ràpida.

> - `SHOW` i `DESCRIBE` permeten consultar l'estructura de la base de dades i les seues taules.

> **📌 Bones pràctiques**
> 

> - Utilitza `ALTER TABLE` sempre que pugues abans d'eliminar i tornar a crear una taula.

> - Abans d'executar un `DROP` o un `TRUNCATE`, asegúrate de disposar d'una còpia de seguretat.

> - Empra `SHOW` i `DESCRIBE` per a comprovar l'estructura de les taules abans de modificar-les.
