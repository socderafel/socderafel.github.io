## 1. Concepte i Justificació dels Sistemes de Gestió de Continguts

Un **CMS** (*Content Management System*) és una aplicació web que permet a usuaris sense formació tècnica avançada crear, editar, organitzar i publicar contingut digital a la World Wide Web mitjançant interfícies gràfiques intuïtives, garantint al mateix temps que els desenvolupadors puguen controlar l'arquitectura, la lògica de negoci i el disseny visual.

Els avantatges clau que han motivat l'adopció massiva dels CMS en l'empresa són:
- **Democratització editorial:** Els equips de comunicació i màrqueting publiquen de forma autònoma sense dependre del departament de programació per a cada canvi de text.
- **Normalització de contingut:** Ús de plantilles consistents que asseguren una identitat corporativa uniforme.
- **Fluxos de treball i govern:** Control de canvis, historials de versions i cicles de revisió prèvia a la publicació.

---

## 2. L'Arquitectura Tradicional Monolítica

En els CMS clàssics (com WordPress, Joomla o Drupal en la seua configuració inicial):
1. **Capa d'Emmagatzematge:** Una base de dades relacional (MySQL / MariaDB) emmagatzema les publicacions, usuaris i metadades.
2. **Capa de Lògica de Negoci (Backend):** Executada en el servidor mitjançant un llenguatge interpretat (principalment PHP).
3. **Capa de Presentació (Frontend):** Acoblada directament al backend; el servidor processa la plantilla en PHP, fa consultes SQL i retorna una pàgina HTML completa al navegador de l'usuari en cada sol·licitud (*Server-Side Rendering* tradicional).

```
+-----------------------------------------------------------+
|                   CMS MONOLÍTIC TRADICIONAL               |
|                                                           |
|  [Panell d'Administració] + [Lògica PHP] + [Plantilla HTML]
|                             |                             |
|                             v                             |
|                 [Base de Dades MariaDB/MySQL]             |
+-----------------------------------------------------------+
                              | Retorna pàgina completa HTML
                              v
                      [Navegador Client]
```

## 3. L'Arquitectura Headless CMS i el Moviment Decoupled

Amb la proliferació de canals digitals múltiples (aplicacions mòbils natives Android/iOS, rellotges intel·ligents, terminals de punt de venda i aplicacions web de pàgina única SPA basades en React, Vue o Angular), el model monolític va mostrar limitacions clares: la capa visual en HTML generada pel servidor no era reutilitzable en dispositius mòbils.

Un **Headless CMS** «talla el cap» (la capa de presentació HTML del frontend) del gestor:
- Manté el panell d'administració corporatiu per als redactors i editors.
- Emmagatzema les dades de manera agnòstica respecte al disseny.
- **Exposa els continguts de forma pura mitjançant una API RESTful o GraphQL**.

```
+---------------------------+        +---------------------------+
|     HEADLESS CMS          |        |        FRONTENDS          |
|                           |        |                           |
|  [Panell de Redacció]     |        | -> [App Web Next.js/Vue]  |
|            |              |  JSON  |                           |
|            v              |  API   | -> [App Mòbil Flutter]    |
|  [API REST / GraphQL]     | -----> |                           |
|            |              |        | -> [Dispositiu IoT / TPV] |
|            v              |        |                           |
|  [Base de Dades / Núvol]  |        +---------------------------+
+---------------------------+
```
