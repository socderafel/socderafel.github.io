## 1. La Pila de Servidor Tradicional: LAMP i LEMP

La gran majoria dels sistemes CMS líders (com WordPress, Moodle, Drupal o Prestashop) requereixen una pila de programari de servidor consolidada:

- **L (Linux):** Sistema operatiu amfitrió (distribucions com Ubuntu Server, Debian o Red Hat Enterprise Linux).
- **A / E (Apache o Nginx):** Servidor HTTP encarregat de rebre les peticions dels clients i encaminar-les. Nginx s'utilitza àmpliament com a intermediari invers (*Reverse Proxy*) per la seua alta concurrència basada en esdeveniments asíncrons.
- **M (MariaDB / MySQL):** Sistema Gestor de Bases de Dades Relacionals (RDBMS) on es persisteixen les taules del CMS.
- **P (PHP):** Entorn d'execució (*runtime*) en el servidor (habitualment gestionat mitjançant el gestor de processos `php-fpm`).

```bash
# Instal·lació de la pila en Ubuntu Server
sudo apt update
sudo apt install apache2 mariadb-server php php-mysql php-curl php-gd php-mbstring php-xml php-zip
```

## 2. Preparació i Seguretat de la Base de Dades

El CMS requereix un esquema de dades buit i un compte d'usuari dedicat amb privilegis restringits exclusivament sobre eixa base de dades:

```sql
-- Creació de la base de dades amb joc de caràcters segur UTF-8 multilingüe
CREATE DATABASE cms_corporatiu CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- Creació de l'usuari amb accés restringit local (localhost)
CREATE USER 'usuari_cms'@'localhost' IDENTIFIED BY 'ContrasenyaComplexa!2026';

-- Concessió de privilegis estrictes sobre la base de dades
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, INDEX, ALTER, LOCK TABLES 
ON cms_corporatiu.* TO 'usuari_cms'@'localhost';

FLUSH PRIVILEGES;
```

> [!WARNING] Risc de Seguretat de Prefixos de Taula
> Per defecte, molts instal·ladors proposen el prefix `wp_` per a totes les taules SQL. Els atacs d'injecció SQL automatitzats aprofiten aquest prefix previsible. És mandatori canviar el prefix durant la instal·lació a una cadena aleatòria com `ies26_`.

## 3. Gestió de Permisos POSIX en el Sistema de Fitxers

En un servidor web Linux, el servidor HTTP s'executa sota un usuari del sistema restringit (generalment `www-data` en Debian/Ubuntu o `apache`/`nginx` en RHEL).

Perquè el sistema siga segur:
1. **Els fitxers i directoris ordinaris no han de ser propietat amb accés d'escriptura per al servidor web**, llevat dels directoris específics destinats a pujades multimèdia (`uploads` o `media`).
2. **Permisos estàndard recomanats:**
   - Directoris: `755` (`rwxr-xr-x`): el propietari pot llegir/escriure/navegar; el grup i altres només poden llegir i navegar.
   - Fitxers: `644` (`rw-r--r--`): el propietari pot llegir i escriure; la resta només llegir.
   - Fitxers de credencials crítics (`wp-config.php`, `.env`): `600` o `640` per a impedir la seua lectura per altres usuaris del sistema operatiu.

```bash
# Ajust canònic de permisos a la carpeta arrel del CMS (/var/www/html)
sudo chown -R www-data:www-data /var/www/html/
sudo find /var/www/html/ -type d -exec chmod 755 {} \;
sudo find /var/www/html/ -type f -exec chmod 644 {} \;
sudo chmod 600 /var/www/html/wp-config.php
```
