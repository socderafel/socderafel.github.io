En aquest apartat tenim com objectiu ser capaços d'identificar, comprendre i seleccionar les tecnologies adequades per a definir l'estructura i les regles dels documents que intercambian les aplicacions.

Definir documents no consisteix únicament en triar un format (XML, JSON…), sinó en especificar formalment:

- què dades es esperan,

- com es organitzen,

- què tipus han de tindre,

- què restriccions han de complir,

- com poden validar-se automàticament.

En el context tecnològic actual, aquestes definicions es apoyan en estàndards consolidats i tecnologies àmpliament utilitzades en el desenvolupament web professional.

## **Tecnologies per a XML**

XML va ser el primer gran estàndard per a l'intercanvi estructurat d'informació. Encara que el seu ús ha disminuido en el desenvolupament web modern enfront de JSON, segueix sent clau a nivell formativo i en sectors concrets, per la qual cosa és imprescindible conèixer els seus mecanismes de validació.

### **DTD**

DTD (Document Type Definition) és la primera tecnologia creada per a definir l'estructura de documents XML. Permet descriure què elements poden aparèixer en un document i com es relacionen entre sí.

> **📌 Exemple DTD**
> 

```html
<!ELEMENT pedido (cliente, total)>
<!ELEMENT cliente (#PCDATA)>
<!ELEMENT total (#PCDATA)>
```

#### **Característiques principals**

Defineix estructura jeràrquica dels elements.
Permet indicar:

- elements obligatoris o opcionals,

- repetició d'elements,

- atributs bàsics.

Utilitza una sintaxi pròpia, independent de XML.

#### **Limitacions**

DTD presenta importants restriccions tècniques:

- No permet definir tipus de dades (tot és text).

- No suporta namespaces.

- No permet validacions complexes ni regles semàntiques.

- Escasa extensibilitat.

#### **Ús actual**

S'utilitza principalment:

- amb fines educativos, per a comprendre la base teórica de les gramátiques,

- en sistemes heretats que encara intercambian XML antics.

És fonamental per a entendre l'evolució cap a tecnologies més potents com XSD.

### **XSD**

XSD (XML Schema Definition) és l'evolució natural de DTD i l'estàndard oficial del W3C per a definir documents XML.
La versió 1.1 és la més completa i la que segueix estant vigent i mantenida.

> **📌 Exemple XSD**
> 

```html
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">

<xs:element name="pedido">
    <xs:complexType>
    <xs:sequence>
        <xs:element name="cliente" type="xs:string"/>
        <xs:element name="total" type="xs:decimal"/>
    </xs:sequence>
    </xs:complexType>
</xs:element>

</xs:schema>
```

#### **Capacitats principals**

XSD permet:

- **Definir tipus de dades**:

  - simples (string, integer, date, boolean…),

  - complexos (estructures amb diversos elements).

- **Establir restriccions avançades**:

  - rangs numèrics,

  - longituds mínimes i màximes,

  - expressions regulars (patterns).

- **Treballar amb namespaces**.

- **Crear estructures reutilitzables**.

- **Expressar regles semàntiques complexes (especialment en XSD 1.1)**.

#### **Avantatges enfront de DTD**

| DTD | XSD |
| --- | --- |
| Sintaxi pròpia | Sintaxi XML |
| Sense tipus de dades | Tipat fort |
| Sense namespaces | Suport complet |
| Validació bàsica | Validació avançada |

#### **Ús en la industria**

XSD segueix sent àmpliament utilitzat en:

- administració pública.

- facturació electrònica.

- sector financiero.

- editorials i documentació tècnica.

- intercanvi de dades entre sistemes corporativos.

Encara que XML no siga dominante en DAW, XSD és essencial per a entendre validació estructurada i tipada.

## **Tecnologies per a JSON**

Amb l'auge del desenvolupament web i de les APIs REST, JSON es ha convertido en el format dominante per a l'intercanvi de dades entre aplicacions.
A diferència de XML, JSON no incorpora mecanismes de validació propis, per la qual cosa és imprescindible usar tecnologies externes per a definir la seua estructura i regles.

### **JSON Schema**

JSON Schema (Draft 2020‑12) és l'estàndard per a descriure i validar documents JSON.
La versió Draft 2020‑12 és la més soportada i recomanada en 2026, ja que està integrada en la majoria de validadors i eines modernes.

> **📌 Exemple JSON Schema**
> 

```html
{
"$schema": "https://json-schema.org/draft/2020-12/schema",
"type": "object",
"properties": {
    "usuario": { "type": "string" },
    "edad": { "type": "integer", "minimum": 0 },
    "email": { "type": "string", "format": "email" }
},
"required": ["usuario", "edad", "email"]
}
```

#### **Què permet JSON Schema**

- Definir l'estructura exacta d'un JSON.

- Especificar:

  - tipus de dades,

  - propietats obligatòries,

  - formats (email, date, uri…),

  - restriccions (rangs, longituds, patrons).

- Reutilitzar esquemes mitjançant referències ($ref).

- Modularitzar definicions.

#### **Mejoras clau introduïdes**

- Sistema de vocabularies, que permet extensions controlades.

- Referències dinàmiques ($dynamicRef).

- Major compatibilitat entre eines.

#### **Ús real**

JSON Schema s'utilitza en:

- APIs REST,

- validació de dades en backend,

- bases de dades NoSQL,

- formularis dinàmics,

- pipelines de CI/CD,

- documentació automàtica.

En DAW, JSON Schema és imprescindible per a treballar amb APIs modernes.

### **JSON Schema 2.0**

JSON Schema 2.0 (2025) representa l'evolució més important de l'estàndard des de 2020‑12, introducent mejoras orientades a l'expresivitat i al desenvolupament professional.

> **📌 Exemple JSON Schema**
> 

```html
{
"type": "object",
"properties": {
    "tipoUsuario": { "enum": ["normal", "admin"] },
    "email": { "type": "string", "format": "email" },
    "permisos": {
    "type": "array",
    "items": { "type": "string" }
    }
},
"required": ["tipoUsuario", "email"],
"if": {
    "properties": { "tipoUsuario": { "const": "admin" } }
},
"then": {
    "required": ["permisos"]
}
}
```

#### **Novetats destacades**

- Validació condicional avançada. Permet definir regles del tipus: si ocorre açò → llavors ha de complir-se açò un altre.

- Vocabularies més flexibles. Faciliten l'extensió de l'estàndard sense romper compatibilitat.

- Tipus personalitzats. A través de patrons i combinacions.

- Missatges d'error més clars. Faciliten el debugging i l'experiència del desenvolupador.

#### **Impacto en el desenvolupament**

Les mejoras introduïdes en JSON Schema 2.0 fan que l'estàndard siga:

- Més expresivo, al permetre modelar regles complexes del domini.

- Més mantenible, gràcies a la reutilització, modularitat i condicionals.

- Més escalable, adequat per a projectes grans i equips numerosos.

- Més alineat amb arquitectures distribuïdes, on la validació ha de ser clara, consistente i automatizable.
