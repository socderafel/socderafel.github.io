## 1. La Jerarquia de Plantilles (Template Hierarchy)

En els sistemes de gestió de continguts, el disseny visual està encapsulat en **Plantilles o Temes** (*Themes*). El motor del CMS utilitza un algorisme de cerca jeràrquica per a decidir quin fitxer de plantilla renderitza cada URL sol·licitada per l'usuari:

Per exemple, si un usuari visita `https://ies.edu/categoria/daw`:
1. El CMS cerca: `category-daw.php` (plantilla específica per al slug «daw»).
2. Si no existeix, cerca: `category-12.php` (plantilla específica per a l'ID 12).
3. Si no existeix, cerca: `category.php` (plantilla genèrica per a qualsevol categoria).
4. Si no existeix, cerca: `archive.php` (plantilla genèrica per a qualsevol llistat o arxiu temporal/taxonòmic).
5. Com a últim recurs de reserva (*fallback* universal): utilitza `index.php`.

## 2. El Concepte de Tema Fill (Child Theme)

Quan un equip de desenvolupament necessita personalitzar el disseny o la lògica d'un tema existent, **està terminantment prohibit modificar directament el codi font del tema pare**:
- Si l'autor del tema publica un pedaç de seguretat o una nova versió i s'actualitza el tema, **totes les modificacions locals se sobreescriuen i es perden de manera irreversible**.

### La Solució: Child Themes
Un **Tema Fill** és un directori autònom que hereta tots els estils, plantilles i funcionalitats del tema pare, però permet sobreescriure o afegir fitxers concrets de manera aïllada:
- `style.css`: Declara la dependència mitjançant la capçalera `Template: nom-tema-pare`.
- `functions.php`: Permet enriquir la lògica mitjançant ganxos (*hooks*) sense tocar el codi original.

```css
/*
 Theme Name:   Tema Corporatiu IES Monastil (Child)
 Template:     twentytwentyfour
 Version:      1.0.0
 Text Domain:  ies-monastil-child
*/

/* Regles CSS personalitzades que sobreescriuen el tema pare */
:root {
  --ies-color-corporatiu: #0056b3;
}
```

## 3. L'Arquitectura Basada en Esdeveniments: Hooks, Accions i Filtres

L'extensibilitat d'un CMS modern s'aconsegueix mitjançant una arquitectura dirigida per esdeveniments coneguda com a **Hooks (Ganxos)**, que permet als connectors (*plugins*) alterar el comportament del sistema sense modificar els fitxers del nucli (*core*):

1. **Actions (Accions):** Permeten executar funcions pròpies en moments concrets del cicle de vida del sistema (com en inicialitzar el CMS, en guardar un article o en renderitzar el peu de pàgina):
   ```php
   // Executa la nostra funció quan el CMS inicialitza els scripts
   add_action('wp_enqueue_scripts', 'carregar_estils_ies');
   function carregar_estils_ies() {
       wp_enqueue_style('estil-propi', get_stylesheet_directory_uri() . '/css/custom.css');
   }
   ```
2. **Filters (Filtres):** Permeten interceptar, transformar i retornar dades abans que siguen guardades a la base de dades o abans de ser dibuixades a la pantalla:
   ```php
   // Afegeix un avís legal al final de cada article
   add_filter('the_content', 'afegir_peu_llicencia');
   function afegir_peu_llicencia($contingut) {
       $avis = '<p class="llicencia">Publicat sota llicència Creative Commons BY-SA 4.0.</p>';
       return $contingut . $avis;
   }
   ```
