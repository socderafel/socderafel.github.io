## **Eines per a l'emmagatzematge i la consulta**

### Bases de dades natives XML

| Eina | Tipus | Ús principal |
| --- | --- | --- |
| **eXist-db** | Servidor | Base de dades nativa amb interfície web, editor eXide i serveis REST |
| **BaseX** | Escriptori | Base de dades nativa amb interfície gràfica, consola i client HTTP |

### Bases de dades relacionals

| Eina | Tipus | Ús principal |
| --- | --- | --- |
| **PostgreSQL / SQL Server / Oracle** | SGBD | Emmagatzemar XML en columnes de tipus `xml` |
| **DBeaver** | Client SQL | Connectar-se a distints SGBD des d'una única interfície |
| **psql / SSMS** | Consola | Executar SQL i SQL/XML des de la terminal |

### Consulta i transformació

| Eina | Tipus | Ús principal |
| --- | --- | --- |
| **XQuery / XPath** | Llenguatge | Consultar documents i col·leccions XML |
| **jq** | Terminal | Filtrar i transformar documents JSON |
| **xsltproc / Saxon** | Procesadors | Transformar XML amb XSLT (vist en la UP07) |

### Motors XQuery

| Eina | Tipus | Ús principal |
| --- | --- | --- |
| **BaseX** | BD nativa + motor | Motor complet de XPath, XQuery i XSLT amb interfície gràfica i consola |
| **Saxon** | Processador | Motor XSLT/XQuery en Java (també C, .NET, PHP, Python, JavaScript) |
| **Fonto** | Online | Probador de consultes **XQuery 3.1** contra un document XML en el navegador |
| **XPath 3.1 Online Tester** | Online | Probador de consultes XQuery 3.1 contra un document XML en el navegador |

#### Provar consultes XQuery amb BaseX

**BaseX** és una base de dades XML nativa i una eina de processament de documents XML de codi obert i multiplataforma. Alguns resultats en BaseX no ixen correctament indentats; per a forçar una indentació correcta i facilitar la lectura del resultat, es afegeix aquesta instrucció en la primera línia de la consulta:

```html
declare option output:indent "yes";
```

#### Executar XQuery amb Saxon des de Java

**Saxon** implementa els estàndards XSLT i XQuery. Per a executar una consulta des de Java es necessiten el **SDK de Java** i la **utilitat Saxon**, i s'utilitza el següent comanda:

```html
java -cp saxon-ee-12.1.jar net.sf.saxon.Query -s:doc.xml -q:query.xq -o:out.xml
```

On:
- `saxon-ee-12.1.jar` és el JAR de Saxon (junt al directori `lib`, tots dos en el directori d'ejecució).
- `doc.xml` és el document XML sobre el que es realitza la consulta.
- `query.xq` és la consulta XQuery.
- `out.xml` és el resultat de la consulta.

#### Provar XQuery en línia: Fonto i XPath 3.1 Online Tester

**Fonto** ([xpath.playground.fontoxml.com](https://xpath.playground.fontoxml.com/)) permet provar consultes **XQuery 3.1**: es còpia el document XML en la part esquerra, es selecciona l'opció *XQuery 3.1* i es escriu la consulta; els resultats apareixen a l'instante a la dreta.

El **XPath 3.1 Online Tester** ([videlibri.de](https://videlibri.de/cgi-bin/xidelcgi)) funciona de forma similar: necessita un document XML, la consulta a avaluar i tindre seleccionada l'opció *XQuery 3.1*.

## **Cas pràctic 1: biblioteca amb base de dades nativa XML**

Una biblioteca emmagatzema les seues fitxes de llibres com documents XML en eXist-db, en la col·lecció `/db/biblioteca`.

**Document d'exemple (`libro.xml`):**

```html
<libro isbn="978-84-00000-01-2">
    <titulo>Lenguajes de marcas</titulo>
    <autor>María López</autor>
    <anio>2026</anio>
    <precio>29.95</precio>
    <disponible>true</disponible>
</libro>
```

**Consulta 1:** llibres disponibles ordenats per títol:

```html
for $l in collection('/db/biblioteca')/libro
where $l/disponible = 'true'
order by $l/titulo
return $l/titulo
```

**Consulta 2:** número de llibres per autor:

```html
for $a in distinct-values(collection('/db/biblioteca')/libro/autor)
let $n := count(collection('/db/biblioteca')/libro[autor = $a])
return <autor nombre="{ $a }" obras="{ $n }"/>
```

## **Cas pràctic 2: de la base relacional al XML (CE6g)**

Una botiga guarda les seues comandes en una base de dades relacional. Al final del dia necessita enviar al seu central un **document XML** amb tots els comandes del dia per al seu anàlisi.

Amb SQL/XML en PostgreSQL:

```html
SELECT XMLELEMENT(name "pedidos",
    XMLAGG(
        XMLELEMENT(name "pedido",
            XMLATTRIBUTES(p.id AS id),
            XMLELEMENT(name "cliente", p.cliente),
            XMLELEMENT(name "total",
                (SELECT sum(l.cantidad * l.precio)
                 FROM lineas_pedido l
                 WHERE l.id = p.id)
            )
        )
    )
) AS xml_dia
FROM pedidos p
WHERE p.fecha = CURRENT_DATE;
```

El resultat es exporta a un fitxer `pedidos_dia.xml` i es integra amb el resta de sistemes. D'aquesta forma **la mateixa informació viatja en dos formats**: files per a la base de dades i XML per a l'intercanvi.

## **Cas pràctic 3: consulta amb agregació i eixida HTML**

Un analista vol un informe **HTML** amb les vendes agrupades per categoria a partir del catàleg emmagatzemat en eXist-db:

```html
xquery version "3.1";

let $productos := collection('/db/catalogo')/productos/producto
let $categorias := distinct-values($productos/@categoria)
return
    <html>
        <head><title>Informe de ventas</title></head>
        <body>
            <h1>Ventas por categoría</h1>
            <table border="1">
                <tr><th>Categoría</th><th>N.º productos</th><th>Precio medio</th></tr>
                {
                    for $c in $categorias
                    let $grupo := $productos[@categoria = $c]
                    return
                        <tr>
                            <td>{ $c }</td>
                            <td>{ count($grupo) }</td>
                            <td>{ avg($grupo/precio) }</td>
                        </tr>
                }
            </table>
        </body>
    </html>
```

Aquest document HTML es pot servir directament des de eXist-db com una pàgina web, cerrant el cercle: **relacional → XML → base nativa → consulta → presentació web**.

## **Cas pràctic 4: JSON i jq per al mateix problema**

En entorns web moderns, la informació emmagatzemada en XML sol convertir-se a JSON per a consumirla des d'una App. Amb `jq` podem consultar un document JSON tan fàcilment com XQuery consulta un XML:

```html
jq '[.libros[] | select(.precio > 20)] | length' biblioteca.json
```

La **integració de tecnologies** és la conclusió d'aquesta unitat: triar el **mètode d'emmagatzematge** adequat i el **llenguatge de consulta** corresponent és el que permet que els sistemes intercanvien i aprovechen la informació.

## **Resum**

- Les eines principals són les **bases de dades natives XML** (eXist-db, BaseX), les **relacionals** amb tipus XML i els **llenguatges de consulta** (XQuery, XPath, SQL/XML, jq).

- Els casos pràctics mostren el **cicle complet**: dades relacionals → XML → emmagatzematge en col·leccions → consulta XQuery → eixida HTML o JSON.

- La combinació adequada d'emmagatzematge i consulta és el que fa possible gestionar la informació de forma **eficient**.
