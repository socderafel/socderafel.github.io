Les bases de dades relacionals són les més extendides en el món empresarial. Per això, una de les tasques més habituals és **guardar documents XML en elles** i, a la inversa, **generar documents XML a partir de les seues dades**. En aquest apartat veurem com fer totes dues coses amb SQL estàndard i amb les extensions SQL/XML.

## **Com guardar un document XML en una taula?**

Existeixen dos estratègies principals: **guardar el document enter** o **descomponer-lo** en les columnes de les taules.

### A. El document complet en una columna XML

Els principals SGBD relacionals ofereixen un tipus de dada natiu per a XML:

| SGBD | Tipus de dada XML | Observacions |
| --- | --- | --- |
| **PostgreSQL** | `xml` | Validació bàsica de bé format |
| **SQL Server** | `xml` | Permet índexs sobre XML i consultes XQuery integrades |
| **Oracle** | `XMLType` | Molt complet, amb suport XQuery |
| **MySQL** | `LONGTEXT` | No té tipus XML; es guarda com text |

```html
CREATE TABLE productos (
    id         INTEGER PRIMARY KEY,
    categoria  VARCHAR(30),
    ficha      XML
);

INSERT INTO productos VALUES (1, 'portatil', '<producto>
    <nombre>Portátil Pro 14</nombre>
    <precio>899.00</precio>
    <stock>12</stock>
</producto>');
```

**Avantatges:** es conserva l'estructura del document, es pot validar i consultar amb XPath/XQuery dins de SQL. **Inconvenients:** l'accés a les dades "interns" exige usar extensions no estàndard.

### B. Descomposició del document en taules

Consisteix en traduir la jerarquia XML al model relacional: cada element amb repeticions es converteix en una taula hija i els atributs en columnes.

```html
<pedido id="p10">
    <cliente>Ana Pérez</cliente>
    <fecha>2027-03-02</fecha>
    <linea ref="l01" cantidad="2" precio="15.00"/>
    <linea ref="l02" cantidad="1" precio="48.50"/>
</pedido>
```

```html
CREATE TABLE pedidos (
    id      VARCHAR(10) PRIMARY KEY,
    cliente VARCHAR(50),
    fecha   DATE
);

CREATE TABLE lineas_pedido (
    id       VARCHAR(10),
    linea    INTEGER,
    ref      VARCHAR(10),
    cantidad INTEGER,
    precio   NUMERIC(8,2),
    PRIMARY KEY (id, linea),
    FOREIGN KEY (id) REFERENCES pedidos(id)
);
```

**Avantatges:** consultes SQL clásiques (JOIN, agregats) i rendiment óptimo. **Inconvenient:** cal reconstruir el XML a l'exportar.

## **SQL/XML: construir XML des d'una base relacional (CE6g)**

Per a **crear documents XML a partir de les dades de la base de dades**, SQL estàndard defineix una família de funcions coneguda com **SQL/XML**. Les més útils són:

- `XMLELEMENT(nombre, valor...)` → crea un element.

- `XMLATTRIBUTES(...)` → afegeix atributs a l'element.

- `XMLFOREST(...)` → crea diversos elements germans.

- `XMLAGG(...)` → agrupa files en elements (necessari per a les repeticions).

### 💡 Exemple: generar un catàleg XML amb PostgreSQL

Partim de les taules anteriors i volem obtindre un document XML amb tots els comandes:

```html
SELECT XMLELEMENT(name "pedidos",
    XMLAGG(
        XMLELEMENT(name "pedido",
            XMLATTRIBUTES(p.id AS id),
            XMLELEMENT(name "cliente", p.cliente),
            XMLELEMENT(name "fecha", p.fecha),
            XMLAGG(
                XMLELEMENT(name "linea",
                    XMLATTRIBUTES(l.ref AS ref, l.cantidad AS cantidad,
                                  l.precio AS precio)
                )
                ORDER BY l.linea
            )
        )
    )
) AS documento
FROM pedidos p
JOIN lineas_pedido l ON l.id = p.id
GROUP BY p.id, p.cliente, p.fecha;
```

El resultat és un document XML bé format que pot enviar-se a un altre sistema:

```html
<pedidos>
    <pedido id="p10">
        <cliente>Ana Pérez</cliente>
        <fecha>2027-03-02</fecha>
        <linea ref="l01" cantidad="2" precio="15.00"/>
        <linea ref="l02" cantidad="1" precio="48.50"/>
    </pedido>
</pedidos>
```

En **SQL Server** existeix una sintaxi alternativa molt popular, `FOR XML`:

```html
SELECT id, cliente, fecha
FROM pedidos
FOR XML PATH('pedido'), ROOT('pedidos');
```

## **Consultar XML dins d'una base relacional**

A més de generar XML, els SGBD relacionals permeten **consultar dins** de les columnes XML usant XPath i XQuery.

### 💡 Exemple amb PostgreSQL

Cercar el nom dels productes de la taula `productos` del qual preu supera 500 €:

```html
SELECT
    xpath('/producto/nombre/text()', ficha) AS nombre,
    xpath('/producto/precio/text()', ficha) AS precio
FROM productos
WHERE (xpath('/producto/precio/text()', ficha))[1]::text::numeric > 500;
```

En **SQL Server** és més directe gràcies als mètodes del tipus `xml`:

```html
SELECT
    ficha.value('(/producto/nombre)[1]', 'VARCHAR(50)') AS nombre,
    ficha.value('(/producto/precio)[1]', 'DECIMAL(8,2)') AS precio
FROM productos
WHERE ficha.exist('/producto[precio > 500]') = 1;
```

## **Avantatges i inconvenients d'emmagatzemar XML en una base relacional**

| Avantatges | Inconvenients |
| --- | --- |
| Reutilitza la infraestructura SQL existent | La sintaxi SQL/XML varia entre SGBD |
| Consultes i transaccions potents | Descomponer un document és laborioso |
| Seguretat i permisos estàndard | El tipus XML perd la "frescura" del fitxer original |
| Generació i consulta de XML des de SQL | Menys natural per a jerarquías profundas |

## **Resum**

- Un document XML es pot guardar en una base relacional **enter** (tipus `xml`) o **descompost** en taules.

- La família de funcions **SQL/XML** (`XMLELEMENT`, `XMLATTRIBUTES`, `XMLAGG`...) permet **crear documents XML** a partir de taules.

- Els SGBD relacionals permeten **consultar dins del XML** amb XPath/XQuery integrat en SQL.

- L'elecció entre document complet o descomposició depèn de com es vaja a usar després la informació.
