En JavaScript, una de les formes més comuns d'implementar la programació asincrónica és **mitjançant l'ús de callbacks**.
Un **callback** és una funció que es passa com argument a una altra funció i s'executa després de que aquesta última complete la seua tasca.
La idea bàsica d'una funció **callback** és que es “anomena de vuelta” una vegada que es realitza una tasca.
Un exemple comú és el maneig d'esdeveniments. Per exemple, quan es fa clic en un botó en una pàgina web, es pot passar una funció de callback com argument a la funció **addEventListener()** perquè s'execute quan es faça clic en el botó.

## **Funcionament**

- Definició d'una funció callback: Una funció callback es defineix com qualsevol funció que pot ser passada com argument a una altra funció.

- Passar el callback com argument: El callback es passa com argument a la funció principal. Aquesta funció principal executarà el callback en el moment apropiat.

- Ejecució del Callback: Una vegada que la funció principal completa la seua tasca principal, invoca el callback.

> **📌 JS**
> 

> 

```html
function saludo(nombre, callback) {
console.log(`Hola, ${nombre}!`);
callback(); // Llamada a la función callback
}

function despedida() {
console.log('Adios!');
}

saludo('Luis', despedida);
// Output:
// Hola, Luis!
// Adios!
```

Explicació de l'exemple:

- **despedida** és una funció de callback.

- **despedida** es passa com paràmetre a la funció principal **salutació**.

- **salutació** executa **despedida** després de que ha acabat la seua ejecució.

## **Operacions asíncrones**

Els **callbacks** es empren per a realitzar operacions asíncrones. A diferència de les operacions sincróniques, que s'executen en seqüència, les operacions asíncrones permeten que el programa continúe ejecutándose mentre espera que una operació es complete.

Per a veure aquest comportament asíncron, veurem un exemple usant la funció setTimeout.

> **📌 JS**
> 

> 

```html
console.log('Inicio');

setTimeout(() => {
console.log('Tarea Asíncrona Completada');
}, 2000);

console.log('Fin');
```

Explicació de l'exemple:

- **setTimeout** pren una funció de callback (en aquest cas, una lambda)

- La funció lambda s'executarà després d'un retraso de 2000 milisegundos.

- El resultat és que **Fi** es imprime abans que **Tasca Asíncrona Completada**.

## **Manejar errors**

Una de les avantatges dels callbacks en JavaScript és que es poden utilitzar per a manejar errors.
És comú seguir el patró d'error-primer, on el primer argument del callback és l'error i el segon argument és el resultat.
Si una tasca asincrónica falla, es pot anomenar a un callback d'error per a manejar la situació.

> **📌 JS**
> 

```html
function miCallback() {
console.log('La tarea se ha completado');
}

function miCallbackError() {
console.error('La tarea ha fallado');
}

function miFuncion(callback, callbackError) {
setTimeout(function() {
    if (Math.random() < 0.5) {
    callback();
    } else {
    callbackError();
    }
}, 3000);
}

miFuncion(miCallback, miCallbackError);
```

Explicació de l'exemple:

- **miFuncion()** accepta dos callbacks com arguments

- **miCallback()** per al cas d'èxit i **miCallbackError()** per al cas d'error.

- Si la tasca té èxit, es anomena a **miCallback()**, i si falla, es anomena a **miCallbackError()**.

Callback hell
    El callback hell (o piràmide de la perdició) ocorre quan tenim molts callbacks imbricats. Per exemple,

> **📌 JS**
> 

> 

```html
doSomething(function(result1) {
doSomethingElse(result1, function(result2) {
    doAnotherThing(result2, function(result3) {
    // Más código aquí
    });
});
});
```

A mesura que tenim més i més callbacks, cada vegada es torna més lío. Al final, el codi es pot fer molt difícil de llegir i mantindre.

> **📌 Important**
> 

> Per a operacions més complexes considera l'ús de promeses i async/await. Aquestes tècniques ofereixen una forma més limpia i manejable de treballar amb codi asíncron.
