**Fetch** és el nom d'una API per a Javascript amb la quin es poden realitzar peticions HTTP asíncrones utilitzant promeses i de forma que el codi siga un poc més senzill i menys verbose. La forma de realitzar una petició és molt senzilla, básicament es tracta d'anomenar a **fetch** i pasarle per paràmetre la URL de la petició a realitzar:

> **📌 JS**
> 

```html
const promise = fetch("/robots.txt");

promise.then(function(response) {
  /* ... */
});
```

El **fetch()** retornarà una **PROMISE** que serà aceptada quan reba una resposta i només serà rebutjada si hi ha un fallada de xarxa o si per alguna raó no es pudo completar la petició.

El mode més habitual de manejar les promeses és utilitzant **.then()**, encara que també es pot utilitzar **async/await**. Açò es sol reescribir de la següent forma, que queda molt més simple i es eviten constants o variables temporals d'un només ús:

> **📌 JS**
> 

```html
fetch("/robots.txt")
  .then(function(response) {
    /** Código que procesa la respuesta **/
  });
```

Al mètode **.then()** es li passa una funció callback on el seu paràmetre **response** és l'objecte de resposta de la petició que es ha realitzat. En el seu interior es realitza la lògica que es vulga fer amb la resposta a la petició petició.

## **Peticions GET**

La petició **GET** és la més habitual quan volem **obtindre informació** d'una API.

Per exemple, si volem consultar personatges d'una API, podem fer:

> **📌 JS**
> 

```html
fetch("https://jsonplaceholder.typicode.com/users")
  .then(response => response.json())
  .then(data => {
    console.log(data);
  });
```

Les parts del fetch són:

- **fetch("url")** inicia la petició HTTP a l'adreça indicada..

- **response** representa el **OBJECT** de la resposta.

- **response.json()** converteix la resposta en un objecte json.

- **data** conté les dades ja convertits i listos per a treballar amb ells.

La major part de les primeres pràctiques amb APIs es basen en peticions **GET**, perquè són les més senzilles i permeten centrar-se en la lectura, tractament i visualizació de dades. Abans d'introduir altres mètodes com **POST**, **PUT** o **DELETE**, convé que l'alumnat domine bé aquest patró.

## **Devolució del fetch**

**fetch()** retorna una **promesa**. Una **promesa**, com es indica en apartats anteriors, és un objecte que representa un resultat que arribarà més avant. Eixe resultat pot acabar en dos estats principals:

- resolverse correctament, si la petició ha pogut completar-se.

- rechazar-se, si es ha producido un fallada que impedeix completar-la.

Açò significa que no podem escriure el codi com si la resposta estuviera disponible a l'instante. En el seu lloc, hem d'indicar què volem fer quan la resposta arribe. Per això solen utilitzar-se **.then ( )** i **.catch ( )**.

- **.then()** per a quan la petició va bé

- **.catch()** per a quan ocorre un error

<details markdown="1">

<summary>💡 Exemple</summary>

```html
fetch("https://jsonplaceholder.typicode.com/users")
  .then(response => response.json())
  .then(data => {
    console.log("Datos recibidos:", data);
  })
  .catch(error => {
    console.error("Ha ocurrido un error:", error);
  });
```

</details>

És important insistir en que la promesa no conté ja les dades, sinó la possibilitat d'obtenerlos més avant. Aquest detall sol costar al principi, però és clau per a entendre per què el treball amb APIs sempre es organitza en passos encadenats.

## **Conversió a JSON**

La majoria de APIs modernes retornen la informació en format **JSON**. Aquest format s'usa perquè és lleuger, llegible i molt fàcil de transformar en objectes de JavaScript.

JSON significa **JavaScript Object Notation**. Encara que es sembla molt a la sintaxi dels objectes de JavaScript, en realitat és un format de text estructurat per a intercanviar informació entre sistemes.

> **📌 JSON**
> 

```html
{
  "name": "Leanne Graham",
  "username": "Bret"
}
```

Quan recibimos una resposta des d'una API, eixa informació no s'usa directament com objecte JavaScript fins a que la convertim. Per a això es empren diversos mètodes:

| Mètode | Descripció |
| --- | --- |
| **.text()** | Retorna una promesa amb el text pla de la resposta. |
| **.json()** | Idem, però amb un objecte **json**. Equival a usar **JSON.parse()**. |
| **.blob()** | Idem, però amb un objecte **Blob** (binary large object). |
| **.arrayBuffer()** | Idem, però amb un objecte **ArrayBuffer** (buffer binari puro). |
| **.formData()** | Idem, però amb un objecte **FormData** (dades de formulari). |
| **.clone()** | Crea i retorna un clon de la instància en qüestió. |
| **Response.error()** | Retorna un nou objecte **Response** amb un error de xarxa associat. |
| **Response.redirect(url, code)** | Redirige a una **url**, opcionalment amb un **code** d'error. |

En aquest cas, ens anem a centrar en el mètode que convirtent l'objecte de la promesa en un objecte **json** amb **response.json()**.

JavaScript converteix automàticament eixe JSON en un objecte que ja podem usar.

<details markdown="1">

<summary>💡 Exemple</summary>

> **📌 JS**
> 

```html
fetch("https://jsonplaceholder.typicode.com/users")
  .then(response => response.json())
  .then(data => {
    console.log(data.name);
    console.log(data.status);
  });
```

En aquest cas:

- `data.name` seria `"Leanne Graham"`

- `data.username` seria `"Bret"`

</details>

## **Maneig d'errors**

Un dels aspectes més importants quan es treballa amb **fetch()** és aprendre a detectar errors de forma correcta. Moltes vegades es pensa que qualsevol problema farà que el codi entre automàticament en **.catch()**, però no sempre és així.

### **Error de xarxa vs error HTTP**

**fetch()** només entra en **.catch()** automàticament quan hi ha un problema de xarxa real, per exemple:

- no hi ha connexió

- la URL està malament escrita i no es pot resoldre

- el servidor no respon

No obstant això, si el servidor respon correctament però indicant que ha habido un problema, per exemple amb un codi `404` o `500`, la promesa no es rebutja automàticament. En eixe cas, la petició es ha completat des del punt de vista tècnic, però la resposta no és vàlida per al nostre objectiu.

Per això hem de comprovar manualment el valor de **response.ok**. Pot prendre els valors:

- val **true** si la resposta està en el rang 200–299.

- val **false** si ha habido un error HTTP.

<details markdown="1">

<summary>💡 Exemple</summary>

> **📌 JS**
> 

```html
fetch("https://jsonplaceholder.typicode.com/users")
  .then(response => {
    if (!response.ok) {
      throw new Error("Error HTTP: " + response.status);
    }
    return response.json();
  })
  .then(data => {
    console.log(data);
  })
  .catch(error => {
    console.error("Error:", error.message);
  });
```

</details>

## **Estructura petició fetch**

Aquesta és una estructura molt útil per a enseñar i repetir:

> **📌 JS**
> 

```html
fetch("https://jsonplaceholder.typicode.com/users")
  .then(response => {
    if (!response.ok) {
      throw new Error("La petición ha fallado");
    }
    return response.json();
  })
  .then(data => {
    console.log(data);
  })
  .catch(error => {
    console.error(error);
  });
```

Aquesta estructura resume diverses ideas importants:

- primer es fa la petició.

- després es valida la resposta.

- després es converteix el contingut a JSON.

- a continuació s'usen les dades.

- finalment es capturan possibles errors.

## **fetch amb async/await**

Una altra forma de treballar amb **fetch()** és utilitzant **async/await**. Aquesta sintaxi permet escriure codi asíncron amb un estil visual més semblant al codi seqüencial tradicional.

> **📌 JS**
> 

```html
async function cargarDatos() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/users");

    if (!response.ok) {
      throw new Error("Error HTTP: " + response.status);
    }

    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error("Error:", error.message);
  }
}
```
