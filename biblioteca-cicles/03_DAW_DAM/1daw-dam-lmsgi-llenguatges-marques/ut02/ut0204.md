## 1. Arquitectura de Captura de Dades en la Web

Els formularis web (`<form>`) són el mecanisme principal que permet als usuaris interactuar i enviar dades cap a un servidor d'aplicacions o servei API REST. Un formulari defineix el context d'enviament a través de tres atributs fonamentals:
- **`action`:** La URL de l'extrem del servidor (endpoint) que processarà les dades enviades.
- **`method`:** El verb del protocol HTTP utilitzat:
  - `GET`: Les dades del formulari es codifiquen en la cadena de consulta (query string) de la URL (`?nom=Joan&edat=25`). No s'ha d'utilitzar mai per a transmetre dades sensibles (contrasenyes, targetes) ni per a operacions que alteren l'estat del servidor (mutacions de base de dades).
  - `POST`: Les dades es transmeten encapsulades en el cos (body) de la petició HTTP, permetent càrregues volumètriques i mantenint les dades fora de l'historial del navegador.
- **`enctype`:** El tipus MIME utilitzat per a codificar el contingut en peticions POST:
  - `application/x-www-form-urlencoded` (per defecte): Les dades es codifiquen com a parelles clau-valor separades per `&`.
  - `multipart/form-data`: Imprescindible quan el formulari inclou càrrega de fitxers binaris mitjançant `<input type="file">`.
  - `text/plain`: Text pla sense codificar (utilitzat exclusivament en tasques de depuració).

## 2. Controls d'Entrada en HTML5 i Teclats Virtuals

Abans d'HTML5, gairebé tots els camps de text eren genèrics `<input type="text">`, obligant a desenvolupar àmplies funcions de validació amb JavaScript. HTML5 va revolucionar aquest àmbit introduint tipus especialitzats que ofereixen validació nativa i adapten automàticament el teclat virtual en dispositius mòbils:

```html
<form action="/api/usuaris" method="POST" novalidate>
  <fieldset>
    <legend>Dades Personals i Accés</legend>

    <div class="form-group">
      <label for="camp-nom">Nom complet:</label>
      <input type="text" id="camp-nom" name="nom" required minlength="3" maxlength="60" placeholder="Ex: Maria Navarro" autocomplete="name">
    </div>

    <div class="form-group">
      <label for="camp-email">Correu electrònic:</label>
      <input type="email" id="camp-email" name="email" required autocomplete="email">
    </div>

    <div class="form-group">
      <label for="camp-pass">Contrasenya:</label>
      <input type="password" id="camp-pass" name="password" required minlength="8" autocomplete="new-password">
    </div>

    <div class="form-group">
      <label for="camp-edat">Edat:</label>
      <input type="number" id="camp-edat" name="edat" min="16" max="99" step="1">
    </div>

    <div class="form-group">
      <label for="camp-web">Lloc web o GitHub:</label>
      <input type="url" id="camp-web" name="website" placeholder="https://...">
    </div>

    <div class="form-group">
      <label for="camp-dni">DNI / NIE (Expressió Regular):</label>
      <input type="text" id="camp-dni" name="dni" pattern="^[0-9]{8}[A-Z]$" title="8 dígits seguits de la lletra majúscula corresponent">
    </div>

    <div class="form-group">
      <label for="camp-cicle">Cicle Formatiu:</label>
      <input list="llista-cicles" id="camp-cicle" name="cicle">
      <datalist id="llista-cicles">
        <option value="Desenvolupament d'Aplicacions Web (DAW)">
        <option value="Desenvolupament d'Aplicacions Multiplataforma (DAM)">
        <option value="Administració de Sistemes Informàtics en Xarxa (ASIX)">
      </datalist>
    </div>
  </fieldset>

  <div class="form-actions">
    <button type="submit">Registrar Usuari</button>
    <button type="reset">Netejar Camps</button>
  </div>
</form>
```

### Relació Estricta entre `<label>` i Controls

Per a complir amb les directrius d'accessibilitat WCAG (Criteri 1.3.1 i 3.3.2):
- Tot control de formulari ha de posseir una etiqueta `<label>` associada.
- L'atribut `for` del `<label>` **ha de coincidir exactament amb el valor de l'atribut `id` del control**.
- Això permet que els lectors de pantalla anuncien el nom del camp quan l'usuari s'hi posiciona, i a més expandeix l'àrea d'activació interactiva: en fer clic sobre el text de l'etiqueta, el focus salta automàticament al control d'entrada associat.

## 3. Validació Nativa en Client (Constraint Validation API)

El motor d'HTML5 avalua les regles de validació abans de disparar l'esdeveniment `submit`. Si un camp és invàlid, el navegador bloqueja l'enviament i mostra un missatge informatiu natiu.

Principals atributs declaratius de validació:
- **`required`:** Impedeix l'enviament del formulari si el camp roman buit.
- **`minlength` i `maxlength`:** Restringeixen el nombre mínim i màxim de caràcters permesos.
- **`min`, `max` i `step`:** Delimiten els valors numèrics o dates vàlides i l'interval de variació.
- **`pattern`:** Restringeix l'entrada a través d'una expressió regular de JavaScript (RegEx).
- **Pseudoclasses CSS per a feedback visual:**
  - `:valid` i `:invalid`: S'apliquen segons l'estat de compliment de les regles.
  - `:required` i `:optional`: Identifiquen si el camp és obligatori.
  - `:focus-visible`: Permet donar estil al contorn d'accessibilitat quan l'usuari navega amb teclat.
