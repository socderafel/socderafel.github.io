# **Sintaxi i regles de les especificacions de conversió**

Una **especificació de conversió** és el conjunt de regles que determina com es transforma un document d'origen en un document de destí. En XML, l'especificació és la **full d'estils XSLT**; en JSON, l'especificació es expressa mitjançant **filtres jq** o scripts.

Tota especificació de conversió respon a tres preguntes:

- **Què es selecciona?** → localització de les dades d'origen (XPath / JSONPath).

- **Com es transforma?** → regles que generen l'estructura de destí.

- **Què s'obté?** → el document d'eixida.

## **Estructura d'una especificació XSLT**

Una full d'estils XSLT és, a la seua vegada, un document XML. La seua estructura bàsica és:

```html
<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="1.0"
                xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
    <xsl:output method="xml"/>

    <xsl:template match="/">
        <!-- contenido de salida -->
    </xsl:template>

</xsl:stylesheet>
```

### **Regles principals**

#### **1. Selecció de nodes amb `match`**

Cada plantilla indica què nodes del document d'origen va a processar:

```html
<xsl:template match="/">       <!-- el documento completo -->
<xsl:template match="producto"> <!-- todos los elementos producto -->
<xsl:template match="precio">   <!-- todos los elementos precio -->
```

#### **2. Generació d'eixida amb `apply-templates` i `value-of`**

- `<xsl:apply-templates select="...">` delega el processament dels fills en els seus plantilles corresponents.

- `<xsl:value-of select="...">` insereix el valor de text d'un node o atribut.

```html
<xsl:template match="producto">
    <tr>
        <td><xsl:value-of select="nombre"/></td>
        <td><xsl:value-of select="@id"/></td>
    </tr>
</xsl:template>
```

#### **3. Iteració amb `for-each`**

Permet repetir un bloc d'eixida per cada node seleccionat:

```html
<xsl:for-each select="catalogo/producto">
    <p><xsl:value-of select="nombre"/> -- <xsl:value-of select="precio"/> €</p>
</xsl:for-each>
```

#### **4. Condicionals amb `if` i `choose`**

```html
<xsl:if test="precio > 100">
    <td class="caro"><xsl:value-of select="precio"/></td>
</xsl:if>
```

```html
<xsl:choose>
    <xsl:when test="precio > 100">premium</xsl:when>
    <xsl:otherwise>estandar</xsl:otherwise>
</xsl:choose>
```

## **Regles d'una transformació jq**

En jq, l'especificació és una **cadena de filtres** encadenats amb l'operador pipe `|`. Cada filtre rep l'eixida de l'anterior:

```html
jq '.catalogo.producto[] 
    | select(.precio > 50) 
    | {nombre, precio}' catalogo.json
```

Les construccions bàsiques que actuen com regles de conversió són:

- **`select(condición)`** → filtra els objectes que compleixen la condició.

- **`{campo: .origen}`** → construeix un nou objecte (especificació d'eixida).

- **`map(filtro)`** → aplica un filtre a tots els elements d'un array.

- **`if condición then ... else ... end`** → condicional.

- **`. | length`, `. | add`** → funcions d'agregació.

## **Regles generals de bona especificació**

Independentment de la tecnologia, una especificació de conversió ha de:

- **Ser declarativa**: descriure *què* es vol obtindre, no *com* pas a pas.

- **Cubrir tots els casos del document d'origen**: pensar en elements opcionals, buits o repetits.

- **Definir el format d'eixida** de forma explícita (xml, html, text, json, csv).

- **Ser probada contra dades reals**: la validació previa del document d'origen (UP06) redueix errors de conversió.

- **Mantenerse documentada**: una especificació sense comentaris és difícil d'evolucionar.
